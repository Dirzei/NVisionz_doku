Brotli – Kontextmodellierung und ein Wörterbuch mit Umformungen

Was Brotli (RFC 7932) über Deflate hinaus tut: Präfixcodes in zwei Bauarten, drei unabhängige Blockeinteilungen, Literale, deren Code von den zwei vorigen Bytes abhängt, ein Befehlscode aus Einfüge- und Kopierlänge, vier gemerkte Abstände mit Abweichungen, und ein eingebautes Wörterbuch von 122 784 Byte mit 121 Umformungen. Mit Pseudocode nach Brotli, Brotlibaum und Brotliwoerterbuch.

Worum es geht

Brotli ist ein LZ77-Verfahren mit Huffman-artigen Präfixcodes, wie Deflate. Es packt vor allem Text und Webinhalte besser, aus drei Gründen:

  • Kontext. Welcher Präfixcode ein Literal kodiert, hängt von den zwei zuvor ausgegebenen Bytes ab. Nach einem Leerzeichen ist ein Großbuchstabe wahrscheinlicher als nach einem Kleinbuchstaben; Brotli kann dafür verschiedene Codes benutzen.
  • Blockarten. Literale, Befehle und Abstände haben je eine eigene Einteilung in Abschnitte („Blöcke“) mit eigener Statistik; zwischen ihnen wird im Strom umgeschaltet.
  • Statisches Wörterbuch. Ein Rückbezug, der weiter zurückzeigt als alles bisher Ausgegebene, greift in ein eingebautes Wörterbuch aus 13 504 Wörtern und Wortstücken – mit einer von 121 Umformungen (Großschreibung, angehängtes Leerzeichen, abgeschnittene Enden, …). Die ersten Wörter einer HTML-Seite lassen sich so holen, bevor der Packer irgendetwas gelernt hat.

Der Strom und seine Metablöcke

Der Strom beginnt mit der Fenstergröße WBITS (ein Nullbit heißt 16; sonst 3 Bit mm, bei m≠0m \ne 0 ist es 17+m17 + m; sonst weitere 3 Bit: 0 → 17, 1 → großes Fenster außerhalb von RFC 7932, abgewiesen, sonst 8+m8 + m). Das Fenster ist 2WBITS−162^{\text{WBITS}} - 16 Byte. Dann folgen Metablöcke:

FeldBitsBedeutung
ISLAST1letzter Metablock
ISLASTEMPTY1, nur wenn ISLASTletzter und leer – der Strom ist zu Ende
MNIBBLES20–2: 4, 5, 6 Halbbytes für MLEN; 3: Beiwerkblock (wird übersprungen)
MLEN − 14 · MNIBBLESZahl der Ausgabebytes dieses Metablocks
ISUNCOMPRESSED1, nur wenn nicht ISLASTdie MLEN Bytes stehen ab der nächsten Bytegrenze roh

Der kürzeste gültige Strom ist ein einziges Byte: 06 = Bits 0, 1, 1 – Fenster 16, ISLAST, ISLASTEMPTY. Brotli.entpacke(new byte[]{6}) liefert null Byte (nachgerechnet).

Präfixcodes

Brotli baut seine Codes kanonisch wie Deflate, liest sie aber mit dem niederwertigsten Bit zuerst; der Code steht also bitverkehrt im Strom. Brotlibaum legt deshalb je Codelänge eine Tafel über die umgedrehten Codes an und liest Bit für Bit, bis ein Eintrag belegt ist. Ein Code wird auf zwei Arten übertragen:

  • Einfach (erste 2 Bit = 1): 1 bis 4 Symbole unmittelbar, je ⌈log2⁡Alphabetgröße⌉\lceil \log_2 \text{Alphabetgröße} \rceil Bit. Die Längen sind fest: 1 Symbol → 0 Bit; 2 → 1, 1; 3 → 1, 2, 2; 4 → 2, 2, 2, 2 oder (Wahlbit) 1, 2, 3, 3 – in der Reihenfolge, in der die Symbole dastehen.
  • Zusammengesetzt (sonst; die 2 Bit sind die Zahl der übersprungenen ersten Einträge): zuerst die Längen eines Codes über 18 Codelängen-Symbole, in der festen Reihenfolge 1, 2, 3, 4, 0, 5, 17, 6, 16, 7, 8, 9, 10, 11, 12, 13, 14, 15, jede mit einem festen Code variabler Länge (Längen 2, 4, 3, 2, 2, 4 für die Werte 0 bis 5). Dann damit die Codelängen des eigentlichen Alphabets; 16 wiederholt die vorige von null verschiedene Länge (Vorgabe 8), 17 wiederholt Nullen.

Die Wiederholbefehle haben eine Eigenheit: folgen zwei Befehle derselben Art aufeinander, verlängert der zweite den ersten, statt ihn zu ersetzen:

rneu=(ralt−2)⋅2z+3+bits(z),z=2 (Symbol 16),z=3 (Symbol 17)r_{\text{neu}} = (r_{\text{alt}} - 2) \cdot 2^{z} + 3 + \text{bits}(z), \qquad z = 2 \text{ (Symbol 16)},\ z = 3 \text{ (Symbol 17)}

und es kommen rneu−raltr_{\text{neu}} - r_{\text{alt}} weitere Einträge hinzu. So entsteht ein langer Lauf ohne lange Zusatzfelder. Die Brotlibaumprobe baut damit etwa aus einer 8 und vier verlängernden 16ern 256 Symbole zu je 8 Bit.

Festlegung im Framework: Brotlibaum.ausLaengen prüft die Kraft-Summe: jeder Code der Länge ll belegt 2L−l2^{L - l} von 2L2^{L} Blättern, ein vollständiger Code belegt sie genau. Über- und unterbelegte Längen werfen beim Bauen, nicht erst beim Lesen eines freien Codes. Ein Baum mit nur einem Symbol kostet kein Bit.

Befehle: Einfügen und Kopieren

Die Nutzdaten eines Metablocks sind eine Folge von Befehlen. Jeder Befehl heißt: füge II Literale ein, dann kopiere CC Byte vom Abstand DD. Einfüge- und Kopierlänge stehen zusammen in einem Symbol cc aus 704 möglichen:

g=⌊c/64⌋,i=VI(g)+⌊c/8⌋mod⁡8,k=VC(g)+cmod⁡8g = \lfloor c / 64 \rfloor, \qquad i = V_I(g) + \lfloor c/8 \rfloor \operatorname{mod} 8, \qquad k = V_C(g) + c \operatorname{mod} 8

mit den Versatztafeln VI=(0,0,0,0,8,8,0,16,8,16,16)V_I = (0,0,0,0,8,8,0,16,8,16,16) und VC=(0,8,0,8,0,8,16,0,16,8,16)V_C = (0,8,0,8,0,8,16,0,16,8,16). Aus den Codes ii und kk folgen die Längen über Grundwert und Zusatzbits (Einfügen 0 bis 22594+224−122594 + 2^{24} - 1, Kopieren 2 bis 2118+224−12118 + 2^{24} - 1). Für g<2g < 2, also c<128c < 128, steht kein Abstand im Strom: gemeint ist der letzte (Abstandscode 0).

Beispiel: c=130c = 130 → g=2g = 2, i=0i = 0, k=2k = 2: keine Literale, Kopierlänge 4, Abstand steht im Strom.

Abstände

Brotli merkt sich die letzten vier Abstände in einem Ring; zu Beginn des Stroms 4, 11, 15, 16 (der letzte ist 4). Die Abstandscodes bedeuten:

0, 1, 2, 3letzter, vorletzter, drittletzter, viertletzter
4 … 9letzter −1, +1, −2, +2, −3, +3
10 … 15vorletzter −1, +1, −2, +2, −3, +3
16 … 15 + NDIRECT1 … NDIRECT unmittelbar
darübermit Zusatzbits, siehe unten

Mit P=P = NPOSTFIX (0…3) und ND=N_D = NDIRECT (0…15⋅2P0 \dots 15 \cdot 2^{P}) aus dem Metablockkopf und r=Code−ND−16r = \text{Code} - N_D - 16:

z=1+⌊r2P+1⌋,h=⌊r2P⌋,o=(2+(hmod⁡2))2z−4,D=(o+bits(z))2P+(rmod⁡2P)+ND+1z = 1 + \left\lfloor \frac{r}{2^{P+1}} \right\rfloor, \quad h = \left\lfloor \frac{r}{2^{P}} \right\rfloor, \quad o = \big(2 + (h \operatorname{mod} 2)\big)\, 2^{z} - 4, \quad D = \big(o + \text{bits}(z)\big)\, 2^{P} + (r \operatorname{mod} 2^{P}) + N_D + 1

Mit P=0P = 0, ND=0N_D = 0 ergeben die Codes 16, 17, 18 die Abstände 1–2, 3–4, 5–8 – dieselbe geometrische Staffelung wie bei Deflate. NPOSTFIX erlaubt eigene Codes für die unteren Bits, etwa bei Daten mit fester Satzlänge.

Code 0 und Griffe ins Wörterbuch legen nichts in den Ring; jeder andere Abstand wird der neue letzte.

Das statische Wörterbuch

Ist der Abstand größer als Dmax⁡=min⁡(bisher ausgegeben,Fenster)D_{\max} = \min(\text{bisher ausgegeben}, \text{Fenster}), ist das kein Fehler, sondern ein Griff ins Wörterbuch. Die Kopierlänge CC (4 bis 24) ist dann die Wortlänge; aus dem Überschuss folgen Wortnummer und Umformung:

u=D−Dmax⁡−1,Wort=umod⁡2B(C),Umformung=⌊u/2B(C)⌋<121u = D - D_{\max} - 1, \qquad \text{Wort} = u \operatorname{mod} 2^{B(C)}, \qquad \text{Umformung} = \lfloor u / 2^{B(C)} \rfloor < 121

B(C)B(C) ist die Zahl der Bits der Wortnummer für die Länge CC: von 10 Bit für Länge 4 (1024 Wörter) bis 5 Bit für Länge 24 (32 Wörter). Die Summe ∑C=424C⋅2B(C)\sum_{C=4}^{24} C \cdot 2^{B(C)} ergibt genau 122 784 Byte; das Wörterbuch enthält 13 504 Wörter (beides mit Brotliwoerterbuch nachgerechnet).

Eine Umformung ist: Vorsilbe + verwandeltes Wort + Nachsilbe. Die Verwandlung schneidet vorn oder hinten 1 bis 9 Zeichen ab oder schreibt das erste bzw. alle Zeichen groß. Großschreiben ist eine Byteoperation, die UTF-8 kennt: bei einem Byte unter 0xC0 wird ein Kleinbuchstabe durch xor⁡32\operatorname{xor} 32 groß, bei einem Zwei-Byte-Zeichen wird im zweiten Byte xor⁡32\operatorname{xor} 32 gerechnet, bei drei Byte im dritten xor⁡5\operatorname{xor} 5.

Umformung01234591044
Wort 0 der Länge 4timetime␣␣time␣imeTime␣time␣the␣Timetime␣and␣TIME

Werte mit Brotliwoerterbuch.umgeformt(4, 0, u) berechnet. Das Wörterbuch steht zlib-gepackt und Base64-kodiert im Quelltext (in acht Stücken, weil eine Zeichenkette in einer Klassendatei höchstens 65 535 Byte lang sein darf) und wird beim ersten Zugriff mit dem Zlib des Moduls entpackt und gegen seine Länge geprüft.

Blockarten und Kontext

Für jede der drei Kategorien – Literale (L), Befehle (I), Abstände (D) – nennt der Metablockkopf die Zahl der Blockarten (1 bis 256). Bei mehr als einer folgen ein Code für die Blockart, ein Code für die Blocklänge (26 Symbole, Grundwert plus Zusatzbits) und die erste Blocklänge. Ist ein Block aufgebraucht, liest der Leser vor dem nächsten Symbol dieser Kategorie einen Umschaltbefehl: 0 = die Art vor der aktuellen, 1 = nächste Art (+1mod⁡+1 \operatorname{mod} Zahl), sonst Symbol − 2.

Für Literale kommt der Kontext dazu. Jede Literal-Blockart hat einen von vier Kontextmodi; aus den zwei vorigen Bytes p1,p2p_1, p_2 entsteht eine Kontextnummer 0 bis 63:

ModusKontextp1=p_1 = e, p2=p_2 = ␣p1=p_1 = T, p2=p_2 = a
0 LSB6p1mod⁡64p_1 \operatorname{mod} 643720
1 MSB6⌊p1/4⌋\lfloor p_1 / 4 \rfloor2521
2 UTF8Tafel für p1p_1 oder Tafel für p2p_2 (Zeichenklassen)5655
3 mit Vorzeichen8⋅T(p1)+T(p2)8 \cdot T(p_1) + T(p_2), TT = Größenklasse2627

Werte aus der Kontexttafel von Brotliwoerterbuch.kontexttafel() berechnet. Die Tafel hat 2048 Byte: je Modus zwei Tafeln zu 256 Einträgen, eine für p1p_1 und eine für p2p_2; die Kontextnummer ist bei allen vier Modi ihre Veroderung.

Die Kontextabbildung ordnet jedem Paar (Blockart, Kontext) einen von bis zu 256 Literalcodes zu – für Literale 64⋅Arten64 \cdot \text{Arten} Einträge, für Abstände 4⋅Arten4 \cdot \text{Arten} (Kontext der Abstände ist die Kopierlänge: 2, 3, 4 oder mehr). Sie ist zweifach verdichtet: Nullen laufen lauflängenkodiert (Symbole 1 bis RLEMAX stehen für 2s+bits(s)2^{s} + \text{bits}(s) Nullen), und das Ganze steht wahlweise in Move-to-Front-Ordnung, die am Ende umgekehrt wird.

Pseudocode – ein gepackter Metablock (Brotli.datenblock)

schL ← Blockschalter(zahlBis256())   je: Zahl, Artcode, Längencode, erste Länge – verschränkt
schI ← Blockschalter(zahlBis256())
schD ← Blockschalter(zahlBis256())
P ← bits(2);  N_D ← bits(4) · 2^P
modus[j] ← bits(2) für jede Literal-Blockart j
karteL ← abbildung(64 · Arten_L);  karteD ← abbildung(4 · Arten_D)
lese die Literalcodes (256), Befehlscodes (704), Abstandscodes (16 + N_D + 48·2^P)
solange n < ziel:
    schI.vielleichtWechseln();  c ← befehle[schI.art].symbol()
    I ← Einfügelänge(c);  C ← Kopierlänge(c)
    wiederhole I-mal, solange n < ziel:
        schL.vielleichtWechseln()
        k ← tafel[modus][aus[n−1]] oder tafel[modus][256 + aus[n−2]]
        aus[n++] ← literale[karteL[64·schL.art + k]].symbol()
    wenn n ≥ ziel: abbrechen                  Kopierlänge wird dann nicht gebraucht
    wenn c < 128: code ← 0
    sonst: schD.vielleichtWechseln();  code ← abstaende[karteD[4·schD.art + min(C−2, 3)]].symbol()
    D ← abstandAus(code)
    wenn D > min(n, fenster): ausWoerterbuch(D, C);  weiter
    wenn code ≠ 0: lege D in den Ring

wenn n ≠ ziel: Fehler

Festlegung im Framework: Die drei Blockeinteilungen stehen im Kopf verschränkt: Zahl, ihre beiden Codes, ihre erste Blocklänge – dann erst die nächste Zahl. Wer zuerst die drei Zahlen liest, steht ab dem ersten Code um Bits daneben; bei Dateien mit nur einer Blockart je Kategorie fällt das nie auf. Die Anfangsabstände werden so eingetragen, dass Code 0 die 4 liefert, nicht die 16.

Wie geprüft wird

  • Brotliprobe (36 Prüfungen): das Wörterbuch (Länge 122 784, dieselbe Zahl aus den Größenbits gerechnet, SHA-256, die ersten Wörter time, down, life, left, 1024 Wörter der Länge 4, 2048 der Länge 6, 32 der Länge 24, 121 Umformungen); Umformungen einschließlich Großschreibung bei Zwei-Byte-Zeichen; elf Anker von brotli 1.2.0: leer, lauter Literale, Griff ins Wörterbuch, HTML mit Blockarten und Kontext, UTF-8-Umlaute, 126 000 Byte mit großem Fenster, ungepackter Datenblock (Zufall), erzwungene Blockarten, drei Statistiken mit verschränkten Köpfen, enges Fenster von 1024 Byte, enges Fenster zusammen mit Wörterbuch; vier Fehlerfälle.
  • Brotlibaumprobe (29 Prüfungen): der feste Code des Codelängen-Alphabets gegen die Muster aus RFC 7932 3.5; kanonische Codes über 18 000 Symbole in 60 Alphabeten; alle einfachen Codes (NSYM 1 bis 4, beide Wahlbits); zusammengesetzte Codes mit verlängernden Wiederholbefehlen und übersprungenen ersten Einträgen; über- und unterbelegte Längen.

Grenzen

  • Nur lesend; die Erweiterung „großes Fenster“ (außerhalb von RFC 7932) wird abgewiesen.
  • Ein Einfügebefehl, der über das Ende des Metablocks hinausreicht, wird am Ende abgeschnitten statt abgewiesen.
  • Das Wörterbuch wird beim ersten Zugriff vollständig entpackt (122 784 Byte) und bleibt im Speicher.
  • Die Ausgabe liegt vollständig im Speicher; gedeckelt durch die Entpackgrenze.
