Anleitung: einen eigenen Kern für beide Rückenden schreiben

Vom Java-Vorbild zum Kern, der auf OpenCL und Vulkan dasselbe rechnet wie die CPU: die Regeln für den Quelltext, der Aufruf auf beiden Rückenden, die Probe gegen die CPU, die Gegenprobe und die Messung – Schritt für Schritt an einem kleinen Beispiel, einem expliziten Schritt der eindimensionalen Wärmeleitung.

Das Beispiel

Ein expliziter Schritt der Wärmeleitung auf einem gleichmäßigen Gitter mit festen Randwerten:

Tineu=Ti+r(Ti−1−2Ti+Ti+1),r=aΔtΔx2≤12,i=1,…,n−2T_i^{\text{neu}} = T_i + r\,\big(T_{i-1} - 2\,T_i + T_{i+1}\big), \qquad r = \frac{a\,\Delta t}{\Delta x^2} \le \tfrac12, \qquad i = 1, \dots, n-2

Klein genug, um es ganz zu zeigen, und doch mit allem, worauf es ankommt: Nachbarzugriffe, ein Rand, eine Zahl als Parameter, zwei Puffer und viele Schritte hintereinander.

1. Das Java-Vorbild

static void schritt(double[] t, double[] neu, double r) {
    int n = t.length;
    neu[0] = t[0];
    neu[n - 1] = t[n - 1];
    for (int i = 1; i < n - 1; i++) {
        neu[i] = t[i] + r * (t[i - 1] - 2.0 * t[i] + t[i + 1]);
    }
}

Klammern und Reihenfolge der Rechnung sind jetzt festgelegt: erst t[i-1] - 2.0*t[i], dann + t[i+1], dann mal r, dann t[i] +. Der Kern muss genau so rechnen.

2. Der Kern in OpenCL C

#pragma OPENCL EXTENSION cl_khr_fp64 : enable
#pragma OPENCL FP_CONTRACT OFF

__kernel void waerme(const int n, const double r, __global const double* t, __global double* neu) {
    int i = get_global_id(0);
    if (i >= n) return;
    if (i == 0 || i == n - 1) { neu[i] = t[i]; return; }
    neu[i] = t[i] + r * (t[i - 1] - 2.0 * t[i] + t[i + 1]);
}

Die Regeln, die hier sichtbar sind:

  • FP_CONTRACT OFF am Kopf. Unter Vulkan setzt der Übersetzer NoContraction ohnehin an jede Rechnung.
  • Jeder Faden prüft seine Kennung (if (i >= n) return;): gestartet wird auf ein Vielfaches der Arbeitsgruppe aufgerundet.
  • Nur die Teilmenge des Übersetzers (siehe Übersetzer): int, double, bool, Puffer, Zahlen, Hilfsfunktionen; keine float-Zahlen, kein #if, keine Strukturen. Was nicht geht, meldet der Übersetzer mit Zeile.
  • Minimum und Maximum wie Java nur über eigene Hilfsfunktionen (jmin, jmax, siehe Bitgleich), nicht fmin/fmax.
  • Keine Summen über alle Fäden auf dem Gerät, wenn das Ergebnis bitgleich sein soll; die Werte herunterholen und auf der CPU der Reihe nach summieren. Maxima und Minima dürfen parallel reduziert werden.
  • Den Quelltext als Methode ablegen (static String quelle()), nicht als Konstante: eine Konstante setzt der Java-Übersetzer in die Aufrufer ein, und eine Gegenprobe auf den Kern wirkte dann nicht.

3. Aufruf auf beiden Rückenden

OpenCL

Geraet g = OpenCl.oeffne();                        // null: OpenCl.grund() sagt warum
if (g == null || !g.kannDouble()) { /* auf der CPU rechnen */ }
MemorySegment prog = g.programm(quelle(), null);   // Fehler: Ausnahme mit dem Protokoll des Treibers
try (Warteschlange q = new Warteschlange(g)) {     // je Faden eine
    Puffer a = q.puffer(8L * n), b = q.puffer(8L * n);
    q.schreibe(a, t);
    Kern k1 = q.kern(prog, "waerme").arg(0, n).arg(1, r).arg(2, a).arg(3, b);
    Kern k2 = q.kern(prog, "waerme").arg(0, n).arg(1, r).arg(2, b).arg(3, a);
    for (int s = 0; s < schritte; s += 2) { q.starte(k1, n); q.starte(k2, n); }
    q.lies(a, t);                                  // wartet einmal, auf alles
}

Vulkan

envisionz.vulkan.Geraet g = Vulkan.oeffne();       // null: Vulkan.grund()
if (g == null || !g.float64) { /* auf der CPU rechnen */ }
Kernbau.Beschreibung kb = Uebersetzer.uebersetze(quelle(), 64).get("waerme");   // einmal je JVM genuegt
try (envisionz.vulkan.Warteschlange q = new envisionz.vulkan.Warteschlange(g)) {
    envisionz.vulkan.Puffer a = q.puffer(8L * n), b = q.puffer(8L * n);
    q.schreibe(a, t);
    envisionz.vulkan.Kern k1 = q.kern(kb).arg(0, n).arg(1, r).arg(2, a).arg(3, b);
    envisionz.vulkan.Kern k2 = q.kern(kb).arg(0, n).arg(1, r).arg(2, b).arg(3, a);
    for (int s = 0; s < schritte; s += 2) { q.starte(k1, n); q.starte(k2, n); }
    q.lies(a, t);                                  // schickt alles als ein Paket ab und wartet einmal
}

Die Indizes in arg sind auf beiden Rückenden die Stellen der Kernparameter. Zwei Kerne mit vertauschten Puffern statt eines Kerns, dessen Puffer man umsteckt: unter Vulkan bräuchte jedes Umstecken einen neuen Deskriptorsatz, so kommen beide mit einem aus. Gelesen wird erst am Ende – jedes Lesen dazwischen kostet ein Abschicken mit Warten.

Optional und rückfallfest: Soll ein Rechenmodul (etwa ein Löser) die Grafikeinheit nutzen, ohne an FFM zu hängen, bekommt es eine kleine Schnittstelle, und die Umsetzung mit OpenCL bzw. Vulkan liegt in einem eigenen Modul mit META-INF/services-Eintrag – wie Schrittkern im CFD-Löser. Das Rechenmodul bleibt reines JDK und native-image-fähig, und ohne Gerät rechnet es auf der CPU und sagt, warum.

4. Die Probe

Eine Probe ist eine Klasse mit main unter test/. Sie rechnet dasselbe auf der CPU und auf dem Gerät und vergleicht Bit für Bit:

double[] cpu = t0.clone(), gpu = t0.clone(), tmp = new double[n];
for (int s = 0; s < 1000; s += 2) { schritt(cpu, tmp, r); schritt(tmp, cpu, r); }
rechneAufDemGeraet(gpu, r, 1000);
int anders = 0;
for (int i = 0; i < n; i++) if (Double.doubleToLongBits(cpu[i]) != Double.doubleToLongBits(gpu[i])) anders++;
pruefe(anders == 0, "[W-01] 1000 Schritte Waermeleitung, " + anders + " von " + n + " Werten anders");
  • Im Bauraum ohne Karte laufen die Proben gegen die Nachbildungen auf der CPU (für OpenCL ein freier CPU-Treiber, für Vulkan der Software-Treiber aus Mesa, beide mit ….alle=ja zugelassen). Dort ist Bitgleichheit Pflicht.
  • Auf einer Karte darf eine Probe eine Toleranz zulassen, wenn das Gerät nachweislich anders rundet (Division und Wurzel unter Vulkan) – dann bezogen auf die Größe der Variable, nie je Wert (siehe das Abweichungsmaß).
  • Ohne Gerät prüft die Probe den Rückfall und meldet „kein Gerät“ als Hinweis, nicht als Fehler.

5. Gegenprobe und Messung

Jede Probe braucht eine rote Gegenprobe: eine absichtlich verdorbene Stelle, die die Probe fangen muss. Sie steht in test/gegenproben.dat des Moduls, und tools/Gegenprobe.java verdirbt eine Kopie, übersetzt sie und fährt die Probe:

[waerme-rand-vergessen]
datei    = src/beispiel/Waerme.java
alt      = if (i == 0 || i == n - 1) { neu[i] = t[i]; return; }
neu      = if (i == 0) { neu[i] = t[i]; return; }
probe    = beispiel.Waermeprobe
erwartet = FEHL [W-01]

Gute Gegenproben zielen auf die Stellen, an denen Bitgleichheit verloren geht: FP_CONTRACT OFF entfernen, eine Summe rückwärts laufen lassen, eine Klammer verschieben. Bleibt eine Gegenprobe grün, ist die Probe zu stumpf und wird geschärft – etwa mit einem Fall, der die verdorbene Stelle wirklich erreicht.

Zuletzt messen: einmal als Paket, einmal mit Lesen zwischendurch, gegen die CPU mit allen Fäden. Gewinnt das Gerät nur bei großen Feldern, hilft oft, mehr Arbeit in einen Kern zu legen oder mehrere Schritte hintereinander zu starten, bevor gelesen wird.
