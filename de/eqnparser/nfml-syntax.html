NFML-Syntax – Referenz

Die Eingabesprache .nfml in Grammatikform: Lexik, Flowsheet-Ebene (Stromtypen, Modelle, Baugruppen, Anlage), Modellebene (Gleichungen, Schleifen, Bedingungen), Built-in-Funktionen und die Ablaufsprache .task, mit einem vollständigen Beispiel.

Notation und Umfang

NFML (NVISIONZ Flowsheet Modeling Language, Dateiendung .nfml) ist die gleichungsorientierte Modellierungssprache des NVISIONZ-Gleichungslösers, nach dem Vorbild gleichungsorientierter Eingabesprachen der Prozesssimulation. Diese Referenz gibt den Sprachumfang so wieder, wie ihn die beiden Parserstufen tatsächlich annehmen: die Flowsheet-Ebene und die Modellebene.

Notation der Grammatikblöcke: Aus { } ist ein Element zu wählen, [ ] darf entfallen, | trennt Alternativen, { … } mit Auslassungspunkten heißt: beliebig oft wiederholt, durch das genannte Trennzeichen getrennt. Fett gesetzt sind Schlüsselwörter und Zeichen, die wörtlich im Text stehen; das gilt auch für eckige Klammern, die wirklich geschrieben werden (Index, Attributliste), zum Unterschied von den Metaklammern. Schlüsselwörter und Bezeichner sind groß-klein-unempfindlich (intern in Großbuchstaben); Anweisungen enden mit ; und dürfen Zeilenumbrüche enthalten. Unit, Description und Latex sind rein dokumentarisch; es gibt keine Einheitenrechnung.

Kommentare und Grundbegriffe

Kommentare:

SchreibweiseBedeutung
// und #bis Zeilenende
/* … */Blockkommentar, auch mehrzeilig

Grundbegriffe der Grammatik:

EndMark    → $END [ Kommentar ]
ident      → Zeichenband (Buchstabe oder _, dann Buchstaben, Ziffern, _); groß-klein-unempfindlich
qname      → ident { . ident } [ [ index ] ]
value      → integer | real                    (3, 3., .5, 1.5e-4)
string     → "Zeichenband"
spec_name  → Free | Fixed
attr_name  → Value | Lower | Upper | Spec | Unit | Description | Latex | Start
vergleich  → == | != | <> | < | <= | > | >= | .EQ. | .NE. | .LT. | .LE. | .GT. | .GE.
attrs      → value | attr_name : { [ - ] value | string | spec_name | expression } { , … }
             (ein nacktes (3) bedeutet (Value: 3))
groesse    → Aufbauzeit-Ausdruck aus integer-, INTEGERPARAMETER- und SET-Konstanten  (4, N, N+1)

Ausdrücke und Bedingungen

expression    → ( expression ) | { + | - } expression
              | expression { + | - | * | / | ^ } expression
              | value | qname | stdfct ( expression ) | binfct ( expression , … )
log_condition → ( log_condition ) | NOT log_condition
              | log_condition { AND | OR } log_condition
              | expression vergleich expression
              | qname.spec == spec_name

INCLUDE und TITLE

INCLUDE "pfad" ;
TITLE freitext-bis-zeilenende

INCLUDE übernimmt die DECLARE-, MODEL- und MACRO-Blöcke der Bibliotheksdatei; TITLE und PLANT bleiben zurück. Der Pfad gilt relativ zur einbindenden Datei. Mehrfach- und Ringeinbindung werden still übergangen (Wurzeldatei zählt als eingebunden), die Verschachtelung geht bis Tiefe 16, und in Blockkommentaren ist INCLUDE wirkungslos.

DECLARE – Stromtypen

DECLARE
  { STREAM stream_type ( feld { : feld } ) ; }
EndMark

stream_type → ident
feld        → ident [ [ attrs ] ]

Feld-Attribute ersetzen die Vorgaben des Flatteners (Value 1, Grenzen ±1012\pm 10^{12}).

MODEL – Modelle

MODEL model_name
  [ SET ident [ [ groesse ] ] = value { , … } ; ]
  [ STREAM { { INPUT | OUTPUT } : port_name [ [ groesse ] ] ( stream_type ) ; } ]
  [ TYPE { REAL [ ( attrs ) ] : ident [ [ groesse ] ] { , … } ; } ]
  [ EQUATION { anweisung } ]
  [ INITIALIZE { anweisung } ENDINIT ]
EndMark

model_name → ident
port_name  → ident
Start:     expression in den TYPE-attrs; wird je Instanz als INITIALIZE-Zeile ausgegeben

Ports, Variablen und SET-Parameter teilen einen Namensraum; Variablen und SET-Parameter werden zuerst aufgelöst. Ein SET-Parameter ist je Instanz überschreibbar.

MACRO – Baugruppen

MACRO macro_name
  [ SET ident = value { , … } ; ]                         (keine SET-Arrays im MACRO)
  [ STREAM { { INPUT | OUTPUT } : port_name ( stream_type ) ; } ]
  [ UNIT { { model_name | macro_name } : instanz
         [ ( ident = { value | set_ident } { , … } ) ] ; } ]
  [ FLOWSHEET { stream_type : macro_port = instanz.port ; } ]
  [ EQUATION { equation | assert } ]                (kein IF, FOR oder CALL im MACRO)
EndMark

set_ident → SET-Parametername des Macros
instanz   → ident

Die FLOWSHEET-Zeilen eines Macros sind Port-Bindungen: Alias, keine Zusatzgleichung; jeder Anschluss erhält genau eine Bindung. set_ident reicht einen SET-Wert durch: Beim Instanziieren wird der gegebenenfalls überschriebene Wert eingesetzt. Macros dürfen Macros instanziieren, rekursiv; Zyklen werden mit der Kette gemeldet.

PLANT – die Anlage

PLANT
  [ UNIT { { model_name | macro_name } : instanz
         [ ( ident = { value | [ value { , … } ] } { , … } ) ] ; } ]
  [ FLOWSHEET { stream_type : instanz.port [ [ index ] ] = instanz.port [ [ index ] ] ; } ]
  [ EQUATION { anweisung } ]
  [ INITIALIZE { anweisung } ENDINIT ]
EndMark

Jede Verbindung schließt genau einen OUTPUT an genau einen INPUT an; je Stromfeld entsteht eine Gleichsetzung. Es gibt Ganz-Array- und Element-Verbindungen.

Anweisungen der Modellebene

Anweisungen stehen in EQUATION und INITIALIZE von MODEL und PLANT sowie im flachen Modell, das ohne Abschnitte nur aus Deklarationen und Anweisungen besteht.

anweisung → decl | equation | call | spec | assert | forBlock | ifBlock | initBlock

decl      → ident [ [ groesse ] ] AS { REAL [ ( attrs ) ] | INTEGERPARAMETER ( integer ) } ;
            (Arrays sind 0-basiert: A[N] = A[0] … A[N-1]; Value: [Liste] belegt elementweise)
equation  → [ EQN-zahl : ] expression = expression { = expression } ;
            (eine Kette erzeugt mehrere Gleichungen; Residuum LHS − RHS)
call      → CALL ( qname ) = builtin ( qname { , qname } ) ;
          | qname = builtin ( qname { , qname } ) ;
            (Eingaben müssen Variablen sein; die Anzahl wird gegen die Built-in-Registry geprüft)
spec      → qname.spec = spec_name ;                          (arrayweit und strukturell)
assert    → ASSERT expression vergleich expression ;
            (geprüft NACH dem konvergierten Lauf, keine Nebenbedingung)
forBlock  → FOR ( ident = expression ; ident { <= | < } expression )
              { anweisung }
            ENDFOR
            (Schleifenvariable EIN Zeichen; Auflösung zur Flatten-/Parse-Zeit,
             Indexausdrücke wie [i-1] werden konstant gefaltet)
ifBlock   → IF ( log_condition ) [ THEN ] { anweisung }
            { ELSEIF ( log_condition ) [ THEN ] { anweisung } }
            [ ELSE { anweisung } ]
            ENDIF
initBlock → INITIALIZE { anweisung } { ENDINIT | END }
            (im INITIALIZE nur .spec-Bedingungen, kein ELSE)

Ist eine IF-Bedingung zur Parse- oder Flatten-Zeit konstant (Fixed-Größen, INTEGERPARAMETER, .spec-Vergleich), wird sie strukturell gefaltet: Nur der aktive Zweig existiert. Die Bedingungsvariablen werden vermerkt; ändert man eine davon, löst das vor dem nächsten Lauf eine neue Bindung aus (Struktur-Umschaltung, auch mit Wechsel der Freiheitsgrade durch Spec-Anweisungen). Nicht konstante Bedingungen bleiben Laufzeit-IFs.

Die Ablaufsprache .task

Ablaufskripte (Dateiendung .task, ausgeführt vom TaskRunner oder im Task-Reiter der Oberfläche) steuern Folgen von Lösungsläufen über einem Modell: Spezifikationswechsel, Wertetransfer, Rampen und Konvergenzschleifen. Eine Anweisung je Zeile; Kommentar mit # bis Zeilenende. In der Grammatik steht jede Anweisung auf eigener Zeile.

MODEL pfad.nfml                          (lädt das Modell; INCLUDE wird aufgelöst)
TOL value
MAXITER integer
RELAX value
SOLVER ident
ONFAIL { STOP | CONTINUE }
FIX qname [ = value ]                 (ohne Wert: Einfrieren auf dem gelösten Wert)
FREE qname
SET qname = value
TRANSFER qname -> qname              (kopiert den gelösten Wert)
RUN [ freitext ]                       (löst; der Text benennt den Lauf im Protokoll)
PRINT qname { qname }
LOOP integer [ UNTIL qname value ]
  { anweisung }
ENDLOOP

LOOP wiederholt den Rumpf bis zu integer-mal; mit UNTIL endet die Schleife früher, sobald die relative Änderung von qname zwischen zwei Durchläufen unter value liegt. Schleifen lassen sich nicht verschachteln. Vor jedem RUN prüft der Runner die Freiheitsgrad-Bilanz (Zahl der Gleichungen gleich Zahl der freien Größen) und meldet Abweichungen mit den Kandidaten aus dem bipartiten Matching.

Beispiel

Ein Verdichter und eine Drossel hintereinander, mit Randbedingungen am Eintritt: zwölf Stromfelder, neun Modell- und Verbindungsgleichungen und drei Randbedingungen. Die ASSERT-Zeile wird erst nach dem Lauf geprüft.

TITLE Verdichter und Drossel

DECLARE
  STREAM Gas (W : T : P) ;
$END

MODEL Verdichter
  SET PRC = 4.0, ETA = 0.85;
  STREAM
    INPUT  : ein (Gas);
    OUTPUT : aus (Gas);
  EQUATION
    aus.W = ein.W;
    aus.P = ein.P * PRC;
    aus.T = ein.T * (1 + (PRC^0.2857 - 1) / ETA);
$END

MODEL Drossel
  SET K = 0.9;
  STREAM
    INPUT  : ein (Gas);
    OUTPUT : aus (Gas);
  EQUATION
    aus.W = ein.W;
    aus.P = K * ein.P;
    aus.T = ein.T;
$END

PLANT
  UNIT
    Verdichter : v (PRC = 6.0);      # SET-Überschreibung je Instanz
    Drossel    : d;
  FLOWSHEET
    Gas : v.aus = d.ein;             # OUTPUT = INPUT
  EQUATION
    v.ein.W = 10.0;                  # Randbedingungen
    v.ein.T = 288.15;
    v.ein.P = 1.0e5;
    ASSERT d.aus.P > v.ein.P;
$END
Zusammenhang: Das ältere Eingabeformat .cas ist in der CAS-Syntax-Referenz beschrieben. Ein flaches NFML-Modell deckt den Funktionsumfang von .cas ab.
