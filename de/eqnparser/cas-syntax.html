CAS-Syntax – Referenz

Das klassische Eingabeformat .cas in Grammatikform: Lexik, Prozedur- und Variablenblöcke, Deklarationen, Startwerte, Gleichungsteil mit FOR und IF, Eigenheiten des Bestandsparsers und der Weg zu NFML, mit einem vollständigen Beispiel.

Stellung und Notation

CAS (Dateiendung .cas) ist das klassische Eingabeformat des NVISIONZ-Gleichungslösers. Es bleibt als Bestand und Referenzpfad neben NFML erhalten: Die Parser-Weiche entscheidet nach der Dateiendung, alles außer .nfml läuft über den CAS-Parser. Diese Referenz gibt die Grammatik so wieder, wie der Bestandsparser sie tatsächlich annimmt (rekonstruiert aus der Analyse des Parsers und gegen einen Testbestand geprüft).

Notation wie in der NFML-Syntax-Referenz: Aus { } ist ein Element zu wählen, [ ] darf entfallen, | trennt Alternativen. Fett sind Schlüsselwörter und Zeichen, die wörtlich im Text stehen, auch eckige Klammern, die wirklich geschrieben werden. Schlüsselwörter und Bezeichner sind groß-klein-unempfindlich; Anweisungen enden mit ; und dürfen über mehrere Zeilen laufen. Unit, Description und Latex sind rein dokumentarisch.

Sektionen dürfen in beliebiger Reihenfolge stehen: Der Parser liest die Datei zweimal, zuerst Variablen und Prozeduren, dann die Gleichungen.

Ausdrücke und Funktionen

Ein Ausdruck ist für die Grammatik undurchsichtig: Er reicht bis zum nächsten ; und wird von der Auswertungskette des Bestands ausgewertet. Erlaubt sind die Operatoren + - * / ^ und Klammern; ^ ist rechtsassoziativ, und es gilt -x^2 = -(x^2).

PROCEDURE – Aufruf eines Built-ins

PROCEDURE proc_name
  CALL : builtin_name ;
  INPUTS : REAL { , REAL } ;
  OUTPUTS : REAL ;
END

proc_name    → ident                        (Konvention: p + Built-in-Name)
builtin_name → Name aus der Built-in-Registry (identisch zu NFML, siehe NFML-Syntax-Referenz)

Der Name relhumfar25 ist nicht registriert.

VARIABLE und Deklarationen

Langform: ein benutzerdefinierter Typ.

VARIABLE dottedName
  { { LOWER | VALUE | UPPER } : value ;  |  UNIT : string ; }
END

Kurzform (empfohlen):

declaration → dottedName [ [ arraySize ] ] AS typeRef [ ( attr { , attr } ) ] ;
            | ident AS INTEGERPARAMETER ( integer ) ;
typeRef     → REAL | ident                   (ident = Name eines VARIABLE-Typblocks)
attr        → Description: string | Lower: value | Upper: value
            | Value: { value | [ value { , value } ] }
            | Spec: spec_name | Unit: string | Latex: string

Arrays sind 0-basiert: A[N] ist A[0] … A[N-1]; Value: [Liste] belegt elementweise. Fehlende Attribute erhalten die Vorgaben 0, 0, 0 und FREE.

INITIALIZE – Startwerte

INITIALIZE
  { initStmt }
{ ENDINIT | END }

initStmt → equationStmt | callStmt | initIf
           (das Ziel darf auch dottedName.Lower oder dottedName.Upper sein: Schranken-Überschreibung)
initIf   → IF ( initCond ) { initStmt } [ ELSE { initStmt } ] ENDIF
initCond → specCond | intCond | ( { specCond | intCond } ) { AND | && } ( { specCond | intCond } )
specCond → dottedName.SPEC == spec_name
intCond  → operand relOp operand            (nach INTEGERPARAMETER-Ersetzung konstant)

Die Auswertung geschieht in Dateireihenfolge; rechte Seiten dürfen Variablen referenzieren (Werte aus der Deklaration).

Gleichungsteil

equationStmt → [ EQN-eqnId : ] expression = expression ;
               (Residuum LHS − RHS; KEINE Kettengleichungen im CAS-Bestand)
callStmt     → [ EQN-eqnId : ] CALL ( dottedName ) = proc_name ( dottedName { , dottedName } ) ;
               (Eingaben müssen Variablen sein; Anzahl gemäß INPUTS)
forBlock     → FOR ( ident = integer ; ident { <= | < } { integer | ident } )
                 { equationStmt | ifBlock }
               ENDFOR
               (Schleifenvariable EIN Zeichen; keine FOR-Schachtelung;
                Indexausdrücke wie [i-1] werden konstant gefaltet)
ifBlock      → IF ( condition ) einZweig { ELSEIF ( condition ) einZweig } [ ELSE einZweig ] ENDIF
einZweig     → equationStmt | callStmt
               (Laufzeit-IF: genau EINE Anweisung je Zweig, keine Schachtelung; ELSEIF ist Zucker für ELSE IF)
condition    → operand relOp operand | specCond
specStmt     → ident.SPEC = spec_name ;
               (nur UNGEPUNKTETE Namen; wirkt arrayweit, nur in strukturellen Zweigen)

Ist die IF-Bedingung zur Parse-Zeit konstant (Fixed-Größen, INTEGERPARAMETER, specCond), wird sie strukturell gefaltet: Nur der aktive Zweig bleibt bestehen, und dieser darf, anders als der Laufzeit-IF, mehrere Anweisungen enthalten, einschließlich FOR-Blöcken und Spec-Anweisungen.

Eigenheiten und Weg zu NFML

  • Eine FOR-Schleife mit Obergrenze kleiner oder gleich Untergrenze erzeugt still keine Gleichung.
  • Unit, Description und Latex sind rein dokumentarisch.
  • Alte .cas-Modelle ohne VARIABLE- und PROCEDURE-Blöcke sind in aller Regel unverändert gültige flache NFML-Modelle. Bei der Portierung wird ein VARIABLE-Block zur Kurzform AS REAL, und der Prozedurname pName wird zum Built-in-Namen NAME.

Beispiel

Schnittpunkt eines Kreises mit einer Geraden (Lösung X=4,Y=3X=4,\ Y=3) und eine Kette von Werten, die eine Schleife aufbaut: fünf freie Größen, fünf Gleichungen. Weil nur Kurzform-Deklarationen vorkommen, ist die Datei zugleich ein gültiges flaches NFML-Modell.

// Kreis und Gerade, dazu eine Folge A[i] = 1,5 * A[i-1]
R AS REAL (Value: 5.0, Lower: 0.0, Upper: 100.0, Spec: Fixed, Unit: "m");
X AS REAL (Value: 1.0, Lower: 0.0, Upper: 10.0);
Y AS REAL (Value: 1.0, Lower: 0.0, Upper: 10.0);
N AS INTEGERPARAMETER(3);
A[N] AS REAL (Value: [1.0, 1.0, 1.0], Lower: 0.0, Upper: 100.0);

EQN-1: X^2 + Y^2 = R^2;
EQN-2: Y = 0.75 * X;
A[0] = 2.0;
FOR (i = 1; i < N)
  A[i] = A[i-1] * 1.5;
ENDFOR
