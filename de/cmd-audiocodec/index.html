envisionz-commandline-audiocodec

Audiokodierer auf der Kommandozeile, mit Stapellauf

Übersicht des Kommandozeilenwerkzeugs, Stand 29.09.2026. Es bringt den Kodierer des Audiocodec-Moduls auf die Kommandozeile: kodieren, dekodieren, auf Bitgenauigkeit prüfen, den Steckbrief einer Datei lesen und ganze Sammlungen im Stapel durchlaufen.

6Aufgaben (-op:)
2Quelldateien im Paket cmd.audiocodec
8Rückgabewerte
12Prüfungen der Aufrufprobe

Wozu das Werkzeug da ist

Ein Kodierer ist erst dann vertrauenswürdig, wenn man ihn an vielen Dateien gemessen hat. Dieses Werkzeug fährt den Kodierer aus Skripten und über ganze Verzeichnisse: Es kodiert und dekodiert, prüft, ob jede Datei bitgenau zurückkommt, und schreibt die Ergebnisse in eine CSV. Die Rückgabewerte unterscheiden einen Codec-Fehler von einem Datenproblem, sodass ein Skript darauf reagieren kann, ohne Ausgaben zu zerlegen.

Was es kann

java cmd.audiocodec.Audiocodec -op:kodiere    -in:x.wav -out:x.evz [-block:4096]
java cmd.audiocodec.Audiocodec -op:dekodiere  -in:x.evz -out:y.wav [-nachsichtig:nein]
java cmd.audiocodec.Audiocodec -op:pruefe     -in:x.wav
java cmd.audiocodec.Audiocodec -op:steckbrief -in:x.evz

java cmd.audiocodec.Audiocodec -op:stapel -verz:<verzeichnis> \
     [-endung:.wav] [-rekursiv:ja] [-max:n] [-block:4096] \
     [-ausgabe:<csv>] [-leise:nein] [-lpc:32]

java cmd.audiocodec.Audiocodec -op:flac -in:<x.wav|verzeichnis> \
     [-flac:<programm>] [-block:4096] [-bericht:<datei.md>]

Kodieren, dekodieren, Steckbrief

kodiere schreibt aus einer WAV-Datei einen Strom (.evz), dekodiere daraus wieder eine WAV-Datei. Mit -nachsichtig:nein wird ein beschädigter Rahmen nicht übersprungen. steckbrief beschreibt eine kodierte Datei.

Prüfen

pruefe kodiert und dekodiert im Speicher und meldet über den Rückgabewert, ob das Ergebnis bitgenau war. Das ist der schnellste Weg für einen Stapellauf. Es läuft beide Verfahren durch und meldet die Differenz in Prozent.

Stapellauf

stapel geht ein Verzeichnis durch, auf Wunsch rekursiv und begrenzt in der Zahl der Dateien, und schreibt die Ergebnisse in eine CSV. -lpc:0 schaltet die lineare Vorhersage ab und stellt die Grundlinie her, ohne dass etwas neu übersetzt werden muss.

Vergleich mit FLAC

flac ruft das Programm FLAC als fremdes Werkzeug auf. Es wird nicht eingebunden, nur seine Dateigröße und Zeit werden gemessen. Je Datei stehen dem eigenen Kodierer gegenüber: Größe, Anteil, Zeit, bitgenau, Verhältnis der Größen, dazu Summen, als Markdown-Tafel. Ist FLAC nicht zu finden, stehen die eigenen Zahlen trotzdem da, dazu ein Verweis auf die Bezugsquelle. Eine erste Messung an synthetischen Signalen (drei Stereodateien zu je 8 s) ergab eine um 0,6 % kleinere Ausgabe bei etwa 16-facher Rechenzeit einschließlich Java-Kaltstart. Eine Messung an einer echten Sammlung steht aus.

Rückgabewerte

WertBedeutung
0in Ordnung
10eine Datei kam nicht bitgenau zurück
11beim Dekodieren wurden beschädigte Rahmen übersprungen
12eine Datei war nicht lesbar
13-op:flac: FLAC nicht gefunden (die eigenen Zahlen stehen trotzdem da)
1, 2, 3Aufruf-, Schalter-, sonstiger Fehler

Nicht bitgenau und nicht lesbar haben getrennte Werte: das eine ist ein Codec-Fehler, das andere ein Datenproblem.

Daten und Formate

Liest und schreibt WAV-Dateien, schreibt den kodierten Strom als .evz und die Stapelergebnisse als CSV. Der Vergleich mit FLAC schreibt einen Bericht als Markdown.

Worauf es aufbaut

  • audiocodec: der Kodierer und Dekodierer, der Stapellauf und das Prüfen. Dieses Werkzeug enthält nur Schalterauswertung und Ausgabe.
  • audiometrik: die Messstrecke, mit der Ergebnisse verglichen werden.
  • cmd-audiometrik: die Kommandozeile der Messstrecke, deren Projekt hier im Klassenpfad liegt.

Stand und Grenzen

  • Alle sechs Aufgaben sind vorhanden. Der Stapelmodus ist durch die Proben des Codec-Moduls abgedeckt, die Aufrufe durch eine eigene Aufrufprobe.
  • FLAC gehört nicht zum Lieferumfang und muss selbst beschafft werden.
  • Der Vergleich mit FLAC an einer echten Sammlung steht aus.
