Entropiekodierung – Golomb-Rice mit Abschnitten

Die Rechnung hinter Restkodierung (Verfahren 1): Zickzack-Abbildung, Golomb- und Rice-Codes, warum sie zu Prädiktionsresiduen passen, die abschnittsweise Wahl des Parameters mit genau abgezählten Bits, der Escape-Fall für Rohwerte. Mit Bitbild, Pseudocode nach dem Quelltext, Rechenbeispiel, Proben und Grenzen.

Worum es geht

Nach der Vorhersage bleibt ein Residuum, eine Folge ganzer Zahlen, die meist klein und um null verteilt sind. Große Beträge kommen vor, aber selten. Ein Code fester Länge – etwa 17 Bit für jeden Wert – verschenkt hier fast alles. Gesucht ist ein Code, der kleinen Beträgen kurze und großen Beträgen lange Wörter gibt und der ohne Tabelle auskommt, weil jede Tabelle mit übertragen werden müsste.

Golomb-Codes leisten genau das für eine geometrische Verteilung, und ein Prädiktionsresiduum ist dieser Verteilung näherungsweise ähnlich: Die Wahrscheinlichkeit fällt mit dem Betrag etwa exponentiell. Die Rice-Codes sind der Sonderfall mit einer Zweierpotenz als Teiler; sie kommen ohne Division aus und haben nur einen Parameter kk.

Die Zickzack-Abbildung

Rice-Codes sind für nichtnegative Zahlen gemacht. Das Residuum wird deshalb umkehrbar so abgebildet, dass kleine Beträge beiderlei Vorzeichens kleine Zahlen ergeben:

u={2xx≥0−2x−1x<00,−1,1,−2,2,…↦0,1,2,3,4,…u = \begin{cases} 2x & x \ge 0 \\ -2x - 1 & x < 0 \end{cases} \qquad 0, -1, 1, -2, 2, \dots \;\mapsto\; 0, 1, 2, 3, 4, \dots

Im Code ist das u=(x≪1)⊕(x≫31)u = (x \ll 1) \oplus (x \gg 31) in 64-Bit-Arithmetik und zurück x=(u≫1)⊕−(uand⁡1)x = (u \gg 1) \oplus -(u \,\mathrm{and}\, 1) mit vorzeichenlosem Schub. Die Rechnung in long ist nötig, weil das Verdoppeln des kleinsten int sonst überläuft; uu liegt dann zwischen 0 und 232−12^{32}-1.

Golomb- und Rice-Codes

Ein Golomb-Code mit Parameter mm zerlegt u=qm+ru = q\,m + r und schreibt den Quotienten qq unär (qq Nullen, dann eine Eins) und den Rest rr binär. Mit m=2km = 2^k ist der Rest einfach das untere kk-Bit-Stück von uu, und die Länge eines Codeworts ist

ℓk(u)=⌊u2k⌋+1+k\ell_k(u) = \left\lfloor \frac{u}{2^k} \right\rfloor + 1 + k

Für eine geometrische Verteilung P(u)=(1−θ)θuP(u) = (1-\theta)\,\theta^u ist der Golomb-Code mit θm≈12\theta^m \approx \tfrac12 optimal unter allen Präfixcodes (Gallager und Van Voorhis). Anschaulich: mm ist so groß, dass die Wahrscheinlichkeit für „noch einmal mm weiter“ gerade ein halbes Bit wert ist, also eine Unärstelle rechtfertigt. Für Rice heißt das grob 2k≈2^k \approx mittlerer Betrag. Der Kodierer verlässt sich aber nicht auf diese Faustregel, sondern zählt für jedes kk von 0 bis 30 die Bits genau ab.

Abschnitte und Escape

Ein Rahmen mit einer lauten und einer leisen Passage braucht in beiden Hälften verschiedene Parameter. Das Residuum wird deshalb in 2P2^P gleich große Abschnitte geteilt, die Partitionsordnung PP läuft von 0 bis 6, und jeder Abschnitt bekommt sein eigenes kk. Die Grenzen sind ⌊Ni/2P⌋\lfloor N i / 2^P \rfloor für i=0,…,2Pi = 0, \dots, 2^P; sie ergeben sich aus der Länge und PP, die Länge selbst steht nicht im Bitstrom, sie folgt aus dem Rahmen.

Lohnt sich Rice in einem Abschnitt gar nicht – ein Knacken, ein Sprung –, wird er als Escape mit dem Parameterwert 31 markiert. Dann folgen fünf Bit Wortbreite ww und die Werte als Zweierkomplement mit ww Bit. So kann ein einzelner Ausreißer den Abschnitt verteuern, aber nicht sprengen.

Die Kosten einer Aufteilung werden genau gezählt:

K(P)=3+∑Abschnitte(5+{5+nwEscape∑uℓk(u)sonst)K(P) = 3 + \sum_{\text{Abschnitte}} \left(5 + \begin{cases} 5 + n\,w & \text{Escape} \\ \sum_{u} \ell_k(u) & \text{sonst} \end{cases}\right)

Gewählt wird die Partitionsordnung mit dem kleinsten K(P)K(P). Die Suche bricht ab, sobald ein Abschnitt im Mittel weniger als acht Werte hätte: So kurze Abschnitte tragen ihre fünf Bit Parameter nicht mehr ein.

Pseudocode – Restkodierung.plane(rest)

bestes ← keins
für P ← 0 bis 6:
    anzahl ← 2^P
    wenn anzahl > 1 und N / anzahl < 8:  Schluss          ganzzahlige Division
    kosten ← 3 + 5·anzahl
    für jeden Abschnitt [von, bis):
        (k, w, K) ← besteParameterwahl(rest, von, bis)
        kosten ← kosten + K;  wenn k = 31: kosten ← kosten + 5
    wenn bestes = keins oder kosten < bestes.kosten:  bestes ← (P, k[], w[], kosten)
gib bestes zurück

funktion besteParameterwahl(rest, von, bis):
    n ← bis − von;  wenn n = 0: gib (0, 0, 0) zurück
    umax ← max zickzack(rest[i])
    w ← min(32, Bitlänge(umax) + 1);  besteK ← n·w;  bester ← 31      Escape als Maßstab
    für k ← 0 bis 30:
        K ← 0
        für jedes u = zickzack(rest[i]):
            q ← u ≫ k;  wenn q > 8192: k unbrauchbar, abbrechen
            K ← K + q + 1 + k;  wenn K ≥ besteK: abbrechen
        wenn nicht abgebrochen und K < besteK:  besteK ← K;  bester ← k
    gib (bester, w, besteK) zurück

Pseudocode – schreibe und lies

funktion schreibe(bs, rest, rezept):
    schreibe P (3 Bit)
    für jeden Abschnitt:
        schreibe k (5 Bit)
        wenn k = 31:  schreibe w (5 Bit);  je Wert: rest (w Bit, Zweierkomplement)
        sonst:      je Wert: u ← zickzack(rest);  unär(u ≫ k);  wenn k > 0: u und (2^k − 1) (k Bit)

funktion lies(bl, N):                                N kommt von außen
    P ← lies 3 Bit
    für jeden Abschnitt [⌊N·i/2^P⌋, ⌊N·(i+1)/2^P⌋):

        wenn k = 31:  w ← lies 5 Bit;  je Wert: liesVorzeichen(w)

Festlegung im Framework: Unär heißt hier qq Nullen, dann eine Eins; alle Felder mit dem höchstwertigen Bit zuerst. Die Rezeptkosten sind keine Schätzung, sondern die Bitzahl, die schreibe tatsächlich erzeugt; der Kodierer benutzt sie für die Wahl zwischen Rohform, festem Prädiktor und LPC. Ein Quotient über 8192 macht ein kk unbrauchbar, damit kein einzelnes Codewort ausufert.

Rechenbeispiel

Sechzehn Residuenwerte: 3, −1, 0, 4, −6, 2, −2, 1, 0, −3, 5, −1, 2, 0, −4, 1. Die Zickzack-Werte sind 6, 1, 0, 8, 11, 4, 3, 2, 0, 5, 10, 1, 4, 0, 7, 2. Die Summe der Codewortlängen je kk:

kk01234
∑ℓk(u)\sum \ell_k(u)8061596780

Bei k=0k = 0 ist jedes Wort u+1u + 1 Bit lang, das bestraft die größeren Werte; bei k=4k = 4 kostet jedes Wort mindestens 5 Bit, das bestraft die vielen kleinen. Das Minimum liegt bei k=2k = 2, passend zum mittleren uu von 4. Mit drei Bit Partitionsordnung und fünf Bit Parameter kostet das Residuum 3+5+59=673 + 5 + 59 = 67 Bit; plane liefert genau diese Zahl, und schreibe erzeugt genau 67 Bit. Zwei Abschnitte zu acht Werten (P=1P = 1) wurden ebenfalls gerechnet und waren nicht billiger; P=2P = 2 wird nicht mehr versucht, weil ein Abschnitt dann nur vier Werte hätte. Rohbits im Escape-Fall wären 5 je Wert, 80 für den Abschnitt – die Rohform verliert.

Ein einzelnes Wort: x=−6x = -6, u=11=10112u = 11 = 1011_2, k=2k = 2. Quotient q=2q = 2, Rest r=3r = 3; geschrieben wird 001 11, fünf Bit, wie ℓ2(11)=2+1+2\ell_2(11) = 2 + 1 + 2.

Wie geprüft wird

Die Bausteinprobe (30 Prüfungen) prüft die Bausteine einzeln:

  • Bitstrom: Felder von 3, 16, 1 und 8 Bit und ein Unärwert kommen zurück; ein Unärlauf von 1000 Nullen mit dem Byte danach ebenso; ein abgeschnittener Lauf wird abgewiesen; Zweierkomplement mit 8 Bit für −1, −128, 127, 0, −64, 63.
  • Zickzack: umkehrbar für 0, ±1, 2, −2, ±1000, Integer.MAX_VALUE und Integer.MIN_VALUE + 1; 0, −1, 1 werden zu 0, 1, 2.
  • Restkodierung an drei Fällen mit 2048 Werten – kleines Rauschen, dasselbe mit einem Ausreißer von 900 000, konstant 100 000: Umlauf unverändert, und die Rezeptkosten weichen höchstens 8 Bit von der geschriebenen Bitzahl ab (die Auffüllung bis zur Bytegrenze).
  • Nullresiduum: 1024 Nullen kosten höchstens 1024+641024 + 64 Bit, also rund ein Bit je Wert.

Die Umlaufprobe prüft den Rice-Weg im ganzen Codec (Rahmenseite).

Grenzen

  • Ein Bit je Wert ist die Untergrenze. Jedes Rice-Wort hat mindestens die abschließende Eins. Bei sehr kleinen Residuen (Stille nach der Vorhersage, fast konstante Signale) ist ein Code mit Bruchteilen von Bits im Vorteil; das ist der Anlass für den Bereichskodierer.
  • Keine Anpassung innerhalb eines Abschnitts. Der Parameter gilt für den ganzen Abschnitt; die kleinste Abschnittslänge ist im Mittel acht Werte, die feinste Aufteilung 64 Abschnitte.
  • Escape-Breite. Die Rohbreite wird aus dem größten Zickzack-Wert plus ein Vorzeichenbit bestimmt und ist damit oft ein Bit breiter als nötig. Sie steht in 5 Bit; eine Breite von 32 ist dort nicht darstellbar. Ein Escape-Abschnitt mit Beträgen ab etwa 2292^{29} käme deshalb nicht zurück. Aus 8- bis 24-Bit-Material mit festen Prädiktoren entstehen solche Beträge nicht (Ordnung 4 bei 25 Bit: höchstens 2282^{28}).
  • Geometrische Annahme. Für Residuen, die nicht annähernd geometrisch verteilt sind, ist Rice nicht optimal; die Abschnitte fangen nur Schwankungen der Größenordnung ab.
