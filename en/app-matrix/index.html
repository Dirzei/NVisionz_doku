The running framework as a wireframe world

Overview of the app, as of 29 September 2026. A game that is also a diagnostic view: the plug-ins, the log lines and the memory and thread figures of the running application appear as nodes and glyphs in a grid world, in which a figure assembles herself piece by piece.

23source files in 8 packages
1dependency: framework-api
6progress grades (0, 3, 7, 12, 20, 32 fragments)
2mini-games for the backdoor
365checks in six probes
3help pages, German and English

What the app is for

The Matrix is meant as a game that grows over several sessions, yet it is not mere decoration: what is seen in the world is the real state of the program.

Whoever plays with the view sees which apps are loaded, which of them are writing messages at the moment, how full the memory is and how many threads are running. The Matrix thus shows in passing how the framework is put together. For the design it mattered that world, rules and presentation stay separate, so that the game can grow later without rebuilding the machine.

What it can do

The world

A wireframe floor with nodes on a ring around a rotating core. Everything in it stands for something real.

  • Application nodes: one node per registered app. Only the app's description is read; nothing is started.
  • System nodes: one node for memory (HEAP CORE) and one for threads (THREAD NEXUS), with values from the runtime.
  • Data glyphs: lines from the application's log travel along the edges as glyphs. A line is assigned to the node of the app whose identifier appears as a whole segment in the name of the source.
  • Operation: arrow keys rotate, arrows or wheel zoom, a click picks the target, Escape leaves the Matrix.

Analyse and collect

With the action key one analyses a node and collects code fragments, three per session.

  • An analysis panel shows the node's real values, for instance memory use.
  • A collected fragment appears as a card with a few stylised lines of code from the framework.
  • Progress is kept across sessions and has six grades. The higher it is, the less often glitches disturb and the more clearly the figure speaks.

The face

A stylised face designed for the purpose, as a triangle mesh. It is also the progress display.

  • The mesh is a shell with relief features (eye sockets, nose, cheekbones, lips, chin). At low progress the points lie scattered; with each find triangles come together, the left eye first, the mouth last.
  • The face always turns toward the player. The eyes glow as narrow slits and follow the turn of the head.
  • The texts are written for the purpose and staged by grade, from fragmented to awakened. Error messages appear stuttering, with offset colour copies.
  • A portrait field from app-relief can be added to the computed face as a displacement. If it is missing or damaged, the display silently falls back to the computed shape.

Backdoor: breaking doors open

On an app node the H key starts a small keyboard game. If you win, the real app opens; the Matrix then acts like a launcher.

  • Memorise a sequence: an arrow sequence is shown briefly and must be typed blind.
  • Timing lock: an oscillating pointer must be hit inside the target window, three bolts, one miss loses.
  • With higher progress the games help more: the display time gets longer, the window wider. A failure locks the node for 30 seconds.
  • The core, the system nodes and the Matrix itself cannot be broken into.

Missions, watch and marks

Missions demand real diagnostic work on the running program.

  • Missions: analyse a node; find the node with the most log lines in the session; find the source of the last warning or error; trigger a garbage collection on the memory node that frees a given share.
  • Watch: a score rises with break-in attempts, failures and actions and decays with time. Patrols circling the ring raise it on contact. If it overflows, the backdoors close and the application nodes are locked for 20 seconds; the fragments stay.
  • Marks on nodes, from break-ins or permanently from missions, unlock actions: reading the log tail, showing metadata, garbage collection.

Data and formats

  • Save file: XML with a version number in the user directory. Unknown versions and damaged files are discarded, not half read. Writing fails silently so the game never disturbs the program. The Matrix is not restored with the workspace.
  • Content as XML: grade thresholds, texts per grade, the error template, missions, watch values and code fragments live in a content file. A file of one's own in the user directory takes precedence over the bundled one, and the built-in default applies if both are unusable. Texts and missions can thus be maintained without changing the program.
  • Portrait field: displacement field in XML format from app-relief, read by a small reader of its own.

What it is built on

  • framework-api: the only dependency. Registration as an app and reading the descriptions of all registered apps.

Everything else is code of its own: vectors, a camera with pinhole projection, wireframe drawing with Java2D, disturbance effects (slice offset, colour-channel split, scan lines, noise) only during bursts. The world talks to the real system only through one interface (SystemProbe); it can therefore be checked without a user interface and could run with a dummy. The log connection attaches to the JVM's root logger and is removed on closing.

Status and limits

Version 1.0 is fixed as a closing point: controls, analysis, progress across sessions, glitches, the staged voice and the face. Added since are the content as XML, the missions with real diagnostics, watch and marks, and the fragments as code. Six probes with 365 checks in total cover vectors, camera, progress, save file, mini-games, world, face, disturbance effects and content; the eyes are checked for colour and rotation.

The Matrix runs only in the multi launcher, not in the single-app launchers. It is not an operating tool: it only reads out the runtime and changes nothing except triggering garbage collection. Further expansion stages (for instance more mini-games) have not been started.
