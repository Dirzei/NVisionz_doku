envisionz-framework-viewer

Typesetting HTML, CSS, formulas and SVG – without a browser

Function overview for the presentation of the envisionz framework, as of 28 Sep 2026. An own typesetter in pure Java for the help and documentation pages of all apps: HTML parser, CSS cascade with variables, box model with flexbox, grid and tables, TeX formula setting after the TeXbook, SVG graphics, plus a view with search, history and DE/EN switching. No embedded browser, no JavaFX, no third-party library. For each stage: purpose, API, use in the framework, applications, examples. The examples are shortened.

Principles of the module

No browser. An embedded browser would mean tens of megabytes and a dependency – a steep price for help pages in a GraalVM image. The typesetter needs only the JDK.
A curated subset. It sets what technical documentation needs: blocks, flexbox, grid, tables, a fixed sidebar, formulas, SVG. What is not supported (pseudo-classes, child and sibling combinators, attribute selectors) is skipped, not answered with an error.
A pipeline in four stages. HTML text → HtmlParser (node tree) → StyleResolver (cascade) → LayoutEngine (box tree) → painting in Swing.
Checked against the specification. The anchors of the probes are CSS 2.1, Flexbox, Grid, Cascade 4, Variables, WHATWG HTML, SVG 1.1 and the TeXbook, each with the section given; recomputed in pixels.
Large brackets are drawn. Growing delimiters are created as paths, not from glyph pieces: those exist only in fixed size steps, and in between the bracket always looks wrong.
Free of framework types. The facade returns a JComponent and knows no framework class; the typesetter is wired in through framework-swing.

Facade and view envisionz.viewer · envisionz.viewer.ui

DokuRendererService – the one door to the outside

Returns the embeddable view and opens files, HTML text or class-path resources; for *_de.html/*_en.html it recognises the language versions itself. Toolbar and status line can be hidden for a pure display, the content width fixed and a shared stylesheet set.

Methods

  • createView() → JComponent
  • open(File), openHtml(String), openResource(prefixOrPath), goToAnchor(id)
  • setStylesheet(css), setContentWidth(px), setChromeVisible(b), setHorizontalScrollAllowed(b), isMathFallbackActive()

Used in

framework-swing: HelpPanel, Ueber, HelpDialogeqnparser: formula view, diagnostics tabstats: results and help panelfileanalysis: help cardvia HelpPanel: chiffre, maps, neural, pdfdigitizer, thermovia Ueber: settings

What for

Manuals and method descriptions in every app, formulas of an NFML model in the equation solver, statistics results as a typeset page.

DokuRendererService svc = new DokuRendererService();
panel.add(svc.createView(), BorderLayout.CENTER);
svc.openResource("/envisionz/apps/eqnparser/help/index");      // loads index_de.html or index_en.html

DocView, DocViewerPanel, DocRenderer – display, search, history

DocView is the full view: toolbar with DE/EN and full-text search, back history, status line, re-layout on every resize. If it detects a fixed sidebar (nav{position:fixed}), it puts sidebar and content into two separate scroll panes. DocViewerPanel paints and hit-tests links; DocRenderer is the facade HTML → box tree and holds the user-agent stylesheet.

Methods

  • DocView: loadFile, loadHtml, loadResource, scrollToAnchor, goBack(), setContentWidth
  • DocRenderer: render(html, width) → Box, renderContentWithoutFixed, addStylesheet, setRootFontSize
  • DocViewerPanel.setDocument(box, width), setLinkHandler

Used in

internal: behind DokuRendererService

What for

Linked documentation sets such as the equation solver's pages with fixed navigation on the left; typesetting pages headless to check them.

Parsing, cascade and layout run synchronously on the calling thread, usually the EDT, and every window resize re-lays the page. That is fine for help pages; very large documents would stall the event thread.

Parsing HTML envisionz.viewer.html

HtmlParser, Node, Entities, MathExtractor

A forgiving parser that never fails hard: void elements, implicit closing of li, p, td, tr and table sections after WHATWG, raw text in <style>/<script>, comments and doctype, unquoted attribute values. Entities resolves named and numeric character references. MathExtractor looks for \( … \) (inline) and $$ … $$ (display) in text nodes and replaces them with <nvz-math> nodes.

Methods

  • HtmlParser.parse(String) → Node
  • Node: children(), is(tag), attr(name), classList(), id()
  • MathExtractor.process(root), MATH_TAG = "nvz-math"

Used in

internal: DocRenderer, StyleResolver, LayoutEngine

What for

Read hand-written help pages and generated reports even when they are not strictly well-formed; take over formulas in MathJax style.

CSS cascade envisionz.viewer.css

CssParser, Selector, StyleResolver, ComputedStyle

User-agent stylesheet, <style> blocks, extra stylesheets and style attributes in the cascade with specificity and !important; inheritance; var(--x) resolved against the root variables. Selectors: type, class, ID, universal, compound and descendant. At-rules such as @media and @import are skipped. The shorthands margin, padding, border-width clear individual values set before. Background, formulas and pseudocode →

Methods

  • CssParser.parse(css), rules(), rootVariables()
  • Selector.parse(raw), matches(el), specificity()
  • new StyleResolver(), addStylesheet(css), resolve(document) → Map<Node, ComputedStyle>
  • Length (PX, EM, REM, PERCENT, PT, EX), CssColor.parse, Display.defaultFor(tag)

Used in

internal: DocRenderer, LayoutEngine

What for

One shared documentation stylesheet with variables, a dark theme via redefined variables.

em refers to the element's font and compounds with nesting (three levels at 0.9 em give 0.73), rem to the root's. That is why both exist.

Box model and layout envisionz.viewer.box

LayoutEngine with FlexLayout, GridLayout, TableLayout

Block layout with collapsing margins, line breaking by font metrics instead of character count, position: fixed/absolute for the sidebar. Flexbox, CSS grid with repeat(auto-fill|auto-fit, minmax(…, 1fr)), repeat(N, …) and gap, tables with column widths from the minimum widths of their content. Boxes: BlockBox, TextRunBox, ImageBox (ImageIO, relative paths). Background, formulas and pseudocode →

Formula setting envisionz.viewer.math

TexLexer, TexParser, MathLayout, MathRenderer – a TeX subset

Fractions (\frac, \dfrac, \tfrac, \cfrac), binomial coefficients (\binom), roots, super- and subscripts, big operators with limits (\sum, \int, \prod, \lim), accents (\hat, \bar, \vec, \dot, \tilde), fonts (\mathbf, \mathrm, \mathbb, \mathcal, …), \text verbatim with spaces, \operatorname, \bmod/\pmod, the decimal comma 0{,}5, environments with \begin/\end, \underbrace/\overbrace with labels, \left/\right and \big…\Bigg. Spacing between atoms after TeXbook p. 170. Unknown commands appear as their own name. Background, formulas and pseudocode →

Methods

  • new MathRenderer(mathFont), render(tex, Mode.DISPLAY | INLINE, sizePx) → MathBox
  • TexSymbols: Greek letters, relations, arrows, set and logic symbols, operators (169 entries)

Fonts envisionz.viewer.paint

MathFontProvider, FontResolver

The formula font in this order: embedded STIX Two Math (/fonts/STIXTwoMath-Regular.otf, SIL OFL 1.1), otherwise an installed maths font (STIX Two Math, STIXGeneral, Cambria Math, Latin Modern Math …), otherwise serif; isUsingFallback() tells whether the fallback applies. FontResolver maps font-family lists to AWT fonts, cached, and finds a font that has a given character.

Methods

  • MathFontProvider.getMathFont(sizePx), isUsingFallback(), RESOURCE_PATH
  • new FontResolver(), resolve(style, sizePx), fontForGlyph(base, codePoint)

Used in

internal: MathRenderer, LayoutEngineoutside via DokuRendererService.isMathFallbackActive()

What for

The same formula appearance on every machine, even without an installed maths font.
