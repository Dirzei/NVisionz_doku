The Cascade – Background

How rules, specificity, source order, the style attribute, !important, variables and inheritance combine into the computed style of an element, and how that yields a font size in pixels.

What this is about

Several rules can match one element and set the same property differently: one for all p, one for the class .a, one for the id #x, plus a style attribute on the element itself. Which one wins is not decided by order alone but by the cascade of CSS 2.1, section 6.4, in the form of Cascade 4. Pages that are meant to look the same in a browser and in the viewer need the same precedence, otherwise a colour or a font size silently shifts.

The style of an element arises in three steps: first the declarations of all matching rules are put into a fixed order and applied (cascade), then missing inheritable properties are taken from the parent (inheritance), finally lengths are converted to pixels (computed value). The viewer does this once per node of the document tree, from the root downwards, so that a child finds the finished style of its parent.

Specificity and precedence

Every selector gets a specificity from three counters: aa ids (#x), bb classes (.a), cc element names (p). The universal selector * does not count. The viewer folds them into a single number:

s=100a+10b+c,spseudo-element=s+1s = 100\,a + 10\,b + c, \qquad s_{\text{pseudo-element}} = s + 1

A selector with several compounds, such as #k .a p, counts all compounds of the chain: a=1,b=1,c=1a=1,\ b=1,\ c=1, so s=111s = 111. A pseudo-element (::before, ::after) adds one.

The rules matching an element are sorted by ss ascending; at equal ss the position in the source decides, later before earlier. The declarations are then applied in that order, each later one overwriting an earlier one for the same property. From weak to strong the precedence is therefore:

  1. normal rules, by specificity, at a tie by source order;
  2. the style attribute of the element (not applied to pseudo-elements);
  3. !important declarations from the rules, again by specificity and order;
  4. !important in the style attribute, which is entered last and so beats the important rules.

Variables and shorthands

After the declarations are applied, values of the form var(--name, fallback) are resolved. The fallback ends at the parenthesis that belongs to var(; the nesting depth is counted so that a fallback such as rgb(0,0,0) stays complete. Variables may point to variables; at depth 16 resolving stops, which protects against cycles. If var() occurs in the shorthand font, the individual values are only filled in and not overwritten again, so that later individual declarations stay.

Inheritance

After the cascade the element takes from its parent all inheritable properties it does not carry itself. In the viewer these are: color, font-family, font-size, font-style, font-weight, line-height, letter-spacing, text-align, text-transform, white-space, list-style, list-style-type, text-decoration and visibility. All others, such as margin, padding or background, apply to the element itself only.

The font size is the exception: it is not passed on as text, since 2em in the child would otherwise mean two em of the already doubled parent size. What is inherited is the computed value, which the size computation delivers through the link to the parent style.

Computed values

The font size in pixels ff follows from the declaration, the parent size fPf_P and the size of the root fWf_W:

If the declaration is missing or unreadable, f=fPf = f_P; at the root fWf_W takes the place of fPf_P. A worked example with fW=16f_W = 16: a div with 2em has f=32f = 32; a span inside it with 0.5em has f=0.5⋅32=16f = 0.5 \cdot 32 = 16; with 1.5rem it would be 1.5⋅16=241.5 \cdot 16 = 24; with 12pt it is 12⋅96/72=1612 \cdot 96/72 = 16.

Without a declaration the line height is 1.2 times the font size. The remaining lengths (margins, padding, borders) are resolved only during layout against the width of the containing block, see Blocks, lines and floats.

Pseudocode

function computeStyle(node, parentStyle, pseudo):
    style ← new style linked to parentStyle
    hits ← []
    for each rule i in rules:
        s ← rule.matches(node, pseudo)             // -1 if not
        if s ≥ 0: hits.add([i, s])
    if pseudo ≠ none and hits empty: return none
    sort hits by (s, i) ascending                   // specificity, then source
    important ← empty map
    for each hit in hits:
        for each declaration d of the rule:
            if d important: important[d.name] ← d.value
            else: style.set(d.name, d.value)
    if pseudo = none and node has a style attribute:
        for each entry a in the attribute:
            if a important: important[a.name] ← a.value
            else: style.set(a.name, a.value)
    for each entry in important: style.set(name, value)
    resolveVariables(style)                         // var(…), depth ≤ 16
    style.rememberOwn()
    for each property p of parentStyle:
        if p inheritable and p ≠ "font-size" and style lacks p:
            style.set(p, parentStyle.value(p))
    return style

function fontSizePx(style, rootPx):
    parent ← style.parent ≠ none ? fontSizePx(style.parent, rootPx) : rootPx
    if style has no font-size or unreadable: return parent
    choose unit:
        em: x · parent    rem: x · rootPx    %: x / 100 · parent
        pt: x · 96 / 72   px and 0: x

Source: envisionz.viewer.css.StyleResolver.computeFor, .inheritMissing, .substituteVars, envisionz.viewer.css.Selector.computeSpecificity and envisionz.viewer.css.ComputedStyle.fontSizePx.

Decision in the framework: specificity is the single number 100a+10b+c100a + 10b + c, not a triple; selectors and elements with a pseudo-element get +1+1. The cascade sorts by ss first, then by source rank. A normal style attribute beats every normal rule, !important beats the normal attribute, and an important attribute beats an important rule. The font size is inherited as a computed value in pixels, not as text; without a declaration the line height is 1.2 times the font size.

How it is checked

css.Kaskadenprobe (83 checks) holds cascade, inheritance and variables against CSS 2.1 and Cascade 4, with the precedence of normal and important declarations, nested var() with parentheses in the fallback, and the inheritance of 2em. css.Rechenstilprobe (109 checks) recomputes computed values in pixels. css.Stilprobe checks selectors including the child combinator >, css.Zaehlerprobe (31) the CSS counters. The checks compute from the specification, not against the code itself; faulty versions are recorded as counter-experiments (deliberately corrupted code that must turn red).

Limits

  • Specificity as one decimal number computes like CSS as long as no digit reaches ten; from ten classes in one selector the counter spills into the ids digit, where CSS compares the triple stepwise.
  • The precedence by origin (user agent, user, author) exists in the viewer only as a built-in user-agent sheet that counts as the first group of rules.
  • The viewer does not know calc(). For the font size an unreadable declaration falls back to the parent value; the unit ex is approximated as half the font size.
  • The shorthands background and font are read in simplified form.
