envisionz-framework-core

The foundation every app runs on

Function overview for the presentation of the envisionz framework, as of 28 Sep 2026. The default implementations of the contracts from framework-api, without UI and on the JDK only: app registry via ServiceLoader, event bus, service registry, logging, workspace persistence with StAX, plus three helpers for files and streams and a small JSON reader. For each building block: purpose, API, use in the framework, applications, examples. The examples are shortened. Some API names are German (e.g. Schreibstrom = write stream, Programmordner = program folder, Dateibetrachter = file viewer, lesen/schreiben = read/write); they are shown unchanged.

Principles of the module

No UI. Everything a host needs to run apps, without Swing: the Swing host and a headless test host stand on the same core.
JDK only. StAX for XML, java.util.logging for the log, ServiceLoader for the apps. The only project edge is framework-api.
Low on reflection for native-image. Persistence is hand-written StAX. The only reflection sits in AppRegistry.discover(); standalone launchers bypass it with register(desc, HelloApp::new).
One order, not two. AppRegistry.all() sorts by id. On the JVM and in the native image the discovery order differs, and in a toolbar made only of icons a moved app looks like a missing one.
Errors do not vanish. A throwing listener does not take the others down; a failed writer thread reaches the reader as an IOException with its cause; an unknown format version throws instead of being guessed.
Portable workspace. Paths under path:… are saved relative to the XML file and made absolute again on load; writing is atomic via a temporary file.

App registry envisionz.core.registry

AppRegistry – which apps exist and how to get a new instance

discover() loads all apps via the ServiceLoader and keeps a descriptor and a factory per app; opening a tab creates a fresh instance through the factory. register adds an app by hand without reflection. all() is the only place where the order of menu and toolbar is decided. Background, formulas and pseudocode →

Methods

  • AppRegistry.discover(), discover(ClassLoader)
  • register(AppDescriptor, Supplier<App>) → AppRegistry (chainable)
  • all() → List<AppEntry> by id, findById(id), newInstance(id)
  • record AppEntry(descriptor, factory)

Used in

framework-swing: FrameworkBootstrap, SwingHost, MenuBuilder, ToolbarBuilderlauncher-multi, launcher-hello-standalone, launcher-eqnparser-standaloneapp-settings: VerzeichnisKarte

What for

The multi-app program finds all apps on the class path; a standalone launcher registers exactly one app; the settings app lists the apps for their start directories.

Example 1 – standalone launcher without reflection (as in launcher-hello-standalone)

AppRegistry registry = new AppRegistry()
        .register(new HelloApp().descriptor(), HelloApp::new);

Example 2 – find all apps and open one

AppRegistry reg = AppRegistry.discover();
for (AppRegistry.AppEntry e : reg.all()) System.out.println(e.descriptor().id());
App neu = reg.newInstance("charts");
Under native-image every app class found by discover() needs an entry in the reflection configuration, because the factory calls getDeclaredConstructor().newInstance().

Event bus and service registry envisionz.core.events · envisionz.core.services

SimpleEventBus and SimpleServiceRegistry

The bus delivers synchronously on the publishing thread, by the exact runtime type of the event, in order of subscription. It iterates over a snapshot (a listener may unsubscribe during delivery) and catches runtime errors per listener: the others still get the event, the error goes to the log as a warning. The service registry is a ConcurrentHashMap from type to implementation. Background, formulas and pseudocode →

Methods

  • new SimpleEventBus(): publish(E), subscribe(Class<E>, Consumer<E>)
  • new SimpleServiceRegistry(): register, get → Optional, unregister

Used in

framework-swing: SwingHost holds one instance eachthrough it every app using ctx.eventBus() / ctx.services()

What for

Hand tables between apps, FocusAppEvent to the host, the hex viewer as a service.

Worker threads that want to publish must switch to the EDT themselves via SwingUtilities.invokeLater: the bus does not change threads.

Saving and loading the workspace envisionz.core.persistence

PersistenceManager – facade with path relativisation and version check

On save, every property with the prefix path: (tabs, sections, items) is stored relative to the XML file, as long as the result does not start with more than three ../; otherwise, and across different drives, the path stays absolute. Afterwards the original values are restored, even on error. On load, relative paths become absolute again, and StateMigrator checks the format version. Background, formulas and pseudocode →

Methods

  • new PersistenceManager(): save(PersistableState, Path), load(Path) → PersistableState
  • PATH_PREFIX = "path:"
  • StateMigrator.migrate(state) – "1.0" only; blank counts as 1.0, anything else throws IllegalStateException

Used in

framework-swing: SwingHost.saveWorkspace / loadWorkspace

What for

Take a workspace together with its project folder to another machine; recognise old files instead of misreading them.

Example

PersistenceManager pm = new PersistenceManager();
pm.save(state, Path.of("sitzung.xml"));
PersistableState zurueck = pm.load(Path.of("sitzung.xml"));

StaxStateWriter, StaxStateReader – the XML format

Hand-written StAX, UTF-8, indented by two spaces: <envisionz-state version savedAt>, inside it <tabs>/<tab type title> with <properties>, <section name> and <items>/<item>, finally <activeTab>. The writer first writes to a temporary file in the same folder and then moves it with ATOMIC_MOVE (fallback: an ordinary move). The reader switches off DTD and external entities and keeps unknown properties.

Methods

  • write(state, Path), write(state, OutputStream) (stream stays open)
  • read(Path), read(InputStream)

Used in

internal: PersistenceManager

What for

A crash while saving leaves no half-written file; the file stays readable and comparable by hand.

Logging envisionz.core.logging

JulFrameworkLogger – FrameworkLogger on java.util.logging

configure is called once at start-up: it resets the LogManager and attaches the console, a rotating file (<name>-%g.log, 10 MB per file, 10 files) and an early buffer for up to 1,000 records. The early buffer catches the start-up messages before the log console of the UI exists; drainEarlyBuffer() delivers them and switches the buffer off. Time stamps in the file use Locale.ROOT; stack traces are included.

Methods

  • JulFrameworkLogger.configure(Path logFile, Level) – once; null = console only
  • new JulFrameworkLogger(String | Class), forClass, forName
  • drainEarlyBuffer() → List<LogRecord>

Used in

framework-swing: FrameworkBootstrap, SwingLogHandler

What for

Trace what happened during start-up and operation of the EXE, which has no console window.

Example – as in FrameworkBootstrap

JulFrameworkLogger.configure(workspaceDir.resolve("logs").resolve(appName + ".log"), Level.INFO);
FrameworkLogger logger = new JulFrameworkLogger("envisionz");

Files and streams envisionz.core.io

Schreibstrom – turning a writer into a reader

The producer writes in its own daemon thread into a pipe with a 1 MiB buffer, the consumer reads from it. When the pipe is full, the producer waits. No intermediate result has to sit in memory as a whole; a byte[] holds at most 2 GiB, a DVD title set has almost three. If the producer fails, the next read throws an IOException with the cause, even for an Error in the writer thread.

Methods

  • new Schreibstrom(Schreiber, String threadName) – is an InputStream
  • Schreiber.schreibe(OutputStream) (functional interface; writer, write)
  • read, available, close() (waits at most 500 ms for the thread)

Used in

app-forensik: ForensikPanel, VideoRestore, Farbversatz, Lupe, StapelBeleg, DrizzleProbeframework-restore: Sprungsucher

What for

Split and process video streams from DVD title sets without putting gigabytes into memory.

Example – as in app-forensik

try (InputStream ein = new Schreibstrom(aus -> quelle.videoAus(aus), "Bildstrom-Trenner")) {
    // ein.read(...) pulls while the producer writes
}

Programmordner – where the program lives and where caches may go

In the native image the folder next to the EXE, on the JVM user.dir. tmpOrdner creates a sub-folder under <program folder>/tmp; without write permission there it falls back to ~/.<appName>/tmp/… and records the reason. raeumeAuf (clean up) removes files untouched for longer than the given number of days. A cache is never the source.

Methods

  • programmordner(), tmpOrdner(appName, name) → Path
  • rueckfallgrund() (fallback reason; null while none), raeumeAuf(folder, days) → count

Used in

app-epds: Zwischenspeicher (cache), status line

What for

A cache of imported measurement data that is available faster at the next start and disappears after 90 days.

Example – as in app-epds

Path ordner = Programmordner.tmpOrdner(APP, "epds");
int weg = Programmordner.raeumeAuf(ordner, 90);
String ausweich = Programmordner.rueckfallgrund();       // once into the status line

Dateibetrachter – a service that shows a file byte by byte

The interface through which the hex viewer registers in the service registry. Another app can hand it a file without knowing it; if it is not registered, that is information, not an error.

Methods

  • zeige(Path datei) (show)

Used in

app-fileanalysis: FileanalysisPanel, HexPanel (register)app-hdf5reader: KatalogTab (ask)

What for

Open a file from the HDF5 reader's catalogue in the hex viewer.

Reading and writing JSON envisionz.core.json

Json – a small reader and writer on java.base

Value tree made of ordinary Java types: LinkedHashMap for objects (order kept), List, String, Long and Double, Boolean, null. The output is character-identical to Python's json.dump(…, indent=2, ensure_ascii=False), so generated configuration files can be compared line by line with earlier Python results.

Methods

  • Json.lesen(String) → Object; throws IllegalArgumentException with position
  • Json.schreiben(Object) → String

Used in

ready, no callers outside the probes yet

What for

Read and write configuration files without including a JSON library.

Example

Map<?, ?> cfg = (Map<?, ?>) Json.lesen(Files.readString(pfad));
Files.writeString(pfad, Json.schreiben(cfg));
