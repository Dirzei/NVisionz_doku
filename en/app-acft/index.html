envisionz-app-acft

Read, change and write back aircraft files without loss

Overview of the app, as of 29 September 2026. An editor for the aircraft files (*.acft) of an aircraft performance program: edit and plot function tables, change values of other objects, bring in data from CSV or H2. Whatever is not touched stays identical, byte for byte.

What the app is for

An aircraft performance program describes an aircraft in one file: masses, geometry, engine and aerodynamic maps as function tables. The file format is not openly documented. Anyone who wants to fill such tables with their own data, for instance maps from a calculation, so far has only the program's own input screens.

The app opens these files, shows their structure as a tree, lets you edit and plot the function tables, and writes the file back. Because the format is not specified, it works by the template principle: a file produced by the program is loaded completely, changed in a targeted way and saved again. What you do not touch is not rewritten.

What it can do

Lossless load and save

The promise: load, save, compare, and there is no difference.

  • Every object of the file is kept with all its original lines; objects that were not touched are written back unchanged.
  • A round-trip check in the toolbar shows this on the loaded file itself.
  • Numbers are written in the notation of the original, because a mathematically equal number in a different notation may be read differently without any error showing.

Tree and two editors

On the left the tree: file, objects, sections; for tables the axis blocks with their point counts.

  • Table mode for function tables with one, two or three axes: edit points, read and write CSV, show the meta fields.
  • Object mode for all other objects: sections with value lines, numbers are validated, index identifiers are locked, only changed lines are replaced.
  • Changed objects carry an asterisk in the tree; unsaved changes hold back closing.

Plotting the function tables

Next to the data, every table has a Plot tab.

  • Roles per column (x, y, function value, constraint), expression and value as a filter, a range with minimum and maximum.
  • Defaults: tables with one axis as a line, with two axes as a contour, with three axes as a contour with a free third axis. The third axis can be sliced to a plane or laid over the contour as isolines.
  • Complete grids are drawn as a grid contour, irregular point clouds through a Delaunay triangulation.
  • Multiple values per point are resolved by a selectable strategy: last value, first, mean, minimum, maximum or an error message.
  • Chart, axis, legend and colour-scale options, data points as an overlay, several isoline variables.
  • Undoing a zoom returns to the limits typed in the axis dialog.

Bringing in data

CSV or H2 data replace the points of a table, only on an explicit button press.

  • Load sources: CSV is converted into an H2 database next to the file; a current existing one is reused.
  • The tree gets a node "Data" with a pageable table per source.
  • Columns are taken over with a role (x, y, z, f); filters also work on columns without a role and run inside the database.
  • Sorting follows the block format of the file (z, y, x ascending) and cannot be chosen. Duplicate grid positions are resolved by a strategy.
  • Before replacing, a preview shows points, blocks and duplicates; replacing asks for confirmation. The variable configuration can be saved and loaded as XML.

Data and formats

  • Read and write: *.acft files; the objects with their markers, type line and sections are preserved. Function tables with one to three axes are edited in typed form; the zero-dimensional table is preserved unchanged.
  • Tables: CSV import and export without a database; CSV and .mv.db as data sources.
  • Side file: plot configuration and chart style live in <file>.acft.chartcfg.properties next to the file. Isolines and data-point settings are not saved yet.
  • Session: the file path and the selection in the tree are remembered.

What it builds on

  • framework-api: registration as an app and session state.
  • framework-data: CSV reader and type detection, H2 store, units.
  • framework-swing: tree tables, chart option cards, background runner, searchable selection fields.
  • framework-chart: line and contour charts, Delaunay triangulation.

There is deliberately no dependency on app-charts: the plot setup dialog is rebuilt from the same framework building blocks. The core envisionz.apps.acft.io is free of user interface code.

State and limits

Finished are lossless reading and writing, both editors, plotting of the tables with isolines, the data import with a configuration file, and three help pages in both languages (overview, format, operation). Large files are loaded, plotted and converted in the background.

The core is tested by the round trip with the real example files: load, save, compare byte for byte. In addition there is a self-test, a test against corrupted files (no crash, cleanly rejected) and a test of number notation under several locales.

Limits: Only the function tables have a dedicated screen; all other objects go through the general value editor, including values with a limit switch (such as a maximum take-off mass), which have no special interface. The example files at hand contain no function tables; reading and writing them rests on tests with tables generated for the purpose. A direct route from the tables to app-charts is only noted as a possibility.
