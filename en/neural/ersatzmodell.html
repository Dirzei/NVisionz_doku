Surrogate model, ensemble and the .ennet format – background

The computation behind SurrogateModel, Ensemble and NetIO: how network and normalisers become a function on raw physical values, what the spread of an ensemble measures and how a model is stored and read back bit for bit – with pseudocode following the source, a complete file example, checks and limits.

What this is about

A trained network on its own is hardly usable as a map: it expects normalised inputs and returns normalised outputs. Whoever calls it in a cycle calculation would have to know with which mean and spread every column was normalised during training – and carry these numbers along. Forgotten or mixed-up normalisation is, according to the class description, the most frequent source of error with network surrogates.

The SurrogateModel turns this into one unit: network, input and target normalisers and metadata belong together, are stored together and loaded together. predict takes raw physical values and returns raw physical values. On top sit the Ensemble, which averages several such models and reports their disagreement as a measure of uncertainty, and NetIO, which writes everything into a readable XML file with bit-exact weights.

The evaluation chain

With input normaliser (ox,sx)(o^x, s^x), target normaliser (oy,sy)(o^y, s^y) and the network function NN:

predict(x)=sy⊙N(x−oxsx)+oy,\text{predict}(x) = s^y \odot N\!\left(\frac{x - o^x}{s^x}\right) + o^y,

where division and ⊙\odot act column by column. Both normalisers are optional: if one is missing, nothing is computed in its place. Classification models (such as glyph recognition) have no target normaliser because their outputs are logits.

Pseudocode – SurrogateModel.predict(raw)

x ← (inputNorm ≠ none) ? inputNorm.transform(raw) : raw
y ← net.run(x)                                     copy of the output
return (targetNorm ≠ none) ? targetNorm.inverse(y) : y

Source: envisionz-framework-neural/src/de/envisionz/neural/model/SurrogateModel.java. At construction, of(…) checks that the dimension of each normaliser matches the number of network inputs or outputs.

Framework convention: copy() copies the network deeply and the metadata shallowly; the normalisers are shared, they are immutable. metadata() returns the live table – whatever is entered is stored with the model. ModelSearch.trainFinal enters created, spec, epochs_run, train_loss and, if there is a validation set, val_loss and r2_val; glyph recognition enters charset and raster_n. Like the network, a surrogate model is not thread-safe: one copy per thread.

Ensemble: mean and spread

Training the same network several times on the same data, only with different initial values, lands the runs in different, roughly equally good minima. Where data lie, they agree – the data force them to. Where there are no data, each network takes its own course. The Ensemble uses both: the mean smooths the response and averages out the chance of the initial values, the spread shows where the models disagree.

yj=1K∑k=1Kyj(k),sj=1K−1∑k=1K(yj(k)−yj)2.\bar y_j = \frac{1}{K}\sum_{k=1}^{K} y_j^{(k)}, \qquad s_j = \sqrt{\frac{1}{K-1}\sum_{k=1}^{K}\bigl(y_j^{(k)} - \bar y_j\bigr)^2}.

The spread is a measure of model uncertainty: it grows outside the training range. The module documentation records this as measured – spread 0.02 to 0.04 inside the training range against 0.16 to 0.23 outside. A quantile band (three models with the pinball loss, see Training) measures something else: the spread of the data themselves, such as measurement noise. The band does not reliably stay wide outside the data; the ensemble spread says nothing about the noise inside.

Pseudocode – Ensemble.predictStd(raw)

p[k] ← member[k].predict(raw)     for k ← 1 to K
mean ← Σ p[k] / K                  per output
if K < 2:  return 0              one model has no spread
return √( Σ (p[k] − mean)² / (K − 1) )

Source: envisionz-framework-neural/src/de/envisionz/neural/model/Ensemble.java. The constructor requires at least one member and the same number of inputs and outputs for all members.

Framework convention: The spread is the sample standard deviation (divisor K−1K - 1). The members must be trained with different seeds. With the same seed, the same data and no dropout all runs are bit-identical and the spread is exactly zero everywhere – the feature would look as if it worked while measuring nothing.

The .ennet format

NetIO writes a surrogate model as XML in version 1. The layout:

<ennet version="1">
  <meta>  <entry key="…" value="…"/> …  </meta>
  <net inputs="n">
    <layer in="…" out="…" activation="SILU" [dropout="0.2"]>
      <weights encoding="base64-double-le">…</weights>
      <bias encoding="base64-double-le">…</bias>
    </layer> …
  </net>
  <normalizer role="input"  type="ZSCORE"> <offset>…</offset> <scale>…</scale> </normalizer>
  <normalizer role="target" type="ZSCORE"> … </normalizer>
</ennet>

Weights and biases are stored as Base64 over the raw bytes of the double values in little-endian order – every bit is preserved. The normaliser parameters are plain text written with Double.toString; its shortest decimal representation is read back by Double.parseDouble to exactly the same number. Together this gives a bit-exact round trip: a loaded model delivers the same bits as the stored one.

Pseudocode – NetIO.load(path)

reader ← StAX reader, DTD off, external entities off         hardening against XXE
for each start element:
    ennet      → check version = 1                          otherwise exception
    entry      → meta[unescape(key)] ← unescape(value)
    net        → inputs ← inputs
    layer      → read in, out, activation, dropout (optional)
                 weights ← decode(Base64, expected out·in values)
                 bias    ← decode(Base64, expected out values)
    normalizer → role input or target, otherwise exception; offset and scale as plain text
    otherwise  → skip                                       forward compatible
check inputs > 0 and at least one layer
net ← builder with seed 0: hidden layers, the last one as output
for each layer k:  check in_k = out_(k−1);  copy weights and bias
return SurrogateModel.of(net, inputNorm, targetNorm, meta)

Source: envisionz-framework-neural/src/de/envisionz/neural/io/NetIO.java. Every read or format error, including an unknown activation, surfaces as an IOException naming the file.

Characters outside ASCII

The metadata contain text – column names, units, the character set of a glyph model. The JDK's XML writer replaces a character with a question mark if it cannot be represented in the platform encoding – regardless of which encoding it is told to use for the file. The fault only shows on machines without a UTF-8 environment, and the same file is then damaged elsewhere; it was observed that the degree sign disappeared from the character set of a glyph model. NetIO therefore writes every character above 126 as an escape made of a backslash, "u" and four hexadecimal digits, and doubles a real backslash; reading converts both back. The file is thus pure ASCII and independent of the environment.

Worked example

A model with one input and one output, the network a single linear neuron with weight 1.0 and bias −2.5, input normaliser ZSCORE with o=10o = 10, s=4s = 4, target normaliser MINMAX with o=0.5o = 0.5, s=2s = 2, one metadata entry "einheit = °C". NetIO.save writes exactly this file:

<?xml version="1.0" encoding="UTF-8"?>
<ennet version="1">
<meta>
<entry key="einheit" value="°C"/>
</meta>
<net inputs="1">
<layer in="1" out="1" activation="LINEAR">
<weights encoding="base64-double-le">AAAAAAAA8D8=</weights>
<bias encoding="base64-double-le">AAAAAAAABMA=</bias>
</layer>
</net>
<normalizer role="input" type="ZSCORE">
<offset>10.0</offset>
<scale>4.0</scale>
</normalizer>
<normalizer role="target" type="MINMAX">
<offset>0.5</offset>
<scale>2.0</scale>
</normalizer>
</ennet>

As a double, −2.5 is C004 0000 0000 0000; read in reverse the bytes end in 04 C0, which gives "BMA=". The degree sign appears as the escape for U+00B0. predict(14) computes (14−10)/4=1(14 - 10)/4 = 1, then 1⋅1−2.5=−1.51 \cdot 1 - 2.5 = -1.5, then −1.5⋅2+0.5=−2.5-1.5 \cdot 2 + 0.5 = -2.5 – checked with the stored and the loaded model.

For the ensemble: three linear models y=xy = x, y=2x+1y = 2x + 1, y=3x+2y = 3x + 2 deliver the values 2, 5, 8 at x=2x = 2. Mean 5, sample standard deviation (9+0+9)/2=3\sqrt{(9 + 0 + 9)/2} = 3.

How it is checked

  • Round trip (TestMain [7]): a 16–16 surrogate with both normalisers and metadata from trainFinal is saved and loaded; at 50 random raw inputs the largest difference of the predictions must be exactly 0.0, the metadata must be equal and contain r2_val. The file had 4723 bytes in the run.
  • Dropout rates (TestMain [13]): after the round trip the first layer again has rate 0.2, the output layer 0, and the output is bit-identical.
  • Ensemble (Optimiererprobe): mean 5 and sample standard deviation 3 as above, a single model has spread 0, predictAll agrees with predict, an empty ensemble and members with different input counts are rejected, members() returns a copy.
  • Loading from a directory (Optimiererprobe): a library of self-written .ennet files including a broken one; the broken one yields null or NaN instead of an exception.

Limits

  • Only version 1 is read; any other version number is rejected. Unknown elements within version 1 are skipped.
  • The ensemble spread is not a calibrated confidence interval. With few members it is itself uncertain, and it only captures differences arising from different initial values.
  • A surrogate model does not know where its training data lay. It keeps computing outside without warning; the ensemble spread is the only built-in hint.
  • The file is not compressed. For the usual network sizes this is irrelevant.
  • Not thread-safe; copy() per thread.
