Beam search and error rate – decoding and rating CTC outputs

The computation behind Strahlsuche and Fehlerrate: why greedy decoding finds the most probable path and not the most probable output, how prefix beam search works with two probabilities per prefix, where a language model comes in and how the edit distance rates a recognised sequence – with pseudocode following the source, a recomputed example, checks and limits. Training with CTC is on the page CTC.

What this is about

After training the network delivers, per time window, a distribution over the characters. What is sought is the character sequence ll that fits best – the one with the largest probability P(l∣x)P(l \mid x), i.e. the largest sum over all its paths. This search is called decoding. It cannot be solved exactly because the number of possible sequences explodes with length; two approximations are implemented: greedy decoding and beam search.

Afterwards the recognised sequence has to be rated. "Right or wrong" is too coarse for sound sequences – between "house" and "mouse" lies one sound, between "house" and "telephone" several. The usual measure is the edit distance relative to the length of the correct sequence: the phone error rate.

Greedy decoding

Ctc.gierig takes the character with the largest logit in every window and then collapses the path (equal neighbours into one, blanks removed). That is the most probable path – but what is sought is the most probable output, and it has many paths whose probabilities add up.

The difference is not a subtlety. If in five consecutive windows the blank stands at 0.70 and a sound at 0.30, greedy decoding picks the blank in every window and the sound disappears. The probability that it is emitted in at least one of the five windows, however, is

1−0.705=0.832.1 - 0.70^5 = 0.832 .

More precisely, computed with Ctc.verlust on these five windows: the output "a" has 0.537, "a a" 0.282, the empty output only 0.168. This explains why a CTC model with a low loss can decode badly when greedy: the loss measures the sum over all paths, greedy decoding sees only one.

Prefix beam search

Beam search does not follow paths but prefixes – outputs begun – and keeps only the best BB per time step (the beam width). For each prefix ll two probabilities are carried, both as logarithms:

  • p−(l)p^{-}(l): the sum over all paths so far that yield ll and end on a blank,
  • p+(l)p^{+}(l): the sum over all that yield ll and end on the last character of ll.

The split is necessary because a repeated character extends the output only if a blank came before it. With yy the probabilities of the next window, y(ε)y(\varepsilon) that of the blank, p(l)=p−(l)+p+(l)p(l) = p^{-}(l) + p^{+}(l) and cc a character other than blank, the transitions are:

Whoever carries only one number per prefix gets double letters wrong – the same pitfall as in the jump condition of CTC, in another place.

Pseudocode – Strahlsuche.suche(logits, width, language, weight, lengthBonus)

check width ≥ 1, T ≥ 1
lnY ← row-wise log-softmax
beam ← { empty prefix: (p− = 0, p+ = −∞, bonus = 0) }        values as logarithms
for t ← 1 to T:
    next ← {}
    for each (l, p−, p+, bonus) in beam:
        enter: l,  p− ← p(l) + lnY[t][blank],  bonus
        for c ← 1 to K−1:
            if c = last character of l:
                enter: l,     p+ ← p+(l) + lnY[t][c],  bonus
                enter: l + c, p+ ← p−(l) + lnY[t][c],  bonus + contribution(l, c)
            else:
                enter: l + c, p+ ← p(l) + lnY[t][c],   bonus + contribution(l, c)
    beam ← the best "width" entries by p + bonus
sort beam by p + bonus, best first
for each entry:  logP ← −Ctc.verlust(logits, sequence)           RECOMPUTED, not taken from the beam
return list of (sequence, logP)

function contribution(l, c) = lengthBonus + weight · language.logProbability(l, c)   without a language model only lengthBonus

Source: envisionz-framework-neural/src/de/envisionz/neural/seq/Strahlsuche.java. suche(logits, width) is the form without language model and length bonus and returns only the best hit.

Framework convention: The reported probability of a hit is recomputed with Ctc.verlust. The beam sums only over the paths that survived pruning and therefore underestimates; according to the source comment, the underestimate was up to 1.1⋅10−21.1\cdot10^{-2} in the logarithm for width 50 and short sequences – small enough for the ranking, too large for a number passed on. The reported value contains no language-model share and is thus comparable with the CTC loss. Prefixes are compared by content, not by array identity.

Room for a language model

CTC assumes the windows are independent; the knowledge of which sound sequences exist in a language is not in the model. Beam search can bring it in when extending a prefix: a Sprachmodell delivers ln⁡P(c∣l)\ln P(c \mid l), and the beam ranks by

ln⁡p(l)+∑extensions(λln⁡PLM(c∣prefix)+β),\ln p(l) + \sum_{\text{extensions}} \bigl(\lambda\, \ln P_\text{LM}(c \mid \text{prefix}) + \beta\bigr),

with the weight λ\lambda and the length bonus β\beta per emitted character. The bonus compensates for a language model charging every extension with a negative logarithm and thus favouring short sequences. The interface is deliberately narrow: the search needs no more than "how well does this character fit after this sequence". The module itself ships no language model.

Edit distance and error rate

The Levenshtein edit distance is the smallest number of insertions, deletions and substitutions that turns a sequence aa into a sequence bb. With Di,jD_{i,j} the distance of the first ii elements of aa to the first jj of bb:

Di,0=i,D0,j=j,Di,j=min⁡(Di−1,j−1+[ai≠bj],Di−1,j+1,Di,j−1+1).D_{i,0} = i, \qquad D_{0,j} = j, \qquad D_{i,j} = \min\bigl(D_{i-1,j-1} + [a_i \ne b_j],\ D_{i-1,j} + 1,\ D_{i,j-1} + 1\bigr).

It is computed with two rows instead of the full table – that suffices for the number, the way there is not needed. The error rate divides by the length of the correct sequence; over a set, the sum of distances is divided by the sum of lengths rather than averaging the individual rates – otherwise a three-sound utterance would count as much as a thirty-sound one.

rate=∑uD(recognisedu,correctu)∑u|correctu|.\text{rate} = \frac{\sum_u D(\text{recognised}_u, \text{correct}_u)}{\sum_u |\text{correct}_u|} .

Framework convention: The rate can exceed 1: whoever outputs twenty sounds for three correct ones has seventeen insertions too many. At the start of training a model therefore often looks as if it got worse – it first learns to say anything at all, and only then when to stay silent. If the correct sequence is empty, the rate is 0 for an empty recognition and otherwise the number of recognised elements.

How it is checked

  • Beam against greedy (SequenzSelfTest): the example above. Greedy must lose all sounds, beam search with width 25 must find "4 2 3", this sequence must be more probable than the empty one according to Ctc, and the reported probability must equal that of Ctc.verlust to 10−1210^{-12}.
  • Beam never worse: on the artificial learning task the error rate with beam width 12 must not exceed the greedy one (measured 0.222 against 0.267; with varying durations 0.275 against 0.482).
  • Edit distance: equal sequences 0, one substitution, deletion, insertion 1 each, against the empty sequence the length, in both directions; symmetric and satisfying the triangle inequality for 300 random pairs and triples.
  • Error rate: one wrong out of three gives 1/31/3, six outputs for one correct character give 6, empty against empty 0, the set rate is sum over sum and not the mean of the individual rates.

Limits

  • Beam search is not complete: pruning can discard the correct output if it looks poor in between. With growing width it approaches exhaustive search.
  • Cost per time step: width times number of characters entries, plus sorting when pruning and, at the end, one CTC forward pass per hit.
  • No language model included; the language-model and length share of two merging prefixes is neither averaged nor summed but set to the larger one.
  • The error rate counts every deviation equally; similar sounds are not "less wrong".
