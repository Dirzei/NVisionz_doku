Data, normalisation, metrics – background

The computation behind DataSet, Normalizer, JdbcDataLoader and Metrics: why and how columns are normalised, how data are split into training and validation sets or into folds, what the quality measures measure and how the database loader deals with gaps – with pseudocode following the source, a numerical example, checks and limits.

What this is about

A network sees numbers, not units. If one input lies between 0.4 and 1.6 (corrected mass flow) and another between 8000 and 12000 (speed in rpm), the second dominates every weighted sum, the He and Xavier initial values do not fit, and the learning rate would have to differ for each direction. The usual remedy: bring every column onto a common scale before training and the outputs back after evaluation. That is the job of the Normalizer.

Evaluating honestly is just as important. Whoever measures on the same points that were learned measures memorisation. Data are therefore split – once into training and validation, or several times into kk folds for cross-validation – and quality is measured on the held-back points: for regression with R2R^2 per output, for classification with accuracy and confusion matrix.

Normalisation

Both kinds compute the same affine map per column, only with different parameters:

x˜c=xc−ocsc,xc=x˜csc+oc.\tilde x_c = \frac{x_c - o_c}{s_c}, \qquad x_c = \tilde x_c\, s_c + o_c .

KindOffset oco_cScale scs_cResultProperty
ZSCOREmean xc\bar x_cstandard deviation 1n∑(xc−xc)2\sqrt{\tfrac1n \sum (x_c - \bar x_c)^2}mean 0, spread 1tolerates outliers
MINMAXmin⁡xc\min x_cmax⁡xc−min⁡xc\max x_c - \min x_crange [0,1][0, 1]a single outlier squeezes all other values

Why ZSCORE tolerates outliers better: a single value ten times as far away as the others increases the range tenfold under MINMAX, and all other points end up in a tenth of the interval. Under ZSCORE it enters the spread only through its square, divided by nn; with many points it shifts the scale far less.

Framework convention: The standard deviation is the population one (divisor nn, not n−1n-1). If the scale of a column is below 10−1210^{-12} – a constant column – it is set to 1; the column is then only shifted and appears as a zero column in the network instead of being divided by zero. Normalizer.of(type, offset, scale) builds a normaliser from stored parameters and copies the arrays; transform and inverse always return new arrays.

Pseudocode – Normalizer.fit(type, data)

check data not empty                            otherwise exception
for each column c:
    if type = ZSCORE:
        o ← mean of the column
        s ← √( Σ (x − o)² / n )                  divisor n
    else:                                        MINMAX
        o ← minimum;   s ← maximum − minimum
    offset[c] ← o
    scale[c]  ← (s < 10⁻¹²) ? 1 : s              guard against constant columns

Source: envisionz-framework-neural/src/de/envisionz/neural/data/Normalizer.java.

In the surrogate model inputs and targets are normalised, both with the same kind. Target normalisation makes the mean squared error weight all outputs comparably; how the surrogate model wraps both normalisers around the network is shown on the page Surrogate model.

Splitting: training and validation, k folds

split(fraction, seed) shuffles the row indices with Fisher-Yates and splits at ntrain=round⁡(n⋅fraction)n_\text{train} = \operatorname{round}(n \cdot \text{fraction}), clamped to [1,n−1][1, n-1] – neither set is empty. kFolds(k, seed) shuffles likewise and cuts the shuffled order into kk contiguous pieces

fold f=[⌊fnk⌋,⌊(f+1)nk⌋),f=0,…,k−1.\text{fold } f = \Bigl[\Bigl\lfloor \frac{f\,n}{k} \Bigr\rfloor,\ \Bigl\lfloor \frac{(f+1)\,n}{k} \Bigr\rfloor\Bigr), \qquad f = 0,\dots,k-1 .

The folds differ in size by at most one. In cross-validation each fold serves once as the validation set while the remaining k−1k-1 form the training set; every point is thus rated exactly once, and the mean over the folds depends less on the chance of a single split.

Pseudocode – DataSet.kFolds(k, seed)

check 2 ≤ k ≤ n                                  otherwise exception
idx ← 0 … n−1;  Fisher-Yates shuffle with Random(seed)
for f ← 0 to k−1:
    start ← ⌊f·n/k⌋;   end ← ⌊(f+1)·n/k⌋
    validation ← rows idx[start … end−1]
    training   ← all other rows, in shuffled order
    folds[f] ← (training, validation)             references to the original rows
return folds

Source: envisionz-framework-neural/src/de/envisionz/neural/data/DataSet.java. split and kFolds copy no rows, they only distribute the references.

Framework convention: DataSet takes over the caller's arrays without copying; whoever changes them afterwards changes the data set. A data set must not be empty and must have the same number of input and target values in all rows (otherwise an exception with the row number). oneHot(labels, classes) requires at least two classes and aborts with the row number on a label outside [0,classes)[0, \text{classes}).

Quality measures

For regression Metrics computes over all samples ii and outputs cc:

MSE=1Nm∑i,c(yic−tic)2,RMSE=MSE,MAE=1Nm∑i,c|yic−tic|.\text{MSE} = \frac{1}{N m} \sum_{i,c} (y_{ic} - t_{ic})^2, \qquad \text{RMSE} = \sqrt{\text{MSE}}, \qquad \text{MAE} = \frac{1}{N m}\sum_{i,c} |y_{ic} - t_{ic}| .

The coefficient of determination is computed per output, because a surrogate can be very good for the pressure ratio and poor for the efficiency:

Rc2=1−∑i(tic−yic)2∑i(tic−tc)2.R^2_c = 1 - \frac{\sum_i (t_{ic} - y_{ic})^2}{\sum_i (t_{ic} - \bar t_c)^2} .

R2=1R^2 = 1 means error-free, R2=0R^2 = 0 means no better than the mean of the data; negative values are possible and mean worse than the mean. The RMSE carries the unit of the target and is therefore the better measure for the question "how accurate in efficiency points?" – when computed on raw values.

For classification: softmax turns logits into probabilities (subtracting the largest against overflow), argmax picks the class, accuracy counts the agreements of the argmax of prediction and target, confusionMatrix counts in row "true class" and column "predicted class". The diagonal holds the hits; a filled off-diagonal cell shows which two classes the network confuses.

Framework convention: If the spread of a target column is practically zero (∑(t−t)2<10−300\sum (t - \bar t)^2 < 10^{-300}), R2R^2 returns NaN for it instead of a meaningless number. argmax takes the first index on ties. predictAll(net, data) evaluates the bare network – on the data as they are in the data set, i.e. normalised if the data set is normalised.

Loading from a database

JdbcDataLoader.load(connection, sql, inputColumns, targetColumns) runs a query and builds a data set from the named columns. It needs only java.sql from the JDK; the driver (for example H2 or SQLite) only has to be present at run time and registers itself. The loader is deliberately strict: a database gap (SQL NULL) in a requested column does not silently become 0.0 – that would corrupt a surrogate without a trace – but aborts with column name and row number. An empty result aborts as well; missing columns are reported by the driver.

check input and target columns not empty
result ← run sql
iIn ← findColumn for each input column;  iTarget ← likewise      driver reports missing
row ← 0
while result.next():
    row ← row + 1
    for each requested column:
        v ← getDouble(column)
        if wasNull():  exception "SQL NULL in column …, row …"
if row = 0:  exception "query returned no rows"
return DataSet.of(inputs, targets)

Source: envisionz-framework-neural/src/de/envisionz/neural/data/JdbcDataLoader.java. The connection is not closed; that is left to the caller.

How it is checked

  • Database loader (TestMain [9]): a map table with 500 rows, 10 % of them marked invalid, and an additional row with a gap in the pressure ratio. The query with WHERE valid = 1 must return exactly 450 rows with 2 input and 2 target values; the query on the gap row must abort with a message containing "NULL"; a surrogate for pressure ratio and efficiency trained from the result must reach R2>0.98R^2 > 0.98. Runs against H2 or SQLite, whichever driver is present; without a driver the check is skipped, not counted as a failure.
  • Normalisation and R2R^2 (TestMain [3]): regression with ZSCORE on input and output, 80/20 split, R2>0.99R^2 > 0.99 on the validation set.
  • Classification measures (TestMain [10]): accuracy above 0.95, confusion matrix (diagonal in the run: 84, 50, 46), softmax sum 1 to 10−1210^{-12}, all probabilities in [0,1][0, 1].
  • Folds (TestMain [8]): the model search with 3 folds runs on kFolds.

Limits

  • No stratified split: with rare classes a fold may contain not a single sample of one.
  • No time-ordered split. For measurement series in which neighbouring points are almost equal, and for grid data, a random split flatters the model: next to every validation point lies an almost identical training point.
  • ModelSearch.trainFinal determines the normalisation from all raw data passed in, before splitting into training and validation. The validation points thus influence offset and scale – irrelevant for usual data sizes, not so for very few points.
  • MINMAX is sensitive to outliers; values outside the training range end up outside [0,1][0, 1], which the network has never seen.
  • The database loader reads everything into memory and accepts numeric columns only.
