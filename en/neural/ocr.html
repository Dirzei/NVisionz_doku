Glyph recognition – line segmentation, rasterisation, classification

The computation behind LineSegmenter, GlyphRaster, GlyphDataGen, TrainGlyphOcr, NeuralGlyphOcr and TemplateGlyphOcr: how a text line falls apart into glyphs via the ink projection, how touching glyphs are separated, how every glyph is brought onto a fixed raster and recognised by a network or by template matching – with pseudocode following the source, figures from the checks and the limits.

What this is about

A scanned map carries its axis labels as an image: "1060.38", "0,85", "(NRT1 = 1060.38)". To translate the curves into numbers, the digitiser has to read these labels. Large text recognition programs with native libraries exist for that; for axis labels and table cells – short lines, few distinct characters, one typeface per document – less suffices. The package ocr is a pure Java chain without a native library:

  1. split the line into single glyphs (LineSegmenter),
  2. bring each glyph onto a fixed N×NN \times N greyscale image (GlyphRaster),
  3. assign the greyscale image to a class of the character set – with a trained network (NeuralGlyphOcr) or by comparison with templates (TemplateGlyphOcr).

Training data for the network are produced synthetically from system fonts (GlyphDataGen) or collected from the document itself (in app-pdfdigitizer). Two character sets are predefined: standard() with 73 classes (digits, upper and lower case letters, .,:;=+-()%/) and digits() with 17 classes (0123456789.,+-()=). The digit set deliberately contains no letters – the confusions 0/O and 1/l cannot occur there at all.

What counts as ink

Red, green and blue are combined into brightness with the usual weighting

Y=0.299R+0.587G+0.114B.Y = 0.299\,R + 0.587\,G + 0.114\,B .

Transparent pixels (alpha below 128) are background. Segmentation works with a hard threshold: ink is whatever is darker than 160. Rasterisation works softly so that anti-aliasing is preserved:

t(Y)=min⁡(1,max⁡(0,235−Y235−min⁡(234,s))),s=160,t(Y) = \min\Bigl(1,\ \max\Bigl(0,\ \frac{235 - Y}{235 - \min(234, s)}\Bigr)\Bigr), \qquad s = 160 ,

i.e. 0 from brightness 235 upwards, rising linearly and fully 1 from the threshold 160.

Segmenting a line

The idea is the vertical projection: count the ink pixels per pixel column. Columns with ink belong to a glyph, a run of empty columns separates two glyphs, a wide gap is a word space. To make this work on scans, three measures are added: specks are removed first, all thresholds are relative to the line height hh, and pieces that are too wide are split as touching glyphs.

  1. Remove specks: connected ink regions (8-neighbourhood, breadth-first search) with fewer than 4 pixels are discarded. Full stop and comma lie well above that at usual font sizes.
  2. Projection: a column counts as ink if it has at least max⁡(1,⌊h/20⌋)\max(1, \lfloor h/20 \rfloor) ink pixels.
  3. Pieces: a gap of at least g=max⁡(1,round⁡(0.06h))g = \max(1, \operatorname{round}(0.06\,h)) empty columns closes a piece. If the gap before a piece was at least max⁡(g+1,round⁡(0.45h))\max(g+1, \operatorname{round}(0.45\,h)) wide, a space precedes it.
  4. Split touching glyphs: if a piece is at least 1.6 times as wide as the median of all piece widths, it counts as k=round⁡(width/median)k = \operatorname{round}(\text{width}/\text{median}) glyphs. It is cut k−1k-1 times, each at the column with the least ink in a window of ±max⁡(1,⌊median/4⌋)\pm\max(1, \lfloor\text{median}/4\rfloor) around the even split point.
  5. Cut out: pieces with fewer than 4 ink pixels are dropped; for the rest the vertical ink range is determined and the sub-image cut out.

Pseudocode – LineSegmenter.segment(line)

g ← max(absMinGap, round(h · 0.06));   gSpace ← max(g + 1, round(h · 0.45))
raw ← ink mask (brightness < 160, alpha ≥ 128)
mask ← raw without 8-components of fewer than minGlyphInk (4) pixels
ink[x] ← number of mask pixels in column x
isInk[x] ← ink[x] ≥ max(1, h/20)

// pieces from the projection
for x ← 0 to w (x = w counts as empty):
    if isInk[x]:  start ← start or x;  gap ← 0
    else if a piece is open:
        gap ← gap + 1
        if gap ≥ g or x = w:
            store piece [start, x − gap], space before ← (previousGap ≥ gSpace)
            previousGap ← gap;  close piece
    else:  previousGap ← previousGap + 1

// touching glyphs
if splitting and pieces exist:
    m ← median of the piece widths
    for each piece of width b, k ← round(b / m):
        if k ≥ 2 and b ≥ 1.6 · m:
            for j ← 1 to k−1:
                target ← start + round(b · j / k);   f ← max(1, m/4)
                cut ← first column with the least ink[x] in [target − f, target + f]
            replace the piece by its parts           only the first inherits "space before"

// cut out
for each piece:  if Σ ink ≥ minGlyphInk:  sub-image from the topmost to the lowest mask row

Source: envisionz-framework-neural/src/de/envisionz/neural/ocr/LineSegmenter.java. Defaults: threshold 160, gap 0.06 · h, word gap 0.45 · h (at least twice the gap), absolute minimum gap 1 pixel, splitting on, speck limit 4 pixels.

Rasterisation

The cut-out glyph may be 8 or 80 pixels high. The network needs a fixed number of inputs, and it should see an "8" the same way however large it was printed. GlyphRaster therefore determines the bounding box of the ink, scales it, preserving the aspect ratio, into a field of (N−2)×(N−2)(N-2) \times (N-2) points, places it centred in the N×NN \times N raster (one point margin) and returns the ink strengths row by row as a vector of length N2N^2:

σ=min⁡(N−2bw,N−2bh),dw=max⁡(1,round⁡(bwσ)),dh=max⁡(1,round⁡(bhσ)),offset=⌊N−d2⌋.\sigma = \min\Bigl(\frac{N-2}{b_w}, \frac{N-2}{b_h}\Bigr), \qquad d_w = \max\bigl(1, \operatorname{round}(b_w \sigma)\bigr), \quad d_h = \max\bigl(1, \operatorname{round}(b_h \sigma)\bigr), \qquad \text{offset} = \Bigl\lfloor \frac{N - d}{2} \Bigr\rfloor .

Scaling is bilinear on a white background; transparent areas would otherwise turn black and thus become ink. An empty image yields the zero vector.

Framework convention: The same rasterisation serves training and recognition – it must be bit-identical, otherwise the network would see a different distribution at recognition time than during learning. The raster size is therefore stored with the model (raster_n, default 20). Rasterisation keeps the aspect ratio but discards the absolute size: a full stop and a comma are stretched to the same height as a digit, and only their shape tells them apart.

Recognition with the network

TrainGlyphOcr builds a classification network from the module's building blocks: input N2N^2, two hidden layers with 256 and 128 RELU neurons, each with dropout 0.1, output KK linear logits, He initialisation. Training uses softmax cross-entropy and Adam (learning rate 10−310^{-3}), batch 64, an exponential learning-rate schedule with factor 0.98 per epoch and early stopping after 8 epochs without an improvement of 10−410^{-4}; 85 % of the samples for training, 15 % for validation. With N=20N = 20 and the 17 digit classes the network has 400⋅256+256+256⋅128+128+128⋅17+17=137,745400\cdot256+256 + 256\cdot128+128 + 128\cdot17+17 = 137{,}745 parameters.

Framework convention: The classification model has neither an input nor a target normaliser – the raster values already lie in [0,1][0, 1]. The metadata hold task = glyph-ocr, charset, raster_n, classes and val_accuracy. Called from the command line, training uses 120 samples per glyph, at most 40 epochs, raster 20, the full character set and seed 1234 unless stated otherwise.

Each glyph is recognised by the argmax of the logits. If a minimum confidence is set and the largest softmax probability lies below it, "?" appears instead of a character.

Pseudocode – NeuralGlyphOcr.recognize(line)

if line = none:  return ""
text ← ""
for each glyph image z from segmenter.segment(line):
    if z.spaceBefore:  text ← text + " "
    v ← raster.toVector(z)
    if the model has an input normaliser:  v ← normalise(v)
    logits ← net.run(v);   k ← argmax(logits)
    if minConfidence > 0 and softmax(logits)[k] < minConfidence:
        text ← text + "?";  continue
    text ← text + charset[k]
return text

Source: envisionz-framework-neural/src/de/envisionz/neural/ocr/NeuralGlyphOcr.java. load(path) reads character set and raster size from the metadata (defaults: standard set, 20) and sets the minimum confidence to 0.

Recognition by template matching

TemplateGlyphOcr needs no training. For every glyph of the set, a raster vector is produced once from one typeface and its mean removed. An unknown glyph is rasterised and centred the same way and assigned to the template with the largest normalised correlation:

rk=(v−v)⋅(tk−tk)‖v−v‖‖tk−tk‖,k^=arg⁡maxk⁡rk.r_k = \frac{(v - \bar v)\cdot(t_k - \bar t_k)}{\|v - \bar v\|\;\|t_k - \bar t_k\|}, \qquad \hat k = \arg\max_k r_k .

That is fast and needs no data, but depends on the one typeface of the templates. It serves as a baseline for the network. The templates are produced with GlyphDataGen.generate(1, 12345) – one sample per glyph with the same random variation as training data, i.e. with size and position scatter and noise.

Synthetic training data

GlyphDataGen.generate(perGlyph, seed) draws every glyph of the set perGlyph times black on white into a 48 × 48 pixel field, each time with a random variation, rasterises it with the same GlyphRaster as recognition and creates a one-hot target. The variations per sample:

QuantityRange
font familyuniform from the list; default: the logical fonts SansSerif, Serif, Monospaced
styleplain or bold
font size20 to 35 points, plus a stretch of 0.9 to 1.1
anti-aliasingon or off
offset±2 pixels horizontally and vertically
noiseper raster point uniformly up to ±6 %, then clamped to [0,1][0, 1]

The samples come in blocks per glyph; the trainer does the shuffling. With the same seed and the same installed fonts, the same samples arise.

Worked example

The bar pattern from the figure measures 64 × 36 pixels. With h=36h = 36 the separating gap is g=max⁡(1,round⁡(2.16))=2g = \max(1, \operatorname{round}(2.16)) = 2 columns, the word gap max⁡(3,round⁡(16.2))=16\max(3, \operatorname{round}(16.2)) = 16 columns, the column threshold max⁡(1,36/20)=1\max(1, 36/20) = 1 pixel. The gaps between the bars are 4 columns wide – they separate, but are no word space. The middle piece is 24 wide, the median 12, so k=2k = 2; the even cut would be at column 32, the search window runs from 29 to 35, all columns have 28 ink pixels, the first one is chosen: 29.

A bar of 12 × 28 pixels in the raster N=20N = 20: σ=min⁡(18/12,18/28)=0.643\sigma = \min(18/12,\ 18/28) = 0.643, i.e. 8×188 \times 18 points, offset 6 horizontally and 1 vertically, 144 raster points with ink.

Measured accuracies from the module documentation: the digit model reaches 100 % on the validation set and reads legend numbers such as "1060.38" and "2533.14" exactly; the full set lies at about 98 %. A scanned document showed what these figures do not say: template matching read every 6 there as an 8, a network with 1.0000 on system fonts confused 9 and 3, and only a network trained on glyphs from the same print read everything correctly. The validation accuracy was measured correctly – on the wrong distribution.

How it is checked

  • Rasterisation (OcrSelfTest): an empty image gives the zero vector, the vector length is N2=400N^2 = 400.
  • Segmentation: "12.5" yields exactly four glyphs without a false word gap. The bar pattern yields fewer pieces without splitting than with it, exactly four with it. The pattern is deliberately drawn without a font: with a logical font it depended on the machine whether two letters touch at all.
  • Recognition: a digit model (120 samples per glyph, 25 epochs, seed 7) must reach at least 0.98 on the validation set and read "1060.38", "42.7" and "2533.14" exactly. Template matching must return a non-empty result.
  • Training data (Glyphdatenprobe, 11 checks): number equal to glyphs times samples, raster length, one-hot targets in blocks, all values in [0,1][0, 1], same seed gives the same samples, a different seed different ones, the default fonts are SansSerif, Serif, Monospaced in this order. Only what does not depend on the installed fonts is checked.

Limits

  • One line per call; finding the lines and cells is up to the application.
  • Touching glyphs remain the weak spot of the projection. Splitting presupposes that most glyphs are equally wide, and with even ink it cuts at the left window edge instead of in the middle (figure above). Italics and overhanging letters cannot be separated vertically at all.
  • No language model, no dictionary: every glyph is decided on its own.
  • Synthetic data from system fonts do not reliably cover the typeface of a particular print (see example). The logical font names resolve differently on each operating system; models from synthetic data are therefore not identical across machines.
  • Rasterisation stretches every glyph to full height; afterwards full stop, comma and hyphen differ only by their shape, not by their size or position in the line.
