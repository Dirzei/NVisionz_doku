Training – batches, loss functions, learning-rate schedules, early stopping

The computation behind Trainer, TrainConfig, LrSchedule, MseLoss, SoftmaxCrossEntropyLoss and QuantileLoss: how an epoch runs, which losses exist and where their gradients come from, how the learning rate is steered over the epochs and when training stops – with pseudocode following the source, numerical examples, checks and limits. The step rules themselves (SGD, Adam, L-BFGS) are on the page Optimisers.

What this is about

Training looks for weights θ\theta that make the mean loss over the training data small:

J(θ)=1N∑s=1NL(y(xs;θ),ts).J(\theta) = \frac{1}{N} \sum_{s=1}^{N} L\bigl(y(x_s;\theta),\, t_s\bigr).

Computing the gradient over all NN samples is expensive for large data and not necessary for most optimisers. The Trainer therefore splits the data in each epoch (one pass through all data) into mini-batches of BB samples, averages the gradient over the batch and lets the optimiser take one step. The order is reshuffled before every epoch so that the batches are not always the same.

A second, held-back data set runs alongside: the validation set. After each epoch the trainer measures on it whether the network also improves on unseen data. When it no longer does, training stops and returns to the best state.

The course of an epoch

Per batch: gradients to zero, forward per sample, loss and gradient at the output, backward (the layers accumulate), then divide by the batch size and take one optimiser step with the epoch's learning-rate factor. Shuffling uses Fisher-Yates: from the back to the front, each element is swapped with a random one from the part not yet fixed – every order is equally likely.

Pseudocode – Trainer.train(net, train, valid, loss, opt, cfg, listener, stop)

check dimensions of train match the network          otherwise exception
check early stopping ⇒ valid ≠ none                  otherwise exception
opt.init(net)
idx ← 0 … n−1;   rnd ← Random(cfg.shuffleSeed)
dropRnd ← Random(cfg.shuffleSeed xor 0x64726f70), only if the network has dropout
best ← +∞;  bestEpoch ← 0;  wait ← 0;  snapshot ← none

for epoch ← 1, 2, … to cfg.epochs:
    Fisher-Yates shuffle of idx with rnd
    factor ← cfg.lrSchedule.scale(epoch, cfg.epochs)
    sum ← 0
    for each batch idx[pos … pos+bs−1],  bs = min(B, n − pos):
        net.zeroGrads()
        for each sample s in the batch:
            if dropout:  net.resampleDropout(dropRnd)
            y ← net.forward(x_s)
            sum ← sum + loss.value(y, t_s)
            g ← loss.gradient(y, t_s);   net.backward(g)
        net.scaleGrads(1 / bs)
        opt.step(net, factor)
    trainLoss ← sum / n                         mean over the epoch, with changing weights
    if dropout:  net.clearDropout()
    valLoss ← (valid ≠ none) ? mean of loss over valid : NaN

    if early stopping is on:
        if valLoss < best − minDelta:
            best ← valLoss;  bestEpoch ← epoch
            snapshot ← net.snapshot();  wait ← 0
        else:
            wait ← wait + 1
            if wait ≥ patience:  stopped ← true
    if listener ≠ none and (epoch mod logEvery = 0 or last epoch or stopped):
        listener.onEpoch(epoch, trainLoss, valLoss)
    if stopped:  break
    if stop():  cancelled ← true;  break

if snapshot ≠ none:  net.restore(snapshot)
else:  bestEpoch ← epoch
return (epoch, bestEpoch, trainLoss, loss on valid after restoring, stopped, cancelled)

Source: envisionz-framework-neural/src/de/envisionz/neural/train/Trainer.java. The cancel request is polled after each epoch, not within one; a running epoch is computed to its end.

Framework convention: Defaults of TrainConfig: 1000 epochs, batch size 32, shuffle seed 42, report every 100 epochs, lrDecay 1.0 (constant learning rate), early stopping off (patience 0), minDelta 0. The last batch of an epoch is smaller when BB does not divide the number of samples; it is divided by its own size. The TrainListener is called in the computing thread – a user interface must hand the display over to its event thread itself.

Loss functions

A loss function rates one sample: value(pred, target) returns the value, gradient(pred, target, grad) the derivative with respect to the network output into a preallocated buffer. The backward pass starts there.

Mean squared error

For regression, averaged over the mm outputs:

L=1m∑j=1m(yj−tj)2,∂L∂yj=2m(yj−tj).L = \frac{1}{m}\sum_{j=1}^{m} (y_j - t_j)^2, \qquad \frac{\partial L}{\partial y_j} = \frac{2}{m}\,(y_j - t_j).

Because the targets in the surrogate model are normalised, all outputs contribute on the same scale – a pressure ratio around 3 and an efficiency around 0.85 are weighted equally after normalisation.

Softmax cross-entropy

For classification the network delivers raw values zjz_j, the logits (output layer LINEAR). The softmax turns them into probabilities, the cross-entropy measures the distance to the target yy (one-hot or a soft distribution with ∑jyj=1\sum_j y_j = 1):

pj=ezj∑kezk,L=−∑jyjln⁡pj=ln⁡∑kezk−∑jyjzj.p_j = \frac{e^{z_j}}{\sum_k e^{z_k}}, \qquad L = -\sum_j y_j \ln p_j = \ln\sum_k e^{z_k} - \sum_j y_j z_j .

The right-hand form follows from ln⁡pj=zj−ln⁡∑kezk\ln p_j = z_j - \ln\sum_k e^{z_k} and ∑jyj=1\sum_j y_j = 1. Differentiated with respect to ziz_i, the first term gives ezi/∑kezk=pie^{z_i}/\sum_k e^{z_k} = p_i, the second yiy_i:

∂L∂zi=pi−yi.\frac{\partial L}{\partial z_i} = p_i - y_i .

That is why softmax and cross-entropy are fused in one class: computed separately one would have to divide by pjp_j, which becomes tiny for confident networks; together only the difference remains. Against overflow, the logarithm of the sum is shifted by the largest value:

ln⁡∑kezk=m+ln⁡∑kezk−m,m=maxk⁡zk.\ln\sum_k e^{z_k} = m + \ln\sum_k e^{z_k - m}, \qquad m = \max_k z_k .

Example with three classes, z=(2,1,0.1)z = (2,\ 1,\ 0.1), correct class 0: p=(0.6590,0.2424,0.0986)p = (0.6590,\ 0.2424,\ 0.0986), L=−ln⁡0.6590=0.4170L = -\ln 0.6590 = 0.4170, gradient (−0.3410,0.2424,0.0986)(-0.3410,\ 0.2424,\ 0.0986) – recomputed with SoftmaxCrossEntropyLoss and Metrics.softmax. The gradient sums to zero, as it must.

Quantile loss (pinball)

The mean squared error makes the network learn the conditional mean. Whoever wants a band around the prediction – "with 90 % probability the efficiency lies below this" – needs quantiles. With e=t−ye = t - y (positive: underestimated) the quantile loss is

Lτ(e)=max⁡(τe,(τ−1)e)={τee≥0(τ−1)ee<0,∂Lτ∂y={−τe>01−τe<00e=0.L_\tau(e) = \max\bigl(\tau\, e,\ (\tau - 1)\, e\bigr) = \begin{cases} \tau\, e & e \ge 0 \\ (\tau - 1)\, e & e < 0 \end{cases}, \qquad \frac{\partial L_\tau}{\partial y} = \begin{cases} -\tau & e > 0 \\ 1 - \tau & e < 0 \\ 0 & e = 0 \end{cases}.

Why does this yield the quantile? Minimising E[Lτ(T−y)]\mathrm{E}[L_\tau(T - y)] over a constant yy, the derivative is −τP(T>y)+(1−τ)P(T<y)-\tau\,P(T > y) + (1-\tau)\,P(T < y); it vanishes at P(T<y)=τP(T < y) = \tau. At τ=0.9\tau = 0.9 an underestimate costs nine times as much as an overestimate of the same size; the minimum lies where 90 % of the values are below. At τ=0.5\tau = 0.5 the loss is half the mean absolute error, its minimum the median.

Framework convention: All three losses average over the outputs (factor 1/m1/m), the quantile loss included. τ\tau must lie in (0,1)(0, 1). At the kink e=0e = 0 the gradient is set to 0. The cross-entropy does not check ∑jyj=1\sum_j y_j = 1 in the training loop – for speed; DataSet.oneHot ensures it on the usual path. For an uncertainty band, app-neural trains three models with τ=0.1\tau = 0.1, 0.50.5 and 0.90.9.

Learning-rate schedules

A schedule delivers a factor per epoch by which the trainer multiplies the optimiser's learning rate. The optimiser thus stays free of any knowledge of epochs. With ee the epoch (from 1), TT the number of epochs and the progress p=min⁡(1,(e−1)/(T−1))p = \min\bigl(1, (e-1)/(T-1)\bigr):

Why lower the learning rate at all? With a fixed learning rate a stochastic optimiser keeps jumping around the minimum at the end, because every batch delivers a slightly different gradient. Smaller steps towards the end average this noise out. The warm-up of one-cycle serves the opposite purpose: at the start the gradients are large and Adam's moment estimates still uncertain; small first steps keep the network from being thrown into an unfavourable region right away.

Framework convention: Without an explicit schedule, exponential(lrDecay) applies – with the default lrDecay = 1.0, i.e. constant. A schedule that is set overrides lrDecay. With only one epoch, cosine and one-cycle return the factor 1. The schedule acts on all three optimisers alike, for L-BFGS on its fixed step length.

Early stopping and cancellation

A large network on few, noisy data first learns the relationship and then the noise. The training loss keeps falling, the validation loss rises again. Early stopping watches the validation loss: if it does not improve by more than minDelta for patience epochs, training ends and the weights of the best epoch are written back.

Precisely: an epoch counts as an improvement if Ve<Vbest−Δmin⁡V_e < V_\text{best} - \Delta_\min. Then a snapshot is taken and the counter reset; otherwise the counter is incremented. When it reaches the patience, the run stops. The result TrainResult reports the epochs run and the best epoch, the training loss of the last epoch, the validation loss of the restored network and whether it stopped early or was cancelled.

Cancellation from outside (a stop button in the user interface) goes through a function the trainer polls after each epoch. If a snapshot exists – i.e. early stopping is on and at least one improvement was seen – cancellation also returns to the best state.

  • Learning-rate schedules (Optimiererprobe): the values above for cosine and one-cycle, exponential(0.5) gives 1 in epoch 1 and 0.25 in epoch 3, the cosine falls monotonically, the clamps of one-cycle (fraction 0.9, start 0, end 1) take effect, exponential rejects 0 and 1.5. Comparison to 10−1210^{-12} relative.
  • Quantile loss (Optimiererprobe): τ=0.9\tau = 0.9 with errors +2 and −2 costs 1.8 and 0.2, on average 1; gradient −τ/m-\tau/m and (1−τ)/m(1-\tau)/m; 0 at the kink; τ=0.5\tau = 0.5 equals half the MAE; away from the kink the gradient matches the central difference quotient to 10−810^{-8} for τ=0.1,0.5,0.9\tau = 0.1,\ 0.5,\ 0.9.
  • Cross-entropy: gradient check in GradientCheck (relative error below 10−610^{-6}) and TestMain [10]: three operating regions of a compressor (stable, surge, choke) over mass flow and speed, network 2–16–16–3, accuracy on the validation set above 0.95, softmax sum 1 to 10−1210^{-12}.
  • Early stopping (TestMain [6]): must stop before the epoch limit, the best epoch must precede the last, and the reported validation loss must not exceed the smallest one observed.
  • Listener (Optimiererprobe): with 200 epochs and logEvery 50, exactly the calls 50, 100, 150, 200.

Limits

  • The reported training loss is the mean over the epoch, computed with the changing weights and with dropout masks – not the loss of the network at the end of the epoch.
  • Early stopping needs a validation set; without one the trainer throws an exception. The validation set is evaluated in full every epoch – for large sets that costs time.
  • Each improvement allocates a new snapshot. Irrelevant at surrogate sizes.
  • A cancel request only takes effect after the running epoch.
  • The batch is computed sample by sample, not as a matrix product. Large batches therefore do not make a step cheaper per sample, only less frequent.
  • Cross-entropy presupposes a linear output layer; with an activation in front, its derivative would act a second time.
