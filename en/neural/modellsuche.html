Model search – grid, random search and k-fold cross-validation

The computation behind ModelSearch: how candidates arise from layer widths, activations, learning rates and weight decay, how each is rated with cross-validation and the candidates are computed in parallel, and how the best one becomes the finished surrogate model – with pseudocode following the source, a recomputed run, checks and limits.

What this is about

How many layers, how wide, which activation, which learning rate? A network that is too small cannot represent the map, one that is too large learns the measurement noise as well, and an unsuitable learning rate spoils both. The answer is not to be guessed but measured: train each candidate and rate it on data it has not seen. The model FANN chose the network size with cascade training, which adds neurons one by one; ModelSearch replaces that with today's usual procedure – a list of candidates, each rated with kk-fold cross-validation, the result sorted by mean validation loss.

A candidate (ModelSpec) consists of the widths of the hidden layers, one activation for all hidden layers, a learning rate and a weight decay. The output layer is always LINEAR, the optimiser always AdamW.

Candidates: grid and random search

grid forms the Cartesian product of all options; with three topologies, two activations, three learning rates and two decay values that makes 3⋅2⋅3⋅2=363 \cdot 2 \cdot 3 \cdot 2 = 36 candidates, each with kk training runs. randomSearch instead draws a fixed number of candidates: topology and activation uniformly from the options, learning rate and weight decay log-uniformly between the smallest and the largest value given,

η=exp⁡(ln⁡ηmin⁡+u(ln⁡ηmax⁡−ln⁡ηmin⁡)),u∼U(0,1).\eta = \exp\bigl(\ln \eta_\min + u\,(\ln \eta_\max - \ln \eta_\min)\bigr), \qquad u \sim U(0, 1).

Logarithmically, because for learning rates the step from 10−410^{-4} to 10−310^{-3} matters as much as the one from 10−310^{-3} to 10−210^{-2}. The advantage of random search shows when only a few quantities really matter: a grid with nine candidates tries only three different learning rates, nine random candidates try nine.

Framework convention: Random search draws with replacement and skips duplicates; it stops after at most max⁡(20⋅count,100)\max(20 \cdot \text{count}, 100) attempts, even if fewer candidates were found. If the largest decay value is at most 0, the decay is always 0. If the smallest is at most 0, the drawn value is replaced by 0 with probability ½ – training without decay thus remains a separate option that would otherwise not occur on a logarithmic axis. The initial values follow the activation: Xavier for TANH and SIGMOID, He otherwise.

Rating with k-fold cross-validation

The (already normalised) data are split once into kk folds, the same for all candidates (see Data). For every candidate and every fold ff, a fresh network is built, trained on the other k−1k-1 folds and rated on fold ff. From the kk validation losses VfV_f follow

V=1k∑fVf,σV=1k∑f(Vf−V)2,Q=1k∑fqf,\bar V = \frac1k \sum_f V_f, \qquad \sigma_V = \sqrt{\frac1k \sum_f (V_f - \bar V)^2}, \qquad Q = \frac1k \sum_f q_f ,

with the quality qfq_f: for regression the R2R^2 on the fold averaged over the outputs, for classification the accuracy. Sorting is ascending by V\bar V – the best model first. The spread σV\sigma_V shows how much the verdict depends on the split; if two candidates lie within one spread of each other, their order is chance.

Pseudocode – ModelSearch.kFoldSearch(data, specs, k, cfg, seed, threads, listener, stop, classification)

check specs not empty
folds ← data.kFolds(k, seed)                           the same for all candidates
pool ← thread pool with max(1, threads) threads
for each candidate s (index i), as a separate task:
    if stop():  return none                              do not even start
    specSeed ← seed · 31 + i · 7919
    for f ← 0 to k−1:
        net ← build(s, seed specSeed + f)              Xavier/He by activation, output LINEAR
        loss ← classification ? softmax cross-entropy : MSE
        r ← Trainer.train(net, folds[f].training, folds[f].validation,
                          loss, AdamW(s.learningRate, s.decay), cfg, stop)
        if r.cancelled:  return none                    incomplete: discard
        V[f] ← r.valLoss
        q[f] ← classification ? accuracy : mean of R² per output
    result ← (s, mean(V), spread(V) with divisor k, mean(q))
    listener.done(finished + 1, total, result)         from the worker thread
collect all results ≠ none
sort ascending by mean(V)
return list

Source: envisionz-framework-neural/src/de/envisionz/neural/search/ModelSearch.java. stop is polled before each candidate and – through the trainer – after each epoch. On cancellation, the candidates fully rated so far come back sorted.

Framework convention: Parallelism runs over the candidates, not over the folds: each task computes its kk folds one after the other with its own networks. That keeps thread safety simple – no network is shared, the folds are only read. Each candidate has its own seed computed from seed and index; the result therefore does not depend on the number of threads or on the order in which they finish. With early stopping on, VfV_f is the loss of the restored best network.

From the best candidate to the surrogate model

trainFinal(rawIn, rawTarget, kind, spec, cfg, fraction, seed) trains the chosen candidate one last time on raw data and returns a finished surrogate model:

normIn ← Normalizer.fit(kind, rawIn);   normTarget ← Normalizer.fit(kind, rawTarget)
all ← DataSet.of(normIn.transform(rawIn), normTarget.transform(rawTarget))
if fraction ≥ 1:
    check no early stopping requested                   otherwise exception
    training ← all;  validation ← none
else:  (training, validation) ← all.split(fraction, seed)
net ← build(spec, seed);  Trainer.train(…, MSE, AdamW(spec.learningRate, spec.decay), cfg)
model ← SurrogateModel.of(net, normIn, normTarget)
metadata: created, spec, epochs_run, train_loss; with validation also val_loss, r2_val
return model

Source: envisionz-framework-neural/src/de/envisionz/neural/search/ModelSearch.java, method trainFinal. Numbers in the metadata use a point as decimal separator regardless of the locale.

Worked example

The run from TestMain [8]: 400 points of the map function sin⁡(3x)cos⁡(2y)+0.5x\sin(3x)\cos(2y) + 0.5x with noise 0.02, normalised; two candidates – one hidden layer of 4 neurons against two of 32 each –, both SILU, learning rate 2⋅10−32 \cdot 10^{-3}, no decay; 3 folds, 150 epochs, batch 32, 4 threads.

The small network has 2⋅4+4+4+1=172\cdot4+4+4+1 = 17 parameters and cannot represent the two waves in xx; it stays at R2≈0.72R^2 \approx 0.72. The result is sorted, [32, 32] comes first. The six training runs took 0.6 s together. The second search of the test – classification of two classes separated by the diagonal x1+x2=1x_1 + x_2 = 1, with 300 points – yielded [16, 16] SILU as the best candidate with an accuracy of 0.9867 over the folds.

How it is checked

  • Search (TestMain [8]): the result must be sorted ascending by V\bar V, the best candidate must reach Q>0.98Q > 0.98 and be the two-layer topology.
  • Cancellation: with a cancel request set immediately, the search must return an empty list, without exception and without hanging.
  • Classification: the search with cross-entropy and accuracy must rate both candidates, and the best must be above 0.9.
  • Final training (TestMain [7] and [9]): trainFinal delivers a model with r2_val in the metadata that computes bit-identically after saving and loading; from database data it reaches R2>0.98R^2 > 0.98.

Limits

  • Parallel over candidates only. With few candidates and many folds, threads stay idle.
  • All candidates run with the same TrainConfig – same number of epochs, same batch. A candidate that would need more epochs is disadvantaged; early stopping mitigates this.
  • The cross-validation quality of the best candidate is slightly optimistic: it was chosen precisely because it did well on these folds. An independent test set not involved in the search gives a more honest picture.
  • With grid data, random folding flatters the model (see Data).
  • Only one activation for all hidden layers is searched, no batch size, no dropout.
