Entropy coding – Golomb-Rice with partitions

The computation behind Restkodierung (method 1): zigzag mapping, Golomb and Rice codes, why they suit prediction residuals, the per-partition choice of the parameter with exactly counted bits, the escape case for raw values. With a bit diagram, pseudocode following the source, a worked example, probes and limits.

What it is about

After prediction a residual remains, a sequence of integers that are mostly small and distributed around zero. Large magnitudes occur, but rarely. A fixed-length code – say 17 bits for every value – wastes almost everything here. What is wanted is a code that gives short words to small magnitudes and long words to large ones, and that needs no table, because every table would have to be transmitted as well.

Golomb codes do exactly that for a geometric distribution, and a prediction residual resembles this distribution approximately: the probability falls roughly exponentially with the magnitude. Rice codes are the special case with a power of two as divisor; they need no division and have only one parameter kk.

The zigzag mapping

Rice codes are made for non-negative numbers. The residual is therefore mapped reversibly so that small magnitudes of either sign give small numbers:

u={2xx≥0−2x−1x<00,−1,1,−2,2,…↦0,1,2,3,4,…u = \begin{cases} 2x & x \ge 0 \\ -2x - 1 & x < 0 \end{cases} \qquad 0, -1, 1, -2, 2, \dots \;\mapsto\; 0, 1, 2, 3, 4, \dots

In the code this is u=(x≪1)⊕(x≫31)u = (x \ll 1) \oplus (x \gg 31) in 64-bit arithmetic, and back x=(u≫1)⊕−(uand⁡1)x = (u \gg 1) \oplus -(u \,\mathrm{and}\, 1) with an unsigned shift. Computing in long is necessary because doubling the smallest int would otherwise overflow; uu then lies between 0 and 232−12^{32}-1.

Golomb and Rice codes

A Golomb code with parameter mm splits u=qm+ru = q\,m + r and writes the quotient qq in unary (qq zeros, then a one) and the remainder rr in binary. With m=2km = 2^k the remainder is simply the lower kk-bit piece of uu, and the length of a code word is

ℓk(u)=⌊u2k⌋+1+k\ell_k(u) = \left\lfloor \frac{u}{2^k} \right\rfloor + 1 + k

For a geometric distribution P(u)=(1−θ)θuP(u) = (1-\theta)\,\theta^u the Golomb code with θm≈12\theta^m \approx \tfrac12 is optimal among all prefix codes (Gallager and Van Voorhis). Intuitively: mm is just large enough that the probability of “another mm further” is worth half a bit, justifying one unary digit. For Rice this means roughly 2k≈2^k \approx mean magnitude. The encoder does not rely on this rule of thumb, though, but counts the bits exactly for every kk from 0 to 30.

Partitions and escape

A frame with a loud and a quiet passage needs different parameters in both halves. The residual is therefore divided into 2P2^P equally sized partitions, the partition order PP runs from 0 to 6, and each partition gets its own kk. The boundaries are ⌊Ni/2P⌋\lfloor N i / 2^P \rfloor for i=0,…,2Pi = 0, \dots, 2^P; they follow from the length and PP. The length itself is not in the bit stream, it follows from the frame.

If Rice does not pay off at all in a partition – a click, a jump – it is marked as escape with the parameter value 31. Then five bits of word length ww follow and the values as two's complement with ww bits. A single outlier can thus make the partition more expensive, but cannot blow it up.

The cost of a partitioning is counted exactly:

K(P)=3+∑partitions(5+{5+nwescape∑uℓk(u)otherwise)K(P) = 3 + \sum_{\text{partitions}} \left(5 + \begin{cases} 5 + n\,w & \text{escape} \\ \sum_{u} \ell_k(u) & \text{otherwise} \end{cases}\right)

The partition order with the smallest K(P)K(P) is chosen. The search stops as soon as a partition would contain fewer than eight values on average: such short partitions no longer pay for their five parameter bits.

Pseudocode – Restkodierung.plane(rest)

best ← none
for P ← 0 to 6:
    count ← 2^P
    if count > 1 and N / count < 8:  stop            integer division
    cost ← 3 + 5·count
    for each partition [from, to):
        (k, w, K) ← besteParameterwahl(rest, from, to)
        cost ← cost + K;  if k = 31: cost ← cost + 5
    if best = none or cost < best.cost:  best ← (P, k[], w[], cost)
return best

function besteParameterwahl(rest, from, to):
    n ← to − from;  if n = 0: return (0, 0, 0)
    umax ← max zigzag(rest[i])
    w ← min(32, bitlength(umax) + 1);  bestK ← n·w;  best ← 31       escape as yardstick
    for k ← 0 to 30:
        K ← 0
        for each u = zigzag(rest[i]):
            q ← u ≫ k;  if q > 8192: k unusable, abort
            K ← K + q + 1 + k;  if K ≥ bestK: abort
        if not aborted and K < bestK:  bestK ← K;  best ← k
    return (best, w, bestK)

Pseudocode – schreibe and lies

function schreibe(bs, rest, recipe):
    write P (3 bits)
    for each partition:
        write k (5 bits)
        if k = 31:  write w (5 bits);  per value: rest (w bits, two's complement)
        else:      per value: u ← zigzag(rest);  unary(u ≫ k);  if k > 0: u and (2^k − 1) (k bits)

function lies(bl, N):                                N comes from outside
    P ← read 3 bits
    for each partition [⌊N·i/2^P⌋, ⌊N·(i+1)/2^P⌋):
        k ← read 5 bits
        if k = 31:  w ← read 5 bits;  per value: liesVorzeichen(w)
        else:      per value: q ← readUnary;  u ← (q ≪ k) or read k bits;  rest ← zigzagBack(u)
Convention in the framework: Unary here means qq zeros, then a one; all fields most significant bit first. The recipe cost is not an estimate but the number of bits schreibe actually produces; the encoder uses it to choose between raw form, fixed predictor and LPC. A quotient above 8192 makes a kk unusable, so that no single code word gets out of hand.

Worked example

Sixteen residual values: 3, −1, 0, 4, −6, 2, −2, 1, 0, −3, 5, −1, 2, 0, −4, 1. The zigzag values are 6, 1, 0, 8, 11, 4, 3, 2, 0, 5, 10, 1, 4, 0, 7, 2. The sum of the code word lengths per kk:

kk01234
∑ℓk(u)\sum \ell_k(u)8061596780

At k=0k = 0 every word is u+1u + 1 bits long, which penalises the larger values; at k=4k = 4 every word costs at least 5 bits, which penalises the many small ones. The minimum is at k=2k = 2, matching the mean uu of 4. With three bits partition order and five bits parameter the residual costs 3+5+59=673 + 5 + 59 = 67 bits; plane returns exactly this number, and schreibe produces exactly 67 bits. Two partitions of eight values (P=1P = 1) were computed too and were not cheaper; P=2P = 2 is no longer tried because a partition would then have only four values. Raw bits in the escape case would be 5 per value, 80 for the partition – the raw form loses.

A single word: x=−6x = -6, u=11=10112u = 11 = 1011_2, k=2k = 2. Quotient q=2q = 2, remainder r=3r = 3; written is 001 11, five bits, as ℓ2(11)=2+1+2\ell_2(11) = 2 + 1 + 2.

How it is tested

The Bausteinprobe (30 checks) tests the building blocks individually:

  • Bit stream: fields of 3, 16, 1 and 8 bits and a unary value come back; a unary run of 1000 zeros with the byte after it as well; a truncated run is rejected; two's complement with 8 bits for −1, −128, 127, 0, −64, 63.
  • Zigzag: reversible for 0, ±1, 2, −2, ±1000, Integer.MAX_VALUE and Integer.MIN_VALUE + 1; 0, −1, 1 map to 0, 1, 2.
  • Residual coding on three cases with 2048 values – small noise, the same with an outlier of 900,000, constant 100,000: round trip unchanged, and the recipe cost deviates by at most 8 bits from the written bit count (the padding to the byte boundary).
  • Zero residual: 1024 zeros cost at most 1024+641024 + 64 bits, i.e. about one bit per value.

The Umlaufprobe tests the Rice path in the complete codec (frame page).

Limits

  • One bit per value is the lower bound. Every Rice word has at least the terminating one. For very small residuals (silence after prediction, nearly constant signals) a code with fractions of bits has the advantage; that is the motivation for the range coder.
  • No adaptation within a partition. The parameter applies to the whole partition; the smallest partition length is eight values on average, the finest division 64 partitions.
  • Escape width. The raw width is determined from the largest zigzag value plus a sign bit and is thus often one bit wider than necessary. It is stored in 5 bits; a width of 32 cannot be represented there. An escape partition with magnitudes from about 2292^{29} upwards would therefore not come back. Such magnitudes do not arise from 8- to 24-bit material with fixed predictors (order 4 at 25 bits: at most 2282^{28}).
  • Geometric assumption. For residuals that are not approximately geometrically distributed, Rice is not optimal; the partitions only absorb changes of the order of magnitude.
