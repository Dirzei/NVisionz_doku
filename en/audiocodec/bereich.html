Entropy coding – range coder and context model

The computation behind method 2: arithmetic coding as nested intervals, the carry-less range coder after Subbotin in Bereichskodierer and Bereichsdekodierer, the adaptive Haeufigkeitsmodell and the Restmodell with size classes, predecessor context, preset and top bit. With pseudocode following the source, worked examples, measurements from the probes and limits.

What it is about

A prefix code such as Huffman or Rice gives each symbol a whole number of bits. If a symbol is very likely, that wastes a lot: at p=0.99p = 0.99 it carries only −log2⁡0.99=0.0145-\log_2 0.99 = 0.0145 bits of information but costs at least one bit. Arithmetic coding removes this bound. It does not code symbol by symbol into bit patterns but the whole sequence into one number, and each symbol narrows an interval in proportion to its probability. The length of the result comes within a few bits of the information content of the sequence:

L≈−∑ilog2⁡p(si)+2L \approx -\sum_{i} \log_2 p(s_i) + 2

The second half of the idea is the model. Whoever estimates the probabilities well codes short. Because encoder and decoder update the model by the same rules from the symbols already seen, nothing of it has to be transmitted.

The range coder

A range coder is arithmetic coding with integers and byte-wise output. The state consists of the lower bound low⁡\mathrm{low} and the width range⁡\mathrm{range}, both 32 bits. A symbol with frequency ff, cumulative frequency cc of all smaller symbols and total frequency TT narrows the interval:

r=⌊range⁡T⌋,low⁡←low⁡+rc,range⁡←rfr = \left\lfloor \frac{\mathrm{range}}{T} \right\rfloor, \qquad \mathrm{low} \leftarrow \mathrm{low} + r\,c, \qquad \mathrm{range} \leftarrow r\,f

Rounding rr down loses part of the interval, at most the fraction (T−1)/range⁡(T-1)/\mathrm{range}; the larger range⁡\mathrm{range} compared with TT, the less. The codec's models keep TT below 8192, and range⁡\mathrm{range} moves between 2162^{16} and 2322^{32}. So that range⁡\mathrm{range} does not become too small, it is normalised: once the upper eight bits of low⁡\mathrm{low} and low⁡+range⁡\mathrm{low} + \mathrm{range} are settled, this byte is output and both are shifted left by eight places.

Carry-less after Subbotin

The problem of every arithmetic coder is the carry: the addition low⁡+rc\mathrm{low} + r\,c can produce a carry into bytes already output, which would have to be propagated back. Subbotin's variant prevents this by trimming the range beforehand. If range⁡\mathrm{range} becomes smaller than 2162^{16} without the top byte being settled, it sets

range⁡←(−low⁡)mod216\mathrm{range} \leftarrow (-\mathrm{low}) \bmod 2^{16}

Then low⁡+range⁡\mathrm{low} + \mathrm{range} is a multiple of 2162^{16}, the interval no longer extends across the next 2162^{16} boundary, and all future additions stay below it. This costs some rate but spares the most error-prone spot of arithmetic coding.

Pseudocode – Bereichskodierer

TOP ← 2^24;  BOTTOM ← 2^16;  low ← 0;  range ← 2^32 − 1        everything mod 2^32

function kodiere(c, f, T):                              1 ≤ T ≤ 2^16, f ≥ 1
    range ← range / T
    low ← low + range·c
    range ← range·f
    normalise()

function normalise():
    while (low xor (low + range)) < TOP                    top byte settled
          or (range < BOTTOM and [range ← (−low) and (BOTTOM − 1)]):   Subbotin
        output byte (low ≫ 24)
        range ← range ≪ 8;  low ← low ≪ 8

function kodiereRoh(value, n):                          uniform, in pieces of 15 bits
    while n > 0:  t ← min(15, n);  n ← n − t
        kodiere((value ≫ n) and (2^t − 1), 1, 2^t)

function abschluss():  4 times: output byte (low ≫ 24);  low ← low ≪ 8

Pseudocode – Bereichsdekodierer

code ← the first 4 bytes;  low ← 0;  range ← 2^32 − 1      past the end: zeros

function hole(T):
    range ← range / T
    v ← ((code − low) mod 2^32) / range
    if v ≥ T:  exception “out of step”
    return v                                            the model looks up the symbol for v

function uebernimm(c, f, T):
    low ← low + range·c;  range ← range·f
    normalise()                                          word for word, plus code ← code ≪ 8 + next byte

Source: envisionz-framework-audiocodec/src/envisionz/audiocodec/Bereichskodierer.java and Bereichsdekodierer.java. The normalisation condition is identical word for word on both sides; if it differed in even one special case, the state would drift apart.

The adaptive frequency model

A Haeufigkeitsmodell keeps a frequency for each symbol, initially 1 (uniform) or a given preset. After each symbol its frequency grows by 24. If the total frequency exceeds 213=81922^{13} = 8192, all frequencies are halved, rounding up:

fs←fs+24,T>8192⇒fi←⌈fi/2⌉ for all if_s \leftarrow f_s + 24, \qquad T > 8192 \;\Rightarrow\; f_i \leftarrow \left\lceil f_i / 2 \right\rceil \text{ for all } i

This keeps the denominator small and lets older observations fade: the model follows a distribution that changes in the course of a piece. Rounding is upward so that no frequency drops to zero – a symbol with frequency zero could no longer be coded. Encoder and decoder use the same class: they start identically, see the same symbols and update by the same rule.

The residual model

The residual has too many possible values for one model per value. The Restmodell therefore splits each value. After the zigzag mapping uu (as with Rice) the size class is the bit length of uu:

k=⌊log2⁡u⌋+1 for u>0,k=0 for u=0k = \lfloor \log_2 u \rfloor + 1 \text{ for } u > 0, \qquad k = 0 \text{ for } u = 0

What is coded:

  1. the class kk in the model of the context – that is the class of the previous value (34 models, one per context);
  2. from k≥2k \ge 2 the bit below the leading one, the top bit, in a model of its own per class;
  3. from k≥3k \ge 3 the remaining k−2k - 2 bits uniformly with kodiereRoh.

The leading one is known from the class. The classes are very unevenly distributed, and that is exactly where the fractional bit count of the range coder helps. The context exploits the fact that residual magnitudes change slowly: after a large value another large one is more likely.

The preset

The models restart in every frame – the price for every frame being readable on its own. In short frames the model therefore spent much of its time warming up. Two presets largely remove this, without a single transmitted bit, because both sides produce them identically:

  • Class models centred on the context: fk=1+⌊48/2|k−c|⌋f_k = 1 + \lfloor 48 / 2^{|k - c|} \rfloor for |k−c|≤6|k-c| \le 6, otherwise 1. For context 10 this gives in classes 4 to 16 the frequencies 1, 2, 4, 7, 13, 25, 49, 25, 13, 7, 4, 2, 1, total over all 34 classes 174.
  • Top bit with 20 : 12 towards zero: within a class the smaller values are more frequent.

The initial context is 10, the middle of the usual size classes for audio. Both sub-channels of a frame run through one residual model; the context carries over from the first to the second.

Pseudocode – Restmodell.kodiere(bk, rest)

for each value in rest:
    u ← zigzag(value);  k ← bitlength(u)                  0 … 32
    classModel[context].kodiere(bk, k)
    if k ≥ 2:
        topBit[k].kodiere(bk, (u ≫ (k−2)) and 1)
        if k ≥ 3:  bk.kodiereRoh(u and (2^(k−2) − 1), k−2)
    context ← k

// decoding mirrors this
k ← classModel[context].dekodiere(bd)
u ← 0 (k = 0);  1 (k = 1);  otherwise 2^(k−1) or (top ≪ (k−2)) or raw(k−2)
value ← zigzagBack(u);  context ← k

Source: Restmodell.java and Haeufigkeitsmodell.java. Haeufigkeitsmodell.kodiere calls bk.kodiere(kumuliert(s), f[s], T) and then aktualisiere(s); the decoder gets the cumulative value, looks up the symbol linearly and updates the same way.

Convention in the framework: Increment 24, halving limit 8192, preset weight 48, top bit 20 : 12, initial context 10, 34 class models. With method 2 the frame first holds both subframe headers bit-packed, then from the next byte boundary the shared range stream with its 4-byte termination.

Worked examples

One residual value. x=5x = 5, so u=10=10102u = 10 = 1010_2, class k=4k = 4. Coded are class 4 in the model of the predecessor context, the top bit 0 (the second bit of 1010) and the two raw bits 10. Back: u=23+0⋅22+2=10u = 2^3 + 0 \cdot 2^2 + 2 = 10, x=5x = 5. The next value is coded in context 4.

The Huffman bound. From the Bereichsprobe: 200,000 symbols from two values, the first with probability 0.99, modelled adaptively. The entropy is

H=−0.99log2⁡0.99−0.01log2⁡0.01=0.0808 bitsH = -0.99 \log_2 0.99 - 0.01 \log_2 0.01 = 0.0808 \text{ bits}

and 0.0847 bits per symbol were measured. A Huffman code cannot go below one bit per symbol.

How it is tested

The Bereichsprobe (12 checks) mainly tests that encoder and decoder stay in step – a single difference in state would destroy the whole rest:

  • 2000 raw values with random widths from 1 to 32 bits come back.
  • Five model runs with a wandering favourite symbol (it changes every 5000 symbols): uniform (16 symbols, 200,000 times, measured 4.025 bits/symbol), strongly skewed (0.92; 0.800 bits), two symbols (0.98; 500,000 times; 0.187 bits), 34 symbols (0.5; 3.553 bits), only one symbol (0.115 bits).
  • Residual model with 100,000 values including the outliers ±⌊(231−1)/2⌋\pm\lfloor(2^{31}-1)/2\rfloor comes back unchanged (measured 9.489 bits/value).
  • Preset: both presets lossless, the preset one cheaper on 600 values; every initial preset valid and centred on its context.
  • Huffman bound: at p=0.99p = 0.99 below 0.30 bits per symbol (measured 0.0847).

In the complete codec every case of the Umlaufprobe also runs with method 2.

Limits

  • Not yet ahead on real music. According to the overview, method 2 was 0.1 to 1.5 % larger than Rice in 26 of 27 tracks (MP3, decoded to 16 bits); the point is open. With very small blocks Rice stays ahead, because the fixed overhead per frame dominates there and Rice picks its parameters per partition optimally from the start.
  • Computing time. The symbol search in the model is linear over up to 34 symbols, and the raw bits pass through the range coder one piece at a time.
  • No model across frame boundaries. That is intended (resynchronisation) but costs a warm-up phase in every frame.
  • The subframe choice uses the Rice cost for method 2 as well; a subframe that would be cheapest in a different way with the range coder is not recognised.
  • The range coder rejects total frequencies above 2162^{16}; the model stays far below at 8192.
