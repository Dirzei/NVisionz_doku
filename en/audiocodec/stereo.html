Prediction and stereo – lossless stereo decomposition

The computation behind Stereomodus: four reversible decompositions of a channel pair, why the integer mid/side form comes back without loss, which word length each sub-channel needs, and how the encoder chooses per frame. With proof, pseudocode following the source, numerical examples, probes and limits.

What it is about

The left and right channels of a stereo recording are rarely independent. A voice in the centre is almost identical in both channels, an instrument on the left is somewhat louder on the left than on the right. Coding both channels separately pays for what they share twice. The difference S=L−RS = L - R, the side, is small when the channels are similar – in the limiting case of identical channels it is zero and costs almost nothing.

The decomposition must be losslessly reversible. From LL and SS, R=L−SR = L - S follows trivially. The usual mid (L+R)/2(L+R)/2, however, is not an integer when the sum is odd; rounding it down loses a bit. How to get it back nonetheless is shown in the section on mid/side.

The four modes

The side is always S=L−RS = L - R. The mode determines which second sub-channel goes with it:

ModeIdsub-channel Asub-channel Bbits Abits B
independent0LLRRbbbb
left/side1LLS=L−RS = L - Rbbb+1b+1
right/side2S=L−RS = L - RRRb+1b+1bb
mid/side3M=⌊(L+R)/2⌋M = \lfloor (L+R)/2 \rfloorS=L−RS = L - Rbbb+1b+1

The side needs one more bit: if LL and RR lie in [−2b−1,2b−1−1][-2^{b-1}, 2^{b-1}-1], then L−RL - R lies in [−2b+1,2b−1][-2^{b}+1, 2^{b}-1]. The rounded-down mid stays within the range of the channels. Stereomodus.bitsA and bitsB give the word length of a sub-channel; the encoder writes warm-up values, constants and raw values with this width, and the decoder reads them with the same function.

Mid/side without loss

The key is a property of integers: L+RL + R and L−RL - R differ by 2R2R, so they have the same parity. The lowest bit lost when halving the sum is therefore present unchanged as the lowest bit of the side:

M=⌊L+R2⌋⇒L+R=2M+((L+R)mod2)=2M+(Smod2)M = \left\lfloor \frac{L+R}{2} \right\rfloor \;\Rightarrow\; L + R = 2M + \big((L+R) \bmod 2\big) = 2M + (S \bmod 2)

With the recovered sum Σ=L+R\Sigma = L + R, both Σ+S=2L\Sigma + S = 2L and Σ−S=2R\Sigma - S = 2R are even, and the halving is exact:

L=Σ+S2,R=Σ−S2L = \frac{\Sigma + S}{2}, \qquad R = \frac{\Sigma - S}{2}

In the code ⌊⋅/2⌋\lfloor\cdot/2\rfloor is the arithmetic right shift >> 1, which rounds towards the smaller integer for negative numbers as well, and Smod2S \bmod 2 is S & 1, which in two's complement also gives the correct bit for negative SS.

Pseudocode – Stereomodus.zerlege and setzeZusammen

function zerlege(L, R, mode):                         per index i
    INDEPENDENT:  A ← L;               B ← R
    LEFT_SIDE:    A ← L;               B ← L − R
    RIGHT_SIDE:   A ← L − R;           B ← R
    MID_SIDE:     A ← (L + R) ≫ 1;     B ← L − R          ≫ arithmetic

function setzeZusammen(A, B, mode):
    INDEPENDENT:  L ← A;               R ← B
    LEFT_SIDE:    L ← A;               R ← A − B
    RIGHT_SIDE:   R ← B;               L ← A + B
    MID_SIDE:     Σ ← (A ≪ 1) or (B and 1)               lost bit taken from the side
                  L ← (Σ + B) ≫ 1;     R ← (Σ − B) ≫ 1

Source: envisionz-framework-audiocodec/src/envisionz/audiocodec/Stereomodus.java. An unknown mode raises an exception.

The choice per frame

The encoder decomposes every stereo frame tentatively in all four modes and takes the one with the smallest cost measure. Unlike the subframe choice, no trial encoding takes place here. The measure is the sum of absolute steps from value to value in both sub-channels:

K(mode)=∑i=1N−1(|Ai−Ai−1|+|Bi−Bi−1|)K(\text{mode}) = \sum_{i=1}^{N-1} \big(|A_i - A_{i-1}| + |B_i - B_{i-1}|\big)

This is the sum of magnitudes of the residual of a first-order fixed predictor (fixed predictors): a sub-channel that runs smoothly can be predicted well and coded cheaply. The number is only for comparing the four modes with each other, not a byte value.

Pseudocode – Kodierer.waehleModus(L, R)

best ← INDEPENDENT;  smallest ← ∞
for mode in (INDEPENDENT, LEFT_SIDE, RIGHT_SIDE, MID_SIDE):
    (A, B) ← zerlege(L, R, mode)
    k ← Σ |A[i] − A[i−1]| + |B[i] − B[i−1]|             in long
    if k < smallest:  smallest ← k;  best ← mode
return best

Source: Kodierer.waehleModus and Stereomodus.kostenschaetzung. On a tie the mode tested first wins.

Convention in the framework: The mode is an 8-bit field in the frame body, right after frame number and length. For mono it is written as 0 and not evaluated. The choice by the cost measure is an estimate without trial encoding; the overview and the module documentation speak of a choice by bit cost at this point, but those bits are only counted one stage later, for the subframes.

Worked example

A frame from the example on the frame page. Left a sine with amplitude 12,000, right the same scaled by 0.8, independent noise in both channels (standard deviation 20). The four cost measures:

Modecost measurewhy
independent3,247,367both channels carry the full sine
left/side2,177,804LL full, SS with 0.2 of the amplitude
right/side1,818,233RR with 0.8, SS with 0.2 of the amplitude
mid/side1,997,237MM with 0.9, SS with 0.2 of the amplitude

The ratio matches the reasoning: the sum of the amplitudes of the two sub-channels is 1.8 (independent), 1.2 (left/side), 1.0 (right/side) and 1.1 (mid/side) times 12,000; the ranking of the cost measures is the same. The noise contributes a similar floor in all modes.

Parity at one position. L=1L = 1, R=0R = 0: M=⌊1/2⌋=0M = \lfloor 1/2 \rfloor = 0, S=1S = 1. Back: Σ=2⋅0+1=1\Sigma = 2 \cdot 0 + 1 = 1, L=(1+1)/2=1L = (1+1)/2 = 1, R=(1−1)/2=0R = (1-1)/2 = 0. And L=−1L = -1, R=0R = 0: M=⌊−1/2⌋=−1M = \lfloor -1/2 \rfloor = -1, S=−1S = -1, S & 1 = 1, Σ=−2+1=−1\Sigma = -2 + 1 = -1, L=(−1−1)/2=−1L = (-1-1)/2 = -1, R=0R = 0.

How it is tested

  • Bausteinprobe: all four modes there and back on two noise channels of 512 values (uniform in ±30,000), into which odd sums and extremes are deliberately inserted – (1,0)(1, 0), (−1,0)(-1, 0) and (−32768,32767)(-32768, 32767). Every mode must return both channels unchanged.
  • Umlaufprobe: identical channels (side zero everywhere) come back bit-exactly; the ratio there is 2.07 : 1 (Rice), because the second sub-channel costs almost nothing as a constant subframe and the first is noise. In addition stereo silence and full scale at the limits with both methods.

Limits

  • Only two channels. There is no decomposition for more, and the encoder rejects them.
  • The cost measure is an estimate. It can pick a mode whose actual bit cost is not the smallest – for instance when a sub-channel with a large sum of magnitudes can be predicted very well with LPC.
  • The side is formed in int. For word lengths up to 24 bits (side 25 bits) that is well within range; with 32-bit values the difference would overflow.
  • The decomposition is fixed per frame; there is no switching within a frame.
