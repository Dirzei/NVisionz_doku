Encoder and decoder – frames and subframe choice

How Kodierer cuts a signal into frames, picks for each sub-channel the cheapest of four subframe types by counted bit cost, and how Dekodierer reads a frame back: cost formulas, the LPC order candidates, pseudocode following the source, a worked example, probes and limits. The individual building blocks have pages of their own.

What it is about

A PCM audio signal consists of integers – at CD quality 44,100 values per second and channel, 16 bits each. These numbers are not random: neighbouring values lie close together, and the left and right channels resemble each other. A lossless encoder exploits this similarity to write fewer bits and must still return every single value unchanged. The criterion of success is therefore unambiguous: the round trip is bit-exact or it is wrong.

The path there has three stages, as in FLAC and related methods:

  1. Split. The signal is cut into frames of fixed length (default 4096 samples per channel). For stereo, one of four reversible decompositions into two sub-channels is chosen per frame (stereo decomposition).
  2. Predict. Within each sub-channel every value is predicted from its predecessors; only the prediction error, the residual, remains. It is much smaller than the signal (fixed predictors, LPC).
  3. Entropy-code. The residual is written with variable-length codes, short for small magnitudes and long for large ones (Golomb-Rice or the range coder).

This page covers the framework in between: in which order the building blocks run, how the encoder decides between the subframe types, and how the decoder reads a frame. How the frames lie in the stream and how the decoder resumes after damage is on the page EVAS stream format.

The four subframe types

A subframe is one sub-channel of a frame, that is NN integers x0,…,xN−1x_0, \dots, x_{N-1} with word length bb bits. Its header starts with three bits for the type:

TypeIdwhat is writtencost in bits
constant0a single value3+b3 + b
raw1all NN values with bb bits3+Nb3 + N b
fixed2order p∈{0,…,4}p \in \{0,\dots,4\} (3 bits), pp warm-up values, residual6+pb+KRice(e)6 + p\,b + K_\text{Rice}(e)
LPC3p−1p-1 (5 bits), precision q−1q-1 (4 bits), shift (5 bits), pp warm-up values, pp coefficients of qq bits, residual17+p(b+q)+KRice(e)17 + p\,(b + q) + K_\text{Rice}(e)

The constants are the header fields: 3 bits type, for “fixed” 3 bits order, for LPC 3+5+4+5=173 + 5 + 4 + 5 = 17 bits for type, order, precision and shift. Here KRice(e)K_\text{Rice}(e) is the exactly counted number of bits the Golomb-Rice coding needs for the residual ee, including its own header bits (Rice page). The first pp values are called warm-up values: a predictor of order pp needs pp predecessors; the first pp values of a frame have none and are therefore stored raw. This makes the frame self-contained; it needs nothing from the previous frame.

The word length bb is not always that of the source material. With a stereo decomposition the side channel holds the difference of two channels, which needs one more bit: 16-bit material becomes 17-bit values. Stereomodus.bitsA and bitsB give the width per sub-channel, and encoder and decoder both compute it with the same functions.

Convention in the framework: The choice is made by the actually counted bits of each type, not by a rule of thumb. The Rice cost serves as the yardstick even when the stream is written with the range coder: both entropy stages prefer the same residual, and a second trial encoding per candidate would not be worth the computing time (comment on planeTeilrahmen).

The choice per subframe

The decision runs in four steps. A constant subframe – silence, a DC offset, clipping at the rail – is written as such immediately; that costs 3+b3 + b bits for the whole subframe. Very short subframes with at most five values go raw. Then the raw form competes against the best fixed predictor, and finally a few LPC orders may try to undercut the result.

Which fixed order competes is decided by Festpraediktor.besteOrdnung from the sum of absolute residual values, a quick approximation. For LPC, the Levinson-Durbin recursion delivers the coefficients of all orders up to the maximum in one pass. From the residual energies Lpcpraediktor.schaetzeOrdnung estimates the cheapest order p^\hat p. The estimate hits the order of magnitude but not always the minimum; therefore p^\hat p, its neighbours p^±1\hat p \pm 1, p^±2\hat p \pm 2 and the fixed candidates 8, min⁡(16,pmax)\min(16, p_\text{max}) and pmaxp_\text{max} are computed exactly: quantise, form the residual, plan the Rice recipe, count bits.

Pseudocode – Kodierer.planeTeilrahmen(values, b)

if all values equal:  return CONSTANT
costRaw ← 3 + N·b
if N ≤ 5:  return RAW                               Festpraediktor.MAX_ORDNUNG + 1

// fixed predictor
p ← Festpraediktor.besteOrdnung(values, 4)            sum |e| + 8·p
e ← Festpraediktor.residuum(values, p)
costFixed ← 3 + 3 + p·b + Restkodierung.plane(e).cost
best ← (costRaw ≤ costFixed) ? RAW : FIXED(p)

if maxLpc < 1 or N ≤ maxLpc + 1:  return best

// LPC: all orders at once, then compute a few exactly
pmax ← min(maxLpc, N − 1)
r ← Lpcpraediktor.autokorrelation(values, pmax)        Welch window
solution ← Lpcpraediktor.levinsonDurbin(r, pmax)
p̂ ← Lpcpraediktor.schaetzeOrdnung(solution, N, precision, b)
for p in (p̂, p̂−1, p̂+1, p̂−2, p̂+2, 8, min(16, pmax), pmax):
    if p < 1 or p > pmax or already seen:  continue
    (coeff, shift) ← Lpcpraediktor.quantisiere(solution.coefficients(p), precision)
    e ← Lpcpraediktor.residuum(values, p, coeff, shift)
    cost ← 3 + 5 + 4 + 5 + p·b + p·precision + Restkodierung.plane(e).cost
    if cost < bestCost:  best ← LPC(p, coeff, shift)

A frame from the inside

The encoder walks over the signal in steps of the block size; the last frame is correspondingly shorter. Each frame is built completely on its own:

Pseudocode – Kodierer.kodiereRahmen

if stereo:
    mode ← waehleModus(left, right)                     smallest cost estimate of the four modes
    (a, b) ← Stereomodus.zerlege(left, right, mode)
else:
    mode ← INDEPENDENT;  a ← channel 0
planA ← planeTeilrahmen(a, bitsA);  planB ← planeTeilrahmen(b, bitsB)

write frame number (32 bits), length (16 bits), mode (8 bits)
if method = RICE:
    subframe header A, residual A (Rice), subframe header B, residual B (Rice)
    pad to byte boundary
else:                                                    method 2
    subframe header A, subframe header B, pad to byte boundary
    one range coder, one residual model:  residual A, then residual B
    append the termination of the range stream

frame ← 0xFF5A ‖ body length (32 bits) ‖ body ‖ CRC-16(over everything before)

Source: Kodierer.kodiereRahmen and schreibTeilkopf. With the range coder both subframe headers come first, because the range coder works byte by byte and cannot be interleaved with the bit stream.

All bit fields are written most significant bit first (Bitschreiber); an aligned eight-bit field then appears as one byte in the stream and can be read by hand. Signed fields – warm-up values, coefficients, raw values – are fixed-width two's complement and are read back with Bitleser.liesVorzeichen.

The way back for one frame

The decoder reads the frame in the same order and uses the same classes as the encoder for the reconstruction. That is deliberate: residuum and ruecktransformiere each live in one class, as does the model of the range coder. Two separate versions of the same computation would be the surest way to let encoder and decoder drift apart.

Pseudocode – Dekodierer.liesRahmen

number ← read 32 bits;  length ← read 16 bits;  mode ← read 8 bits
position ← number · nominal block size                 from the stream header
check 0 ≤ position < total samples                      otherwise exception
if method = RICE:
    a ← read subframe A (header, then Rice residual, then reconstruct)
    b ← read subframe B likewise                         only with two channels
else:
    headerA, headerB ← read subframe headers;  jump to byte boundary
    range decoder from here, one residual model
    a ← headerA + residual;  b ← headerB + residual
if stereo:  (left, right) ← Stereomodus.setzeZusammen(a, b, mode)
copy values to the target from position, at most up to total samples

Source: envisionz-framework-audiocodec/src/envisionz/audiocodec/Dekodierer.java, liesRahmen, liesTeilkopf, stelleHer.

Convention in the framework: The write position of a frame follows from its frame number times the nominal block size in the header, not from a running counter. A skipped, damaged frame therefore shifts nothing that follows. The source marks this as a correction.

Worked example

A stereo signal of 8192 samples per channel at 48 kHz, 16 bits: left a 440 Hz sine with amplitude 12,000, right the same sine scaled by 0.8, both channels with independent noise of standard deviation 20. Encoded with the defaults (block size 4096, Rice, LPC up to 32, precision 15) and traced with a small program against the module's classes.

How it is tested

The Umlaufprobe (36 checks) encodes, decodes and compares every value, each case with both methods. The cases are the places where a codec breaks:

  • silence mono and stereo, DC offset, pure sine, full-scale noise, sine with noise, full scale at the limits (alternating ±32767/−32768\pm 32767/-32768), a step in the middle;
  • a single value, exactly one block size (4096), block size plus one (4097);
  • 8, 16 and 24 bits, identical channels, very small (64) and very large (32,768) blocks;
  • resynchronisation: one byte in the stream corrupted (block size 2048). The strict decoder must stop, the lenient one must skip at least one frame, and all values from index 12,000 on must be correct. A corrupted byte in the header must be detected.

The probe reports the ratio for each case; in the last run it ranged from 0.02 : 1 (a single value, the header dominates) via 1.00 : 1 (noise) to 416.67 : 1 (stereo silence, Rice). The module's rule: whoever adds a subframe type or a method extends the Umlaufprobe.

Limits

  • At most two channels. kodiere rejects more with an exception.
  • Everything in memory. A Ganzsignal is encoded into a byte[]; encoding a stream while reading it is not provided. The decoder allocates the total sample count as an int.
  • Fixed overhead per frame: 15 bytes of frame header and trailer (sync word 2, body length 4, CRC 2, number 4, length 2, mode 1) plus the subframe headers. With very small blocks and noise the stream therefore becomes larger than the raw material (Umlaufprobe, block 64: 0.94 : 1).
  • The stereo choice is an estimate, not a trial encoding (stereo page); the subframe choice, in contrast, counts bits.
  • Lead-in and lead-out exist in the format; the lossless encoder writes them as zero.
  • Noise cannot be compressed. Full-scale noise arrives at 1.00 : 1; the raw form prevents the stream from growing noticeably.
