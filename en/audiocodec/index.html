envisionz-framework-audiocodec

Every sample comes back unchanged

Function overview for the presentation of the envisionz framework, as of 28 Sep 2026. An own lossless audio encoder with its own stream format EVAS: stereo decomposition, fixed and LPC predictors, Golomb-Rice or a range coder with a context model, batch runs over whole collections – and, as the first building block of the lossy path, MDCT and filter bank. For each method: purpose, API, use in the framework, applications, examples. The examples are shortened. Many API names are German (e.g. Kodierer = encoder, Bereichskodierer = range coder, Stapellauf = batch run, Fensterbank = window bank); they are shown unchanged.

Principles of the module

Lossless first. The success criterion is unambiguous: every sample comes back unchanged or it does not. Only once the round trip is bit-exact is a quantiser worth building.
Chosen by bit cost. Stereo mode, subframe type and Rice parameters are decided per frame by the actual cost, not by a rule of thumb.
The model lives in exactly one class. Haeufigkeitsmodell and Restmodell are shared by encoder and decoder; residuum and ruecktransformiere sit in the same class.
Integer from quantisation on. LPC coefficients are determined in floating point, then quantised; from there on each side computes only in long. The rounding error is passed on to the next coefficient.
Frames are self-contained. No bit reservoir, no back pointer. A damaged frame is detected, and the decoder resynchronises at the right position.
No third-party library. Nothing from java.util.zip; the only dependency is framework-audiometrik for Ganzsignal.

Encoder and decoder envisionz.audiocodec

Kodierer and Dekodierer

Per frame first the cheapest stereo decomposition (independent, left/side, right/side, mid/side), then per sub-channel the cheapest of four subframe types: constant, raw, fixed predictor of order 0…4, LPC up to order 32. The residual goes to Golomb-Rice or to the range coder. Defaults: block size 4096, Rice, full LPC order. On a damaged frame the decoder stops, or skips it in lenient mode. Stream format EVAS envisionz.audiocodec

Stromkopf and Pruefsumme – the fields whose absence became a problem with MP3

A 36-byte header with the tag “EVAS”, version, method identifier, sample rate, channel count, word length, total number of samples, lead-in and lead-out, nominal block size and a 64-bit checksum over all samples. Without the total and the lead-in/out gapless playback is impossible, without a method identifier a format does not survive its first codec. Each frame carries sync word, body length, frame number and CRC-16; the write position follows from the frame number, not from a counter. Background, formulas and pseudocode →

Prediction and stereo envisionz.audiocodec

Festpraediktor, Lpcpraediktor, Stereomodus

Fixed predictors of order 0…4 cost no coefficients. LPC: autocorrelation, Levinson-Durbin, order estimation, quantisation with the rounding error passed on (default 15 bits), sums in long – at order 32, 25-bit word length and 15-bit coefficients the 32-bit limit is clearly exceeded. The stereo decomposition is chosen per frame from a cost estimate. Entropy coding envisionz.audiocodec

Restkodierung, Bereichskodierer, Haeufigkeitsmodell, Restmodell

Method 1: Golomb-Rice with zigzag mapping, its own parameter per partition (partition order up to 6) and an escape case for raw values. Method 2: carry-less range coder after Subbotin; what is coded is the magnitude class of the residual, with the magnitude class of the predecessor as context. Because the models restart in every frame, the class models are pre-initialised and the top free bit is modelled too – without a single extra transmitted bit. Batch run envisionz.audiocodec

Stapellauf and Stapelergebnis – baseline over a whole collection

Each file is encoded with both methods and decoded again; recorded are raw size, both stream sizes, bit-exactness, encoding time and the difference in percent. The overall balance is weighted by the sums of bytes, not as a mean of individual ratios – otherwise a short file would count as much as a long piece. Background, formulas and pseudocode →

MDCT and filter bank envisionz.audiocodec

Mdct, Fensterbank, Fensterart, Fensterform – the transform of the lossy path

Still without a quantiser, and deliberately so: as long as nothing is quantised, the round trip must be bit-exact. Mdct turns 2M values into M coefficients via a DCT-IV with an own complex FFT of length M/2; the inverse alone yields the time-domain aliasing, only the windowed overlap-add cancels it. Window shapes sine and KBD (alpha 4 long, 6 short, as in AAC), window types LANG, START, KURZ (eight blocks) and STOPP. The left slope has the shape of the previous frame. Command line envisionz-commandline-audiocodec · cmd.audiocodec

Audiocodec and Flacvergleich

Tools in the house format -name:value: kodiere, dekodiere, pruefe (both methods there and back in memory), stapel, steckbrief and flac. For the comparison FLAC is not linked in but called as an external program (flac -8); if it is missing, the own figures are still reported, together with the link https://xiph.org/flac/download.html. Return codes: 0 OK, 10 not bit-exact, 11 damaged frames skipped, 12 file failed, 13 FLAC not found, 1/2/3 usage, switch, other error.

Examples

Audiocodec -op:kodiere -in:x.wav -out:x.evz -block:4096 -verfahren:2
Audiocodec -op:dekodiere -in:x.evz -out:y.wav -nachsichtig:ja
Audiocodec -op:pruefe -in:x.wav -lpc:0
Audiocodec -op:stapel -verz:./sammlung -rekursiv:ja -ausgabe:stapel.csv
Audiocodec -op:flac -in:./sammlung -bericht:vergleich.md
