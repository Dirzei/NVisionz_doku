Prediction and stereo – fixed predictors

The computation behind Festpraediktor: prediction by polynomial continuation, the residual as a difference of order pp, what that means in the frequency domain, how the order is chosen, pseudocode following the source, a numerical example, probes and limits. LPC and the stereo decomposition have pages of their own.

What it is about

A music signal usually changes only a little from sample to sample. Whoever estimates the next value from the last ones is therefore often close, and only the deviation – the residual – has to be stored. The decoder repeats the same estimate from the values it has already recovered and adds the residual. Because the estimate and the addition are integer operations and run identically on both sides, the path is reversible without any loss:

en=xn−x^n,xn=en+x^ne_n = x_n - \hat{x}_n, \qquad x_n = e_n + \hat{x}_n

The simplest estimate needs no side information at all: one assumes that the last values continue as a polynomial. These fixed predictors cost no coefficients in the stream, only three bits for their order. They are the baseline against which the more elaborate linear prediction (LPC) has to prove itself per subframe.

Prediction by polynomial continuation

The predictor of order pp fits the polynomial of degree p−1p-1 through the last pp values and reads it off at the next position. With the backward difference ∇xn=xn−xn−1\nabla x_n = x_n - x_{n-1} this is equivalent to assuming that the pp-th difference vanishes. The residual is then exactly this difference:

en=∇pxn=∑j=0p(−1)j(pj)xn−je_n = \nabla^p x_n = \sum_{j=0}^{p} (-1)^j \binom{p}{j}\, x_{n-j}

The weights are the binomial coefficients with alternating sign; there is nothing to transmit. The first pp values of a subframe have no pp predecessors. They are stored raw as warm-up values, and the residual has N−pN - p entries.

What this means in the frequency domain

The difference is a filter. For an oscillation xn=eiωnx_n = e^{i\omega n} with angular frequency ω\omega per sample, ∇xn=(1−e−iω)xn\nabla x_n = (1 - e^{-i\omega})\,x_n, and hence

|Hp(ω)|=|1−e−iω|p=(2sin⁡ω2)p|H_p(\omega)| = \left|1 - e^{-i\omega}\right|^p = \left(2 \sin\frac{\omega}{2}\right)^p

Below ω=π/3\omega = \pi/3, one sixth of the sample rate, 2sin⁡(ω/2)<12\sin(\omega/2) < 1: low components are attenuated, the more so the higher the order. That is why the fixed predictors work so well on music – most of its energy lies low. Above that, components are amplified, at half the sample rate by the factor 2p2^p. For white noise the variance of the residual grows by ∑j(pj)2=(2pp)\sum_j \binom{p}{j}^2 = \binom{2p}{p}, i.e. by 2, 6, 20 and 70 for orders 1 to 4. That is why order 0 and the raw form exist: for noise every prediction is worse than none.

Choosing the order

besteOrdnung computes the residual for every order from 0 to min⁡(pmax,4,N−1)\min(p_\text{max}, 4, N-1) and takes the one with the smallest sum of absolute values. The sum of absolute values approximates the bit cost of Rice coding, whose length grows roughly linearly with the magnitude (Rice page). Because every order pp costs pp warm-up values at full word length, it receives a small surcharge:

S(p)=∑n=pN−1|en|+8p,p∗=arg⁡minp⁡S(p)S(p) = \sum_{n=p}^{N-1} |e_n| + 8p, \qquad p^\ast = \arg\min_p S(p)

On a tie the smaller order wins. The exact bit count of the chosen order is then computed by Restkodierung.plane, and only with this number does the fixed predictor compete against the raw form and LPC (subframe choice).

Pseudocode – Festpraediktor

function prediction(w, i, p):
    p = 0: 0   p = 1: w[i−1]   p = 2: 2w[i−1] − w[i−2]
    p = 3: 3w[i−1] − 3w[i−2] + w[i−3]
    p = 4: 4w[i−1] − 6w[i−2] + 4w[i−3] − w[i−4]
    otherwise: exception

function residuum(values, p):                        length N − p
    for i ← 0 to N−p−1:  rest[i] ← values[i+p] − prediction(values, i+p, p)

function ruecktransformiere(values, rest, p):        values[0..p−1] are the warm-up values
    for i ← p to N−1:  values[i] ← rest[i−p] + prediction(values, i, p)

function besteOrdnung(values, pmax):
    limit ← min(pmax, 4, N−1);  best ← 0;  smallest ← ∞
    for p ← 0 to limit:
        s ← Σ |values[i] − prediction(values, i, p)| for i ← p … N−1   in long
        s ← s + 8p
        if s < smallest:  smallest ← s;  best ← p
    return best

Source: envisionz-framework-audiocodec/src/envisionz/audiocodec/Festpraediktor.java. The reconstruction runs forward, because every prediction needs the just-recovered predecessors in the same array.

Convention in the framework: At most order 4 (MAX_ORDNUNG), a 3-bit field in the subframe header. The prediction computes in int; at 25-bit word length (side channel from 24-bit material) the largest magnitude of order 4, 16⋅224=22816 \cdot 2^{24} = 2^{28}, stays within range. The surcharge of 8 per order is a fixed number in the code, not a derived quantity.

How it is tested

In the Bausteinprobe (30 checks, eight of them for this predictor):

  • A straight line 7i+37i + 3 has a residual of all zeros at order 2, and besteOrdnung picks exactly order 2 for it.
  • A parabola 3i2−5i+113i^2 - 5i + 11 has a zero residual at order 3.
  • For every order 0 to 4 a noise signal (256 values, uniform in ±5000) comes back unchanged through residual and reconstruction.

In combination the Umlaufprobe checks all subframe types for a bit-exact round trip (frame page).

Limits

  • Fixed predictors only know polynomials. They predict an oscillation with few samples per period poorly; there LPC wins, which determines its weights from the signal.
  • For noise and high frequencies every order from 1 up enlarges the residual (see above); then order 0 or the raw form wins.
  • The choice by S(p)S(p) is an approximation. It can pick an order whose exact Rice cost is not the smallest; only the chosen order is counted exactly.
  • Subframes with at most five values are not predicted at all but written raw.
