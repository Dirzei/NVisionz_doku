envisionz-app-forensik

Inspect, restore, compare and document image and video material

Overview of the app, as of 29 September 2026. Survey and restoration of video recordings, with comparison views and verifiable still images; plus seven command-line tools for the same tasks.

What the app is for

Anyone who has to evaluate video material, say an old recording from a DVD, faces two questions. First: what is actually there? In what form is the material stored, is it complete, which of the known pitfalls apply? Second: what can be made of it? Reduce noise, average frames over time, measure colour offsets, enlarge details, extract the sound – and in the end be able to present an image that shows plainly what was treated and what was not.

The app brings these steps together in one place. It is meant for inspection and for evidence: a wrongly labelled exhibit is worse than none, so the labelling of comparison images is a building block of its own, and a tested one.

What it can do

Survey: the profile (Steckbrief)

The profile takes a disc image, a VIDEO_TS directory, an MPEG file or a picture stream and says what is in it, in what form, and which of the known pitfalls apply. It is strictly read-only and decodes nothing. A directory is read as a title set: all part files come together as one stream, and completeness is checked against the description files. Size figures in the findings are formatted independently of the computer’s locale, because they go into a restoration plan.

java -cp bin envisionz.apps.forensik.Steckbrief scheibe.iso
java -cp bin envisionz.apps.forensik.Steckbrief /pfad/zu/VIDEO_TS
java -cp bin envisionz.apps.forensik.Steckbrief film.mpg

Inspect and compare

The comparison view knows five modes: slider with the mouse, side by side, original, treated and difference. The difference view is usually the most telling and can be amplified. Comparing here means showing the same section; the left half of one against the right half of the other would be two different places in the picture. A playback bar is included; sections can be enlarged with the Lupe tool.

Restore

Temporal averaging over several frames reduces noise without smearing moving parts: there is an adjustable motion threshold and a window of selectable size. The threshold can be derived from the noise of the material. The pixel aspect ratio (for example 1.067 for PAL 4:3) is corrected for display. The computations live in the framework’s restoration module; the app sets them up and shows their effect.

Sound

The sound can be extracted from the stream (as WAV) and auditioned and mixed in a dialog with track choice, sync offset and a level display.

Producing exhibits

Still images are saved as PNG with a footer, at full resolution and corrected for aspect ratio. Comparison images carry a label on the left and right. StapelBeleg creates an exhibit from a stack of images. Farbversatz determines the offset with the best match, measured on image edges; for material with no edges at all it says there is nothing to measure rather than naming a number.

Command line: seven tools

The computations can be called without the interface, for batch runs and for checking. The central tool is VideoRestore.

Tools

  • VideoRestore – restore and document
  • Bildfolge, Lupe – image sequences, enlarged sections
  • Farbversatz, StapelBeleg – measurement and exhibits; DrizzleProbe
  • TonAuszug – sound track as WAV

Return value of VideoRestore

  • 0: read and written
  • 1: stream rejected
  • 2: usage help
java -cp bin cmd.forensik.VideoRestore <strom.m2v|.vob|VIDEO_TS> [-o:<verzeichnis>]
     [-bild:N[,N...]] [-alle:N] [-schwelle:N] [-fenster:N]
     [-ansicht:ART] [-verstaerkung:N] [-verhaeltnis:X] [-messen]
SwitchMeaning
-o:target directory for the still images (created if missing)
-bild:, -alle:which frame numbers are saved, or every Nth frame
-schwelle:, -fenster:motion threshold and number of frames averaged
-ansicht:SCHIEBER, NEBENEINANDER, ORIGINAL, BEHANDELT, UNTERSCHIED (slider, side by side, original, treated, difference)
-verstaerkung:amplification of the difference view
-verhaeltnis:pixel aspect ratio, for example 1.067 for PAL 4:3
-messenmeasure only, write no images

The output is shortened and appears in German, as the tool prints it. The run judges real-time capability only from 50 frames on: with fewer one mostly measures the start-up of the runtime environment, and a wrong verdict is worse than none. Below that it prints the measured value with a note that it is not reliable.

Data and formats

  • Reads: MPEG picture streams (.m2v), .vob files and whole VIDEO_TS directories, disc images with an ISO 9660 file system, MPEG program streams; MPEG-1 Layer II as the sound format.
  • Writes: still images and exhibit boards as PNG, the sound track as WAV, nothing with -messen.
  • State: the app saves its state in the workspace and restores it.

What it builds on

  • framework-restore – the restoration computations: temporal averaging, motion threshold, look-ahead chain.
  • framework-video – reading and decoding the video streams.
  • framework-media – media building blocks on which video and restoration rest.
  • framework-audio – the sound: extraction and mixer for the sound dialog.
  • framework-swing – vertical toolbar with cards of 350 px, icons with tooltips, no pop-up windows.
  • framework-core and framework-api – basic building blocks and registration as an app.

Status and limits

The app is finished as an inspection and evidence tool; the tools can be used in the application as well as on the command line. Testing works on three levels: a wiring probe of its own (124 checks) for the interface, probes for each command-line tool and for the profile, which create their own inputs (picture stream, system packets, VIDEO_TS, silent sound frames), and the restoration module’s probes for the computations underneath. A probe with maliciously malformed input sends damaged streams through the profile and the decoder; it found an oversized sequence header, which has been fixed, and has reported no crash since.

Deliberately limited: the profile only assesses, it does not decode. The real-time verdict needs enough frames. And the restoration computations belong to the framework, not the app; the app only explains what was set.

Help texts in the interface are checked against the code: a wrong explanation misleads even when the calculation is right.
