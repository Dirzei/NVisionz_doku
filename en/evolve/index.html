envisionz-framework-evolve

Searching for quality and diversity, for any application

Function overview for the presentation of the envisionz framework, as of 28 Sep 2026. Quality-diversity search following the MAP-Elites pattern, interchangeable proposal operators from random mutation via differential evolution and CMA-ES to a surrogate model, storage of genomes and archives, discovery via ServiceLoader and a preference model learned from pairwise judgements. For each method: purpose, API, use in the framework, applications, examples. The examples are shortened.

Principles of the module

Domain-free. No image, digitizer or app terms in the module. Applications plug in via Evaluator and Proposer; domain knowledge belongs in their evaluator.
java.base is a contract. No jar, no network access, no reflection, so the module can ride along in any native-image launcher. The former LLM operator was removed for that reason.
Niches instead of a leaderboard. The archive keeps the best candidate per behaviour cell. A worse candidate in a different niche is accepted: mediocre solutions are stepping stones to good ones.
Invalid is not error. An invalid candidate is normal search traffic; an error points at the evaluator. Both are unusable but remain distinguishable.
Numbers only within bounds. Numeric operators touch genes only via NumericGenome; enumerations, switches and sequences have their own operators.
First check whether the metric can see the fault. A learned preference model is used as a target only with a confidence() bound; without it the search runs into regions where the model merely guesses.

Core: candidate, evaluation, archive, search run envisionz.evolve

Candidate, Evaluation, Evaluator

A genome is a map of named strings, with origin (seed, mutation, crossover, repair) and generation. The evaluation carries fitness, the descriptors for the niches, the status and additional metrics. The evaluator names axes, gene schema and starting population. MAP-Elites – Background, formulas and pseudocode → Search run – Background, formulas and pseudocode →

Methods

  • Candidate.seed(genes), child(newGenes, origin); Origin: SEED, MUTATION, CROSSOVER, REPAIR
  • Evaluation.ok(fitness, descriptors, metrics), invalid(msg), error(msg), isOk()
  • Evaluator: id(), displayName(), axes(), seeds(), geneSpec(), evaluate(c)
  • Evaluator.Axis(name, unit, min, max, bins), bin(value) – values outside fall into the edge cells

Used in

app-digitizer: DigitizerEvaluator (curve tracing)app-eqnparser: GuessEvaluator (start values)app-learn: LearnRootPanel

What for

Tuning the parameters of an image analysis; finding start values for the Newton solver that converge over many operating points.

Example – evaluating a candidate

public Evaluation evaluate(Candidate c) {
    double x = Double.parseDouble(c.genes().get("x"));
    return Evaluation.ok(-x * x, new double[] {x}, Map.of());   // fitness, one descriptor per axis
}

MapElitesArchive and EvolveEngine

The archive is a grid of niches, thread-safe, with parent selection that favours good elites. The QD score measures quality and diversity at once. The loop evaluates in parallel, reports every evaluated child back to the operator and can be cancelled; it can continue on a pre-filled archive.

Methods

  • new MapElitesArchive(axes), insert(c, eval), cellOf(descriptors), best(), elites(), sampleParents(n, eliteBias, rnd)
  • coverage(), capacity(), qdScore(), totalInserts(), totalAccepted(), totalRejected()
  • new EvolveEngine(evaluator, proposer, config[, archive]), run(onProgress), cancel(), archive()
  • Config(budget, batchSize, parentsPerJob, eliteBias, threads, topExamples, seed), Config.defaults(); Progress(generation, evaluations, coverage, qdScore, bestFitness, acceptedThisGen)

Used in

app-learn: search run with progressapp-digitizer: RandomProposer (measurement driver)

What for

Finding not just the one best setting but a map of good solutions across the behaviour axes.

Example – search run with two mixed operators

NumericGenome ng = NumericGenome.inferFrom(startGenom, 3.0);
Proposer prop = new MixedProposer(1L, true)
        .add("zufall", new GaussianMutationProposer(ng, 0.1, 3, 1L), 1.0)
        .add("de", new DifferentialEvolutionProposer(ng, 0.7, 0.9, false, 2L), 1.0);
EvolveEngine engine = new EvolveEngine(bewerter, prop, EvolveEngine.Config.defaults());
MapElitesArchive archiv = engine.run(p -> System.out.println(p.bestFitness()));
Config.budget is not a hard upper limit: it is checked before each generation, which then runs to completion, and the seeds come on top.

Operators for numeric genes envisionz.evolve

NumericGenome, GaussianMutationProposer, DifferentialEvolutionProposer

NumericGenome maps genome and vector onto each other with bounds, integers included, and can derive the bounds from a sample genome. Gaussian mutation is the baseline and warm-up. Differential evolution (DE/rand/1 or DE/best/1) computes v = a + F·(b − c) and needs at least four individuals. Gauss and DE – Background, formulas and pseudocode → CMA-ES and surrogate – Background, formulas and pseudocode →

Methods

  • new NumericGenome(genes), Gene(key, min, max, integer), inferFrom(sample, factor)
  • toVector(genome), toGenome(v, base), normalize(v), clamp(v)
  • new GaussianMutationProposer(map, sigmaFraction, maxChanges, seed)
  • new DifferentialEvolutionProposer(map, F, CR, bestVariant, seed)

Used in

app-learn: operator choiceapp-digitizer, app-eqnparser: NumericGenome in the provider

What for

Numeric parameters with bounds; differential evolution is the first choice.

CmaEsProposer and SurrogateProposer

CMA-ES adapts the covariance (Jacobi eigendecomposition) and has the edge with strongly coupled parameters; it is stateful and needs feedback via tell, invalid children count as −∞. The surrogate (RBF) chooses by utility plus uncertainty and pays off with expensive evaluations.

Methods

  • new CmaEsProposer(map, start, sigma0, lambda, seed) (λ = 0: rule of thumb 4 + 3 ln n), generation(), sigma(), tell(…)
  • new SurrogateProposer(map, beta, probes, seed), observe(genome, fitness), predict(x), uncertainty(x), observations()
  • Proposer: propose(parents, context, n), tell(child, eval, accepted)

Used in

app-learn: operator choice

What for

Coupled parameters (CMA-ES); evaluations that take a minute or longer (surrogate).

Measured comparison on twelve tracer parameters (target from human judgements, larger is better, start −0.9842): after 200 evaluations random mutation −0.8948, CMA-ES −0.8906, differential evolution −0.8462, surrogate −0.8593.

Structural genes and sequences envisionz.evolve

StructuralGenome, StructuralMutationProposer, SequenceGenome, SequenceMutationProposer

Structural genes are enumerations and switches; the operator changes a value or toggles. The switches are stored in order, so the same seed gives the same candidates on every start. Sequence genes are ordered lists from a pool (comma-separated encoding); the operator swaps, moves, inserts and removes. Background, formulas and pseudocode →

Mixing operators envisionz.evolve

MixedProposer – several operators over the same archive

Picks an operator per proposal by weight, optionally adapted to the hit rate. Feedback goes to the originating operator, so CMA-ES and the surrogate also receive their observations inside the mix. Background, formulas and pseudocode →

Methods

  • new MixedProposer(seed, adaptive), add(name, proposer, weight), entries()
  • Entry: name(), weight(), proposed(), accepted(), hitRate(); feedback(child, accepted)

Used in

app-learn: mix of random, DE and structure

What for

Numeric and structural genes in one run; measuring which generation route actually produces improvements.

proposed() is incremented in feedback, not when proposing: without feedback it stays at zero.

Storage and evaluation cache envisionz.evolve

GenomeIO, ArchiveIO, MemoizingEvaluator

A genome as an ordered key=value text file: the exchange format between search and GUI presets. An archive as a directory with axes.properties and elite-*.properties, so learning continues across runs and sessions. The cache wraps an LRU store genome → evaluation around a deterministic evaluator. Background, formulas and pseudocode →

Methods

  • GenomeIO.load(file), loadResource(near, name), save(genes, file, comment)
  • ArchiveIO.save(archive, dir), load(dir), exists(dir), describe(dir)
  • new MemoizingEvaluator(delegate[, capacity]) (default 10,000), hits(), misses()

Used in

app-learn: load and save archive, save genomeapp-digitizer: GenomeIO (presets)MemoizingEvaluator: ready, no callers outside the probes yet

What for

Using settings found by the search in the GUI; continuing a search tomorrow where it stood today.

Example – saving an archive and continuing later

ArchiveIO.save(archiv, Path.of("lauf-01"));
MapElitesArchive weiter = ArchiveIO.load(Path.of("lauf-01"));
new EvolveEngine(bewerter, prop, cfg, weiter).run(null);
Never wrap it around a stochastic evaluator: the cache hides the spread.

Preference model from pairwise judgements envisionz.evolve

PreferenceModel – Bradley-Terry with a confidence measure

When the objective cannot be written down: a human says “A or B is better”, and the model learns feature weights (L2-regularised). confidence() measures the distance to the nearest judged example. Reliable from 30 to 50 judgements. Background, formulas and pseudocode →

Methods

  • new PreferenceModel(featureNames), fit(pairs, lambda, steps), Pair(better, worse)
  • score(x), confidence(x), accuracy(pairs), weights(), names()

Used in

ready, no callers outside the probes yet

What for

Quality of a curve extraction judged by eye; any objective whose hand-written version misses the point.

Example – weights from judgements, search only within the confidence region

PreferenceModel pm = new PreferenceModel(new String[] {"glatt", "abdeckung"});
pm.fit(urteile, 0.05, 500);
double nutzen = pm.score(merkmale), vertrauen = pm.confidence(merkmale);
Measured on the digitizer: six hand-designed objectives placed the preferred results at ranks 11, 6 and 9 of twelve; after 19 judgements the preference model was right 89 % of the time. Without the confidence bound an unjudged candidate received twenty times the best utility and was in fact poor.
