PostScript and EPS: execute only as much as needed – background

How PsLeser and PsAuswerter obtain paths, texts and bitmaps from generated PostScript files, how curves and arcs become polylines, and how PsBild computes an image from them.

What this is about: a file that has to be executed

PostScript is a programming language with an operand stack: 3 4 add puts 3 and 4 on the stack, add replaces them by 7. A PostScript file does not describe a page, it draws it by running. Strictly speaking such a file therefore cannot be read, only executed – the language is Turing-complete.

Programs such as gnuplot, matplotlib, dvips, Tecplot or old plotter libraries generate PostScript, however, to a narrow pattern: a prologue defines short abbreviations (/M {moveto} bind def), followed by a straight sequence of moveto, lineto, stroke, show. This is exactly what the evaluator is built for: operand stack, dictionary stack with def, procedure call, transformation stack, path construction. For older diagrams this is more useful than an image: the curves are numbers in the file and can be digitised as vector data.

The reader: values instead of commands

PsLeser splits the source text into values: numbers (as Double), strings (…) with the same escapes as in PDF and hex strings <…> (odd digit count: a 0 appended), names, arrays […] and – new compared with PDF – procedures {…}, the heart of the language. A name with a slash (/x) is literal and goes on the stack; without a slash (x) it is executed.

The evaluator

Each value of a program is executed in turn: if it is an executable name, it is treated as an operator, every other value goes on the stack. For an operator a fixed order applies, and it is essential:

Implemented are stack operators (pop, dup, exch, roll, index, copy, marks), arithmetic (add to ln, atan with result 0 to 360 degrees), arrays and strings (getinterval shares the memory, as the language reference demands), comparisons, control flow (if, ifelse, for, repeat, loop, forall, exit, stopped), dictionaries (def, begin, end, load, store, known, where), graphics state and transformations (gsave, translate, scale, rotate, concat), colours (setgray, setrgbcolor, setcmykcolor, sethsbcolor), paths (moveto, lineto, curveto, arc, arcn, arcto and the relative forms), painting (stroke, fill, eofill, rectfill), imagemask and show and relatives as text pieces. image and colorimage are skipped.

The graphics state

According to the language reference, gsave saves more than the matrix: transformation matrix, line width, grey and colour, the current path, the current point and the selected font. If only the matrix is saved, the outline is lost when a file writes filled areas with a border as gsave fill colour fill grestore stroke. The current point lives in device space: translate, rotate, scale and concat change the mapping (CTM⁡'=M⋅CTM⁡\mathrm{CTM}' = M \cdot \mathrm{CTM}) but do not move the point. Tecplot writes moveto first, then rotate, then show; anyone who holds the point in user coordinates places the axis labels rotated by 90 degrees as a horizontal row far to the left of the drawing.

Colours: setcmykcolor computes R=1−min⁡(1,C+K)R = 1 - \min(1,\, C + K) according to the language reference, likewise for G and B. Example: C=0.2C = 0{.}2, K=0.1K = 0{.}1 gives R=0.7R = 0{.}7.

Arcs and curves

A circular arc (arc: centre, radius, start and end angle in degrees) is split into segments of at most one degree each: n=max⁡(2,⌈span⌉)n = \max(2, \lceil \text{span} \rceil), the span being w2−w1w_2 - w_1 (for arcn w1−w2w_1 - w_2), increased by 360 if negative. A quarter circle thus becomes 90 segments (91 points), a full circle 360. Cubic Bézier curves (curveto) stay curves in the path; PsPfad.streckenzuege(stücke) subdivides them on request with

P(t)=(1−t)3P0+3(1−t)2tP1+3(1−t)t2P2+t3P3,t=i/nP(t) = (1-t)^3 P_0 + 3(1-t)^2 t\, P_1 + 3(1-t) t^2\, P_2 + t^3 P_3, \qquad t = i/n

Example: P0=(0,0)P_0 = (0,0), P1=(0,10)P_1 = (0,10), P2=(10,10)P_2 = (10,10), P3=(10,0)P_3 = (10,0) at t=12t = \tfrac12: x=0.375⋅0+0.375⋅10+0.125⋅10=5x = 0{.}375\cdot 0 + 0{.}375\cdot 10 + 0{.}125\cdot 10 = 5, y=0.375⋅10+0.375⋅10=7.5y = 0{.}375\cdot 10 + 0{.}375\cdot 10 = 7{.}5.

Pseudocode – PsAuswerter

fuehreAus(werte):
    for each value w:
        if ++schritte > 20 000 000: return
        if w is a non-literal name: operator(name)
        else stapel.push(w)                       number, string, literal name, procedure, array

operator(op):
    if tiefe ≥ 400: schritte ← limit+1;  return      a self-calling procedure ends quietly
    eigen ← schlage(op) in the dictionary stack, from the top
    if eigen:  procedure → fuehreAus(body)  |  name (alias) → operator(alias)  |  else push(eigen);  return
    select op:  ... built-in operators ...
        moveto: pfad.anfang(map(x, y));  point ← mapped
        curveto: curve with mapped points
        gsave: zustaende.push(matrix, width, colour, copy of path, point, font)
        fill, stroke, eofill: pfade += (path, kind, colour, line width)
        show: texte += (string, font, size, angle, colour)
        otherwise: unbekannt[op]++

Source: envisionz-framework-pdf/src/envisionz/ps/PsAuswerter.java (fuehreAus, operator, operatorRumpf, bogen, sichereZustand), PsLeser.java, PsPfad.java (streckenzuege).

Decision in the framework: evaluation has a step limit (20 000 000 executed values) and a depth limit (400 nested operators): a file that computes instead of drawing does not halt the program. Both end quietly with what has been drawn up to then. The advance of show is estimated without metric files. clip is not evaluated.

EPS header and image

EpsDokument.lies first reads the header from the comments of the Document Structuring Convention: %%BoundingBox, %%Creator, %%Title, %%Pages. The creator tells what one is dealing with: a dvips file is something different from one by Tecplot. Preview images are recognised: the ASCII preview between %%BeginPreview and %%EndPreview (stands as a comment, does not disturb, is reported) and the binary DOS EPS, which has 30 bytes prepended that begin with C5 D0 D3 C6 and give position and length of the PostScript part; that part is cut out.

PsBild.zeichne(dokument, dpi) computes an image from the paths. A PostScript point is 1/72 inch; the scale is m=dpi⁡/72m = \mathrm{dpi}/72, the image size ⌈(x1−x0)m⌉×⌈(y1−y0)m⌉\lceil (x_1 - x_0)\, m \rceil \times \lceil (y_1 - y_0)\, m \rceil according to the %%BoundingBox. PostScript counts yy upward, an image downward: the point (x,y)(x, y) of an area HH points high lies in image row H−yH - y. Example: an area of 400 × 300 points at 150 dpi: m=2.0833m = 2{.}0833, so 834 × 625 image points. Lines are drawn at least 0.4 image points wide (0.4/m0{.}4/m in points); width 0 of the language reference means the thinnest line that can be shown, visible and not vanished. With %%Orientation: Landscape the content stands rotated on the portrait sheet and is shown upright.

Source: envisionz-framework-pdf/src/envisionz/ps/EpsDokument.java (lies), PsBild.java (zeichne, zeichnePfad).

How it is checked

  • Auswerterprobe: small programs whose result the PostScript language reference fixes: idiv truncates, mod has the sign of the dividend, round takes the larger number on a tie, atan gives 0 to 360 degrees, (a)(b)(c) 3 1 roll gives (c)(a)(b); strings with \ddd and balanced parentheses; gsave saves the whole state; setcmykcolor after 7.2.4.
  • Pfadprobe: a generated EPS with known geometry, in which scale and translate deliberately have awkward values so that every target point can be recomputed by hand; and, where available, real files: every point must land in the file's own %%BoundingBox – the file brings its target values itself. If the files are missing, this is reported, not counted as failure.
  • Punktprobe: the current point survives a change of mapping (moveto, then rotate).
  • Psbildprobe: pixel values in the interior of areas and strokes, far from edges so that anti-aliasing has no effect: red 0xFF0000, black, 0.5 grey = 128; at 72 dpi one point per image point, at 144 dpi two; the landscape mark at top left stays at top left. Psbausteinprobe: strings and bitmaps (most significant bit left, rows padded to whole bytes).

Limits

  • Not a complete PostScript interpreter: files that compute instead of drawing are ended at the step limit; unknown operators are skipped and stand in unbekannt().
  • image and colorimage are not evaluated (imagemask is); clipping paths (clip) are ignored.
  • The text advance is estimated as long as no metric files of the font exist; texts therefore stand as pieces with font name, size, angle and colour, not as fully set glyphs.
  • Arcs are polylines with at most one degree per segment, not exact curves.
