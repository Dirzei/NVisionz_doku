envisionz-app-learn

A workbench for the evolutionary search for good settings

Overview of the app, as of 7 October 2026. Choose a task, set search method and budget, start and watch the search, and hand out the best result as a preset file.

3source files (LearnApp, LearnRootPanel, Msg)
6search operators to choose from
6buttons in the toolbar
169checks in 3 probes

What the app is for

Some programs have settings that cannot be calculated: the parameters of an image evaluation, the starting values of an equation solver, the order of processing steps. One tries, judges the result and tries again. The learning workbench turns that into an orderly search: a task defines what a candidate is and how good it is; the workbench proposes candidates, has them evaluated and keeps the best in an archive organised by properties of the solution (MAP-Elites), so that not just one winner but a variety of good solutions remains.

The workbench is general. What is searched for comes with the tasks; the app does not know them itself but finds them at start-up through a framework service. Two tasks are bundled: the search for settings for tracing curves in an image (see the Image Digitizer), with an image and a reference curve as input, and the search for starting values with which the equation solver converges quickly and reliably (see EqnParser), with a model file as input.

How to use the workbench, what MAP-Elites and the archive are and what the fields mean is shown on the How to use page.

What it can do

Choose task and inputs

The available tasks appear in a list sorted by display name. For each task the app builds the required input fields from its declaration: one text field with a file chooser per key. If a task fails to be created, the others remain usable.

Search method and budget

Six proposal methods are available:

Operators

  • Mixed from random, differential evolution and structure (default)
  • Gaussian random
  • Differential evolution: DE/rand/1 and DE/best/1
  • CMA-ES
  • Surrogate model (kernel regression)

Why “Mixed” is the default

Differential evolution needs at least four different members. With a single starting value it yields nothing at first; the random share fills the archive first. The bounds of the search come from the task, otherwise they are derived from the starting value.

Search, watch, cancel

The search runs in the background and the interface stays usable. Progress and log appear continuously; cancelling takes effect after the generation currently running, and the status line then says “cancelled”. If a run ends because the operator proposes nothing more, it says that too. Closing while a search is running prompts for confirmation. A task’s evaluations run in parallel and must therefore be thread-safe.

A table of the best candidates is shown, descending by fitness, with archive cell, generation, origin and the first four metrics; a double click shows the genome in the log.

Continued learning and export

The archive can be saved to a directory and loaded again. After a run, the next start automatically builds on the archive; if the task is changed or the inputs are altered, it is discarded and the log says so.

The best result, or the selected table row, is exported as a preset file with a comment header (task, fitness, generation). That file can be loaded directly in the tracing stage of the Image Digitizer.

Data and formats

  • Inputs: whatever the chosen task requires; for tracing an image and a reference curve as CSV, for the starting-value search a model file and optionally operating points as CSV.
  • Archive: a directory with an axes file and one file per elite candidate, in properties format.
  • Preset: a genome file in the format of the framework’s search module.
  • State: chosen task, operator, budget and input paths are kept in the workspace; an unreadable or unsuitable remembered value is skipped without aborting the restore.

What it builds on

  • framework-evolve – the search engine: MAP-Elites archive, operators, task interface and genome formats. The workbench is its user interface.
  • framework-swing – the framework’s conventions for user interfaces (toolbars, texts, icons).
  • framework-api – registration as an app, tab state, closing and clean-up.

No app depends on another: tasks register through a service that other applications can provide, without the workbench knowing them by name.

Status and limits

The basic framework works completely: task choice, inputs, search run, archive, export and state. It is tested in a language probe (28 checks: both bundles, translation, placeholders), a workbench probe (75 checks: task choice, input fields, a failing and a real search run, continued learning and discarding the archive, state, app registration) and a user-interface probe (66 checks: toolbar with icons, help button, English interface, cancelling, early end, window layout).

Planned extensions: a warm start for performance maps through a surrogate model, a rating card for preferences in image comparisons and a chart of the fitness history in place of the text log.

Categorical genes (enumerations, booleans) stay frozen in random and DE search; they are changed only by the structural mutation contained in the “Mixed” operator. Anyone choosing a task’s metric should first check that it can actually see the error one wants to remove.
