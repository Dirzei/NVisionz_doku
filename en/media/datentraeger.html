Discs and file systems – background

The computation behind Sektorquelle, Iso9660, Udf and Lesbarkeit: how an image falls into sectors, how the two file systems of a DVD are read, and what an image can and cannot tell about read errors.

Sectors and the sync pattern

A disc image is a file that holds the sectors of the disc one after another. There are two forms. The ordinary image (.iso) keeps only the 2048-byte payload of each sector. The raw image keeps the whole sector of 2352 bytes: header, payload and error protection. Video CDs are stored in mode 2 form 2, which leaves 2324 bytes of payload because form 2 gives up part of the error protection.

Copying a .DAT file of a video CD through the file system yields either breakage or the header bytes in the middle of the data stream. The module therefore works sector by sector and computes the address itself. For sector number ss, raw form and mode:

a(s)=s⋅G+V,G={2352raw image2048otherwise,V={24raw image, mode 216raw image, mode 10otherwisea(s) = s \cdot G + V, \qquad G = \begin{cases} 2352 & \text{raw image} \\ 2048 & \text{otherwise}\end{cases}, \qquad V = \begin{cases} 24 & \text{raw image, mode 2} \\ 16 & \text{raw image, mode 1} \\ 0 & \text{otherwise}\end{cases}

and the number of sectors is ⌊file size/G⌋\lfloor \text{file size} / G \rfloor.

Pseudocode – Sektorquelle

// open: read only
head ← first min(2352, file size) bytes
raw ← head starts with the sync pattern (12 bytes)
if raw and length(head) ≥ 24:
    mode ← head[15]
    form ← (mode = 2 and bit 5 of head[18] set) ? 2 : 1
else: mode ← 1;  form ← 1

payload ← if not raw: 2048;  else (mode = 2 and form = 2) ? 2324 : 2048

// reading in the logical data space – across sector borders, without header and protection
read(offset, length):
    s ← offset div payload;  i ← offset mod payload
    while fewer than length bytes collected and s < sectors:
        copy min(length − collected, payload − i) bytes from sector(s) starting at i
        s ← s + 1;  i ← 0

Source: envisionz-framework-media/src/envisionz/media/disc/Sektorquelle.java. The image is opened with READ only.

Convention in the framework: The payload is 2324 bytes only for mode 2 and form 2; mode 2 form 1 has 2048 bytes but also starts after 24 bytes of header. If the sync pattern is mangled, the image counts as ordinary and the sector count is computed with 2048 – the probe checks exactly this case. puffer reads multi-byte numbers of the raw sector least significant byte first.

ISO 9660

The older of the two file systems on a DVD. From sector 16 on there are volume descriptors of 2048 bytes each, every one with a type byte and the identifier CD001, until one carries type 255. The primary descriptor (type 1) holds the root directory record from byte 156. A supplementary descriptor (type 2) with one of the escape sequences %/@, %/C or %/E from byte 88 marks Joliet: names in UCS-2 instead of upper case with the version suffix ;1.

Numbers are stored twice, least significant byte first, then most significant first. The first half is read. A directory record has fixed fields: record length (byte 0), first sector (from 2), size (from 10), flags (byte 25, bit 1 = directory), name length (32) and the name from 33. A record never crosses a sector border; the rest of the sector is filled with zeros.

Pseudocode – Iso9660

// find descriptors
for i ← 0 to 31:
    s ← sector(16 + i)
    if s[1..5] ≠ "CD001": stop               at i = 0: finding "pure UDF or not an image"
    if s[0] = 255: stop
    if s[0] = 2 and escape sequence at 88 ∈ {%/@, %/C, %/E}: joliet ← true
    if s[0] = 1 or joliet:
        if s[0] = 1 and root already known: continue      Joliet takes precedence
        name ← s[40..71];  sectorsPerDescriptor ← number(s, 80)
        root ← (number(s, 158), number(s, 166))
if image shorter than sectorsPerDescriptor: finding FALLE   incomplete, the end may be missing

// directory tree, recursive, depth ≤ 12, at most 1 MiB per directory
collect(sector, length, path):
    p ← 0
    while p < length(data):
        len ← data[p]
        if len = 0: p ← next sector border;  continue
        skip the entries "." and ".."   name = 00 or 01
        name ← name field (UCS-2 for Joliet);  cut off at ";"
        report entry(name, path, first sector, size, directory?)
        if directory: collect(first sector, size, path/name)
        p ← p + len

Source: envisionz-framework-media/src/envisionz/media/disc/Iso9660.java. Rock Ridge is recognised and reported by the system fields RR, NM or PX after the name, but not evaluated.

Convention in the framework: Sizes are 32-bit values. A file over four gigabytes cannot be represented in ISO 9660; then the truth is only in the UDF, and Udf is the source of choice. If the image is shorter than the descriptor says, the module reports a FALLE – this looks like an aborted read-out.

UDF

The actual file system of a DVD. It is chained: the anchor at sector 256 (alternatively at the end of the disc) gives location and length of the descriptor sequence. In it sit the partition descriptor with the first sector of the partition and the logical volume descriptor with block size and a reference to the file set. The file set refers to the control block (ICB) of the root directory, the control block says where the content lies, and the directory entries refer to further control blocks.

The trap in this chain: all block references are relative to the partition. The absolute sector of a control block with reference bb is

s=P+b,P=first sector of the partitions = P + b, \qquad P = \text{first sector of the partition}

Forgetting PP means reading beside the target everywhere – plausibly beside it, because data lies there too. The file set descriptor also carries a checksum of its tag: byte 4 is the sum of bytes 0 to 15 without byte 4, modulo 256.

Pseudocode – Udf

// find the anchor: sector 256, last sector, last − 256
for at in (256, last, last − 256):
    if tag(at) ≠ 2: continue
    (length, place) ← fields at 16 and 20
    for each sector of the descriptor sequence (at most 64):
        if tag = 5:  P ← first sector                  partition descriptor
        if tag = 6:  blockSize ← field at 212;  fileSet ← field at 252
    if P known: read file set at P + fileSet
        if tag checksum wrong: finding ACHTUNG, do not read the root
        rootIcb ← field at 404

contentOf(icb):
    d ← sector(P + icb)
    if tag 261: length of extended attributes at 168, of allocation descriptors at 172
    if tag 266: (40 bytes longer) at 208 and 212
    if address type = 3: data sits in the entry itself, lad bytes long
    else: for each address (short 8, long 16, extended 20 bytes):
        length ← field & 0x3FFFFFFF;  type ← upper 2 bits;  if length = 0: end
        if type = 3: continue in the allocation extent descriptor (tag 258) at P + place
        else: note extent (P + place, length);  total ← total + length
    place ← place of the first extent;  length ← total

collect(icb, path):                                  depth ≤ 10
    for each directory entry (tag 257):
        if characteristic "parent" (bit 3) or "deleted" (bit 2): skip
        name ← name field; first byte 8 or 16 = bits per character
        report entry; if directory: collect(childIcb, path/name)
        next entry: pad to a multiple of 4

Source: envisionz-framework-media/src/envisionz/media/disc/Udf.java. Standards: ECMA-167 and UDF 2.01, against which the probe is also checked.

Convention in the framework: A deleted entry does not appear in the list. A file set with a wrong tag checksum is reported and not used; ISO 9660 can then still name the files. Directories embedded in the file entry itself are read. Files and directories made of several extents are followed across all extents, including continuation blocks; this is needed precisely for files over four gigabytes, because one extent holds at most 230−12^{30}-1 bytes. Extents that are not recorded read as zeros.

Readability: read errors and sessions

The C2 error report arises in the drive while reading and is in no image; an image is a copy of the payload, not of the reading process. Session borders are in the table of contents of the disc, not in the sectors. Lesbarkeit therefore never asserts either from the image, but looks at what the read-out tool has recorded:

  • A .cue or .toc file names tracks. The line INDEX 01 mm:ss:ff gives, at 75 frames per second, the sector number (60m+s)⋅75+f(60\,m + s)\cdot 75 + f. Example: 04:30:12 is sector 270⋅75+12=20262270 \cdot 75 + 12 = 20262. A track, however, is not a session – an audio CD has a dozen tracks in one session. Ripping tools write session borders as REM SESSION nn; a session starts at the INDEX 01 of its first track. Without such a line there is exactly one session, starting with the first track. Tracks (spuren()) and session starts (sitzungen()) are kept separately; only with more than one session is there a warning, because then the last one counts and earlier ones may hold older versions of the same files.
  • An error map from ddrescue (.map, .mapfile, .log, .ddrescue) gives per line start, length and a status character; everything except + counts as not read. Byte values become sectors: from ⌊start/2048⌋\lfloor \text{start}/2048 \rfloor to ⌊(start+length−1)/2048⌋\lfloor (\text{start}+\text{length}-1)/2048 \rfloor. Example: 0x00100000 0x00004000 - concerns sectors 512 to 519.
  • If both are missing, the suspicion remains: long contiguous runs of zero sectors. A black picture looks the same.

Pseudocode – Lesbarkeit.verdacht

// only if no error map has delivered gaps
n ← number of sectors;  if n < 64: done
step ← max(1, n div 4000)                          sampling, so the profile stays fast
run ← none
for s ← 16, 16 + step, … while s < n:
    empty ← all bytes of sector(s) are 0
    if empty and no run open: run ← s
    if not empty and run open:
        if s − run > n div 100: report gap(run, s − 1, suspicion)
        run ← none
if run still open and n − run > n div 100:     zero area up to the end of the image
    report gap(run, n − 1, suspicion)

Source: envisionz-framework-media/src/envisionz/media/disc/Lesbarkeit.java. Each gap carries a field nachgewiesen (proven) and its origin; only an error map turns it into proof.

Convention in the framework: A gap is reported only above one hundredth of the image. The final run is checked as well: an aborted read-out ends exactly like this, and the first version of the class missed it because a run was closed only if a written sector followed. With several sessions the last one counts; earlier ones may contain older versions of the same files.

How it is checked

The probe Medienprobe lays out sectors, ISO 9660 directories and descriptors byte by byte itself; no stored test files exist. disc.Udfprobe checks the UDF chain against ECMA-167/UDF 2.01 with generated test pieces. Every damage case has a case with intact material beside it, because a judge that deems everything broken is as wrong as one that notices nothing.

  • Sektorquelle: a mangled sync pattern is not read as a raw image; the sector count is then computed with 2048.
  • ISO 9660: an image without Joliet reports none; a Joliet image yields the volume name and long names in UCS-2; a too short image raises the FALLE finding.
  • UDF: deleted entries are missing, embedded directories appear, a file set with a wrong checksum is reported; a file made of two extents and one with a continuation block have the sum of the lengths as their size, and the entries of a directory in two extents all appear.
  • Lesbarkeit: proven gaps from an error map, suspicion without a map, intact material without a report, a zero area at the end of the image; two tracks without REM SESSION are one session without a warning, three tracks in two sessions give two session starts and a warning.

Limits

  • Not checkable and not asserted: the drive's C2 report and real session borders without a companion file. Both are named as LÜCKE in the finding.
  • The suspicion is a sample: a zero area shorter than the sampling step can stay undetected, and the borders of a reported run are inexact by up to one sampling step. Every run above the reporting threshold (forty sampling steps) is seen.
  • Rock Ridge is only recognised. Directories are read with at most 1 MiB each; depth is limited to 12 for ISO 9660 and 10 for UDF.
  • A chain of continuation blocks is followed for at most 64 links.
