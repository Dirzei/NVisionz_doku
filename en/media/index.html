envisionz-framework-media

From disc image to elementary stream, without inventing anything

Function overview for the presentation of the envisionz framework, as of 28 Sep 2026. The layer beneath the video decoder: sectors and file systems (ISO 9660, UDF), DVD navigation (IFO, VOB), MPEG program streams with picture, sound and time stamps, readability of damaged images and a detector for what a file is – every statement as a graded finding. For each method: purpose, API, use in the framework, applications, examples. The examples are shortened. Many API names are German (e.g. Befund = finding, Sektorquelle = sector source, Lesbarkeit = readability, Tonstrom = audio stream); they are shown unchanged.

Principles of the module

Invent nothing. A DVD backup is to become a picture without anything being made up along the way. What is only suspected is called a suspicion, not a finding.
Read-only. Images are opened exclusively with READ; large title sets are streamed file by file, not loaded into memory.
Findings with consequences. Every statement carries a grade and says what it means for further processing – not “here is a video” but “non-square pixels, otherwise distorted faces”.
Traps named. Navigation packs in the middle of the stream, partition-relative UDF sectors, BCD times in the IFO, MPEG-1 headers with stuffing bytes, random sync words in audio – each one is documented in the Javadoc of the class that handles it.
Without dependencies. No project references, no third-party library. framework-video, framework-restore and app-forensik build on it.

Findings envisionz.media

Befund, MediaException, UnsupportedMediaException

The profile of a disc is not prose but a list of findings: level, area, statement and consequence. INFO is a plain fact, ACHTUNG must be heeded, FALLE is a known place where things tend to go wrong, LUECKE says what this tool does not handle.

Discs and file systems envisionz.media.disc

Sektorquelle, Iso9660, Udf – sector by sector, not file by file

Sektorquelle recognises by the sync pattern 00 FF … FF 00 whether a raw image with 2352 bytes per sector is present (Video CD, mode 2 form 2 with 2324 bytes of payload) or an ordinary one with 2048. Iso9660 reads primary and supplementary descriptors and recognises Joliet and Rock Ridge. Udf follows the chain anchor → descriptor sequence → file set → control block → directory, with sector numbers relative to the partition; it skips deleted entries, verifies the tag checksum and reads data embedded in the file entry itself. Lesbarkeit – read errors and multi-session, and what an image can tell about them

C2 errors and session boundaries are in no image. The class therefore looks at what the ripping tool recorded: a .cue or .toc file names the sessions, a ddrescue map the unreadable areas. Without either, the suspicion from contiguous zero sectors remains – explicitly marked as a suspicion, because a black frame looks the same.

Methods

  • Lesbarkeit(abbild, quelle), luecken() → Luecke(vonSektor, bisSektor, nachgewiesen, herkunft)
  • sitzungen(), befunde()

Used in

app-forensik: Steckbrief

What for

Distinguish “there was a read error here” from “this looks like one” – only the first justifies marking an area as replaced.

DVD-Video envisionz.media.dvd

Ifo – in which order the performance belongs together

The VOB files are not a film in playback order but a store of cells; the order is in the program chain. Read are titles, program chains with cells and duration, angle blocks, audio format and subtitles. Numbers are big-endian, times are BCD. vobPruefung checks the sizes of the VOB files against the IFO.

Methods

  • Ifo(Path), titel(), ketten() → Programmkette(nummer, programme, sekunden, zellen)

Vobs – the VOB files of a title set as one stream

DVD limits each file to one gibibyte; an eighty-minute recording lies in three or four files, and the boundary falls in the middle of a picture. Vobs streams them in name order as one stream and reports when the IFO names a different chain. From it, picture and audio streams can be extracted from any sector and the time stamps at a jump position read.

Methods

  • Vobs(verzeichnis, titelsatz), gegen(ifo), dateien(), groesse(), groessen(), befunde()

MPEG program stream envisionz.media.ps

Programmstrom and Videokopf – what is inside the stream

Splits a program or system stream at the start codes 00 00 01: pack header (different lengths in MPEG-1 and MPEG-2), system header, padding packets, navigation packs (BF), private stream 1 (BD, AC-3/LPCM/DTS/subtitles at the first payload byte), MPEG audio and video. Videokopf evaluates the sequence header and extensions: non-square pixels, interlacing and field order per picture, pulldown via repeat_first_field, colour space from the display extension, custom quantiser matrices. Elementarstrom – the pure video stream

Cuts out navigation packs and PES headers; passed through, they would cause breakage exactly at the chapter points. In MPEG-2 the header length is in the third byte, in MPEG-1 stuffing bytes FF come first – the reason why an extractor that only knows MPEG-2 fails on a Video CD. Works on a sliding window of 1 MiB.

Methods

  • new Elementarstrom().kennung(0xE0), videoAus(byte[]), videoAus(daten, aus), videoAus(ein, aus)

Sound and time stamps envisionz.media.ps

Tonstrom, Tonauszug, Zeitmarken

Tonstrom inspects: which tracks are present, MPEG audio in C0–DF or AC-3/DTS/LPCM in the private stream, with sample rate, channels and bit rate; a find only counts when several frames match in a chain. Tonauszug extracts an audio stream streaming – a title set of almost three gibibytes fits into no byte[] – and remembers the first time stamp. Zeitmarken reads presentation time stamps (90 kHz) from MPEG-1 and MPEG-2 headers; their difference after a jump is the offset between picture and sound. Background, formulas and pseudocode →

Methods

  • new Tonstrom().untersuchen(d), spuren() → Spur(kennung, unterstrom, art, abtastrate, kanaele, bitrate, bytes), daten(kennung)

Damage in the video stream envisionz.media.ps

Bitfehler – where a decoder must conceal, found without decoding

A decoder fills destroyed areas with an estimate, and the result looks like picture content. Bitfehler finds such places at the slice start codes: each macroblock row carries its number in the last byte, a PAL picture needs 36 of them without gaps. Missing, duplicate or invalid numbers and pictures without any slice are located to within sixteen picture lines. Background, formulas and pseudocode →

Methods

  • Bitfehler(hoehe), untersuchen(d)

What kind of file is this? envisionz.media.erkennung

Erkenner and Dateiart – container and video stream separately

Reads the identifiers every container carries at a known position and reports container (elementary stream, program and transport stream, AVI, QuickTime/MP4, Matroska, DVD IFO) and video stream (MPEG-1/2, MPEG-4 Part 2, H.264, MJPEG, DV, Indeo, Cinepak, uncompressed) separately. Inferring the codec from the container regularly goes wrong; for a restoration the video stream decides. Readable today are MPEG-1 and MPEG-2.

Methods
