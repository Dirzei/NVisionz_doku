Sound and time stamps – background

The computation behind Tonstrom, Tonauszug and Zeitmarken: how an audio track is recognised from a chain of frames, how the 33-bit time stamps sit in five bytes, and how the offset between picture and sound after a jump follows from them.

Recognising audio tracks

Sound lies in two places on a video disc. MPEG audio is in the streams C0 to DF (video CD, most European DVDs). Private stream 1 (BD) carries AC-3, DTS, LPCM and subtitles; the actual identifier is in the first payload byte, followed by four bytes of administration. Overlooking this mixes sound, subtitles and several languages together.

For MPEG audio, sampling rate, bit rate and channel count are read from the frame header. A frame begins with eleven set bits, but this pattern also occurs by chance in compressed data. In an experiment there were three hits, two of them false; a reader that believes the first reports nonsense like “layer 1 at 24 kHz”. So the chain is checked: bit rate BB and sampling rate ff give the frame length, and exactly there the next frame with the same key values must stand.

LII/III⁡=⌊144⋅Bf⌋+p,LI=4(⌊12⋅Bf⌋+p)L_{\mathrm{II/III}} = \left\lfloor \frac{144 \cdot B}{f} \right\rfloor + p, \qquad L_{\mathrm{I}} = 4 \left( \left\lfloor \frac{12 \cdot B}{f} \right\rfloor + p \right)

with BB in bit/s and the padding bit p∈{0,1}p \in \{0,1\} from the header. Examples: layer II at 192 kbit/s and 48 kHz has 144⋅192000/48000=576144 \cdot 192000 / 48000 = 576 bytes per frame; at 44.1 kHz it is ⌊626.9⌋=626\lfloor 626{.}9 \rfloor = 626 bytes, with the padding bit set 627. The padding bit compensates the fraction so that the mean bit rate is right.

Pseudocode – Tonstrom.ersterEchterRahmen

for i ← 0 to min(length(b), 1 MiB):
    k ← parseHeader(b, i)                     null if not a valid MPEG-1 header
    if k = null: continue
    hits ← 0;  q ← i;  length ← k.length
    for n ← 1 to 4:
        w ← parseHeader(b, q + length)
        if w = null or w.rate ≠ k.rate or w.layer ≠ k.layer: break
        q ← q + length;  length ← w.length;  hits ← hits + 1
    if hits ≥ 2: return (layer, rate, channels, bitrate)
return null                                      "MPEG-Ton, Rahmen nicht deutbar"

parseHeader(b, at):
    require sync: b[at] = FF and upper 3 bits of b[at+1] = 111
    require version MPEG-1, layer ≠ 0;  bit rate index ∉ {0, 15};  rate index ≠ 3
    channels ← (mode = 3) ? 1 : 2                        mode 3 = mono
    length ← formula above;  if length < 24: null

Source: envisionz-framework-media/src/envisionz/media/ps/Tonstrom.java. Tonauszug pulls a track out in streaming fashion (same window and same packet borders as Elementarstrom) and remembers the first time stamp; a title set of almost three gibibytes fits in no byte[].

Convention in the framework: A find counts only if the first frame has at least two successors at the computed place; up to four are checked. For AC-3, DTS, LPCM and subtitles only the kind is named from the substream identifier; sampling rate, channels and bit rate stay 0. More than one audio track is reported as ACHTUNG: they lie in the same container and would otherwise be mixed.

Presentation time stamps

The order of packets in the stream is not the order of playback. The multiplexer writes each packet early enough that it lies in the decoder buffer in time, and because picture and sound decoders have buffers of different size, the two streams run offset against each other in the container. The time stamps (PTS) count in 90kHz⁡90\,\mathrm{kHz} and tell, for each packet, when its content is to be seen or heard. A 33-bit counter at 90 kHz overflows after 233/90000s≈26.52^{33}/90000\ \mathrm{s} \approx 26{.}5 hours.

The 33 bits are not contiguous: marker bits are interspersed so that the five bytes never look like a start code by chance.

The value is assembled as follows, with b0…b4b_0 \ldots b_4 the five bytes:

PTS⁡=((b0&0E)≪29)|(b1≪22)|((b2&FE)≪14)|(b3≪7)|((b4&FE)≫1)\mathrm{PTS} = \big((b_0 \,\&\, \mathtt{0E}) \ll 29\big) \;|\; (b_1 \ll 22) \;|\; \big((b_2 \,\&\, \mathtt{FE}) \ll 14\big) \;|\; (b_3 \ll 7) \;|\; \big((b_4 \,\&\, \mathtt{FE}) \gg 1\big)

The example of the figure: b=(21,00,05,BF,21)b = (21, 00, 05, BF, 21) gives 0+0+(04≪14)+(BF≪7)+(20≫1)=65536+24448+16=900000 + 0 + (04 \ll 14) + (BF \ll 7) + (20 \gg 1) = 65536 + 24448 + 16 = 90000.

Two versions of the PES header have to be read. In MPEG-2, bit 7 of the flags shows whether a stamp is present, and the marker depends on whether a decoding stamp follows as well: 0010 for a presentation stamp only, 0011 for both. Pictures almost always have both because of B pictures, audio never. In MPEG-1 there are first stuffing bytes FF, then optionally a buffer marker, then optionally the stamps, recognisable only by the upper four bits.

Pseudocode – Zeitmarken.pts

pts(d, start, end, mpeg2):
    if mpeg2 and upper 2 bits of d[start] = 10:
        flags ← d[start + 1]
        if bit 7 not set: return −1                   no stamp
        marker ← (upper 2 bits of flags = 11) ? 0x30 : 0x20
        return fiveBytes(d, start + 3, marker)
    q ← start;  skip FF
    if upper 2 bits of d[q] = 01: q ← q + 2                  buffer marker
    if upper 4 bits = 0010 or 0011: return fiveBytes(d, q, matching marker)
    return −1

fiveBytes(d, at, marker):
    if upper 4 bits of d[at] ≠ marker: return −1
    return the 33-bit value by the formula above

Source: envisionz-framework-media/src/envisionz/media/ps/Zeitmarken.java. nachDemKopf also computes where the payload begins behind the PES header; it exists twice so that Tonauszug does not depend on a private method of another class.

The offset between picture and sound

If one jumps to a sector and starts decoding both from there, the result is not in sync; on DVD-Video the offset is usually a few tenths of a second, enough for lips and voice to visibly fall apart. The difference of the first two stamps after the jump is exactly the offset by which one stream has to wait:

Δt=PTSaudio⁡⁡−PTSpicture⁡⁡90000s\Delta t = \frac{\mathrm{PTS}_{\mathrm{audio}} - \mathrm{PTS}_{\mathrm{picture}}}{90000}\ \mathrm{s}

Positive means: the sound at this point belongs to a later picture and has to wait. Negative means: the picture has to wait. Example with assumed values: PTSpicture⁡⁡=126000\mathrm{PTS}_{\mathrm{picture}} = 126000 and PTSaudio⁡⁡=135000\mathrm{PTS}_{\mathrm{audio}} = 135000 give Δt=9000/90000=0.1s\Delta t = 9000/90000 = 0{.}1\ \mathrm{s}.

Pseudocode – Zeitmarken.suchen

video ← −1;  audio ← −1
while start code found:
    if BA: skip pack header (14 + stuffing for MPEG-2, 12 for MPEG-1), remember mpeg2
    if B9: end
    end ← p + 6 + packet length
    if video (E0..EF) or code = audioId:
        t ← pts(...)
        if t ≥ 0:  set video or audio, if still empty
        if both set: return pair(video, audio)
    p ← end
return pair(video, audio)                         vollstaendig() = both ≥ 0
Convention in the framework: Vobs.zeitmarken(sektor, tonKennung) reads two mebibytes from the sector on; at DVD rate that is about three seconds of material, with several stamps of both streams. If a stamp is missing, the pair is incomplete and the offset 0 – the absence of stamps is allowed, which is why it must not lead to a silent value: check vollstaendig(). A first draft tested the marker fixed against 0010; then the audio stamp was found and the picture stamp never, and that did not look like an error but like a stream without picture stamps.

How it is checked

ps.Tonauszugprobe (20 checks) works with generated streams against ISO/IEC 11172-1 and 13818-1: a stream of 3.1 MiB in packets of 2048 bytes via byte[] yields exactly the audio payloads, and an MPEG-1 pack header beginning 8 bytes before the 1 MiB border yields the same via the data stream as via byte[]. An earlier version of the audio extract aborted at the window border with an index exception; that is fixed and covered by this probe.

Limits

  • The frame header is interpreted for MPEG-1 only. MPEG-2 audio at half sampling rate appears as “frame not interpretable”.
  • AC-3, DTS and LPCM are named but not parsed.
  • The offset is the initial offset after a jump. A drift of the stamps later on is not measured by this class; jumps of the video stamps are reported by Programmstrom.
  • Time stamps are 33 bits; an overflow after about 26.5 hours is not handled.
