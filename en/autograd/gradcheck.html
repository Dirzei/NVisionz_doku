Gradient check – analytical against numerical derivative

The computation behind GradCheck: central differences and their error, choosing the step between truncation and rounding error, the relative step for quantities with units, the relative error measure with a floor, and the random sample of checked components – with pseudocode following the source, a recomputed error curve, the probes and the places where the check itself measures wrongly.

What this is about

A wrong gradient does not make itself noticed. A forgotten term on the way back, a wrong sign, a swapped axis – the model trains anyway, the loss falls, only more slowly or to a worse value. The fault is suspected only after days of training, if at all. That is why the gradient check is the safety net of the whole module: every operation and every new model is held against a derivative obtained in an entirely different way – by wiggling the inputs and measuring how the loss changes.

This second route is expensive (two evaluations of the whole model per checked component) and inexact (rounding), but it shares no code with the backward path. If both agree to within a few digits, the analytical gradient is very probably correct.

Central differences and their error

For a smooth function the Taylor expansion gives

f(x±h)=f(x)±hf'(x)+h22f''(x)±h36f'''(x)+O(h4).f(x \pm h) = f(x) \pm h\,f'(x) + \frac{h^2}{2} f''(x) \pm \frac{h^3}{6} f'''(x) + O(h^4).

The difference of the two equations cancels the even terms:

Dh=f(x+h)−f(x−h)2h=f'(x)+h26f'''(x)+O(h4).D_h = \frac{f(x+h) - f(x-h)}{2h} = f'(x) + \frac{h^2}{6} f'''(x) + O(h^4).

The truncation error of the central difference thus falls with h2h^2, that of the one-sided one (f(x+h)−f(x))/h(f(x+h) - f(x))/h only with hh. Against that stands the rounding error: ff is accurate only to about ε|f|\varepsilon\,|f| (ε≈2.2⋅10−16\varepsilon \approx 2.2\cdot 10^{-16} in double precision), and the difference of two almost equal numbers divided by 2h2h has an error of size ε|f|/h\varepsilon\,|f|/h. The total error

E(h)≈h26|f'''|+ε|f|hE(h) \approx \frac{h^2}{6}\,|f'''| + \frac{\varepsilon\,|f|}{h}

is smallest at hopt⁡∼(3ε|f|/|f'''|)1/3h_{\mathrm{opt}} \sim (3\varepsilon\,|f|/|f'''|)^{1/3}, i.e. at a few 10−610^{-6} for quantities of order one. The default h=10−5h = 10^{-5} lies in that range.

Relative step

A fixed step only suits quantities of order one. For a formant frequency of 700 Hz, h=10−5h = 10^{-5} is a relative step of 1.4⋅10−81.4\cdot 10^{-8}; the rounding part ε|f|/h\varepsilon\,|f|/h grows, and the difference loses digits to cancellation. A correct gradient then looks wrong. According to the class comment exactly that happened with the band-pass checks: they reported a relative error around 10−510^{-5} until the step scaled along. Since then, per component,

hi=max⁡(h,ρ|xi|)h_i = \max\big(h,\ \rho\,|x_i|\big)

with the absolute minimum step hh and the relative step ρ\rho (default 10−610^{-6}). For values below h/ρ=10h/\rho = 10 nothing changes; for 700 Hz the step becomes 7⋅10−47\cdot 10^{-4}.

Relative error with a floor

The numerical value nn is compared with the analytical aa via

r=|n−a|max⁡(10−8,|n|,|a|).r = \frac{|n - a|}{\max(10^{-8},\ |n|,\ |a|)}.

The larger of the two magnitudes in the denominator makes the measure symmetric and independent of the gradient's order of magnitude. The floor 10−810^{-8} prevents gradients that are both practically zero from producing a large relative error by division by a tiny number – below it the comparison is effectively absolute.

The procedure

GradCheck.check first runs forward and backward once and saves the analytical gradients before any value is changed. Then it draws random pairs (parameter, component) without repetition, perturbs the component by ±hi\pm h_i, recomputes the loss each time and compares. The sample is necessary because a model has hundreds of thousands of components and each costs two full forward passes; the fixed seed makes the selection repeatable.

Pseudocode – GradCheck.check(params, lossFn, h, relStep, maxProbes, seed)

for each p in params:  check p carries a gradient;  p.zeroGrad()
L ← lossFn();  check L is a scalar;  L.backward()
analytic ← copy of all p.grad                  save before any perturbation

total ← Σ |p|;   probes ← min(maxProbes, total)
rnd ← Random(seed);  taken ← empty;  max ← 0;  sum ← 0
done ← 0;  attempts ← 0
while done < probes and attempts < 20·probes:
    attempts += 1
    pi ← rnd.nextInt(|params|);  ci ← rnd.nextInt(|params[pi]|)
    if (pi, ci) ∈ taken: continue
    taken ← taken ∪ {(pi, ci)}
    x ← p.data[ci];   s ← max(h, relStep·|x|)
    p.data[ci] ← x + s;  lp ← lossFn()           fresh graph
    p.data[ci] ← x − s;  lm ← lossFn()
    p.data[ci] ← x                                restore value
    n ← (lp − lm)/(2s);   a ← analytic[pi][ci]
    r ← |n − a| / max(1e−8, |n|, |a|)
    sum += r;  if r > max: max ← r, record description
    done += 1
return Report(done, max, sum/done, description)

Source: envisionz-framework-autograd/src/envisionz/autograd/GradCheck.java. Report.passed(tol) is true if the largest relative error is at most tol.

Decision in the framework: the short form check(params, lossFn) uses h=10−5h = 10^{-5}, relative step 10−610^{-6}, at most 40 probes and the seed 12345. The five-argument form check(params, lossFn, h, maxProbes, seed) also sets the relative step to 10−610^{-6}. The loss function must build a fresh graph on every call and return a scalar; the parameters are modified in place in between and restored exactly afterwards.

What the sample sees. First the tensor is drawn, uniformly, then the component within it. Every tensor therefore gets the same number of probes on average, whatever its size: for a model of P=10P = 10 tensors and 40 probes about four per tensor – for a bias with three components as for a weight matrix with 65,536. If the gradient of a whole tensor is wrong, the check misses it with probability (1−1/P)40=0.940≈1.5%(1 - 1/P)^{40} = 0.9^{40} \approx 1.5\,\%. If only a fraction qq of a tensor's components is wrong – a single edge row, say – it is approximately (1−q/P)40(1 - q/P)^{40}; for q=0.01q = 0.01 about 96 %. A small sample hardly finds such faults. For small shapes with at most 40 components, on the other hand, almost always all are checked, because components already drawn are skipped and up to 20⋅20\cdotprobes attempts are made.

How it is checked

GradCheck is itself a checking tool – all gradient checks of the acceptance runners go through this one class. If it were faulty, say with a one-sided instead of a central difference or a shifted denominator, all checks would pass without proving anything. Therefore:

  • Gradientenprobe computes its difference quotients itself by the same rule (central, max⁡(10−5,10−6|x|)\max(10^{-5},\ 10^{-6}|x|), tolerance 10−610^{-6}) and deliberately does not call GradCheck. Where a derivative by hand exists, it additionally checks against that (tolerance 10−1010^{-10}) – the sharper anchor.
  • Use in the acceptance runners: AutogradTest with 40 probes, h=10−5h = 10^{-5} and tolerance 10−610^{-6}; EncoderTest likewise; LanguageModelTest, ModernTest, SpectralTest and SourceTest with h=10−6h = 10^{-6}, relative step 10−610^{-6} and 30 probes. According to the module documentation the worst value over the whole path embedding – positions – encoder – head was 4.9⋅10−74.9\cdot 10^{-7}.

Limits

  • Kinks. At x=0x = 0 for relu or p=tp = t for l1Loss the central difference measures across the edge and yields the mean of the two one-sided slopes – systematically wrong without the gradient being wrong. The probes start away from there.
  • Saturated regions. Far out on tanh or sigmoid the derivative is many orders of magnitude smaller than the function value; the difference loses almost all digits, and the anchor becomes less accurate than what is being checked.
  • Randomness in the loss function. If the loss function draws a new dropout mask on every call, the difference measures two different functions. Check without dropout or with a Random created freshly with a fixed seed inside the loss function.
  • A sample, not a proof. At most maxProbes components are checked. A fault that affects only a few entries (say a boundary row) can slip through; the acceptance runners therefore check small models in which 30 or 40 probes cover a large share. After 20⋅20\cdotmaxProbes attempts the drawing stops; Report.probes() gives the actual number.
  • Double precision only. With the float matrix product switched on (Ops.schnellesMatmul) the forward value would only be accurate to about 10−710^{-7}; the check is not meant for that.
  • Cost. Two full forward passes per probe, plus one backward pass at the start.
