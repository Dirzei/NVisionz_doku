Sequence training and sampling – choosing the next token

The computation behind lm.Sampler and text.Sampler: softmax with temperature, restriction to the best kk or to the nucleus with probability mass pp, a penalty on repetitions, and drawing via the distribution function – with pseudocode following the source, recomputed distributions, the statistical probes and the limits.

What this is about

During training the next token is known – it is in the target vector. When generating there is no correct answer: for the last position the model delivers a score zkz_k (logit) for each of the VV vocabulary entries, and exactly one must be chosen to continue writing. This choice shapes the character of the output more than most model parameters.

The obvious choice – always the largest logit – reliably produces loops: "the little girl was a little girl was a little girl …". The reason is structural: if the state after "was a little" is the same as last time, the same decision follows. That looks like a broken model but is only a too rigid selection. Randomness in the selection step breaks the circle; three knobs keep it in check.

Temperature

The logits are divided by the temperature TT before softmax:

pk(T)=ezk/T∑jezj/T.p_k(T) = \frac{e^{z_k/T}}{\sum_j e^{z_j/T}}.

For T=1T = 1 this is the distribution the model has learned. Below 1 differences are amplified – the distribution contracts onto the best entries, and for T→0T \to 0 only the largest logit remains (greedy choice). Above 1 they are flattened; for T→∞T \to \infty the distribution becomes uniform. The ratio of two probabilities is pa/pb=e(za−zb)/Tp_a/p_b = e^{(z_a - z_b)/T}: the temperature scales the logit distances.

Top-k and top-p

Even at a sensible temperature a large vocabulary contains thousands of entries with tiny probabilities. Individually insignificant, together they are frequent enough to occasionally draw a completely unsuitable entry that derails the sentence. Two restrictions cut off this long tail; afterwards the remaining mass is renormalised:

  • Top-k: only the kk most probable entries are eligible.
  • Top-p (nucleus sampling): the entries are sorted in descending order, and the smallest leading group whose probabilities together reach at least pp is taken. Unlike top-k the size adapts to the situation: if the model is confident, few entries remain; if it is uncertain, more.

If both are set, the selection is first limited to kk and then to pp within that.

Penalty on repetitions

lm.Sampler can additionally penalise tokens that already occurred in the sequence so far. For every occurrence of a token tt in the first count entries of previous, its logit is reduced by the penalty rr – before the temperature, so that it changes the score and not the sharpness of the distribution:

zt←zt−r⋅nt,nt=number of occurrences of t.z_t \leftarrow z_t - r\cdot n_t, \qquad n_t = \text{number of occurrences of } t.

A value around 1 dampens repetitions noticeably without forbidding them. Because the penalty grows with frequency, a token repeated often is pushed back more and more.

The procedure

Pseudocode – lm.Sampler.next(logits, previous, count, opt, rnd)

check logits has shape [T, V];  z ← last row (copy)
if opt.repetitionPenalty > 0 and previous ≠ null:
    for i ← 0 to count−1:  t ← previous[i];  if 0 ≤ t < V: z[t] −= r
if opt.temperature ≤ 0:  return argmax z             greedy, first one on ties
z ← z / T
p ← softmax(z) with the maximum subtracted
ord ← indices sorted by p descending                 stable: smaller index first on ties
limit ← V;  if topK > 0: limit ← min(limit, topK)
if topP < 1:
    sum ← 0;  n ← 0
    while n < limit:  sum += p[ord[n]];  n += 1;  if sum ≥ topP: break
    limit ← n                                         at least one token
rest ← Σ_{i < limit} p[ord[i]]
u ← rnd.nextDouble() · rest;  run ← 0
for i ← 0 to limit−1:  run += p[ord[i]];  if u ≤ run: return ord[i]
return ord[limit−1]                                   rounding at the edge

Source: envisionz-framework-autograd/src/envisionz/autograd/lm/Sampler.java. Instead of renormalising after cutting, the random number is multiplied by the remaining mass rest – which is the same.

Drawing is the inversion of the distribution function: a uniform number u∈[0,rest)u \in [0, \text{rest}) falls into token kk's sub-interval with probability pk/restp_k/\text{rest}.

Two sampler classes

The module has two routes to the same goal, matching the two trainers (see Language model):

Decision in the framework: randomness always comes from a generator that is passed in or created with a fixed seed, never from a global one – the same seed and the same input give the same text, and two model states can be compared. text.Sampler rejects temperature 0, pointing to waehleGroesstes and the repetition loops: the greedy choice exists, but one chooses it deliberately. Defaults of lm.Sampler.Options: temperature 1, top-k off (0), top-p off (1.0), no penalty; Options.greedy() sets the temperature to 0.

How wide the choice is. A handy measure of the width of a distribution is eHe^{H} with the entropy H=−∑ipiln⁡piH = -\sum_i p_i \ln p_i: the number of equally likely candidates that would carry the same uncertainty. For the five logits of the table it is 1.84 at T=0.5T = 0.5, 3.34 at T=1T = 1 and 4.44 at T=2T = 2 (at most 5). Temperature thus shifts continuously between "almost always the best token" and "almost uniform"; top-k and top-p then cut off hard.

How it is checked

A sampler is random on purpose; "runs through" says nothing. What is checked are therefore statistical properties over many draws from one generator:

  • TrainerTest (lm.Sampler): the greedy choice takes the best-scored token; top-k = 1 equals the greedy choice (50 draws); top-k = 3 draws only from the best three and really uses all three – otherwise the first check would be vacuous; temperature controls the variety; the same seed gives the same token; the repetition penalty steers away from the repeated token.
  • SamplerTest (text.Sampler, 18 checks): frequencies follow the softmax distribution to within 0.02; with top-k = 2 only the two best occur, with top-k = 1 always the best, top-k larger than the vocabulary is harmless; cold picks the largest clearly more often than hot (according to the module documentation 96.4 % against 45.7 % at temperature 0.3 and 2.0); same seed same sequence, other seed other sequence; with a uniform distribution all five occur; temperature 0 is rejected with a pointer; a vocabulary of size 1 and a dominant logit work; logits around +800+800 and −800-800 give valid indices.
  • According to the module documentation the check found an error in the probe itself: 400 draws with new Random(i) for i=0…399i = 0 \dots 399 were practically a single one, because Java's generator returns almost the same first value for small consecutive seeds. Since then one generator is drawn from repeatedly.

Limits

  • lm.Sampler sorts the whole vocabulary for every token (Vlog⁡VV \log V, with object indices) – noticeable for large vocabularies and long texts.
  • The repetition penalty grows without bound with frequency and has no window; in long texts it also hits function words that must repeat.
  • No beam search and no cache for keys and values: text.Sampler.erzeuge recomputes the whole sequence so far for every new token and is limited by the model's sequence length (see Language model, limits).
  • With text.Sampler, top-k can admit more than kk tokens when logits are equal at the threshold.
