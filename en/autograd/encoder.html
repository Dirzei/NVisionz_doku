Network blocks and transformer – encoder block, variants and language head

The computation behind EncoderBlock, TransformerEncoder, SwiGluFeedForward and LanguageModelHead: the block in pre-norm arrangement, the classic and the modern variant with equal parameter count, the final normalisation, the language head with tied weights, and the learning proof on a task with non-local rules – with pseudocode following the source, figures, the probes and the limits.

What this is about

A transformer encoder stacks identically built blocks. Each block first fetches information from other positions of the sequence via attention (see Attention) and then processes each position on its own with a small feed-forward network. Around both parts lies a residual: the block computes a correction that is added to its input.

Three decisions determine whether such a stack trains stably with a home-made optimiser on small amounts of data: where the normalisation sits, which nonlinearity the feed-forward network has, and whether input and output of the language model use the same matrix.

The block in pre-norm arrangement

The normalisation sits before the sub-block, the residual around it:

h=x+drop⁡(MHA⁡(N1(x))),y=h+drop⁡(FF⁡(N2(h))).h = x + \mathrm{drop}\big(\mathrm{MHA}(\mathrm{N}_1(x))\big), \qquad y = h + \mathrm{drop}\big(\mathrm{FF}(\mathrm{N}_2(h))\big).

In the 2017 original the normalisation came after (post-norm, y=N(x+MHA⁡(x))y = \mathrm{N}(x + \mathrm{MHA}(x))). The difference shows on the way back: with pre-norm

∂y∂x=I+∂(sub-blocks)∂x,\frac{\partial y}{\partial x} = I + \frac{\partial\,(\text{sub-blocks})}{\partial x},

so across all layers the gradient has an undisturbed additive path from the loss to the input. With post-norm every path runs through every normalisation, and in the first steps – while the sub-blocks are still random – training diverges without a carefully tuned warm-up. Pre-norm is stable without that tuning.

The stack TransformerEncoder appends a final normalisation after the last block. It belongs to the pre-norm arrangement: since each block only gives its sub-blocks a normalised input, the output of the last block would be unnormalised and its magnitude would depend on the number of layers. Embedding and output head deliberately lie outside the stack, because they depend on the task (phoneme alphabet, vocabulary, number of control quantities) and the stack does not.

Pseudocode – EncoderBlock.forward and TransformerEncoder.forward

// EncoderBlock
a ← attn(norm1(x), mask, rnd, training)
if training and p > 0: a ← dropout(a, p, rnd)
h ← x + a
f ← feedForward(norm2(h))          CLASSIC: ff2(gelu(ff1(·)))   MODERN: swiglu(·)
if training and p > 0: f ← dropout(f, p, rnd)
return h + f

// TransformerEncoder
h ← x
for each block b:  h ← b.forward(h, mask, rnd, training)
return finalNorm(h)               LayerNorm (CLASSIC) or RMSNorm (MODERN)

Source: envisionz-framework-autograd/src/envisionz/autograd/nn/EncoderBlock.java and TransformerEncoder.java. The same dropout rate also acts on the attention weights inside MultiHeadAttention.

The modern form replaces the fixed characteristic with a gate: one branch decides multiplicatively how much of the other passes. For that it needs a third matrix. A fair comparison requires the new variant not to be secretly larger. Two matrices of width dFF⁡d_{\mathrm{FF}} have 2ddFF⁡2\,d\,d_{\mathrm{FF}} entries, three of width hh have 3dh3\,d\,h; equal counts give

h=23dFF⁡.h = \tfrac23\, d_{\mathrm{FF}}.

Decision in the framework: SwiGluFeedForward.hiddenForEqualParams(dFF) computes ⌊2dFF⁡/3⌋\lfloor 2\,d_{\mathrm{FF}}/3\rfloor and rounds down to a multiple of 8 (at least 8). Rounding up would make the modern form larger than the classic one. At dFF⁡=256d_{\mathrm{FF}} = 256, 23dFF⁡=170.7\tfrac23 d_{\mathrm{FF}} = 170.7; rounded up it would be 176 and, according to the module documentation, 1.0 % more parameters; rounded down it is 168. The first acceptance run failed on exactly that; the check "MODERN not larger than CLASSIC" has been permanent since. The variant CLASSIC is the one accepted in acceptance M2 and remains as an option – a comparison requires both to be available.

The classic variant initialises the first feed-forward layer per He, because GELU follows, and the second per Xavier; the modern one initialises gate and up branch per He and the down branch per Xavier (see Initial values).

Language head with tied weights

The output head of a language model maps every position [T,d][T, d] to a score per vocabulary entry [T,V][T, V]. The embedding maps word to vector, the head vector to word – the same relation in the opposite direction. With tied weights (Press and Wolf) the head therefore uses the embedding matrix E∈RV×dE \in \mathbb{R}^{V\times d} itself:

z=hET+b.z = h\,E^T + b.

The gradient with respect to EE receives contributions from both uses – from the embedding (rows of the tokens that occur) and from the head (all rows) –, and accumulation in the backward pass (see Reverse mode) handles that without further ado. The bias stays separate: it has no counterpart in the embedding and represents the different base frequencies of the words.

Decision in the framework: in the tied case LanguageModelHead does not register the shared matrix again; it appears exactly once in the parameter list. If it appeared twice, Adam would move it twice per step (effectively a doubled learning rate on the embedding), and the weight file would contain it twice. extraParameterCount() returns only the size of the bias in the tied case.

Learning proof: prosody with non-local rules

Correct gradients do not prove that a model learns. ToyProsody generates a synthetic task in the form the speech output will need later – phoneme sequence in, duration and pitch factor per position out –, with rules that deliberately cannot be read off the single symbol:

  • Stress on the first vowel after a word boundary: duration times 1.35, pitch plus 0.06 – needs look-back.
  • Final lengthening for the last vowel before a word boundary or the end of the sentence: duration times 1.15 – needs look-ahead.
  • Declination: pitch 1.08−0.26⋅i/(T−1)1.08 - 0.26\cdot i/(T-1) – needs the sentence length.
  • Final rise to 1.45 over the last three positions, only for questions – recognisable only at the last symbol.

The base duration per phoneme class (full vowel 0.16 s, reduced 0.07 s, plosive 0.05 s, fricative 0.11 s, sonorant 0.08 s, word boundary 0.14 s, sentence end 0.22 s) carries most of the variance of the duration. The comparison is therefore a lookup table that takes the mean per symbol from the training data: it shows what is achievable without context.

In EncoderTest a model of embedding, positional encoding, two classic blocks (d=48d = 48, four heads, dFF⁡=96d_{\mathrm{FF}} = 96) and a linear head learns for 45 epochs on 320 generated sentences and is evaluated on 64 held-out ones. According to the module documentation it reached R2=0.9984R^2 = 0.9984 for duration and 0.99360.9936 for pitch; the table reached 0.9517 and 0.5228. The gain of almost 0.47 on pitch – the purely non-local part – is the actual evidence that attention contributes something.

How it is checked

  • EncoderTest: gradients of the whole path embedding – positions – encoder – head against central differences (tolerance 10−610^{-6}, worst value 4.9⋅10−74.9\cdot 10^{-7} according to the module documentation); learning proof with the thresholds R2>0.98R^2 \gt 0.98 (duration) and R2>0.97R^2 \gt 0.97 (pitch), duration better than the table, pitch better by more than 0.30. The thresholds are deliberately separate.
  • ModernTest (18 checks according to the module documentation): MODERN is not larger than CLASSIC; both variants learn (loss falls by a factor of 100); gradients of RMSNorm, SwiGLU and the modern block.
  • LanguageModelTest: tied, the head costs only the bias; the shared matrix appears exactly once in parameters(); the gradient reaches it. Learning proof on xi+1=(xi−1+1)modVx_{i+1} = (x_{i-1} + 1) \bmod V – the next symbol depends on the second-to-last, merely copying the predecessor fails: loss below 0.05, all positions predicted correctly, starting loss close to ln⁡V\ln V. According to the module documentation the loss fell from 2.4979 to 0.0006 with 16,000 parameters, 24 of 24 positions correct.

Limits

  • Encoder only: no cross-attention, no separate decoder. A language model is an encoder with a causal mask.
  • One sequence per call, no batch axis; batches are formed in the trainer via accumulated gradients.
  • One dropout rate for all places in the block (attention weights, attention output, feed-forward output); separate rates do not exist.
  • The variant applies to the whole stack; mixed forms are not provided.
  • The learning proofs are synthetic. They prove the wiring, not the suitability for a real speech corpus.
