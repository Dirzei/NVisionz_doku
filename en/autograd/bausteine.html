Network blocks and transformer – building blocks and initial values

The computation behind Module, Linear, Embedding, LayerNorm, RmsNorm and Init: how parameters are collected in a fixed order, what an affine layer and an embedding compute, and why Xavier and He initial values have exactly these spreads – derived from the requirement that signals neither grow nor vanish on their way through. With pseudocode following the source, figures, the probes and the limits. Attention and encoder are on the pages Attention and Encoder.

What this is about

A network is a nesting of a few building blocks: affine layers, embedding tables, normalisations. Two things decide whether such a network can be trained at all, and both are easy to get wrong without anything crashing:

  • The initial values. If the weights are too large, the spread of the activations grows from layer to layer, nonlinearities saturate, gradients vanish. If they are too small, the signal vanishes. Both slow down or prevent learning – the network "only learns worse".
  • The order of the parameters. Optimiser, weight file and checkpoint talk about lists of tensors, not about names. If the order on loading does not match the order on saving, weights end up in the wrong layer.

Module: parameters in a fixed order

A Module keeps two lists: its own parameters (with names, for diagnostics) and its submodules. Both are filled in the constructor in registration order, via register(name, tensor) and child(module). There is no reflection and no state dictionary; a module is what it registers in its constructor.

Pseudocode – Module.parameters()

all ← copy of own parameters                    in registration order
for each submodule c in registration order:
    append c.parameters() to all                recursively, depth first
return all

Source: envisionz-framework-autograd/src/envisionz/autograd/nn/Module.java. register rejects a tensor without gradient; parameterCount() sums the sizes, zeroGrad() resets all gradients.

Decision in the framework: the order of parameters() is at the same time the storage order of the weight file (see Weight file). Whoever reorders the registration in a constructor makes existing weight files unreadable – loading checks count and shapes and rejects rather than putting weights into the wrong layers. Having no reflection also keeps the native-image path clear.

Linear and Embedding

Linear computes the affine map

y=xW+b,W∈Rnin⁡×nout⁡,b∈Rnout⁡.y = x\,W + b, \qquad W \in \mathbb{R}^{n_{\mathrm{in}}\times n_{\mathrm{out}}},\quad b \in \mathbb{R}^{n_{\mathrm{out}}}.

The input may have any number of leading axes – the matrix product treats them as a batch with a shared matrix (see Matrix product), and the bias is stretched right-aligned over all rows. The same layer thus acts on a vector as on a whole sequence. Backwards, gW=xTgyg_W = x^T g_y, gx=gyWTg_x = g_y W^T, and gbg_b is the column sum of gyg_y. The bias starts at 0, the weights per Xavier; with heInit = true per He, and with withBias = false there is no bias.

Embedding is a lookup table E∈RV×DE \in \mathbb{R}^{V\times D}: symbol ii becomes row Ei,⋅E_{i,\cdot}. Backwards the gradient of each output row is added into the symbol's row; symbols that occur several times collect all contributions. The table starts normally distributed with σ=0.02\sigma = 0.02 – small enough that the positional encoding (values in [−1,1][-1, 1]) is not drowned at the start, and large enough that symbols are distinguishable.

Initial values: preserving the spread

For a layer yj=∑i=1nin⁡xiwijy_j = \sum_{i=1}^{n_{\mathrm{in}}} x_i\,w_{ij} with independent, zero-mean weights and inputs,

Var⁡(yj)=nin⁡Var⁡(w)Var⁡(x).\mathrm{Var}(y_j) = n_{\mathrm{in}}\;\mathrm{Var}(w)\;\mathrm{Var}(x).

For the spread to be preserved in the forward pass, Var⁡(w)=1/nin⁡\mathrm{Var}(w) = 1/n_{\mathrm{in}} is needed; in the backward pass the same computation runs over the outputs and demands 1/nout⁡1/n_{\mathrm{out}}. Glorot and Bengio take the middle road:

Var⁡(w)=2nin⁡+nout⁡.\mathrm{Var}(w) = \frac{2}{n_{\mathrm{in}} + n_{\mathrm{out}}}.

A uniform distribution on [−a,a][-a, a] has the variance a2/3a^2/3; this gives the limit of the Xavier initialisation

a=6nin⁡+nout⁡.a = \sqrt{\frac{6}{n_{\mathrm{in}} + n_{\mathrm{out}}}}.

If a ReLU-like nonlinearity follows, it halves the spread on average (half the values become zero). He and colleagues compensate with the factor 2 and consider only the forward pass:

Var⁡(w)=2nin⁡,w∼N(0,2nin⁡).\mathrm{Var}(w) = \frac{2}{n_{\mathrm{in}}}, \qquad w \sim \mathcal{N}\!\left(0,\ \tfrac{2}{n_{\mathrm{in}}}\right).

The decisive difference: He depends only on nin⁡n_{\mathrm{in}}. For square matrices the two methods differ only by a factor of 2 in variance; at nin⁡=100n_{\mathrm{in}} = 100, nout⁡=400n_{\mathrm{out}} = 400 by a factor of 5.

Pseudocode – Init

xavier(rnd, in, out):   a ← sqrt(6/(in+out));  return uniform(rnd, a, in, out)
he(rnd, in, out):       σ ← sqrt(2/in)
                        for each entry: w ← rnd.nextGaussian() · σ
normal(rnd, σ, shape…): for each entry: w ← rnd.nextGaussian() · σ
uniform(rnd, a, shape…): for each entry: w ← (2·rnd.nextDouble() − 1) · a
constant(v, shape…):    all entries ← v
// every method returns a parameter (with gradient), shape [in, out] for xavier/he

Source: envisionz-framework-autograd/src/envisionz/autograd/nn/Init.java.

Decision in the framework: every initialisation takes an explicitly passed Random, never a global source of randomness. A training run is therefore repeatable from seed and data – the precondition for comparing two variants or two settings at all. LayerNorm defaults to ε=10−5\varepsilon = 10^{-5} and registers γ\gamma before β\beta; RmsNorm defaults to ε=10−6\varepsilon = 10^{-6} and has only γ\gamma. The formulas of the normalisations are on the page Derivatives.

parameterCount() returns both totals as well. The hidden width 168 of the SwiGLU variant is explained on the page Encoder.

For the initial values at nin⁡=100n_{\mathrm{in}} = 100, nout⁡=400n_{\mathrm{out}} = 400: Xavier limit a=6/500=0.10954a = \sqrt{6/500} = 0.10954, variance a2/3=0.004a^2/3 = 0.004; He spread σ=2/100=0.14142\sigma = \sqrt{2/100} = 0.14142, variance 0.020.02.

Memory. Values, gradients and the two Adam moments are each held as double, i.e. 32 bytes per parameter during training. The CLASSIC block above thus occupies 49,792⋅32=1,593,34449{,}792 \cdot 32 = 1{,}593{,}344 bytes, just over 1.5 MB; the weight file holds only the values, 49,792⋅8=398,33649{,}792 \cdot 8 = 398{,}336 bytes plus header (see Weight file). The intermediate results of the computation graph come on top and grow with sequence length and batch size, not with the parameter count.

How it is checked

  • Anfangswerteprobe (29 checks) measures against the defining properties, not against a run: constant delivers the requested shape and values as a parameter; uniform with a=0.25a = 0.25 on 200×200200\times 200 stays within the limit, comes within a per mille of it, has the variance a2/3a^2/3 (to 3 %) and mean zero; xavier on 100×400100\times 400 has the limit 6/500\sqrt{6/500}, the variance 2/5002/500 and explicitly not 2/1002/100; he has the variance 2/1002/100, explicitly neither 2/4002/400 nor 2/5002/500, and 3.5 to 6.0 % of the values beyond 2σ2\sigma; normal with σ=0.02\sigma = 0.02 has the variance σ2\sigma^2, also values beyond 2σ2\sigma and a largest magnitude above 1.74σ1.74\sigma – the limit of a uniform distribution of equal variance. The same seed gives the same matrix, a different seed a different one.
  • Why unequal axes: for square matrices Xavier and He would differ in variance only by a factor of 2, and swapping nin⁡n_{\mathrm{in}} and nout⁡n_{\mathrm{out}} would not be visible at all; the probe with 100×400100\times 400 separates them. Why the tails: a uniform distribution on [−σ3,σ3][-\sigma\sqrt3, \sigma\sqrt3] has exactly the variance σ2\sigma^2; only the share beyond 2σ2\sigma distinguishes it from the normal distribution.
  • Normierungsprobe (17 checks): parameters are called gamma, beta in that order; 8 scalar parameters at width 4; γ=1\gamma = 1 and β=0\beta = 0 at the start.
  • AutogradTest and EncoderTest: gradients of all modules against central differences.

Limits

  • No names in the weight file: whoever changes the registration order needs a translation of old files.
  • xavier and he always produce a matrix of shape [nin⁡,nout⁡][n_{\mathrm{in}}, n_{\mathrm{out}}]; convolution kernels or other shapes must be initialised via normal or uniform with a spread computed by hand.
  • The spread of the embedding is fixed at 0.02, independent of the width.
  • The derivations assume independent, zero-mean inputs. In deep networks that holds only approximately; the normalisations in each block (pre-norm) catch the rest.
