Tensor, operations, gradient check – Reverse-mode automatic differentiation

The computation behind Tensor and Ops: how the forward pass builds a computation graph, how backward() sorts it topologically without recursion and walks it backwards, why gradients are accumulated, and how the one-sided stretching of unequal shapes is collected again on the way back – with pseudocode following the source, a worked example checked by hand, the probes and the limits. The derivative rules of the individual operations are on the page Derivatives of the operations, the matrix product on Matrix product, the numerical check on Gradient check.

What this is about

A network learns by reducing a scalar loss function L(θ)L(\theta) over its parameters θ\theta. Every optimiser step needs the gradient ∇θL\nabla_\theta L for that – for each of the often hundreds of thousands of parameters, the derivative of the loss with respect to exactly that parameter.

With difference quotients this would be hopeless: two extra evaluations of the whole model per parameter. With 500,000 parameters that is a million forward passes for a single step. Reverse mode automatic differentiation delivers the same gradient, exact up to rounding, for the cost of roughly two to three forward passes – regardless of how many parameters there are. That is why networks with millions of weights can be trained at all.

The idea is the chain rule, applied consistently from the back. The computation is split into elementary steps whose derivatives are known – addition, matrix product, tanh, mean –, the forward pass records which step came from which inputs, and afterwards this chain is walked backwards once. Each step passes the sensitivity of the loss with respect to its output on to its inputs.

The computation graph and the chain rule

Every intermediate value vv of the computation is a node. A node arises from its parents u1,…,uku_1,\dots,u_k through an elementary operation, v=φ(u1,…,uk)v = \varphi(u_1,\dots,u_k). The leaves are input data (without gradient) and parameters (with gradient); the root is the scalar loss LL.

Sought for every node is the quantity

gv=∂L∂v,g_v = \frac{\partial L}{\partial v},

often called the adjoint of vv in the literature and written v\bar v. In the code it is the field grad of the tensor, as long as data. At the root, trivially gL=1g_L = 1. If a node uu feeds several children v1,…,vmv_1,\dots,v_m, the multivariate chain rule says

gu=∑j=1mgvj∂vj∂u.g_u = \sum_{j=1}^{m} g_{v_j}\,\frac{\partial v_j}{\partial u}.

The whole design follows from this: every child vv adds its contribution gv∂v/∂ug_v\,\partial v/\partial u to gug_u. Once all children of uu are done, gug_u holds the complete sum, and only then may uu pass on to its own parents. This order – every node only after all nodes that use it – is the reverse topological order of the graph.

For tensors ∂v/∂u\partial v/\partial u is a Jacobian matrix that nobody ever builds. Instead each operation knows the product gvT∂v/∂ug_v^{\,T}\,\partial v/\partial u in closed form: for v=tanh⁡(u)v = \tanh(u) element-wise gv⊙(1−v2)g_v \odot (1 - v^2), for C=ABC = AB the matrix products gCBTg_C B^T and ATgCA^T g_C. This product is called a vector-Jacobian product, and it is exactly what the backward function of an operation computes.

The tensor as a node

A Tensor is a flat double[] data with a shape int[] shape, stored row-major. The strides follow from the shape: for [d0,d1,…,dr−1][d_0, d_1, \dots, d_{r-1}], sr−1=1s_{r-1} = 1 and si=si+1di+1s_i = s_{i+1}\,d_{i+1}; the flat index of a multi-index is ∑icisi\sum_i c_i s_i. In addition every tensor carries

  • grad – an array of the same length, or null if no gradient is needed for this tensor,
  • parents – the inputs of the operation that produced it,
  • back – the backward function (interface Backward with one method accumulate(self)) that distributes self.grad to the parents.

There are three kinds of tensors. Tensor.of creates a leaf without gradient (input data, constants), Tensor.param a leaf with gradient (parameters), and every operation in Ops produces a result tensor through Tensor.result. That tensor carries a gradient and a backward function exactly when at least one parent carries a gradient. Computations that involve only data – a positional encoding, a mask, a precomputed spectrum – therefore never hang on the graph, and their backward path costs nothing.

Decision in the framework: the graph is built implicitly during the forward computation. There is no tape, no recording and no mode to switch on: whoever computes, builds. Hence every call of the loss function builds a fresh graph – GradCheck, the trainers and the fitting methods rely on that.

All values are double. That is deliberate: the gradient check needs the resolution, and bit-exact comparisons between the serial and the parallel path, or between an uninterrupted and a resumed training run, can only be made sharply in double precision. The optional float path concerns only the forward step of the matrix product (see Matrix kernels).

The backward pass

backward() is only allowed on a tensor with exactly one element – the loss. It sets that gradient to 1, sorts the graph topologically and calls the backward functions in reverse order.

Pseudocode – Tensor.backward()

if size() ≠ 1:          throw "backward() only on a scalar"
if grad = null:         throw "no gradient path (no parameter in the graph?)"
order ← topoSort(this)                    parents before child
grad[0] ← 1                               g_L = 1, set, not added
for i ← |order|−1 down to 0:
    t ← order[i]
    if t.back ≠ null: t.back.accumulate(t)     distributes t.grad to t.parents

The topological sort runs without recursion. A transformer with several blocks produces graphs with thousands of nodes in sequence; a recursive depth-first search would blow the call stack for deep networks. Instead the sort keeps its own stack with two phases per node: in phase 0 the parents are scheduled, in phase 1 the node is emitted – that is, only once all its parents have been emitted.

Pseudocode – Tensor.topoSort(root)

order ← [];  done ← {};  onStack ← {}
stack ← [(root, 0)]
while stack not empty:
    (t, phase) ← top element
    if t ∈ done:  pop;  continue
    if phase = 0:
        phase of top element ← 1
        onStack ← onStack ∪ {t}
        for each parent p of t (not null, not done):
            if p ∈ onStack:  throw "cycle in computation graph"
            push (p, 0)
    else:
        pop;  onStack ← onStack \ {t}
        done ← done ∪ {t};  append t to order
return order

Source: envisionz-framework-autograd/src/envisionz/autograd/Tensor.java, methods backward and topoSort. The sets are HashSets over object identity; a tensor used several times appears exactly once in the order.

A cycle cannot arise through the public interface, because every operation creates a new tensor and never changes an existing one. The check guards against later extensions.

Accumulating instead of overwriting

Every backward function writes into its parents' gradients with +=. That is the sum of the chain rule from section Computation graph, and it has three consequences worth knowing:

  • Shared weights collect every contribution. A tensor used at several places – the embedding matrix that also serves as output head, or a value multiplied by itself – receives the sum of all contributions. For L=∑x⊙xL = \sum x \odot x the result is correctly 2x2x.
  • Reset before every pass. Parameter gradients remain after backward(). Before the next backward pass zeroGrad() must set them to zero; Adam.zeroGrad() and Module.zeroGrad() do that.
  • Batches without a batch axis. Two backward passes over two different sequences without zeroGrad() in between give exactly the sum of the two individual gradients. That is how the sequence trainer batches sequences of different length without padding them (see Sequence training).

If an intermediate value is to be used further as a constant, detach() cuts it off: the result is a copy of the values without parents and without gradient. For L=∑x⊙detach⁡(x)L = \sum x \odot \mathrm{detach}(x) the gradient with respect to xx is therefore xx, not 2x2x – the second factor counts as a number.

One-sided stretching of unequal shapes

add, sub, mul and div allow the second operand to be smaller than the first. It is stretched right-aligned into the shape of the first: missing leading axes and axes of length 1 are repeated. That covers the two cases a transformer needs: a bias [D][D] on a sequence [T,D][T, D] and a mask [T,T][T, T] on the scores of all heads [H,T,T][H, T, T].

This is implemented with effective strides. For each axis ii of the first operand, the second one gets the stride sibs^b_i if the lengths are equal, and 0 where it is stretched. The flat index into bb for the flat index ff into aa is then

idxb⁡(f)=∑ici(f)ei,ei={si−obif bi−o=ai0if bi−o=1 or i<o\mathrm{idx}_b(f) = \sum_i c_i(f)\, e_i, \qquad e_i = \begin{cases} s^b_{i-o} & \text{if } b_{i-o} = a_i \\ 0 & \text{if } b_{i-o} = 1 \text{ or } i \lt o \end{cases}

with the offset oo = rank(a) − rank(b) and the coordinates ci(f)c_i(f) of ff. On the way back the chain rule implies that every value of bb that was copied to many places in the forward pass receives the sum of the gradients of all those places:

gb[j]=∑f:idxb⁡(f)=jga+b[f].g_{b}[j] = \sum_{f:\ \mathrm{idx}_b(f) = j} g_{a+b}[f].

For a bias this means: its gradient is the column sum of the output gradient over all rows.

Pseudocode – Ops.add(a, b)

e ← broadcastStride(a.shape, b.shape)      throws for incompatible shapes
for f ← 0 to |a|−1:  out[f] ← a[f] + b[idx_b(f)]
backward:
    if a.grad ≠ null: for each f: a.grad[f] += g[f]
    if b.grad ≠ null: for each f: b.grad[idx_b(f)] += g[f]    sum over stretched axes

Source: envisionz-framework-autograd/src/envisionz/autograd/Ops.java, methods broadcastStride, mapIndex, add; sub, mul and div are built the same way.

Decision in the framework: stretching is one-sided – only the second operand is stretched – and limited to right-aligned axes of length 1 or missing axes. If the second operand has more axes than the first, or an axis does not match, the operation throws ([2,3] against [2]: "shapes not broadcast-compatible … (axis 1)"). Better an exception than a silently wrong shape.

How it is checked

  • AutogradTest, part 1: every operation of Ops individually against central differences via GradCheck (40 probes, step 10−510^{-5}, relative step 10−610^{-6}, tolerance 10−610^{-6}), including add, sub, mul with a stretched bias and with two stretched axes, all three forms of the matrix product, reshaping and nonlinearities; in addition composed blocks (self-attention with two heads, feed-forward with residual and LayerNorm) and an embedding with a repeated index that proves accumulation into the same row. According to the module documentation the worst relative error was 4.0⋅10−94.0\cdot 10^{-9}.
  • AutogradTest, learning proof: a 2-32-32-1 network with GELU learns sin⁡(3x1)x2+0.5x12\sin(3x_1)\,x_2 + 0.5\,x_1^2 and must reach R2>0.99R^2 \gt 0.99 on held-out points; the gradient norm afterwards must be finite and greater than zero. Correct gradients say nothing about the interplay with initial values and optimiser – hence separately.
  • Gradientenprobe (63 checks) computes its difference quotients itself and deliberately does not call GradCheck. Among other things it pins down detach(): ∑x⊙detach⁡(x)\sum x \odot \mathrm{detach}(x) has the gradient xx and explicitly not 2x2x, the detached tensor carries no gradient and keeps the values.
  • EncoderTest: two backward passes without zeroGrad() in between give the sum of the individual gradients to better than 10−1210^{-12} (measured 4.4⋅10−164.4\cdot 10^{-16} according to the module documentation).

Limits

  • First derivatives only. The backward functions compute on raw arrays and build no graph; a derivative of the derivative (Hessian-vector products, gradient penalties) is not possible.
  • One backward pass per graph. The gradients of intermediate nodes are not reset before a second backward() on the same graph. Recomputed for L=∑tanh2⁡(w)L = \sum \tanh^2(w): after the second call w.grad does not hold twice but four times the single gradient. Whoever wants to differentiate twice builds the graph twice.
  • Memory grows with the graph. Every intermediate value is kept until the end of the backward pass – for a transformer all activations of all layers, for attention quadratically in the sequence length.
  • No in-place operations. Every operation creates a new tensor. Whoever changes a parameter's data directly (like the clamps in the fitting methods) does so outside the graph and after the optimiser step.
  • Not for concurrent backward passes. Parallelism lives inside the matrix product; two threads differentiating into the same parameters at the same time would corrupt each other's gradients.
  • Kinks. For relu and l1Loss the derivative at the kink is defined as 0; see Derivatives, limits.
