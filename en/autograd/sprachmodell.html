Text, tokeniser, language model – from text corpus to trained model

The computation behind TextKorpus, SprachmodellTrainer and text.Sampler.erzeuge: block-wise reading with cuts at word boundaries, token pairs shifted by exactly one, the assembly of the model with a tied head, the start check against ln⁡V\ln V, perplexity and continuing text – with pseudocode following the source, figures, the probes and the limits.

What this is about

A language model learns to predict the next token in a text. For that it needs three things: a stream of training examples from a text file that may be too large to keep in memory as a whole; a model of embedding, positional encoding, encoder with causal mask and output head; and a loop that notices early when a run is worthless.

The most dangerous faults on this path produce the right number of examples with the wrong content. During training that goes unnoticed – the model only gets somewhat worse, or it learns a trivial task and looks excellent doing so.

Pairs shifted by one

A sequence of L+1L+1 tokens yields two sequences of length LL:

before=(x0,…,xL−1),after=(x1,…,xL).\text{before} = (x_0, \dots, x_{L-1}), \qquad \text{after} = (x_1, \dots, x_L).

At every position ii the model learns to guess token xi+1x_{i+1} from x0…xix_0 \dots x_i; the causal mask prevents it from looking ahead. The shift by exactly one is the most important point: were it zero, the model would learn to repeat the current token. The loss would fall to almost zero because the task is trivial – and only when generating text would one notice that nothing was learned.

Reading block-wise, cutting at word boundaries

Reading and tokenising a corpus of several hundred megabytes as a whole needs a multiple of that in memory. TextKorpus therefore reads in blocks of a fixed number of characters, tokenises each block and buffers the tokens until a sequence is full. Two traps lie at the block boundary, and both produce the right number of pairs with the wrong content:

  • The tokeniser works word by word. "Verdichter" gives different tokens than "Verdich" plus "ter". Buffering tokens across the boundary is not enough – the tokenisation itself must end at a word boundary. The cut-off remainder is kept as text and prepended to the next block.
  • Cut before the separator. The tokeniser attaches the leading space to the following word (see Byte pair encoding); " Druck" and "Druck" are different symbols. The cut therefore lies immediately before the last whitespace character, not after it.

A UTF-8 character cannot be cut at the block boundary: reading is character-wise via a BufferedReader, not byte-wise.

Pseudocode – TextKorpus.Leser.vorruecken()

while |buffer| < L + 1 and not atEnd:
    block ← read up to blockChars characters
    if end of file:
        atEnd ← true;  if textRest ≠ "": buffer += encode(textRest)
        break
    text ← textRest + block
    s ← last position i > 0 with whitespace at text[i]   before the separator
    if s ≤ 0:  textRest ← text;  continue              no separator: read on
    textRest ← text[s …];   buffer += encode(text[0 … s))
if |buffer| < L + 1:  next ← none;  return          truncated end discarded
next ← Pair(buffer[0 … L), buffer[1 … L+1))
remove the first L tokens from buffer                    x_L stays: seamless join

Source: envisionz-framework-autograd/src/envisionz/autograd/text/TextKorpus.java. Defaults: sequence length 256, blocks of 8192 characters; paareGeschaetzt() assumes four bytes per token and is meant only for a progress display.

The model and the loop

SprachmodellTrainer assembles: embedding V×dV\times d, sinusoidal positional encoding up to the sequence length LL, a TransformerEncoder of the classic variant, and a language head that shares the embedding matrix and has its own bias (see Language head). The shared matrix appears exactly once in the parameter list. Training uses Adam with norm clipping, one sequence per step, against the causal mask L×LL\times L and the cross-entropy over all LL positions.

Start check against ln⁡V\ln V. An untrained model guesses uniformly over VV entries. The cross-entropy of a uniform distribution is

ℓ0=−ln⁡1V=ln⁡V.\ell_0 = -\ln\frac1V = \ln V.

If the first loss deviates downwards by more than 1, the trainer stops: the model then already knows its target, and the shift in the data is probably wrong. A deviation of more than 1 upwards is only reported (hint at a wrong vocabulary size). A loss that is not finite aborts at once, with a pointer to learning rate and norm clipping – otherwise the run would go on for hours with NaN weights.

Perplexity. More intuitive than the loss is PP⁡=eℓ\mathrm{PP} = e^{\ell}: the number of equally likely candidates between which the model still wavers on average. At the start it is VV; a perfect model would have 1.

Pseudocode – SprachmodellTrainer.trainiere(corpus)

opt ← Adam(parameters, learningRate);  opt.maxGradNorm ← maxGradNorm
mask ← causalMask(L);  rnd ← Random(seed + 1);  expected ← ln V
for each pair (before, after) in corpus:
    ℓ ← crossEntropy(forward(before, mask, rnd, training = true), after)
    if ℓ not finite: return abort "lower the learning rate …"
    if first step:
        if ℓ < expected − 1: return abort "model sees its target"
        if |ℓ − expected| > 1: warning "check vocabulary size"
    opt.zeroGrad();  ℓ.backward();  opt.step();  step += 1
    every reportEvery steps: print mean, perplexity, gradient norm, sequences per second
    every saveEvery steps: WeightIO.save(output, parameters)
    if maxSteps reached: break
if saveEvery > 0 and step > 0: WeightIO.save(output, parameters)

Source: envisionz-framework-autograd/src/envisionz/autograd/text/SprachmodellTrainer.java. trainiere takes an Iterable<Paar>, so that the trainer can also be tested with generated pairs without a file.

Decision in the framework: defaults of the Einstellungen: 2 layers, d=128d = 128, 4 heads, dFF⁡=512d_{\mathrm{FF}} = 512, dropout 0.1, sequence length 128, learning rate 3⋅10−43\cdot 10^{-4}, norm bound 1.0, report every 100 steps, save every 5000, seed 1234. Deliberately without batches, without warm-up and without a learning-rate schedule: that pays off only once it is established that the chain learns at all. For resumable runs with schedule and checkpoints there is SequenceTrainer.

Continuing text

text.Sampler.erzeuge(model, start, count, T, k) appends token by token: for the sequence so far a forward pass without dropout is computed with the causal mask, a token is drawn from the logits of the last position with temperature and top-k (see Sampling), and the drawn token is appended.

Worked examples

  • Starting loss. For V=8000V = 8000, ln⁡V=8.987\ln V = 8.987; a first loss below 7.987 stops the run. For V=268V = 268 (twelve merges on top of the bytes, as in the example of Byte pair encoding) ln⁡V\ln V would be 5.591.
  • Measured. According to the module documentation the loss in SprachmodellTrainerTest fell from 5.6266 to 3.1510; that corresponds to a perplexity of e3.151=23.4e^{3.151} = 23.4. At d=64d = 64 about 90 sequences per second were processed.
  • Lengths must match. With the defaults – TextKorpus 256, SprachmodellTrainer 128 – the first step aborts with "Sequenzlaenge 256 ueberschreitet maxLen 128" (recomputed); the corpus sequence length must be set explicitly to that of the model, for example new TextKorpus(file, bpe, e.sequenzLaenge, 8192).
  • Cutting. With L=6L = 6 on a small corpus, TextKorpus yields as first pair [261, 290, 290, 288, 298, 289] → [290, 290, 288, 298, 289, 292], as second [292, 287, …]: the last target of the first pair is the first input of the second.

How it is checked

  • TextKorpusTest (11 checks): at least one pair; both sequences of equal length; after[i]=before[i+1]\text{after}[i] = \text{before}[i+1] – the most important check; the sequences are not identical; small blocks (32 characters) give as many pairs and the same content as large ones (65,536) – according to the module documentation this check found both block-boundary faults; the sequences join seamlessly; a too short corpus gives no pairs instead of failing; umlauts survive odd block sizes.
  • SprachmodellTrainerTest (11 checks): the model can be built; the shared matrix appears exactly once, the head is tied; a width not divisible by the number of heads is rejected; the starting loss is within 0.5 of ln⁡V\ln V, without abort; after 400 steps the loss has fallen below 60 % of ln⁡V\ln V, the perplexity is below the vocabulary size and finite; a fresh model also starts at ln⁡V\ln V on deliberately wrongly shifted pairs.
  • SamplerTest checks the drawing (see Sampling).

Limits

  • The start check only takes effect with pre-trained weights. A freshly initialised model does not know even a trivial task yet; its first loss lies at ln⁡V\ln V even if input and target are equal. The probe records this explicitly. A wrong shift therefore shows only in the course of training – as a loss that falls towards zero unusually fast.
  • Sequence length. Corpus and model must have the same sequence length (see above), and the model processes at most LL tokens. erzeuge therefore throws as soon as start sequence plus generated tokens exceed LL; there is no sliding window.
  • No batches, no schedule, no resuming. One sequence per step, fixed learning rate; the saved weights carry no provenance and no optimiser state.
  • Output to the console and a fixed weight file (modell.ennet by default); a listener as in the sequence trainer is missing.
  • The truncated end of a file that is not enough for a full pair is discarded.
