Differentiable spectral model of the formant voice – fitting whole frame sequences

The computation behind FrameSequenceFit: warm start along the time axis, blocks that run in parallel, the cold restart of a derailed frame, and why the parallel result must be bit-identical to the serial one – with pseudocode following the source, a cost estimate, the probes and the limits.

What this is about

For the second stage of the speech output, formant trajectories are to be derived from a speech corpus as learning targets: for every frame (every 10 ms) the formants, bandwidths and source quantities the synthesiser would need to reproduce that frame. A single frame is fitted with FrameFit (see Spectral fitting) – cold, with nine starting points of 900 steps each.

According to the class description that takes about four seconds per frame. A corpus of 22 hours has about 7.9 million frames at a 10 ms hop – on the order of a year of computing time. Label generation is not feasible that way. Two levers bring it within reach, and they contradict each other.

Warm start along time

Formants move continuously – the vocal tract has mass. The result of the previous frame is therefore a very good starting point for the next. Instead of nine starting points of 900 steps, one with 60 steps suffices: arithmetically 9⋅900/60=1359\cdot 900 / 60 = 135 times fewer steps. According to the module documentation a cold frame measured about 7000 ms, a warm one about 53 ms – a factor of 130.

The warm start, however, makes frame nn depend on frame n−1n-1. That is exactly the sequential chain that prevents distribution over the frames. The second lever – all cores – would be lost.

The resolution: blocks

The signal is split into blocks of a fixed number of frames. Within a block the warm chain runs sequentially; the blocks run in parallel. Each block starts with a cold multi-start, carries its chain itself and needs no predecessor. The price is one cold start per block; with 200 frames per block that is one expensive frame for 199 cheap ones.

Fallback on derailment

A warm start can derail – for example at a phoneme transition where the formants jump. Without a countermeasure the chain drags the error through the rest of the block, because every following frame starts from the wrong result. If the residual of a warm frame exceeds rescueRmsDb (default 6 dB), the frame is repeated cold with multi-start, and the chain continues from the new result.

Pseudocode – FrameSequenceFit.fitAll(…)

frames ← min(number of whole frames in the signal, |f0|);  check frames > 0
blocks ← ⌈frames / blockSize⌉
for each block — in parallel if blocks ≥ parallelFromBlocks:
    prevF ← none
    for each frame i of the block:
        if f0[i] ≤ 0: result empty, continue                  unvoiced
        P ← periodogram(i);  points ← harmonicBins(P, f0[i], loHz, hiHz)
        if |points| < 6: result empty, continue
        if prevF = none:
            r ← cold(…)                                     9 starting points × coldIterations
        else:
            r ← fitFast(start = prevF, prevBw, warmIterations steps)
            if r.rms > rescueRmsDb:  r ← cold(…);  rescues += 1
        store r for frame i;  prevF, prevBw ← r
return results, number of cold starts and rescues, run time

Source: envisionz-framework-autograd/src/envisionz/autograd/dsp/FrameSequenceFit.java. cold takes the starting points from FrameFit.spreadStarts and picks the smallest residual; with fastGrid = false cold and warm frames compute on the full grid.

Bit-identical in parallel

Blocks are independent of each other, and every block computes deterministically: the same inputs, the same starting points, the same sequences of steps. The parallel result must therefore be bit-identical to the serial one. If it were only "almost equal", there would be a fault in the block decomposition. One trap: the settings of a frame are changed per frame (number of steps cold or warm). A settings object shared by all blocks would be a race; every frame therefore gets its own copy.

Decision in the framework: defaults of FrameSequenceFit.Options: 200 frames per block, 900 steps cold, 60 warm, harmonics between 150 and 5500 Hz, rescue from 6 dB residual, fast grid on, parallel from 2 blocks. The optimisations are explicitly split into two groups: exact ones that only change the computational path and give bit-identical results (the fast grid, on by default), and approximations that change the result and would each need their own proof (fitting only every nn-th frame, a different method, an LPC starting estimate). Approximations deliberately do not exist as unused switches – a field that does nothing is worse than none.

Cost

With NN voiced frames, block size bb, costs tkt_k of a cold and twt_w of a warm frame, and RR rescues, the cost on one core is

t≈⌈Nb⌉tk+(N−⌈Nb⌉)tw+Rtk,t \approx \Big\lceil \frac{N}{b} \Big\rceil\, t_k + \Big(N - \Big\lceil \frac{N}{b} \Big\rceil\Big)\, t_w + R\,t_k,

and with KK cores, as long as there are enough blocks, roughly t/Kt/K. Blocks that are too short spend the gain on cold starts, blocks that are too long waste parallelism; the block size is therefore adjustable. According to the module documentation the estimate for a 22-hour corpus at a 10 ms hop and block size 200 was initially about 115 hours on one core; with the fast grid it dropped to about 16 hours, and on the target machine with all cores to about 3 hours. The recommendation is to start with a 5-hour subset at a 20 ms hop and then measure.

Worked example

The acceptance in SequenceTest: a glide from /a/ (700/1220/2600 Hz) to /i/ (330/2200/2950 Hz) over 0.9 s at 22,050 Hz, i.e. 19,845 samples. With frames of length 2048 and a hop of 512 that gives 1+⌊(19,845−2048)/512⌋=351 + \lfloor (19{,}845 - 2048)/512 \rfloor = 35 frames. With block size 12 there are three blocks (12, 12, 11 frames) and thus at least three cold starts. According to the module documentation the chain followed the known trajectory to 1.18 % (F1) and 1.50 % (F2) on average and was 10.8 times faster per frame than all-cold – a factor depressed by the short block length, at which 3 of 35 frames are cold and dominate the cost.

For comparison with block size 200: one minute of speech at a 10 ms hop (6000 frames) gives 30 blocks, i.e. 30 cold and 5970 warm frames.

How it is checked

  • SequenceTest on a signal with moving formants – with steady ones a warm start would be trivially right and the check worthless:
    • block distribution parallel equals serial, bit-exact over all frames (comparison of bit patterns);
    • fast grid equals full grid, bit-exact;
    • the warm start follows the target trajectory: mean error of F1 and F2 each below 5 %;
    • warm is more than three times faster per frame than all-cold (sample over four frames).

Limits

  • Unvoiced frames and frames with fewer than six harmonics stay empty. The chain afterwards continues from the last voiced frame – after a long unvoiced stretch that may be far away; the rescue catches that only if the residual exceeds the threshold.
  • At block boundaries fitting starts afresh; small jumps in the trajectory between two blocks are possible.
  • The rescue threshold is a fixed value in dB, independent of speaker and recording.
  • The setting coldStarts has no effect: the starting points come from FrameFit.spreadStarts, which always delivers nine.
  • The whole signal is held in memory as float[]; long recordings are split into pieces beforehand.
