envisionz-app-stats

A statistics workbench for CSV data

Overview of the app, as of 29 September 2026. The app makes the method catalogue of the statistics module usable: load a CSV, assign roles to columns, pick suitable methods, set options, run them and read the results as cards.

10source files
7probes, all in the collective run
3help pages, each in German and English
52counter-tests on the user interface, all red

What the app is for

Anyone who wants to evaluate measurement series or calculation results statistically first needs answers to two questions: which method fits the data, and how do I give it the right columns? The app answers the first through the roles of the columns. Marking one column as a number and one as a group leaves only the methods that can apply at all; everything else is greyed out.

The calculation itself lives in the framework's statistics module. The app is the operation in front of it: finding and importing data sets, setting roles, choosing methods and keeping the results.

What it can do

Data set navigator

The navigator is split in two. The CSV files of the working directory are at the top, the already imported data sets below. An imported data set carries a status mark: current, outdated (the CSV has changed), orphaned (the CSV is gone) or external. CSV files that have already been imported appear greyed out at the top.

Roles and restrictions

A variable table shows name, type, role and restriction for each column. The roles are number, group, x, y and multi-select; apart from multi-select they are exclusive, and a text column cannot take a number role. The restriction is a row filter per column in a short notation (equality, range, comparison); the role bar shows how many rows of how many remain. The variable area can be folded away with a narrow bar.

Method tree with role check

The tree groups the catalogue of the statistics module into headings, for example descriptive statistics, distributions, tests, regression, multivariate methods, time series and process monitoring. Methods whose roles are not assigned are greyed out. Several methods can be ticked and run one after another in one go.

Options from the description

The options panel builds itself for each method from its parameter description: a choice as a list, yes/no as a checkbox, numbers as a spinner. The values per method are kept during a multi-select run.

Result cards with data stamp

Each run gives a card with the result as text and a note on the overlays. The card carries a data stamp made of a short checksum and the import time. If the data set is imported again later, the app marks the affected cards as outdated. They can be recomputed one by one or all together with the remembered options.

State per data set

Roles, restrictions and result cards are remembered per data set. Switching between data sets finds each in its last state.

Help

Three help pages in German and English: overview, assigning roles, methods and results. They state that the role check tests the shape of the data and not its suitability: three numeric columns do not make a sensible regression. And that the effect size sits next to the p-value, not in its place.

Data and formats

  • Input: CSV files, including semicolon separators and decimal commas. A comma becomes a point only in pure numbers; dates and version numbers stay text. The import runs through the framework's load panel with a preview.
  • Intermediate store: an H2 file next to the CSV (flow.csv becomes flow.mv.db) with the data table and a metadata table: source, size, modification time, SHA-256, row and column count, import time. Column types are detected. The table has the name the other apps expect, so that they can open the file.
  • Economical with memory: the whole CSV is not loaded into memory. For each run only the assigned columns and the filtered rows are read from the database; the filter is translated to SQL and runs in the database.
  • Output: result cards in the user interface.

What it builds on

  • stats: the method catalogue with the role check and the parameter description. Every calculation runs there.
  • data: CSV reader, type detection and the H2 store.
  • viewer: display of the help pages.
  • swing: the load panel for the import, icons, background runner and remembering the last used directory.
  • api: the app interface and registration in the host.
  • core: start-up of the host.

State and limits

  • The path directory, CSV, roles, methods, options, run, result card can be operated from start to finish and is covered by probes. The import runs in the background with a wait notice.
  • Roles, restrictions and runs are kept only within a session. Saving them across sessions in the workspace state is still to do.
  • The overlays of the results (curves, markers) appear as a note so far, not as a chart.
  • There is no editor for contingency tables yet, so the tests on categorical tables cannot be operated yet.
  • Design of experiments (Latin hypercube, factorial designs, Sobol and Halton sequences) is not part of the app. Instead of column roles it needs an editor for factors and ranges.
  • The method calculations still run on the event thread.
