Avro — comparison against specification and fastavro

As of: 2026-09-26
Our implementation: envisionz.fileformats.avro.AvroQuelle, read-only, no third-party library
Specification: Apache Avro Specification 1.12; references name the sections "Binary Encoding" and "Object Container Files"
Compared against: fastavro 1.12.2 (Python)
Test bench: envisionz.fileformats.avro.Avroprobe — 59 checks; Avroaufloesungsprobe — 40 checks (AV5)

The reference implementation. fastavro is an Avro implementation written in Cython, the usual one in Python around Kafka and data pipelines — much faster than the Apache Software Foundation's reference library avro and tested against it.

Why this one. Because it writes all six codecs and knows the logical types completely. The fixtures come from fastavro, the expected values from fastavro's own reading.

What was measured

Thirteen files, written by fastavro (docs/avro/erzeuge.py): a schema of 21 fields — all primitive and complex types and six logical ones — in seven records and three blocks, once per codec; plus the recipe from OFFENE-PUNKTE, a schema without a record, a recursive one and an empty one. Equal in every value fastavro reads (docs/avro/auskunft.txt); the six codecs yield the same rows.

Four mutations go red: without zigzag (17 failures), deflate read as zlib (2), without the snappy CRC check (1), without the sync check (3).

What is hard about the format

Without the schema nothing can be read. Values carry neither names nor lengths nor types; whoever misreads the schema reads nonsense from the first deviation on without noticing. The only feedback is the sync marker at the block end — and the block's byte count, which has to add up.

Two codecs are not what their name says. deflate is raw, without the zlib frame; snappy is the raw block followed by four bytes of CRC-32 — not snappy's framing format.

Deliberate decisions

AV6 (decided) — Writing

fastavro writes. This module reads.

AV4 (decided) — decimal as text, timestamps in UTC

decimal comes out as text so that no digit is lost — as a floating-point number 0.1 would no longer be 0.1. Timestamps become ZEITPUNKT in UTC; fastavro returns them with time zone UTC. Composite values come as JSON text, bytes inside them in hex.

Properties of the format

AV1 (property) — The sync marker is checked

If it does not match after a block, reading stops there and it is reported. The records before it stay readable.

AV2 (property) — The CRC-32 after snappy is checked

fastavro checks it too. A block whose checksum fails is not handed out.

AV3 (property) — Recursive types stay finite

A named type is registered before its fields; a reference to it is the same object. A field's description names named types by name only.

AV5 (property) — Schema resolution with a reader schema

AvroQuelle.oeffne(file, readerSchema) reads a file with a schema other than the one it was written with (Aufloesung). Fields are matched by name or field alias, record names also by alias; a field only in the writer is skipped, one only in the reader gets its default. Promotions int → long/float/double, long → float/double, float → double, string ↔ bytes. An enum symbol unknown to the reader becomes its default. If the reader is a union, the first matching branch applies. What can be decided from the schemas fails on opening, with location; what depends on a value — an unknown symbol without default, a union branch that matches nowhere — fails at that record, and the records before stay readable. fastavro behaves the same: in all ten cases it fails at the same record. Without a reader schema the file's own applies.

Findings against the reference implementation

AV7 (open there) — fastavro returns defaults raw

Two places, both concerning reader-schema defaults, measured with fastavro 1.12.2. A record default that omits a field ({"a":7} for a record with a and b, b having its own default "x") is returned by fastavro as written — Apache Avro fills b with its default, and so does this reader. And fastavro does not apply the logical type to the default: a decimal(5,2) with default "\u0001\u0000" comes out as those two characters, here as 2.56. The probe puts in the value per the specification at exactly these places and checks it separately.
