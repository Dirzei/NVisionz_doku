envisionz-framework-fileformats

Read every file, change none

Function overview for the presentation of the envisionz framework, as of 28 Sep 2026. Own pure-Java readers for databases and tables, measurement data, scientific containers, meshes and CFD results, images, Office files and engine maps, plus SQL over every source and structure recognition for unknown text formats. For each method: purpose, API, use in the framework, applications, examples. The examples are shortened. Many API names are German (e.g. Datenquelle = data source, Satzkursor = record cursor, Wert = value, Befund = finding); they are shown unchanged.

33formats with their own comparison document, 1,254 feature rows
55formats in magic-byte recognition
8formats with no other pure-Java reader
0third-party libraries; decompression from framework-compress
95probe classes, plus a read-only checker
125counter-probes, all red

Principles of the module

Read-only, provably. Files are opened only with READ or READ_ONLY, without journal, lock or temporary files. Nurlesenprobe scans the whole source tree for 24 patterns of writing calls.
Content, not extension. Recognition always uses the magic bytes. The extension may at most influence the order of the checks.
The raw value is kept. Every Wert carries the bytes it was interpreted from. A date 00000000 does not become the year 2.
Findings instead of repair. Broken trees, uncleaned journals and overflows end up in befunde(); nothing is invented or silently skipped.
Cursor, not list. Tables can be larger than main memory; they are read record by record.
Compared against the reference. One document per format: specification, own reader, third-party tool (Pillow, h5py, astropy, asammdf, pyarrow …). Bugs in third-party readers are documented as findings.

One view for all tabular formats envisionz.fileformats

Datenquellen, Datenquelle, Satzkursor, Wert, Knoten

A factory opens a file by its content and returns a Datenquelle (data source): format, metadata tree, tables and findings. The factory is a switch the compiler checks for completeness, deliberately not a ServiceLoader. Hierarchical formats (HDF5, netCDF, CGNS, Exodus, VTK, Gmsh, HDF4) also appear in the long form: one table per axis combination. Background, formulas and pseudocode →

Methods

  • Datenquellen.oeffne(path) (open), oeffne(path, Format.PLOT3D), oeffneVerbund(leadFile) (Ensight)
  • format(), wurzel() (root), tabellen() (tables), kursor(table[, preselection]), befunde()
  • Satzkursor: felder() (fields), weiter() (next), wert(i|name), satznummer()
  • Wert: typ(), istLeer(), alsText(), alsZahl(), roh() (raw)
  • Knoten (node): kinder(), eigenschaften(), finde(name), baum()

Used in

app-fileanalysis: data panel, format docscmd.fileformats.Datei

What for

Write one import for many formats; inspect old and foreign data sets without touching them.

Example – iterate over every table of a file

try (Datenquelle q = Datenquellen.oeffne(Path.of("measurement.parquet"))) {
    for (String t : q.tabellen()) {
        try (Satzkursor k = q.kursor(t)) {
            while (k.weiter()) { Double p = k.wert("pressure").alsZahl(); /* … */ }
        }
    }
    q.befunde().forEach(System.out::println);
}

Formaterkennung and Dateikunde – what kind of file is this?

One signature table for 55 formats, including some without a reader (PDF, PostScript, Tecplot binary, Java class file, zstd, LZ4). The file inspection (Dateikunde) adds size, share of printable characters, null bytes, UTF-8 validity, BOM, line endings, Fortran record markers and the tools of the hex viewer.

SQL over every data source envisionz.fileformats.sql

Sql – SELECT without a database engine

An own evaluator for a SELECT subset, not only over SQLite but over every Datenquelle: dBASE, Parquet, XLSX, TDMS, HDF5 in long form … Three-valued logic as in the standard (NULL = NULL is unknown). Without ORDER BY, GROUP BY and DISTINCT the query streams and stops at LIMIT.

Scope

  • SELECT [DISTINCT] … FROM … WHERE … GROUP BY … HAVING … ORDER BY … LIMIT … OFFSET
  • AND/OR/NOT, LIKE, IN, BETWEEN, IS NULL, arithmetic and concatenation
  • UPPER LOWER TRIM LENGTH ABS ROUND COALESCE IFNULL SUBSTR; COUNT SUM AVG MIN MAX
  • rejected by name: joins, subqueries, UNION, window functions, anything that writes
  • Sql.frage(source, sql) (ask) → Ergebnis(spalten, zeilen) (columns, rows)

Used in

cmd.fileformats.Datei -sql:

What for

Query a 1990 dBASE file like a table; filter measurement channels without converting them.

Example – filter test-bed data

try (Datenquelle q = Datenquellen.oeffne(Path.of("testbed.tdms"))) {
    Ergebnis e = Sql.frage(q, "SELECT time, pressure FROM Measurement WHERE pressure > 2e5 ORDER BY time LIMIT 100");
}

Datencontainer, Datenkatalog, Langform – data container, catalogue, long form

The container reader interprets an in-house structure on top of HDF5: /MASTER with header attributes, /MISCDATA with embedded model texts, one column per measured quantity; the catalogue holds collections, projects and tests. The long form turns multidimensional arrays into tables with the axes as columns, so HDF5, netCDF and CGNS can be queried with SQL too (C versus Fortran order respected).

Methods

  • Datencontainer.lies(path), kopf(), abschnitte(), spalten(), spalte(name)
  • Datenkatalog.bestaende(catalogue), projekte, versuche (tests), dateien
  • Langform.oeffne(path), ueberHdf5, ueberNetcdf, ueberCgns, ueberExodus, ueberVtk, ueberGmsh, ueberHdf4

Maps and NPSS output envisionz.fileformats.gasturb · .npss

GasTurbLeser, NpssLeser, NpssSchreiber, GasTurbSchreiber – compressor and turbine maps

GasTurb .MAP and NPSS map tables into a common Kennfeld (map: mass flow, efficiency, pressure ratio, surge line, Reynolds points). The writers build the text in both directions and are secured against the readers by round-trip probes. The file itself is written by the caller, not by this module.

Methods

  • GasTurbLeser.lies(path|text), NpssLeser.lies(path[, fieldWidth, preamble])
  • Kennfeld: tabelle(Kennfeldart.WIRKUNGSGRAD) (efficiency), pumpgrenzeMassenstrom(), pumpgrenzeDruckverhaeltnis() (surge line), reynolds()
  • new NpssSchreiber("\n").baue(kf), new GasTurbSchreiber('\t', "\n").baue(kf)

Used in

What for

Example – GasTurb map to NPSS

Kennfeld kf = GasTurbLeser.lies(Path.of("hpc.MAP"));
Files.writeString(Path.of("hpc.map"), new NpssSchreiber("\n").baue(kf));

NpssView, NpssAusgabe, Fallleser – NPSS output by its page layout

Parses the .view description of the NPSS DataViewer and reads the PageViewer output accordingly: anchors, blocks, fields at the format positions. Nothing is guessed; overflow, text in a number field and every unassigned character are reported.

Methods

Used in

What for

Evaluate NPSS results automatically and compare them with other computations (such as the NPSS translation in the eqnparser).

Understanding unknown text formats envisionz.fileformats.text

An ASCII data file is the trace of a small program, such as a Fortran FORMAT statement. The short grammar is inferred from the long trace. The end result is a standalone Java reader.

Structure → description → comparison → Java skeleton

Layer 0 checks character set, BOM and line endings (per line, with round trip). Layer 1 turns every line into a shape such as E R W. Layer 2 recognises count fields, wrapped records and blocks. A rule tree tiles the file without gaps; an .fmt description generates the file forwards and reads it backwards. The comparison loop locates deviations to the byte and repairs them. The skeleton is a Java reader that needs only the JDK.

Methods

  • Textdatei.lies(path), Zeilenzerleger (line splitter), Strukturleser.lies(path, splitter) → Strukturbefund
  • Regelbaum, Regel, Regelart, Sicherheit (rule tree, rule, kind, confidence)
  • Beschreibungsleser.lies(fmt), Vorwaerts.schreibe(b, space), Rueckwaerts.lies(b, raw)
  • Abgleich, Guete (comparison, quality); Geruest.schreibe(b, package, class) (skeleton)
  • Analysekette (analysis chain: steps, parameters, run), Anonymisierer.ersetze(text, settings)

Used in

app-fileanalysis: analysis, chain card, anonymise, line panelcmd.fileformats.Textstruktur

What for
