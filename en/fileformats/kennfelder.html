Component maps and NPSS output – background

How compressor and turbine maps in the GasTurb and NPSS table formats are read and written back byte-identically, what the corner cell encodes, why a number format is measured rather than assumed, and how an NPSS page output is taken apart by its .view.

A map is a cross table

A map gives a quantity f (corrected mass flow, efficiency, pressure ratio) over two axes: the corrected speed n as row value and the auxiliary coordinate β as column value. Stored are f(nᵢ, βⱼ) for i = 1…N, j = 1…M, plus the surge line as one curve (mass flow, pressure ratio) and optional Reynolds correction points. Both formats carry the same information in different shape; both are read into a common model.

The corner cell encodes the size

In the GasTurb format every logical table row starts on a new line and is wrapped after five numbers (see round trip). The reader does not rely on this: it takes the values of a block as a stream, and the size is in the first number alone, the corner cell. A file that runs the values on at five per line regardless of the logical rows is therefore read the same way. Until 2026-10-25 the reader's class description described only this stream form, as if GasTurb wrote it.

c=(N+1)+M+11000,N+1=⌊c⌋,M+1=round⁡(1000(c−⌊c⌋))c = (N+1) + \frac{M+1}{1000}, \qquad N+1 = \lfloor c \rfloor,\quad M+1 = \operatorname{round}\bigl(1000\,(c - \lfloor c\rfloor)\bigr)

N + 1 includes the header row, M + 1 the label column. The block then carries exactly (N+1)(M+1) numbers: corner cell, M column values and N rows of one row value and M function values each. If the count is wrong, the block is incomplete; it is reported and skipped, the other blocks are kept. Two consequences:

  • Rounded, not truncated. 4.005 − 4 (three speeds, four β values) is 0.004999… in floating point; truncation would give 4 columns instead of 5.
  • At most 998 columns. With 999 β values M + 1 would be 1000, and 2 × 999 would give the corner cell 4.000 – the same number as a 3 × 0 table. That is a limit of the format; such a table is rejected when writing rather than produced as a wrong file.

The number format: ten significant digits and a measured field width

Measured on real files: every number has ten significant digits in fixed point, decimal places are padded; with the separator that makes eleven characters. Below 1 the leading zero counts as a digit (0,763082092). Fixed point applies to zero and to magnitudes from 0.001 with at most ten integer digits; otherwise ten significant digits are written in exponent notation – wider than the field, but lossless. Rounding happens exactly once from the exact value; rounding twice can lift a 5 from the first rounding again in the second.

The field width is measured. Numbers are right-aligned, so the fields end at intervals of the field width b. With the end columns e₁ … eₖ of the widest line

b=ek−ek−1,v=ek−kb,0≤v<b,b = e_k - e_{k-1},\qquad v = e_k - k\,b,\qquad 0 \le v < b,

if all intervals equal b; v is the leading padding. The pure divisor test (line length over field count) is ambiguous for few fields – 29 characters are 2 × 13 + 3 and 2 × 14 + 1 – and is only the fallback. Comma and point are both read: a comma is a decimal separator only if no point occurs. Only [±]digits[.digits][E[±]digits] with a finite value counts as a number; NaN, Infinity or Java literals appear in no map file.

NPSS tables: nesting instead of a corner cell

NPSS writes one table per quantity, in it one block per speed with the β vector and the function vector. The β vector is written out only for the first speed; after that BetaMap= *; refers back to it. The header line // 98 title is a comment – uncommented it swallows the following Table. Reading goes over a token stream; every speed line must carry as many values as the β vector. If a block fails it is reported and skipped from the start of the block: skipping from the point of failure would let the already completely read block swallow the next one. The Reynolds points have no NPSS counterpart and are kept as a comment so the way stays reversible.

The round trip as a measuring tool

Both writers return text, not a file. Their main purpose is measuring: read, write back in the same format, compare byte by byte. If it matches, the reading rule is proven. When writing, GasTurb breaks the line at the end of every logical table row, five numbers per line, at the measured field width; a number that fills its field completely gets a space in front because the fields are concatenated without separators.

NPSS page output by its .view

An NPSS output is a page image of text blocks side by side and one below the other. Where a value is, how wide its field is and what it is called is not in the output but in the .view. Reading follows the layout model of the .view, not search patterns: the anchor of a group is at the top left, the right neighbour starts after the block's width, the lower one below the pair of block and right neighbour; fields are cut at the positions of the format placeholders. A page (separated by form feed) is one case and becomes one table row.

Format placeholders. The number of characters is the field width: ????? integer or text, ??.???? decimal, ??.???E??? with exponent, ??????S??? with significant digits. Only the significant-digit form may grow wider than given; a reader cutting fixed columns cannot trust such a column. If a value does not fit, NPSS writes dashes and keeps the shape: ?????.? becomes -----.-. A field of at least two dashes and otherwise only . and E is therefore an overflow; a single dash is not.

Nothing is guessed. Overflow and text in a numeric field leave the cell empty and are reported; every non-blank character of the page that no block explains appears as “unassigned” with its column in the findings.

What follows

  • The shape of a GasTurb block hangs on one number; one misread thousandth shifts every value. The length check (N+1)(M+1) turns that into a yes/no statement.
  • Because the field width is measured, files with a different grid go there and back byte-identically as long as their numbers fit the field.
  • Assigning a block name to a quantity is the only guess; an unknown name is kept as an unknown block.

How it is tested

Npssprobe and Zahlformatprobe (round trip over magnitudes from 10−15 to 1015), NpssAusgabeprobe, Fallleserprobe, Npsssprachprobe and TheorieFBprobe in gasturb ([TD22-FB-G1]–[TD22-FB-G5]: corner cell at 998/999 columns, field width from field ends, GasTurb and NPSS byte-identical there and back, rejected blocks without losing the others) and in npss ([TD22-FB-N1], [TD22-FB-N2]: placeholders, overflow, unassigned characters). Counter-probes td22fb-*.

Limits

  • The field width of an NPSS map file is not measured (different grid); converting to GasTurb uses the default 13.
  • More than 998 β values cannot be written as a GasTurb file.
  • A UserTextBlock has no description of its content; it is bounded by the position of its neighbours and kept as text.
