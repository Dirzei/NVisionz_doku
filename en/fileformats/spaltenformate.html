Parquet, Arrow and Avro – background

Three formats from data processing, two ideas: store by column (Parquet, Arrow) or by record with a schema (Avro). This page covers the encodings a reader has to compute – zigzag and varint, the RLE/bit-packing hybrid, delta encoding, definition levels, the Bloom filter with xxHash64, validity bitmaps and the resolution of two Avro schemas.

What this is about: columns instead of rows

A table with a million rows and twenty columns can be stored row by row – each record after the other – or by column: first all values of the first column, then the second. By column, similar values sit together and pack well; whoever needs only three columns reads only three. Parquet stores this way on disk, Arrow in memory (and as an IPC file), while Avro stores records one after another with a schema in the header. All three encode numbers as compactly as possible, and all three distinguish “value missing” from “value empty” – exactly at these two points lie the errors a reader makes without notice.

Parquet: Thrift Compact, zigzag and field deltas

The directory of a Parquet file – schema, row groups, column chunks – is at the end, in Thrift Compact. Integers are varints, least significant group first; signed ones are zigzag-folded first so that small negative numbers stay short too:

$$ z(n) = 2n \ \text{for}\ n \ge 0, \quad z(n) = -2n - 1 \ \text{for}\ n < 0, \qquad n = \left\lfloor z/2 \right\rfloor \oplus (-(z \bmod 2)) . $$

So 0,−1,1,−2,2↦0,1,2,3,40, -1, 1, -2, 2 \mapsto 0, 1, 2, 3, 4. A reader that does not fold the sign bit back reads every negative number as a large positive one.

A field does not carry its number but the delta to the previous one in the upper nibble of the field header; inside a nested structure the count restarts. A reader that forgets the stack of structures reads nothing but wrong fields after the first inner structure.

Parquet: RLE and bit packing alternating

Definition levels, repetition levels and dictionary indices are stored in the RLE/bit-packing hybrid: a sequence of runs, each with a varint header hh. If hh is even, a run of h/2h/2 equal values follows, the value in ⌈b/8⌉\lceil b/8 \rceil bytes (least significant first) at bit width bb. If hh is odd, (h−1)/2(h-1)/2 groups of eight values follow, bit-packed with the least significant bit first, bb bytes per group. The bit width for values up to mm is b=⌈log2⁡(m+1)⌉b = \lceil \log_2 (m+1) \rceil.

Example (from the specification). The values 0 to 7 at b=3b = 3 pack to 88 C6 FA (binary 10001000 11000110 11111010). With a preceding run 0A 04 (five times 4), 0A 04 03 88 C6 FA gives the sequence 4, 4, 4, 4, 4, 0, 1, …, 7.

Delta encoding. With DELTA_BINARY_PACKED, the first value is stored, then per block the smallest delta δmin⁡\delta_{\min} and per miniblock a bit width; stored are di−δmin⁡≥0d_i - \delta_{\min} \ge 0. Back: xi+1=xi+δmin⁡+eix_{i+1} = x_i + \delta_{\min} + e_i.

Parquet: definition levels

A missing value takes no space. Instead each position carries a definition level dd: the number of optional or repeated fields on the path from the root that are actually present. The highest level of a leaf is

dmax⁡=number of fields on the path with OPTIONAL or REPEATED,d_{\max} = \text{number of fields on the path with OPTIONAL or REPEATED},

and a value is in the data exactly when d=dmax⁡d = d_{\max}. A page with a thousand levels can carry three values; a reader that stubbornly reads a thousand values reads into the next page.

Parquet: Bloom filter with xxHash64

A Bloom filter says “certainly not there” or “maybe there”. Parquet uses the split block filter: blocks of 256 bits (eight 32-bit words). The PLAIN encoding of the value is hashed with xxHash64 (seed 0) to hh; the upper part chooses the block, the lower part the eight bits:

block=⌊(h≫32)⋅B232⌋,biti=⌊(hmod232)⋅simod232227⌋,i=0…7,\text{block} = \left\lfloor \frac{(h \gg 32)\cdot B}{2^{32}} \right\rfloor, \qquad \text{bit}_i = \left\lfloor \frac{(h \bmod 2^{32})\cdot s_i \bmod 2^{32}}{2^{27}} \right\rfloor, \quad i = 0 \ldots 7,

with eight fixed salts sis_i. The block choice is a multiplication, not a remainder – a remainder would give the same distribution with two blocks, but not with four. What is hashed is the encoding, not the text: a 32-bit number as four bytes least significant first, a string without the four length bytes in front.

Checked. xxHash64 of the empty input is EF46DB3751D8E999, of “a” D24EC4F1A98C6E5B, of “abc” 44BC2CF5AD770999; the hash of the number 1 as INT32 is F42F94001FCB5351.

Arrow: validity bits and buffers

Arrow stores each column as a sequence of buffers: a validity bitmap, for strings and binaries an offsets buffer o0≤o1≤…≤ono_0 \le o_1 \le \ldots \le o_n, and the data. The bitmap carries one bit per row, least significant first; row ii is valid if

⌊g⌊i/8⌋2imod8⌋mod2=1,\left\lfloor \frac{g_{\lfloor i/8 \rfloor}}{2^{\,i \bmod 8}} \right\rfloor \bmod 2 = 1 ,

and string ii is the slice [oi,oi+1)[o_i, o_{i+1}) of the data buffer. A validity buffer of length zero means “all valid”, not “all missing”. The number of buffers per column depends on the whole field tree (a list brings the buffers of its child); a reader that guesses it per column shifts everything after the first nested field.

Avro: blocks, zigzag and schema resolution

An Avro file has a header with the schema and a 16-byte sync marker, then blocks: record count and byte count as zigzag varints, the packed records and the sync marker again. If the marker behind a block does not match, nothing from there on is safe; the blocks before it stay valid. Integers are zigzag-folded as in Thrift.

Records are read with the writer schema from the file; a reader schema may differ. Then the resolution rules apply: fields are matched by name (or alias), a field missing at the writer takes the reader’s default, and numbers may only be widened: int → long → float → double, string ↔ bytes. A narrowing (double → int) is incompatible and rejected when opening.

What follows

  • Assumptions. The files follow the specifications; length fields are still checked against the rest of the file (a number from the file is a claim of the file).
  • “Missing” and “empty” differ: a definition level below dmax⁡d_{\max}, a validity bit 0 or an Avro null branch give a missing value; an empty list or an empty string are present.
  • The Bloom filter can only exclude a row group, never confirm one; the condition is still evaluated on every row read.
  • Zigzag and varint make small numbers short – and every number a byte sequence of unknown length; a reader has to read it to the end before it knows where the next field starts.

How it is tested

  • Parquetprobe, Deltaprobe, Blattpfadprobe, Vorauswahlprobe against files from pyarrow; Arrowprobe against pyarrow; Avroprobe and Avroaufloesungsprobe against fastavro.
  • TheorieFDprobe recomputes the RLE hybrid example by hand, the bit widths, the xxHash64 test vectors and the PLAIN encoding for the Bloom filter.
  • Counter-probes shift zigzag, run flag and run value width, a prime of xxHash64, the block choice, the encoding of a float and the bit order of validity; all turn red.

Limits

  • Parquet: one column per leaf does not separate “structure missing” from “field missing”.
  • Arrow: maps, unions and decimals are named, not interpreted.
  • Avro: if several branches of a union match, the first wins.
