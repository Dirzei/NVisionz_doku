The common abstraction: read limits, neighbour files, values – background

Why a number from the file is a claim of the file, how to check it without overflowing yourself, and which rules apply to files a file refers to.

What it is about

All readers of the module stand on the same few building blocks: a Datenquelle (data source) with tables, a Satzkursor (record cursor) that holds one record at a time, a Wert (value) that keeps the raw bytes next to their interpretation, and a Knoten (node) tree for metadata. Two building blocks protect the reader from the file: Lesegrenzen (read limits) checks every count and every image size before an array is allocated from it, and Nachbardatei (neighbour file) decides which further files a file may name. Format detection is on the page Detection, containers on the page Containers.

A count against the rest of the file

A header names a count nn of entries of kk bytes each. Before an array for nn entries is allocated, it must be certain that that many bytes still follow: nk≤rn\,k \le r, with rr the rest of the file. The product nkn\,k must not be formed for this. Both numbers come from the file; with n=230n = 2^{30} and k=240k = 2^{40} the product is 2702^{70} and overflows 64 bits – the result can be a small number, and the check would pass. Equivalent and without the product is

n≤⌊rk⌋,n \le \left\lfloor \frac{r}{k} \right\rfloor ,(1)

because for integers nk≤r⟺n≤r/k⟺n≤⌊r/k⌋n\,k \le r \iff n \le r/k \iff n \le \lfloor r/k \rfloor. On the boundary nk=rn\,k = r exactly nn entries pass, at r−1r - 1 no longer. Three edge rules come on top: a negative count is always wrong, an entry size of 0 counts as 1 byte (otherwise one would divide by zero and every count would fit), and more than 231−92^{31} - 9 entries fit no Java array.

Image sizes

Images have a fixed upper limit of 2252^{25} pixels (about 33.5 million, an image of 8192 × 4096). Here, too, the trap is in the product: b⋅hb \cdot h with b=h=240b = h = 2^{40} gives exactly 0 in 64 bits. The sides are therefore checked individually first; after b,h≤225b, h \le 2^{25} we have bh≤250b\,h \le 2^{50}, which can no longer overflow.

b≤225h≤225bh≤225b \le 2^{25} \quad h \le 2^{25} \quad b\,h \le 2^{25}(2)

Neighbour files: only a name in the same folder

Some formats consist of several files: a shapefile of .shp, .dbf, .prj, an EnSight set of a case file and the files it names. The case file is text, and whoever writes it also decides what it points to. Without a rule, a tool that "only reads" would open any file on the machine. The rule: a single name, no path separator (not that of the other operating system either), no colon (drive or data stream), neither . nor .., no null byte, not absolute – and the resolved file must be a regular file in the same folder. The check is made on the resolved path, not on the name, because a harmless name can point elsewhere through a symbolic link.

External links in HDF5 have their own, configurable rule with four levels; its default is exactly this one.

Values, byte order mark, metadata tree

A text file may start with a byte order mark. It arrives in two ways: read correctly as the character U+FEFF, or – if the file was read as Latin-1 – as the three characters ï»¿ (the bytes EF BB BF). Both forms are recognised and removed.

The metadata tree is walked depth-first with a node before its children, so that a search for all tables reproduces the order of the file. Two findings are equal if key and values are equal – also when a value is itself an array; the comparison is deep for that. A column is found by name regardless of case; a missing one is reported together with the names that exist.

What follows

  • Assumption: the file size is known before reading. For streams without a length the limits do not apply; only the fixed decompression limit of the compression module remains.
  • A broken or malicious file cannot make the reader allocate more memory than the file itself is large (up to a fixed factor per entry) – whatever the header says.
  • The neighbour-file rule is deliberately stricter than necessary: a set that names files in subfolders is rejected rather than half read. About one in nine random eight-byte names already contains one of the four forbidden characters.

How it is checked

  • TheorieFEprobe: the boundary nk=rn\,k = r and r−1r - 1, the overflow 230⋅2402^{30} \cdot 2^{40}, 240×2402^{40} \times 2^{40} pixels, all rejections of the neighbour-file rule on real files in a temporary folder (among them a symbolic link to the outside), the two forms of the byte order mark, depth-first search and deep comparison.
  • Boeswilligprobe and Sauberabweisungsprobe: corrupted files of all formats; none may cause a crash or a foreign exception.
  • Recalculation: docs/theorie/rechnung/fileformats_grundlagen.py (equivalence of (1) with nk≤rn\,k \le r on 200,000 random cases, the two overflows).

Limits

  • The limits bound memory, not computing time: a file naming many small, valid entries is read completely.
  • A link can be changed between check and opening; the rule does not protect against an attacker writing at the same time.
