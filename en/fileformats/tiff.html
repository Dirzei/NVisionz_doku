TIFF – background

A directory of fields instead of a fixed header: byte order, field values in the field or behind it, the two predictors and the colour interpretations WhiteIsZero, CMYK and YCbCr.

What this is about: a format without a normal case

TIFF describes an image through a directory (IFD) of fields: tag, type, count, value. Width, bit depth, compression, colour interpretation, position of the strips – all are fields, and every combination is allowed. The reading work therefore lies less in unpacking (see Compression) than in interpreting the fields correctly.

Byte order and field values

The first two bytes say how every number of the file is read: II least significant byte first, MM most significant. This also applies to 16-bit samples; the same values stand byte-swapped in the two variants and must come out the same.

A field occupies n⋅wtn \cdot w_t bytes with the width wtw_t of its type (BYTE 1, SHORT 2, LONG 4, RATIONAL 8 …). If nwt≤4n\,w_t \le 4, the value stands in the last four bytes of the field, otherwise an offset. A SHORT with two entries is therefore inside, one with three is not. Signed types (SBYTE, SSHORT, SLONG, SRATIONAL) are sign-extended; a rational is numerator over denominator.

Predictor 2: horizontal differences

With Predictor = 2 the file holds instead of the sample xix_i the difference to the previous value of the same channel, modulo 2b2^b:

di=(xi−xi−k)mod2b,xi=(di+xi−k)mod2bd_i = (x_i - x_{i-k}) \bmod 2^b, \qquad x_i = (d_i + x_{i-k}) \bmod 2^b(1)

with kk the number of channels per point. The computation runs over samples, not bytes: for 16 bits with 16 bits and in the file's byte order. Computed bytewise it happens to be right at 8 bits and produces stripes at 16 bits.

Predictor 3: floating-point numbers

Neighbouring floating-point numbers differ in almost all bytes even when they lie close together: sign, exponent and upper mantissa bits agree, the lower ones are noise. Predictor 3 therefore, when writing, re-sorts a row of NN values of ww bytes each by byte position – the most significant byte of all values first, independent of the file's byte order –

u[jN+i]=Bytej(xi),j=0 (most significant)…w−1u[j\,N + i] = \text{Byte}_j(x_i), \quad j = 0 \text{ (most significant)} \ldots w-1(2)

and then forms bytewise differences with the distance kk (channels per point). Reading runs the other way: first the sums with distance kk, then join the byte positions, and for II finally reverse each value.

Until 2026-10-19 the reader computed the differences with distance one. For one channel this is the same; floating-point images with three channels came out wrong. Corrected while writing this page.

Colour interpretation

WhiteIsZero (0) inverts: the value vv means the brightness (2b−1)−v(2^b - 1) - v.

CMYK (5) is subtractive, and multiplicatively so: two colour layers act one after the other, of what the first lets through the second takes its share. With components in [0,1][0, 1]:

R=(1−C)(1−K),G=(1−M)(1−K),B=(1−Y)(1−K)R = (1 - C)(1 - K), \quad G = (1 - M)(1 - K), \quad B = (1 - Y)(1 - K)(3)

For C=50/255C = 50/255, K=20/255K = 20/255 this gives 189; the obvious additive computation 1−C−K1 - C - K gives 185.

YCbCr (6) depends on two fields with defaults: YCbCrCoefficients (LR,LG,LB)(L_R, L_G, L_B), default (0.299;0.587;0.114)(0.299;\ 0.587;\ 0.114), and ReferenceBlackWhite, default black 0 and white 255 for Y, zero point 128 for Cb and Cr. From the definition Y=LRR+LGG+LBBY = L_R R + L_G G + L_B B, Cb=(B−Y)/(2−2LB)C_b = (B - Y)/(2 - 2L_B), Cr=(R−Y)/(2−2LR)C_r = (R - Y)/(2 - 2L_R) it follows backwards

R=Y+(2−2LR)Cr,B=Y+(2−2LB)Cb,G=Y−LBB−LRRLGR = Y + (2 - 2L_R)\,C_r, \quad B = Y + (2 - 2L_B)\,C_b, \quad G = \frac{Y - L_B B - L_R R}{L_G}(4)

Green is computed from the unclamped RR and BB; clamping first gives a different green at saturated places.

What follows

  • A TIFF reader cannot "skip" a field: every field that changes the interpretation must be known or named. Unknown compressions and colour interpretations are reported, the header is read anyway.
  • Both predictors are lossless and only a reordering for the packer; a wrongly undone predictor still delivers valid numbers.
  • The computation (4) is the same as for JPEG (T.871), only with selectable coefficients.

How it is checked

tiff.TheorieFCprobe builds uncompressed TIFF files with one strip in II and MM, writes the predictors forward itself according to the description (also floating point with three channels) and computes the colour interpretations from the formulas on this page. The foreign anchors from Pillow and libtiff stand in Tiffprobe.

Limits

  • Predictor 2 is built for 8 and 16 bits, predictor 3 for depths from 16 bits in whole bytes; other depths are reported and skipped.
  • Floating-point values are clamped to [0,1][0, 1] for display; the raw values remain reachable through the fields.
  • If the pointer to the next directory is missing entirely or in part, the chain ends there with a finding. Until 2026-10-25 the pointer was checked with the width of the field count (two instead of four bytes): half a pointer aborted reading, a missing one cost the last field.
  • The compressions (LZW, PackBits, Deflate, CCITT, JPEG in TIFF) are not the subject of this page; LZW and PackBits are on the page Compression, the scope in the comparison.
