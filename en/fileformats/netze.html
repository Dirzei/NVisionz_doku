Meshes and geometry: formats without a signature, byte order, reference systems – background

How to recognise a format that has no signature, namely by its size; how a check number reveals the byte order; why node numbers are not indices; and how eastings and northings turn back into longitude and latitude.

What it is about

Mesh formats come from solvers, and many were written before anyone thought of signatures. Binary STL and PLOT3D carry none; Gmsh and EnSight carry one but reveal the byte order only through a number; a shapefile stores coordinates in a reference system described in a second file. This page derives the rules by which the reader decides.

STL: the size is the signature

Binary STL consists of an 80-byte header text, a count nn in four bytes and 50 bytes per triangle (normal and three corners as twelve floats, two attribute bytes). Hence the condition

G=84+50n.G = 84 + 50\,n .(1)

Many binary writers put the word solid at the start of the header text – the keyword of the text version. That is why (1) decides first and the word only afterwards. A text file cannot meet the rule by chance: four printable characters at positions 80 to 83 make a number of at least 2292^{29}; the file would have to be larger than 25 GB.

PLOT3D: try every layout

PLOT3D has neither a signature nor a header with a version. A file may carry Fortran record marks or not, hold one or several blocks, have two or three dimensions, be a grid, a solution or a function, single or double precision, with or without IBLANK, and in either byte order – 26⋅3=1922^6 \cdot 3 = 192 layouts in total. The reader tries all of them and accepts only one whose expected size matches the file exactly: if even one byte is left over, the layout does not fit.

With Fortran record marks the check is especially sharp: the length stands before and after every record, both must be equal and match the expected length. If several layouts fit nevertheless, the reader says so.

Gmsh: the check number reveals the byte order

Behind the header line of a binary Gmsh file stands the integer 1. Read in the wrong order it gives 224=16,777,2162^{24} = 16{,}777{,}216. The reader reads it, and if it is not 1, switches the order and checks that 1 comes out then – otherwise the file is broken.

Node numbers are not indices

Gmsh, EnSight and UFF allow node numbers with gaps, and elements refer to these numbers. A reader that uses the number as an array index reaches the wrong node. In EnSight the geometry header states whether the node count is followed by the numbers first (node id given) or directly by the coordinates; connectivity then counts nodes in coordinate order, one-based – even when the numbers start at zero.

Reference systems: back to longitude and latitude

The coordinates of a shapefile are in the reference system the .prj describes as WKT. For the transverse Mercator projection (UTM, Gauss-Krüger) the reader uses Krüger's sixth-order series in the third flattening n=f/(2−f)n = f/(2 - f), via the conformal latitude

τ'=τ1+σ2−σ1+τ2,σ=sinh⁡(eartanh⁡eτ1+τ2),τ=tan⁡φ.\tau' = \tau \sqrt{1 + \sigma^2} - \sigma \sqrt{1 + \tau^2}, \qquad \sigma = \sinh\left(e \operatorname{artanh} \frac{e\,\tau}{\sqrt{1 + \tau^2}}\right), \quad \tau = \tan\varphi .(2)

Mercator (also on the sphere), Lambert conformal conic and geographic systems are supported as well. Prime meridian, angular unit and linear unit are taken from the WKT; there is no datum shift.

What follows

  • Assumption: the file is complete. A truncated binary STL or PLOT3D file is not recognised as its format but rejected – intentionally, because a partly fitting layout would be a guess.
  • A size condition is as strong as a signature when a chance match is impossible at realistic sizes; for STL and PLOT3D this is the case.
  • The byte order is measured from the file, not assumed; the same check reads the same meshes in both orders.

How it is checked

  • Stlprobe: size rule, text and binary versions equal, the word solid in the header of a binary file.
  • Plot3dprobe: all sixteen layouts of a grid round-trip, one byte too many, a bent record mark.
  • Gmshprobe, Ensightprobe: third-party anchors in both byte orders, node numbers from zero.
  • Bezugssystemprobe: fifteen codes with nine points each against a reference implementation of the map projections.
  • Recalculation: docs/theorie/rechnung/fileformats_netze.py.

Limits

  • Reference systems without datum shift: coordinates in a datum other than WGS 84 stay in it.
  • Gmsh auxiliary quantities, EnSight multiple time steps and element types not in the table are named, not read.
  • EnSight variables are placed per part on its nodes and elements, empty description lines are allowed, a number that is none is rejected. Until 2026-10-25 the first part read the values of all parts, and an empty description shifted the file by one line.
  • A .prj that cannot be interpreted, even with text where a number belongs, leaves the shapefile readable; the reference system stays uninterpreted and is reported as such.
