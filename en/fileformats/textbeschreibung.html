Format description, matching loop and Java skeleton – background

How a recognised structure becomes a format description .fmt, why it describes the writer rather than the reader, how the matching loop repairs it against the round trip without memorising, and how a Java reader is generated from it.

A description of the writer

A .fmt describes what the writing routine emits, not what a reader may accept. The difference is field widths, separators and line breaks – details that are superfluous for reading. Only with them is reading the description run backwards and writing it run forwards, and the byte-identical round trip becomes a property of the description rather than a test result (the same idea as DFDL's unparse). Between the two directions sits the value space: the values read, without formatting, with names as paths (0.nx, 1.nx) because a repetition uses the same name several times.

A closed vocabulary of eight words

Wordmeaning
zahlan integer with width (count fields)
werteas many numbers as an expression says, in one number form, so many per line
markeliteral text that must be there – with its columns
wiederhole … endethe body as often as a count expression says
text, wort, zeiletext by columns, up to white space, the whole line – each preserved
wahlfreia section that may be present; on failure the read position is reset

The vocabulary is closed. The goal is a hand-written Java reader, not an interpreter; a format that cannot be expressed is therefore no failure but the normal case at the edge. A language meant to capture every format grows into a worse Java.

In the body of a wiederhole loop that counts lines, each pass holds exactly one line. A draft therefore writes the values of one line there (anzahl equal to proZeile) and no second counter; the value count of the whole block belongs only in a block whose count field counts the values.

Number forms: E, N, D, F, I

The form belongs to the description because it describes the writer. E15.7 here explicitly means the C notation: printf("%15.7E") gives 1.2340000E+05, mantissa between 1 and 10. Fortran's E15.7 gives 0.1234000E+06 instead – the same name, different bytes. The Fortran normalisation therefore has its own letter:

x=m⋅10e,e=⌊log10⁡|x|⌋+1,m=x⋅10−e∈[0.1,1)x = m\cdot 10^{e},\qquad e = \lfloor \log_{10}|x| \rfloor + 1,\qquad m = x\cdot 10^{-e}\in[0.1,\,1)

If the mantissa rounds to 1 at d digits, that is exactly the form N is meant to differ from; the exponent then moves by one: 999999.9 with three digits becomes 0.100E+07, not 1.000E+06. D writes Fortran double precision 1.2340000D+05, F fixed point, I integer.

Count expressions: integer and without silent rounding

The number of repetitions is an expression over previously read fields, such as nx*ny*nz*3. Allowed are numbers, names, + − * /, unary minus and parentheses, with the usual precedence. Arithmetic is integer, and a division must come out exactly: a count expression that yields 3.5 is an error and stays one. Truncating would turn a wrong format into a plausible number. Overflow is reported as well. A generated Java skeleton takes the expression literally and warns at the spot: Java's / truncates.

The matching loop: generate, compare, locate, repair

The loop can converge only because the round trip locates: for every byte the active statement is known, and on a read error the exception names the line of the description. “Does not fit” would be no information; “from byte 137, statement zahl nx” is. Repairs are only named interventions that carry a falsifiable claim: field width, values per line, number shape (E/D/N, digit count) and count (the expression times or divided by 2..8). None of them changes the length of the description.

The quality measure has two terms and a strict order. Let r be the bytes generated correctly from the start and ℓ the length of the description. Description A is better than B if

rA>rBor(rA=rBandℓA<ℓB).r_A > r_B \quad\text{or}\quad \bigl(r_A = r_B \;\text{and}\; \ell_A < \ell_B\bigr).

Without the second term every search reliably finds the description “write exactly this byte sequence”: it generates the file completely and has recognised nothing. The shortest description that generates the file is the best guess at a writing routine, because writing routines are short (the idea from PADS). There is no weighting: an exchange rate between bytes and statements could only be invented. The more effective safeguard is a second file from the same writer: a repair is accepted only if it does not make the second file worse.

The Java skeleton

A .fmt becomes a Java reader that depends only on the JDK and carries its reading helpers (Fortran numbers, column positions) with it. Names in the description are not chosen with Java in mind; a field may be called class, n-punkte or 3d. Renaming happens character by character and visibly: first every character is checked, then the start, so that 3d and 4d do not both become _d; the old name stays beside it as a comment.

Passing on without content: the anonymiser

For structure work what matters is the column position, field width and shape of a number, not its value. So every digit is replaced by a digit and nothing else: the file keeps its length, every token its columns and its kind. Replacement is random without a stored mapping; there is no way back.

What follows

  • Because the description describes the writer, every gap in understanding is measurable as a byte difference; a reader formalism could skip over it.
  • The loop invents no structure: it changes details, adds no statement and drops none. What could only be fixed by new statements (another separator, one more blank line) it presents to a person.
  • A count expression is integer or wrong; wrong descriptions thus surface early instead of yielding a plausible count.

How it is tested

Beschreibungsprobe (forwards and backwards, byte-identical from a hand-written description), Abgleichprobe (quality measure, location, repairs, second file), Geruestprobe (the generated code compiles against an empty class path and reads the sample) and TheorieFBprobe (ids [TD22-FB-T9] to [TD22-FB-T12]): N form with moving exponent, exact division, the order of the quality measure, name collision and length preservation.

Limits

  • Formats that are a program (macros, nested texts) cannot be captured with eight words; a reader is written by hand for them.
  • The second quality term has no effect in the loop as long as no repair changes the length.
  • The loop does not store its result; whoever wants to keep it saves it.
