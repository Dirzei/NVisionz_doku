Measurement data: conversion, byte order, time axes – background

How the raw value of a control unit becomes a physical value (MDF 3 and MDF 4), what the byte order of a channel depends on, why TDMS segments are not independent, and how a UFF data set interprets its column of numbers.

What it is about

Measurement formats rarely store the physical quantity. The record holds the raw value – a uint16 of a control unit – and a conversion rule next to it turns it into degrees Celsius or bar. The rule is part of the file; a reader that skips it delivers raw values that look like measurements. Likewise the time axis, the byte order and the number of values per point are not always stored with the value itself but elsewhere in the file. This page derives the rules the reader applies; the format overviews are in the comparisons MDF 3, MDF 4, TDMS and UFF.

Linear and rational conversions

The linear conversion is, in both versions,

y=P1+P2x,y = P_1 + P_2\,x ,(1)

with the offset first and the factor second. Only the number of the type differs: in MDF 3 it is 0, in MDF 4 it is 1 – and 1 means "table with interpolation" in MDF 3, 0 means "identity" in MDF 4. Mixing the two numberings silently drops a linear conversion. Swapping the parameters turns P1=100P_1 = 100, P2=0.5P_2 = 0.5, x=4x = 4 into 400.5 instead of 102.

The rational conversion (MDF 3 type 9, MDF 4 type 2) is a quotient of two second-degree polynomials, y=(P1x2+P2x+P3)/(P4x2+P5x+P6)y = (P_1 x^2 + P_2 x + P_3)/(P_4 x^2 + P_5 x + P_6). MDF 3 type 6 is called "polynomial" but is also a fraction, namely a linear-fractional function of the shifted quantity u=x−P5−P6u = x - P_5 - P_6:

y=P2−P4uP3u−P1.y = \frac{P_2 - P_4\,u}{P_3\,u - P_1} .(2)

It is the inverse of the linear-fractional sensor characteristic u=(P2+P1y)/(P4+P3y)u = (P_2 + P_1 y)/(P_4 + P_3 y): solving for yy gives exactly (2). A zero denominator gives no value (NaN), not infinity – the characteristic has no preimage there.

Exponential and logarithm

MDF 3 has two more types with seven parameters and two branches each. For P4=0P_4 = 0

yexp⁡=1P2ln⁡(x−P7)P6−P3P1,ylog⁡=1P2exp⁡(x−P7)P6−P3P1,y_{\exp} = \frac{1}{P_2} \ln\frac{(x - P_7)\,P_6 - P_3}{P_1}, \qquad y_{\log} = \frac{1}{P_2} \exp\frac{(x - P_7)\,P_6 - P_3}{P_1} ,(3)

for P1=0P_1 = 0 the numerator is P3/(x−P7)−P6P_3/(x - P_7) - P_6, and P4,P5P_4, P_5 take the place of P1,P2P_1, P_2. What is computed is exactly what the format description prescribes: type 7 takes the logarithm, type 8 the exponential. If neither P1P_1 nor P4P_4 is zero, the rule is undefined and the reader returns NaN.

Tables and ranges

A value table with interpolation interpolates linearly between the points (xi,yi)(x_i, y_i) and holds the edge value outside. Without interpolation the versions differ: MDF 3 takes the lower point (on a point its own value), MDF 4 the nearest, with the midpoint (xi+xi+1)/2(x_i + x_{i+1})/2 going up. Ranges are half open in both versions,

$$ x_{\min} \le x < x_{\max} , $$(4)

so that a value exactly on the border of two adjacent ranges belongs unambiguously to the upper one. A value in no range gets the default at the end of the list; in MDF 4 the default may itself be a conversion.

Not computed: the formula as text in MDF 3 (type 10), the algebraic conversion (type 3) and the bit-field table (type 11) in MDF 4. The raw value stays, and the rule is listed in the findings.

“Text to text” (MDF 4, type 10) carries its references in pairs: input ii at position 2i2i, output ii at position 2i+12i+1, the default text last.

An unsigned 64-bit number from 2632^{63} on fits no signed integer; in both versions it comes out as a floating-point number, rounded as a 53-bit mantissa must – never as a negative number.

Byte order per channel

In MDF 3 the byte order of a channel depends on the data type and on the file header: types 0 to 3 follow the header, types 9 to 12 are always most significant first, types 13 to 16 always least significant first. Two channels of the same record can lie in different orders; fixing the order once for the file reads 258 as 513.

TDMS: segments and the 1904 epoch

A TDMS file is a sequence of segments. What a segment does not state continues from the previous one; the raw-data index 0 of a channel means "as last time" – type and count are not stored at all. The reader therefore keeps a state per channel across all segments.

Timestamps consist of whole seconds since 1 January 1904 and a fraction in units of 2−642^{-64} s. The distance to the 1970 epoch is 2,082,844,800 s, i.e. 24,107 days; mixing up the epochs is 66 years off, and the date still looks plausible. The upper 32 bits of the fraction suffice, since 2−322^{-32} s is less than a nanosecond.

t=1904-01-01+s+⌊f/232⌋232t = 1904\text{-}01\text{-}01 + s + \frac{\lfloor f / 2^{32} \rfloor}{2^{32}}(5)

UFF: how many numbers belong to a point

A UFF data set 58 carries a column of numbers that cannot be interpreted on its own. How many numbers belong to a point is given by two fields that have nothing to do with each other: the abscissa spacing (even: the x values are not in the file and are computed from start and step) and the ordinate type (complex: two numbers per value).

m=[uneven]+{2complex1realm = [\text{uneven}] + \begin{cases} 2 & \text{complex} \\ 1 & \text{real} \end{cases}(6)

Five points with ten numbers are therefore either uneven and real or even and complex – two files that look the same and must be read completely differently.

What follows

  • Assumption: the rule in the file is correct. The reader evaluates it; whether it matches the sensor it cannot know.
  • A physical value is only as good as its conversion: where a type is not computed, the raw value stands with a finding, never a guessed value.
  • Half-open ranges and the midpoint "going up" make the assignment unambiguous even when range borders lie exactly on measured values – the normal case for integer raw values.

How it is checked

  • mdf.TheorieFEprobe: every computed type of both versions with hand-calculated target values (including both branches of exponential and logarithm, zero denominator, the border of a half-open range, the midpoint between two points).
  • Mdfprobe, Mdf3probe: real files of a third-party writer, byte order per type and header, conversions within a file.
  • Tdmsprobe, Uffprobe: segment inheritance, epoch, abscissa and ordinate type on third-party anchors.
  • Recalculation: docs/theorie/rechnung/fileformats_messdaten.py.

Limits

  • Formulas as text and bit-field tables are not evaluated.
  • In MDF 4 the range border is always half open; whether integer channels require a closed upper border according to the format description is not decided by the available third-party anchors.
  • TDMS times are rounded to nanoseconds; finer fractions are lost.
