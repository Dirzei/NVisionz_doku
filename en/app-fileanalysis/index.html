envisionz-app-fileanalysis

Reading and understanding arbitrary files: bytes, text structure, documents and images

Overview of the app, as of 6 October 2026. A strictly read-only view with automatic signature detection: what kind of file is this, and what is in it?

What the app is for

Next to the result files of the programs there are files of unknown origin: settings files with an unknown extension, measurements as .dat or .bin, output of older programs, documents. The question “what is this?” is answered by signature detection; the question “and what is in it?” is answered by the app.

It shows a file as it is. There is no write path, not even as a disabled option: a writing branch that once exists will one day be used. That is why a probe searches the view’s source for every write call. The file is also not kept open; each page opens, reads and closes, so that on Windows the program that produces the file does not find it locked.

How to look through a working folder, interpret bytes, have a text structure detected and view documents is shown on the How to use page.

What it can do

Byte view with interpretation

The file is read page by page (1024 bytes), not as a whole: loading a file of several gigabytes to show 512 bytes would not be a viewer. From the jump mark on, the interpretation shows the same bytes simultaneously as byte, short, int, long, float and double, little and big endian side by side. That is how one cracks an unknown format: one sees at once which interpretation gives plausible magnitudes and which nonsense. NaN and infinity are written out, because they are the most common sign of a wrong interpretation.

Cards of the vertical bar

  • Search: text (UTF-8) or byte sequence (89 48 44 46, 0x894844); the location line says what was actually searched for. “Next” starts from the beginning at the end and says so. Hits on block boundaries are found.
  • Interpretation: the bytes from the jump mark in all interpretations
  • View: colouring on or off

Record grid and colours

  • With Fortran record markers, the record boundaries are computed and written above the page; if the chain breaks, the grid stops rather than guessing.
  • Record starts green, search hits yellow; everything else black, so that colour means something.

Line view: recognised text structure

Text files are organised by their structure and shaded in colour, with the rule beside it. The colouring is deliberately the reverse of what one expects: what is recognised lies in pale tones, what is unknown stands out. Three levels stay distinguishable: “400 lines have the same form”, “line 11 says 400, and there are exactly 400”, and merely measured rules. The colour is mixed into the background of the current theme, so light and dark interfaces read equally well.

  • seven cards in the rail: instructions, outline (the rule tree), finding (measured on this file), rule (the claim about it), draft (the generated format description including a round trip), analysis chain (the detection step by step) and anonymise
  • two coverage bars at the bottom, for lines and for values
  • at most 4 MB are recognised; beyond that the beginning is taken and this is said
  • When a file is handed to the app, the content decides which tab opens, not the extension; choosing in the working folder keeps the tab in front: measurement files are often called .dat and are text, a .txt sometimes is not

Documents and images in the data tab

For document and image formats the data tab shows the outline on the left and the result on the right. Detection is by content, not by extension.

FormatWhat the app shows
PDFPages and outline; the drawn page with the original fonts, lines, areas and images. It states explicitly that it is not the whole page and names what is missing (gradients, patterns, transparency). Zoom redraws instead of enlarging pixels. A scan is shown as a scan, a page with visible text as a typeset page.
PPTXSlides are redrawn: shapes, fills, gradients, lines, images, text, rotation, groups, tables with merged cells, background, autofit. What is not drawn or only approximated (charts, SmartArt, effects) is listed in the finding.
PostScript, EPSPages, outline (producer, drawing area, paths, texts and pixel patterns per page) and drawn page; the finding says it is an evaluation and not a full interpreter, and names skipped operators.
JPEG 2000 (.jp2, .j2k)the image, the outline (shape, size, colour space, components, wavelet, levels, tiles) and a footer. The colour of a bare code stream is guessed, and the app says so.
HDF4, GIFOutline, plus a structure card with name, kind, number of children and every property on its own line; for HDF4 the table list with table.
ImagesImage view with fit, mouse-wheel zoom (factor 1.15, limits 0.05 and 20), dragging, chessboard for transparency.

Extracting elements

An element can be extracted from the menu. For a PDF the root yields the text of all pages, “Page n” only that page; the text goes into one file (explicitly UTF-8), the images into a folder, as PNG. An image that could not be converted (for example CCITT or JBIG2 in a certain form) is named rather than skipped. For PPTX the embedded images come out unchanged. This is the explicitly invoked write path of a tool; the file read is never modified.

Command line and hand-over

Two tools in the package cmd.fileanalysis: Analyse and Anonymisieren (anonymise), with usage help (--hilfe) and return values. Anonymisieren writes a byte-length-preserving copy to a target file and never over the source. In addition the Dateikunde tool from framework-core answers the same “what is this” on the command line, with the same analysis as the app: two versions would drift apart.

The byte view registers as a file viewer in the framework’s service registry; other apps, for example the HDF5 reader, can hand it a file without knowing it. On closing, the app deregisters again.

Data and formats

  • Reads: any file; signatures, text or binary, Fortran record markers, PLOT3D text and the document and image formats named above are recognised.
  • Writes: only on request and always into a new file: the anonymised copy, the saved analysis chain, the extractions (text, images) and the command-line tools. The file read stays unchanged.
  • State: not saved, not even the working folder; after a restart you choose it again.

What it builds on

  • framework-core – the file analysis itself (signatures, text/binary, structure, record markers), read-only; interface and command line share it.
  • framework-fileformats – text-structure detection, PPTX layout and shapes, image readers, JPEG 2000 detection.
  • framework-pdf – PDF, PostScript and JPEG 2000 decoding, including the page painter for fonts, paths and images.
  • framework-viewer – building blocks for viewers; the app lists the module on its class path.
  • framework-swing – vertical bar with cards under 360 px, icons with tooltips.
  • framework-api – registration as an app and as a file viewer.

Status and limits

The app is usable in all the views named; every class is named by a probe. The probes run headless and create their templates themselves, for example the PLOT3D file with String.format and not with the writer they check. Colour distances are measured in both themes; zoom, text layer and extraction on built PDF files; JPEG 2000 on a standard test vector and a JP2 file built for the purpose; PPTX on a presentation written by a third-party library and on a slide built by hand. In addition, probes with maliciously malformed input send PDF and JPEG 2000 through the view.

Deliberately limited: the views are evaluations, not complete renderings. For PDF, gradients, patterns and transparency are missing; for PPTX charts, SmartArt, bullets, indents, line and paragraph spacing; PostScript zooms without redrawing. Font programs are not extracted. Searching backwards and colouring all hits on the page are still missing.
