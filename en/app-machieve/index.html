m-ACHIEVE: real-gas flow simulation for nozzles and cascades, as an app and on the command line

Overview of the app, as of 29 September 2026. A flow solver for compressible, viscous and reacting flows in two dimensions and axisymmetric, with a real-gas equation of state, turbulence and combustion; ported from a Fortran 77 code of its own.

232Java source files in three packages (solver core, command line, interface)
5solution modes, from the explicit Euler step to the non-dimensional pipeline
3chemistry mechanisms (H2-O2, global methane, methane with 16 species)
3turbulence models: k-ω, SST, k-ε
726controls, 94 % of them unambiguously addressable
27pages of manual as PDF, per language

What the app is for

For nozzles, diffusers and blade cascades simple figures of merit are not enough: shocks, boundary layers and, in combustors and rockets, chemical reactions determine the flow. That calls for a flow solver that solves the conservation equations of gas dynamics on a mesh. m-ACHIEVE is such a solver, for two-dimensional and axisymmetric flows, and it also handles gases at high pressure (real gas), where the ideal gas law is noticeably off.

The solver is a Java port of the original Fortran 77 code, with an expanded architecture: the computational core is free of user-interface libraries, so it also runs without a screen and as a standalone program. The same programming interface serves the command line and the interface, so that both behave alike. The app is aimed at fluid-dynamics engineers who want to prepare a case, run it and evaluate it.

What it can do

Numerics and models

Fluxes and order

  • flux schemes Roe, AUSM and Van Leer
  • MUSCL reconstruction with five limiters, among them Albada
  • Roe averaging for real gas (frozen equation of state or Vinokur-Liu projection)

Time integration

  • explicit: Euler, Runge-Kutta of 4th and 5th order, local time step for steady cases
  • implicit: Beam-Warming with ADI (Liu), Roe symmetric (Gauss-Seidel)
  • dual-time stepping for unsteady cases

Physics

  • viscosity: laminar Navier-Stokes with Sutherland viscosity, no-slip wall adiabatic, isothermal or with heat flux, moving wall
  • turbulence: k-ω (Wilcox), SST, k-ε
  • gas model: ideal gas, real gas AGA8-DC92 or GERG-2008
  • rotation and swirl, mixing plane, multi-block meshes

Combustion

  • species transport with the mass fractions summing to one
  • mechanisms: H2-O2, global methane (Westbrook-Dryer), methane with 16 species
  • box solver for the chemistry, explicit or stiff (RODAS4), with element balance

Boundary conditions and meshes

A catalogue of boundary conditions: inviscid and no-slip walls, inflow and outflow boundaries (among them in the Riemann-invariant form of the Fortran code), far field, jet boundary, periodic boundaries, block interfaces and mixing plane. Meshes are read as multi-block meshes; an editor in the interface assigns the boundaries their conditions. Full mesh generation is not part of the app.

Diagnostics

Mass flow per block and in total, a thrust report on every outflow boundary (mass flow, thrust from momentum and pressure against ambient pressure, mean quantities, effective velocity, specific impulse; per metre of depth for planar flow, with 2πr for axisymmetric), and a convergence history of the residuals. A restart from the last state is bit-identical.

The interface: six tabs

  • Test case: scans directories for cases and shows their description
  • Mesh: the mesh with block statistics, editor for boundary conditions, card for the initial field
  • Setup: the input files as a form (read-only)
  • Run: solver choice with a card per mode (standard, non-dimensional, combustion), advanced settings, real-time log; the solver runs in the background
  • Convergence: residuals over the iterations, semi-logarithmic, drawn along during the run
  • Results 2D: contours, isolines and vectors, block boundaries joined, with live updating; plus a view for restart files

Command line

Two entry points without the interface, both through the same programming interface: the standard path (SI units) and the non-dimensional pipeline following the convention of the Fortran code. --help lists all switches; the manual covers 21 switches and 14 keys of the configuration file.

# standard path (SI units)
java -cp bin cmd.machieve.CfvnSolver <testcase-directory> -S:MUSCL_ALBADA_RK1 \
     --cfl 0.5 --max-iter 5000 --output-every 500 --output-dir out/

# non-dimensional pipeline (cases for validation against the Fortran code)
java -cp bin -Dmachieve.flux=roe de.machieve.framework.nondim.NondimMachievePipeline \
     <directory> <iterations> <output> <every-n-steps> [explicit|implicit]

Settings that used to act as hidden system properties are available as a typed configuration per run (SolverSettings); two parallel runs with different values are isolated from each other for the migrated settings.

Data and formats

  • Reads: cases in the format of the Fortran code: achieve.inp (control), gascomp.inp (gas composition), .grd (mesh) and .blk (block structure); plus a configuration file with precedence command line over configuration file over input file. Result fields are read through the shared VTK reader.
  • Writes: result fields as VTK (with a fixed character set and uniform line endings, so that the same calculation gives the same file on two computers) or Tecplot, the convergence history as CSV, restart files (.machstate, bit-exact).
  • Manual: HTML help and PDF in German and English; topics range from a quick start through solvers, fluxes, boundaries, turbulence and combustion to troubleshooting.

What it builds on

  • framework-thermo – the equations of state (ideal gas, AGA8-DC92) with the derivatives for Roe averaging; GERG-2008 is addressed through the same interface. They were moved from the app into the framework on 28 September 2026, verifiably bit-identical.
  • framework-math – the stiff method RODAS4 for the chemistry.
  • framework-chart – contours, isolines and colour scales of the results view; the app no longer draws its own contours.
  • framework-fileformats – the one shared VTK reader (header check, line endings, optional table line).
  • framework-swing – interface conventions, vertical toolbars with cards, charts.
  • framework-api – registration as an app and saving the tab state.

Status and limits

About 95 % of the Fortran code by size has been carried over; deliberately not carried over are MPI, a multigrid method, a Krylov solver and the implicit turbulence iteration. Known errors of the Fortran code were not ported along but rewritten correctly. The physics is checked on executable cases: Ringleb flow, bump channel, shock reflection, flat plate against Blasius (deviation from isentropic theory under 0.13 %, grid convergence to about 2 %), Couette, Poiseuille, Falkner-Skan and a compressor cascade whose result on the coarse mesh matches that of the Fortran code. H2-air combustion keeps the sum of the mass fractions to machine precision; a restart is bit-identical. On top come probes for thrust, Vinokur-Liu averaging, the heat-flux boundary condition, the enthalpy reference of the mechanisms, GERG-2008 and the stiff chemistry, each with counter-tests, as well as 58 stand-alone runners and a wiring probe of the interface.

Two conventions, deliberately side by side. The standard path computes in SI units, the non-dimensional pipeline in the convention of the Fortran code (acoustic, referred to the stagnation speed of sound); the Java convention is referred to the free-stream velocity. The same reference Reynolds number means something different in each, and there is no single conversion factor. Profile shapes are comparable, absolute boundary-layer thicknesses only after conversion.

Further limits: the 16-species methane chemistry is computationally expensive and becomes practical only with the coupled-implicit solver, whose building blocks exist but are not yet built into the standard solvers. The GERG model is about 3.7 times slower than AGA8. Not provided are three-dimensional geometry, LES combustion, mesh adaptation and mesh generation. Anyone changing flux scheme, boundary condition, equation of state or scaling must run the validation cases again; the residual is the reliable indicator.
