Run, Solver Loop and Results – Background

Which method runs when and on which thread: from loading a case through the start on the worker thread and the loop of the dimensionless pipeline to the results view, which reloads newly written solutions during the run.

What this is about

m-ACHIEVE computes for a long time – minutes to hours. The interface has to stay usable meanwhile, show the progress and be able to stop a run. This page shows the three paths that carry this: the run from the interface into the worker thread and back, the loop in which one step is computed, and the reloading of results. What the methods themselves compute is described in the solver manual; operation on the page Operation.

From the case to the run and back

A case is loaded on the event thread: the button in the Test cases tab hands the path to the main window, which informs the mesh, setup and run tabs in turn. The run tab reads achieve.inp for its defaults and takes the run settings run.* from testcase.properties. On start it assembles the settings of one run – switches of the interface, defaults of the case, advanced settings of the user, which win last – and writes the combustion and additional entries as achieve.jconfig only if they carry at least one entry.

The computation runs in a SwingWorker. It reads the case a second time, now completely with mesh and gas composition, and calls the solver. Every step reports through a listener that collects the values with publish; process hands them on the event thread to the log and the convergence chart. Log lines of the solver loggers and the mass flow line go through invokeLater. The final result is fetched by done, also on the event thread.

The loop of the dimensionless pipeline

The dimensionless pipeline is the path that follows the Fortran code in its scales. Before the loop it reads the case, builds the equation of state and the reference state, chooses limiter, corner treatment and initial field from deck and settings, and creates residual, time-step calculator and stepping method per block. Each step of the loop first asks whether to stop, then computes the smallest time step over all blocks and advances every block by this step. When the blocks are computed in parallel, they first freeze their border strip: each block then reads its neighbour as at the start of the step, as in the halo exchange of the Fortran code.

The residual is the root mean square change of density over all interior cells:

r2=1N∑b∑i,j(ρb,ijn+1−ρb,ijn)2.r_2 = \sqrt{\frac{1}{N}\sum_{b}\sum_{i,j}\big(\rho^{\,n+1}_{b,ij}-\rho^{\,n}_{b,ij}\big)^2}\,.

The loop has no convergence criterion: it ends after the maximum number of steps or on request. A residual that is no longer finite does not stop it either; only afterwards does nondimStatus determine whether the run was stopped, reached the maximum, or carries a residual that is not finite.

Results during the run

On start the results tab learns the output folder. When automatic reloading is switched on, a timer checks every two seconds whether a solution with a higher step number lies there, and loads it when the distance to the displayed one reaches at least the set step width. A multi-block case consists of files block<N>_…vtk; all siblings of the same output are loaded, ordered by block number. When drawing, the node values at block borders are averaged so that the contour does not jump there. After the run the tab loads the latest written solution from the result.

Limits

  • Mesh and results are read on the event thread: the mesh when a case is loaded in the mesh tab, the solution when reloading and after the run. With large cases the interface then stalls briefly; the run itself is not affected.
  • Some older classes of the solver still read their settings from the system properties. The worker thread therefore mirrors the settings of a run there before the start; two runs at the same time in the same JVM would overwrite each other there.
  • The dimensionless pipeline has no convergence criterion and does not stop on a residual that is not finite either: a run that diverges keeps computing up to the maximum number of steps. The path in SI units stops at once in this case.
