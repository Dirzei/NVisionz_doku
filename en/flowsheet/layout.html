Layered layout – background

How LayeredLayout turns a graph of blocks and connections into a readable flowsheet: breaking cycles, layers, dummy nodes, crossings, coordinates, orthogonal routes, the quality figures and how they are tested.

What this is about

A flowsheet is initially just a list: units (compressor, combustor, turbine …) and streams between them. A reader expects a picture in which the flow runs from left to right, connections cross as little as possible and lines run at right angles. Operating a drawing program by hand is out of the question when the model changes, so the layout has to be computed – and in such a way that the same model always gives the same picture.

The module strictly separates model and picture. Graph is pure topology: Node with ports (Port, fixed to a side via PortSide), Edge between two PortRefs. Every edge has a kind: PRIMARY determines the layering, SECONDARY (e.g. couplings) is fitted in afterwards. The method is the Sugiyama approach, made of steps that each solve one manageable subproblem.

Step 1: breaking cycles

Layers presuppose a direction; recycles and recuperation, however, form loops. What is needed is a set of edges that, once reversed, removes all cycles, and a small one at that (feedback arc set). The exact problem is NP-hard; the framework uses the greedy method of Eades, Lin and Smyth. It builds a node order by repeatedly

  • moving sinks (no outgoing primary edge in the remainder) to the back of the order,
  • appending sources (no incoming edge) to the front,
  • and, when neither is possible, appending the node with the largest surplus δ(v)=d+(v)−d−(v)\delta(v) = d^{+}(v) - d^{-}(v) to the front.

Every edge that runs backwards in this order counts as a feedback edge. Self-loops (source and target in the same node) take no part in the layering.

Steps 2 and 3: layers and dummy nodes

The layer of a node is the length of the longest path ending in it, counted over the primary edges (acyclic after step 1):

ℓ(v)=max(u,v)∈Eprim⁡⁡(ℓ(u)+1),ℓ(v)=0 without predecessors\ell(v) = \max_{(u,v)\in E_{\mathrm{prim}}} \bigl(\ell(u) + 1\bigr), \qquad \ell(v) = 0 \text{ without predecessors}

This is a relaxation that runs until nothing changes any more (at most number of nodes + 1 passes). The longest path gives the smallest number of layers and keeps the main chain in one row. If an edge spans kk layers (k>1k>1), k−1k-1 dummy nodes are inserted, one in each layer crossed. After that every segment connects adjacent layers, and two later problems become simple: ordering is a pure sorting problem, routing is a lane assignment in the gap between layers.

Nodes with no primary edge at all (portless units, equation nodes) stay outside the layers; they are placed at the very end.

Pseudocode – LayeredLayout.layout(graph), steps 1 to 3

for each primary edge e with source ≠ target: add e to the list primary

// 1. break cycles (Eades/Lin/Smyth)
rest ← all nodes;  head ← [];  tail ← []
while rest ≠ ∅:
    repeat while something changes:
        for v in rest: if out(v) = 0:  remove v;  tail ← v + tail
        for v in rest: if in(v) = 0:   remove v;  head ← head + v
    if rest = ∅: stop
    v ← node with largest out(v) − in(v);  remove v;  head ← head + v
order ← head + tail
for each edge e: if rank(source) > rank(target): reversed[e] ← true

// 2. layers: longest path
layer[v] ← 0 for all v
while something changes and passes ≤ number of nodes+1:
    for each edge (a,b) in drawing direction:
        if layer[b] < layer[a] + 1: layer[b] ← layer[a] + 1
free ← nodes without primary edge and without layer hint
layer hints (LayoutHints) overwrite layer[v]

// 3. dummy nodes
for each edge (a,b): for l ← layer[a]+1 to layer[b]−1:
    create dummy node d in layer l;  connect predecessor to d

Step 4: minimising crossings

Within each layer only the order of the nodes is free. Two segments between the same adjacent layers cross exactly when their positions (p1,q1)(p_1,q_1) and (p2,q2)(p_2,q_2) run in opposite directions:

(p1−p2)(q1−q2)<0(p_1 - p_2)(q_1 - q_2) < 0

Finding the minimum number of crossings is NP-hard. The framework uses the median method: in the sweep from left to right every node gets as sort key the median of the positions of its neighbours in the previous layer; for an even count the mean of the two middle ones. Then the same step runs from right to left. Nodes without neighbours keep their position as key. Example: neighbour positions {0,2,5}\{0, 2, 5\} give key 2, {1,4}\{1, 4\} give key 2.5.

A sweep can make the result worse. Therefore the crossings are counted after every sweep and the best state seen is kept, not the last.

Convention in the framework: LayeredLayout.defaults() makes 12 sweeps (alternating forward and backward, starting forward). Hints from LayoutHints (position in the layer, 0 at the top, limited to the layer size) are binding: after every sort the nodes with a hint are put back at their position and the others order themselves around them. If two nodes want the same position, the second takes the next free one below, otherwise above.

Pseudocode – minimizeCrossings, sortByMedian

best ← copy of arrangement;  bestCount ← crossings()
for s ← 0 to sweeps−1:
    if s even:  for l ← 1 to lastLayer:               sort(l, byPredecessors)
    else:        for l ← secondToLast down to 0:       sort(l, bySuccessors)
    renumber positions
    if crossings() < bestCount: bestCount ← …;  best ← copy
arrangement ← best

sort(l, direction):
    for each cell c in layer l:
        nb ← sorted positions of the neighbours in the relevant adjacent layer
        key[c] ← if nb empty: position(c)
                 else if |nb| odd: nb[|nb|/2]
                 else (nb[|nb|/2−1] + nb[|nb|/2]) / 2
    sort layer by key;  put cells with a hint at their position

Steps 5 and 6: coordinates and ports

The layers are fixed horizontally: each layer is as wide as its widest node, with the layer gap in between. If there are freely placed nodes, the gap is widened by their largest width plus one node gap – otherwise there would be no overlap-free position for them.

Vertically, median alignment applies: each cell wants to sit at the median of the centres of its neighbours. Because the wishes overlap, the layer is packed without overlap from top to bottom: the top edge is the maximum of the wish and the end of the predecessor plus gap. Then the layer as a whole is shifted back by the median of the deviations wi−miw_i - m_i. This gives the straight through-lines that make a flowsheet readable. Like the sorting, packing runs in 12 sweeps, alternating forward and backward.

Free nodes (without primary edge) come last: into the gap between layers given by the centroid of their partners, and there with the same packing, vertically. This is deliberately a closed-form solution; a force simulation that pushes nodes out of overlaps can oscillate between two boxes in jammed cases and gives no guarantee, whereas packing does. The ports of each block sit on fixed sides and are sorted by the position of the partner block.

Convention in the framework: defaults LayoutConfig.defaults() (drawing units): layer gap 90, node gap 34, minimum width 110, minimum height 54, port gap 16, gap at dummy nodes 14, margin 24. Dummy nodes have width and height 0 and therefore need only the small gap. DefaultNodeMetrics estimates node sizes by calculation rather than from font metrics, so that screen and file give the same picture and the layout is reproducible bit for bit.

Step 7: orthogonal routing

Each segment that is not straight (height difference ≥ 1) consists of horizontal – vertical – horizontal. The vertical part sits in a lane in the gap between layers. Two segments may share a lane if their height ranges are disjoint. The assignment is an interval colouring: sort the segments by the lower end of their height range and give each the first lane whose last end lies below its start, otherwise open a new lane. Example: the ranges [10,50][10,50], [30,80][30,80], [60,90][60,90] give lane 0, lane 1 and lane 0 again, so two lanes.

If lane jj (counted from 0) lies in a gap from aa to bb with mm lanes in total, its position is

xj=a+(j+1)(b−a)m+1x_j = a + \frac{(j+1)\,(b-a)}{m+1}

so lanes are spread evenly. If the gap is narrower than 4 units, the middle is taken. Feedback edges are turned back from drawing direction into their true direction.

Pseudocode – lane assignment assignLanes

for each gap g between layers:
    list ← non-straight segments in g, ascending by min(y1,y2)
    laneEnd ← []
    for each segment h in list:
        lo ← min(y1,y2);  hi ← max(y1,y2)
        lane ← first i with laneEnd[i] < lo   otherwise append a new lane
        laneEnd[lane] ← hi;  h.lane ← lane
    for each segment h: h.laneCount ← |laneEnd|

Source: flowsheet/src/envisionz/flowsheet/layout/LayeredLayout.java (assignLanes, Hop.laneX, Hop.points); coordinates: assignCoordinates, wanted, pack, placeFree

Quality figures: layout quality in numbers

A layout method always produces a picture; whether it is good is visible only to someone who knows the flowsheet anyway. LayoutResult therefore carries numbers for what a person perceives as untidy: crossings() (genuine intersections of two segments from different edges; touching at a shared endpoint does not count), totalEdgeLength() and bends(). crossings(Set) counts only within a subset of edges, because the layout steers only the structure-determining edges – crossings between secondary edges are a different matter.

How it is tested

The probe Aufteilungsprobe (43 checks, purely computational, no screen) does not test appearance but what can be recomputed:

  • Only PRIMARY layers: the same edge once structure-determining, once secondary gives three layers versus two.
  • Avoidable crossings vanish, unavoidable ones remain: two edges crossing must be crossing-free after ordering; four edges between two times two nodes cannot be in any order. The second half prevents the first from passing with a count that always returns zero.
  • No box covers another, and each lies within the sheet.
  • Determinism: the same input twice gives the same output twice, also with a different insertion order.
  • Cycle, self-loop and node without edge must not break.

The probe was cross-checked with four deliberate corruptions of the production code, each turning it red: layering secondary edges as well (2 red checks), crossings() always returning zero (1), negative node gap (1), one node dropping out of the arrangement (6). The acceptance check on the real model (FlowsheetCheck in the application) additionally tests, among other things, repeatability (two runs, bit-identical SVG) and the crossing-freeness of the streams; state of the module description 2026-08-27: 40 and 36 passed, 0 failed.

Limits

  • Crossing minimisation and cycle breaking are heuristics; the result is good, not provably optimal.
  • Layering uses only PRIMARY; secondary edges are fitted in and may cross (in the full model 50 crossings in total against 0 for the streams).
  • Streams still run through the gaps in which the free nodes sit; groups (SCC blocks) are not yet drawn by the renderer as outlined areas; coupling edges do not yet carry diagnostic values (open items in the module description).
  • LayoutHints are provided but have no callers outside the probes so far.
