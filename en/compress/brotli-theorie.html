Brotli – context modelling and a dictionary with transforms

What Brotli (RFC 7932) does beyond Deflate: prefix codes in two forms, three independent block splittings, literals whose code depends on the two previous bytes, a command code combining insert and copy length, four remembered distances with deviations, and a built-in dictionary of 122,784 bytes with 121 transforms. With pseudocode following Brotli, Brotlibaum and Brotliwoerterbuch.

What it is about

Brotli is an LZ77 method with Huffman-like prefix codes, like Deflate. It packs text and web content in particular better, for three reasons:

  • Context. Which prefix code encodes a literal depends on the two bytes output before it. After a space an upper-case letter is more likely than after a lower-case letter; Brotli can use different codes for this.
  • Block types. Literals, commands and distances each have their own division into sections (“blocks”) with their own statistics; the stream switches between them.
  • Static dictionary. A back-reference that points further back than everything output so far reaches into a built-in dictionary of 13,504 words and word fragments – with one of 121 transforms (capitalisation, appended space, cut-off ends, …). The first words of an HTML page can be fetched this way before the encoder has learned anything.

The stream and its meta-blocks

The stream begins with the window size WBITS (a zero bit means 16; otherwise 3 bits mm, for m≠0m \ne 0 it is 17+m17 + m; otherwise another 3 bits: 0 → 17, 1 → large window outside RFC 7932, rejected, otherwise 8+m8 + m). The window is 2WBITS−162^{\text{WBITS}} - 16 bytes. Then meta-blocks follow:

Fieldbitsmeaning
ISLAST1last meta-block
ISLASTEMPTY1, only if ISLASTlast and empty – the stream has ended
MNIBBLES20–2: 4, 5, 6 nibbles for MLEN; 3: metadata block (skipped)
MLEN − 14 · MNIBBLESnumber of output bytes of this meta-block
ISUNCOMPRESSED1, only if not ISLASTthe MLEN bytes follow raw from the next byte boundary

The shortest valid stream is a single byte: 06 = bits 0, 1, 1 – window 16, ISLAST, ISLASTEMPTY. Brotli.entpacke(new byte[]{6}) returns zero bytes (recomputed).

Prefix codes

Brotli builds its codes canonically like Deflate but reads them least significant bit first; the code thus appears bit-reversed in the stream. Brotlibaum therefore sets up a table per code length over the reversed codes and reads bit by bit until an entry is occupied. A code is transmitted in one of two forms:

  • Simple (first 2 bits = 1): 1 to 4 symbols directly, ⌈log2⁡alphabet size⌉\lceil \log_2 \text{alphabet size} \rceil bits each. The lengths are fixed: 1 symbol → 0 bits; 2 → 1, 1; 3 → 1, 2, 2; 4 → 2, 2, 2, 2 or (choice bit) 1, 2, 3, 3 – in the order in which the symbols appear.
  • Complex (otherwise; the 2 bits are the number of leading entries skipped): first the lengths of a code over 18 code-length symbols, in the fixed order 1, 2, 3, 4, 0, 5, 17, 6, 16, 7, 8, 9, 10, 11, 12, 13, 14, 15, each with a fixed variable-length code (lengths 2, 4, 3, 2, 2, 4 for values 0 to 5). Then, with it, the code lengths of the actual alphabet; 16 repeats the previous non-zero length (default 8), 17 repeats zeros.

The repeat commands have a peculiarity: if two commands of the same kind follow each other, the second extends the first instead of replacing it:

rnew=(rold−2)⋅2z+3+bits(z),z=2 (symbol 16),z=3 (symbol 17)r_{\text{new}} = (r_{\text{old}} - 2) \cdot 2^{z} + 3 + \text{bits}(z), \qquad z = 2 \text{ (symbol 16)},\ z = 3 \text{ (symbol 17)}

and rnew−roldr_{\text{new}} - r_{\text{old}} further entries are added. This gives a long run without long extra fields. The Brotlibaumprobe uses it to build, for instance, 256 symbols of 8 bits each from an 8 and four extending 16s.

Convention in the framework: Brotlibaum.ausLaengen checks the Kraft sum: every code of length ll occupies 2L−l2^{L - l} of 2L2^{L} leaves, a complete code occupies them exactly. Over- and under-subscribed lengths throw when building, not only when a free code is read. A tree with a single symbol costs no bit.

Commands: insert and copy

The payload of a meta-block is a sequence of commands. Each command means: insert II literals, then copy CC bytes from distance DD. Insert and copy length are combined in one symbol cc out of 704:

g=⌊c/64⌋,i=VI(g)+⌊c/8⌋mod8,k=VC(g)+cmod8g = \lfloor c / 64 \rfloor, \qquad i = V_I(g) + \lfloor c/8 \rfloor \operatorname{mod} 8, \qquad k = V_C(g) + c \operatorname{mod} 8

with the offset tables VI=(0,0,0,0,8,8,0,16,8,16,16)V_I = (0,0,0,0,8,8,0,16,8,16,16) and VC=(0,8,0,8,0,8,16,0,16,8,16)V_C = (0,8,0,8,0,8,16,0,16,8,16). From the codes ii and kk the lengths follow via base value and extra bits (insert 0 to 22594+224−122594 + 2^{24} - 1, copy 2 to 2118+224−12118 + 2^{24} - 1). For g<2g < 2, i.e. c<128c < 128, no distance is in the stream: the last one is meant (distance code 0).

Example: c=130c = 130 → g=2g = 2, i=0i = 0, k=2k = 2: no literals, copy length 4, distance given in the stream.

Distances

Brotli remembers the last four distances in a ring; at the start of the stream 4, 11, 15, 16 (the last one is 4). The distance codes mean:

Codedistance
0, 1, 2, 3last, second-to-last, third-to-last, fourth-to-last
4 … 9last −1, +1, −2, +2, −3, +3
10 … 15second-to-last −1, +1, −2, +2, −3, +3
16 … 15 + NDIRECT1 … NDIRECT directly
abovewith extra bits, see below

With P=P = NPOSTFIX (0…3) and ND=N_D = NDIRECT (0…15⋅2P0 \dots 15 \cdot 2^{P}) from the meta-block header and r=code−ND−16r = \text{code} - N_D - 16:

z=1+⌊r2P+1⌋,h=⌊r2P⌋,o=(2+(hmod2))2z−4,D=(o+bits(z))2P+(rmod2P)+ND+1z = 1 + \left\lfloor \frac{r}{2^{P+1}} \right\rfloor, \quad h = \left\lfloor \frac{r}{2^{P}} \right\rfloor, \quad o = \big(2 + (h \operatorname{mod} 2)\big)\, 2^{z} - 4, \quad D = \big(o + \text{bits}(z)\big)\, 2^{P} + (r \operatorname{mod} 2^{P}) + N_D + 1

With P=0P = 0, ND=0N_D = 0 the codes 16, 17, 18 give the distances 1–2, 3–4, 5–8 – the same geometric grading as in Deflate. NPOSTFIX allows separate codes for the lower bits, for example with data of fixed record length.

Code 0 and dictionary references put nothing into the ring; every other distance becomes the new last one.

The static dictionary

If the distance is larger than Dmax⁡=min⁡(output so far,window)D_{\max} = \min(\text{output so far}, \text{window}), that is not an error but a dictionary reference. The copy length CC (4 to 24) is then the word length; word number and transform follow from the excess:

u=D−Dmax⁡−1,word=umod2B(C),transform=⌊u/2B(C)⌋<121u = D - D_{\max} - 1, \qquad \text{word} = u \operatorname{mod} 2^{B(C)}, \qquad \text{transform} = \lfloor u / 2^{B(C)} \rfloor < 121

B(C)B(C) is the number of bits of the word number for length CC: from 10 bits for length 4 (1024 words) to 5 bits for length 24 (32 words). The sum ∑C=424C⋅2B(C)\sum_{C=4}^{24} C \cdot 2^{B(C)} gives exactly 122,784 bytes; the dictionary contains 13,504 words (both recomputed with Brotliwoerterbuch).

A transform is: prefix + modified word + suffix. The modification cuts 1 to 9 characters off the front or the back, or capitalises the first or all characters. Capitalisation is a byte operation that knows UTF-8: for a byte below 0xC0 a lower-case letter becomes upper-case by xor32\operatorname{xor} 32; for a two-byte character xor32\operatorname{xor} 32 is applied to the second byte, for three bytes xor5\operatorname{xor} 5 to the third.

Values computed with Brotliwoerterbuch.umgeformt(4, 0, u). The dictionary is stored zlib-compressed and Base64-encoded in the source (in eight pieces, because a string in a class file may be at most 65,535 bytes long) and is unpacked on first access with the module's own Zlib and checked against its length.

Block types and context

For each of the three categories – literals (L), commands (I), distances (D) – the meta-block header gives the number of block types (1 to 256). If there is more than one, a code for the block type, a code for the block length (26 symbols, base value plus extra bits) and the first block length follow. When a block is used up, the reader reads a switch command before the next symbol of that category: 0 = the type before the current one, 1 = next type (+1mod+1 \operatorname{mod} count), otherwise symbol − 2.

For literals the context is added. Each literal block type has one of four context modes; from the two previous bytes p1,p2p_1, p_2 a context number 0 to 63 arises:

Modecontextp1=p_1 = e, p2=p_2 = ␣p1=p_1 = T, p2=p_2 = a
0 LSB6p1mod64p_1 \operatorname{mod} 643720
1 MSB6⌊p1/4⌋\lfloor p_1 / 4 \rfloor2521
2 UTF8table for p1p_1 or table for p2p_2 (character classes)5655
3 signed8⋅T(p1)+T(p2)8 \cdot T(p_1) + T(p_2), TT = magnitude class2627

Values computed from the context table of Brotliwoerterbuch.kontexttafel(). The table has 2048 bytes: per mode two tables of 256 entries, one for p1p_1 and one for p2p_2; for all four modes the context number is their bitwise or.

The context map assigns one of up to 256 literal codes to each pair (block type, context) – 64⋅types64 \cdot \text{types} entries for literals, 4⋅types4 \cdot \text{types} for distances (the context of distances is the copy length: 2, 3, 4 or more). It is compressed twice: zeros are run-length coded (symbols 1 to RLEMAX stand for 2s+bits(s)2^{s} + \text{bits}(s) zeros), and the whole map optionally stands in move-to-front order, which is inverted at the end.

schL ← Blockschalter(zahlBis256())   each: count, type code, length code, first length – interleaved
schI ← Blockschalter(zahlBis256())
schD ← Blockschalter(zahlBis256())

modus[j] ← bits(2) for every literal block type j
karteL ← abbildung(64 · types_L);  karteD ← abbildung(4 · types_D)
read the literal codes (256), command codes (704), distance codes (16 + N_D + 48·2^P)
while n < ziel:
    schI.vielleichtWechseln();  c ← befehle[schI.art].symbol()
    I ← insert length(c);  C ← copy length(c)
    repeat I times, while n < ziel:
        schL.vielleichtWechseln()
        k ← tafel[modus][aus[n−1]] or tafel[modus][256 + aus[n−2]]
        aus[n++] ← literale[karteL[64·schL.art + k]].symbol()
    if n ≥ ziel: break                       the copy length is then not needed
    if c < 128: code ← 0
    otherwise: schD.vielleichtWechseln();  code ← abstaende[karteD[4·schD.art + min(C−2, 3)]].symbol()

    if D > min(n, fenster): ausWoerterbuch(D, C);  continue

Source: envisionz-framework-compress/src/envisionz/compress/brotli/Brotli.java (lies, datenblock, abstandAus, ausWoerterbuch, abbildung, Blockschalter).

Convention in the framework: The three block splittings are interleaved in the header: count, its two codes, its first block length – only then the next count. Whoever reads the three counts first is off by bits from the first code on; with files having only one block type per category this never shows. The initial distances are entered so that code 0 yields 4, not 16.

How it is checked

  • Brotliprobe (36 checks): the dictionary (length 122,784, the same number computed from the size bits, SHA-256, the first words time, down, life, left, 1024 words of length 4, 2048 of length 6, 32 of length 24, 121 transforms); transforms including capitalisation of two-byte characters; eleven anchors from brotli 1.2.0: empty, only literals, dictionary reference, HTML with block types and context, UTF-8 umlauts, 126,000 bytes with a large window, uncompressed data block (random data), forced block types, three statistics with interleaved headers, narrow window of 1024 bytes, narrow window together with dictionary; four error cases.
  • Brotlibaumprobe (29 checks): the fixed code of the code-length alphabet against the patterns of RFC 7932 3.5; canonical codes over 18,000 symbols in 60 alphabets; all simple codes (NSYM 1 to 4, both choice bits); complex codes with extending repeat commands and skipped leading entries; over- and under-subscribed lengths.

Limits

  • Read-only; the “large window” extension (outside RFC 7932) is rejected.
  • An insert command that reaches beyond the end of the meta-block is cut off at the end instead of being rejected.
  • The dictionary is unpacked completely on first access (122,784 bytes) and stays in memory.
  • The output lies completely in memory; capped by the decompression limit.
