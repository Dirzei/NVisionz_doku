LZ4 — comparison against the format description and lz4

As of: 2026-09-25
Our implementation: envisionz.compress.lz4.Lz4 (frame) and Lz4Block (raw block) — read-only
Specification: LZ4 Frame Format Description and LZ4 Block Format, both public
Compared against: lz4 1.9.4 (über Pythons lz4)
Test bench: envisionz.compress.Lz4probe — 65 checks, five foreign anchors; envisionz.compress.Lz4woerterbuchprobe — 9, three foreign anchors

The reference implementation. lz4 by Yann Collet is at once reference implementation and publisher of the format.

Why this one. Because both formats — frame and block — come from the same hand, and there is no second implementation fit to serve as a yardstick.

Coverage, computed from the rows below: of 11 features we have 10 present, 0 partial and 1 absent; the reference implementation has 11 / 0 / 0.

The Note column points into section 5 of this document — not into the workspace item list. The word in front says what kind of thing it is: gap is something we lack and that is open; decided is something we deliberately do not do; property is a trait of the format affecting both implementations; open there is a gap of the reference product. Only the gaps are work — they are collected in section 5.1 and appear as one item in OFFENE-PUNKTE.md.

Two formats, one name. The block is the bare stream of literals and back-references; the frame wraps a header around it, splits into blocks and optionally carries checksums. Parquet uses the block without a frame (LZ4_RAW), Hadoop the block with two lengths in front, files ending in .lz4 the frame. Three meanings for one word.

The trap in the frame: linked blocks are the default. A back-reference may then reach across the block boundary into the previous block. Unpacking each block on its own yields, at the first boundary, data of the right length with the wrong content.

Deliberate decisions

LZ4.2 (decided) — No writing

Formerly: L42.

This module reads. A writer would be many times the work of the reader — it must not only know the format but choose well — and nobody here needs one: nothing is compressed, everything is decompressed.

Properties of the format

LZ4.1 (property) — Preloaded dictionary — read since 2026-09-25

Formerly: L41.

The frame names at most an ID, freely chosen by the writer — unlike zlib it cannot be computed from the dictionary, and it may be missing altogether. Whoever has the dictionary supplies it: Lz4.entpacke(daten, woerterbuch). It applies to every frame; of a longer one the last 64 KiB count. The trap: with independent blocks the dictionary precedes every block, with linked ones only the first. Without a dictionary the reader still stops and names the ID.

Measured against three frames from liblz4 1.9.4 (LZ4F_compressFrame_usingCDict via ctypes, docs/lz4/lz41_erzeuge.py): linked, independent and without ID, 140,000 bytes each in three blocks. The mutation test clears the independent bit: the dictionary then precedes only the first block, and the content checksum catches it.
