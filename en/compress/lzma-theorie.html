LZMA – range coder and adaptive models

The core behind Lzma and Bereichsleser: how a range coder charges bits with a fractional bit count, how the probabilities are learned while reading, and how LZMA builds literals, back-references, four remembered distances and a state machine from them. The LZMA2 chunking, the XZ container and the pre-filters are on a page of their own.

What it is about

LZMA writes the same things as Deflate – literals and back-references – but encodes them differently. Deflate gives every symbol a whole number of bits, fixed for an entire block. LZMA splits every decision into single yes/no questions (“is this a back-reference?”, “is the next bit of the literal a 1?”) and encodes each answer with a probability that adapts after every answer. A bit that is almost always 0 then costs far less than one bit. That is the reason for the high compression ratio – and for the property that a single read error turns everything after it into noise.

The range coder

The encoder carries an interval. To encode a bit with probability P0P_0 for “0”, the interval of width RR is split: the lower part of width P0RP_0 R stands for 0, the upper one for 1, and the interval shrinks to the chosen part. After many bits the interval is very narrow; any number inside it denotes the whole bit sequence. Its length in bits is approximately

L≈−∑klog2⁡P(bk)L \approx -\sum_k \log_2 P(b_k)

i.e. exactly the amount of information – without rounding up to whole bits per symbol. A bit with P=0.98P = 0.98 costs −log2⁡0.98≈0.029-\log_2 0.98 \approx 0.029 bits.

The reader keeps the width RR (breite) and the distance CC of the value read from the lower interval bound (wert), both as unsigned 32-bit numbers. The probability is stored as an integer p∈[0,2048)p ∈ [0, 2048) with 11 bits of precision, P0=p/211P_0 = p / 2^{11}. The split is

g=⌊R211⌋⋅pg = \left\lfloor \frac{R}{2^{11}} \right\rfloor \cdot p

If C<gC < g, the bit was 0 and R←gR \leftarrow g; otherwise it was 1, C←C−gC \leftarrow C - g, R←R−gR \leftarrow R - g. If RR falls below 2242^{24}, it is normalised: R←28RR \leftarrow 2^8 R, C←28C+next byteC \leftarrow 2^8 C + \text{next byte}. The arithmetic thus stays within 32 bits, and never more than eight bits of precision are lost at once.

Adaptive models

After every bit the model used moves one thirty-second of the distance towards the bit seen:

after 0:p←p+⌊2048−p32⌋,after 1:p←p−⌊p32⌋\text{after 0:}\quad p \leftarrow p + \left\lfloor \frac{2048 - p}{32} \right\rfloor, \qquad \text{after 1:}\quad p \leftarrow p - \left\lfloor \frac{p}{32} \right\rfloor

This is an exponential moving average with weight 1/321/32. Every model starts at p=1024p = 1024, i.e. P0=1/2P_0 = 1/2. Reader and writer compute exactly the same, bit for bit; that is why not a single probability is stored in the file.

Worked example. Nothing but zero bits: pp runs 1024 → 1056 → 1087 → 1117 → … The step ⌊(2048−p)/32⌋\lfloor (2048-p)/32 \rfloor becomes zero as soon as 2048−p<322048 - p < 32; the sequence stops at p=2017p = 2017. An expected bit then costs at most

−log2⁡20172048≈0.022bits-\log_2 \frac{2017}{2048} \approx 0.022\ \text{bits}

Conversely, with nothing but ones pp falls to 31. The Lzmabausteinprobe measures the start: 1024 becomes 1056 after a zero bit and 992 after a one bit. With a range writer of its own following the LZMA SDK it encodes 5000 bits into 515 bytes and reads them back bit-exactly.

Bits without a model and bit trees

  • Direct bits (direkt): uniformly distributed, R←R/2R \leftarrow R/2, bit = 1 if C≥RC \ge R. For the upper bits of large distances, where every value is equally likely.
  • Bit tree (baum): a number of nn bits, most significant first; every bit has its own model depending on the prefix so far. The index runs m=1,2m+b1,…m = 1, 2m + b_1, \dots, the result is m−2nm - 2^n. A tree of nn bits has 2n2^n models.
  • Reverse bit tree (baumUmgekehrt): the same, but least significant bit first. Only for the alignment bits and the middle bits of small distances.

Pseudocode – Bereichsleser

start(daten, ab, ende):
    if ab + 5 > ende: error
    if daten[ab] ≠ 0: error "not an LZMA stream"      the first byte is always 0
    breite ← FFFFFFFF;  wert ← next 4 bytes, most significant first

function nextByte():  return stelle < ende ? daten[stelle++] : 0       zeros behind the end

function normieren():
    if breite < 2^24 (unsigned): breite ← breite·256;  wert ← wert·256 + nextByte()

function bit(p, i):
    normieren()
    g ← (breite >>> 11) · p[i]
    if wert < g (unsigned):  breite ← g;  p[i] ← p[i] + ((2048 − p[i]) >>> 5);  return 0
    otherwise:  breite ← breite − g;  wert ← wert − g;  p[i] ← p[i] − (p[i] >>> 5);  return 1

function direkt(n):
    repeat n times: normieren(); breite ← breite >>> 1; wert ← wert − breite
                     t ← (wert negative) ? −1 : 0;  wert ← wert + (breite and t)
                     r ← 2r + (t + 1)
function baum(p, ab, n):          m ← 1; n times: m ← 2m + bit(p, ab + m);  return m − 2^n
function baumUmgekehrt(p, ab, n): m ← 1; r ← 0; for i ← 0..n−1: b ← bit(p, ab+m); m ← 2m+b; r ← r + b·2^i

Source: envisionz-framework-compress/src/envisionz/compress/lzma/Bereichsleser.java.

Convention in the framework: Beyond the end of the stream the reader delivers zero bytes instead of an exception. That is intentional: the reader keeps four bytes of look-ahead and regularly reads past the end at the last symbol. Xzprobe shows it: an .lzma stream without its last one or two bytes gives the same result; only without three does it break. The precision (11 bits), the adaptation (5 bits) and the normalisation threshold 2242^{24} are part of the format and are therefore named constants, not tuning knobs.

LZMA: what is encoded

An LZMA stream is a sequence of packets. Which packet follows is decided by a chain of model bits:

Bitspacketmeaning
0LITa literal
1 0 + length + distanceMATCHback-reference with a new distance
1 1 0 0SHORTREPexactly one byte from the last distance
1 1 0 1 + lengthREP0last distance
1 1 1 0 + lengthREP1second-to-last distance
1 1 1 1 0 + lengthREP2third-to-last distance
1 1 1 1 1 + lengthREP3fourth-to-last distance

The models of these decisions depend on the state, and istBezug and istKurz additionally on the lower pb bits of the output position. A remembered distance that is used moves to the front; a new distance shifts the four remembered ones along by one place.

The state

The state s∈{0,…,11}s ∈ \{0, \dots, 11\} roughly remembers what the last packets were. s<7s < 7 means: the last packet was a literal. The transitions are tables:

ss01234567891011
after LIT000012345645
after MATCH77777771010101010
after REP88888881111111111
after SHORTREP99999991111111111

The idea: a literal is followed by a literal with a different probability than a back-reference is, and this information is free because both sides know it.

Literals

A literal is read as a bit tree of eight bits, with 0x300 models per context. The context consists of the upper lc bits of the previous byte and the lower lp bits of the position:

k=((nand⁡(2lp−1))⋅2lc)+⌊prev28−lc⌋,models from 768kk = \big((n \operatorname{and} (2^{lp}-1)) \cdot 2^{lc}\big) + \left\lfloor \frac{\text{prev}}{2^{8-lc}} \right\rfloor, \qquad \text{models from } 768\,k

Directly after a back-reference (s≥7s \ge 7) the situation is different: the next byte is often the byte that would have come next at the last distance, but not quite – otherwise the back-reference would have been longer. LZMA then encodes the literal against this match byte: as long as the bits read so far agree with those of the match byte, a separate set of models is used for each bit, depending on the bit of the match byte; from the first mismatch on, the ordinary tree continues.

function literal():
    vorig ← (n > wbAb) ? aus[n−1] : 0
    k ← ((n and lpMaske) << lc) + (vorig >>> (8 − lc));  ab ← 0x300 · k;  m ← 1
    if zustand ≥ 7:                                  "matched literal"
        gegen ← aus[n − a0 − 1]                          byte at the last distance
        repeat:
            bitG ← top bit of gegen;  gegen ← gegen << 1
            b ← bit(literale, ab + ((1 + bitG) << 8) + m);  m ← 2m + b
            if b ≠ bitG: break
        while m < 0x100
    while m < 0x100:  m ← 2m + bit(literale, ab + m)
    zustand ← NACH_LITERAL[zustand];  write(m − 0x100)

Lengths

Lengths 2 to 273 go through a three-stage coder: a choice bit, then either 3 bits for 2–9 (a separate tree per pb position), or a second choice bit and 3 bits for 10–17 (likewise), or 8 bits for 18–273. New back-references and remembered distances each have their own length coder.

Distances

A new distance begins with a 6-bit slot qq (bit tree, a separate tree per length class min⁡(l−2,3)\min(l - 2, 3)). Slots 0 to 3 are the distance itself. Otherwise

z=⌊q2⌋−1,d=(2+(qmod⁡2))⋅2z+remainder of z bitsz = \left\lfloor \frac{q}{2} \right\rfloor - 1, \qquad d = \big(2 + (q \operatorname{mod} 2)\big) \cdot 2^{z} + \text{remainder of } z \text{ bits}

For q<14q < 14 the zz remaining bits come from a reverse bit tree; for q≥14q \ge 14 the upper z−4z - 4 bits are direct and the lower 4 come from the reverse alignment tree. The distance is stored minus one; the true reference goes back d+1d + 1 bytes.

Slot qqzzddremaining bits

The value d=FFFFFFFF16d = \text{FFFFFFFF}_{16} is the end marker. It appears only if the output size is not known.

Pseudocode – Lzma.entpacken and abstandLesen

while n < ziel:
    st ← n and pbMaske
    if bit(istBezug, 16·zustand + st) = 0:  literal();  continue
    if bit(istGemerkt, zustand) = 1:

            if bit(istKurz, 16·zustand + st) = 0:

            else if bit(gemerkt2, zustand) = 0:  neu ← a2;  a2 ← a1
            otherwise:                            neu ← a3;  a3 ← a2;  a2 ← a1
            a1 ← a0;  a0 ← neu

    copy ℓ bytes from n − a0 − 1, byte by byte

function abstandLesen(klasse):
    q ← baum(platz, 64·min(klasse, 3), 6)
    if q < 4: return q
    z ← (q >>> 1) − 1;  a ← (2 + (q and 1)) · 2^z          computed as long
    if q < 14: a ← a + baumUmgekehrt(mittel, a − q, z)
    otherwise: a ← a + direkt(z − 4) · 16 + baumUmgekehrt(ausrichtung, 0, 4)
    return a

Source: envisionz-framework-compress/src/envisionz/compress/lzma/Lzma.java (entpacken, literal, abstandLesen, bezug, class Laenge). The middle bits of all slots below 14 share one model array of 115 entries; the offset a − q gives each slot its own branch.

Convention in the framework: In abstandLesen the base is computed as long before shifting. For slot 63 there are 30 bits, and (2|1) << 30 as an int computation would run into the sign bit: the result would be 0xFFFFFFFFC0000000 instead of 0xC0000000. Exactly this caused the end marker not to be recognised on 2026-09-06; the error shows only for the largest slot.

The properties lc, lp, pb

The three numbers sit together in one byte, as a positional notation with bases 9 and 5:

e=(pb⋅5+lp)⋅9+lc,lc=emod⁡9,lp=⌊e/9⌋mod⁡5,pb=⌊e/45⌋e = (pb \cdot 5 + lp) \cdot 9 + lc, \qquad lc = e \operatorname{mod} 9,\quad lp = \lfloor e/9 \rfloor \operatorname{mod} 5,\quad pb = \lfloor e/45 \rfloor

The default is lc=3,lp=0,pb=2lc = 3, lp = 0, pb = 2, i.e. e=(2⋅5+0)⋅9+3=93=0x5De = (2\cdot 5 + 0)\cdot 9 + 3 = 93 = \text{0x5D}. The largest permissible byte is 224 (lc=8,lp=4,pb=4lc = 8, lp = 4, pb = 4).

The old .lzma file (Lzma.entpackeAlone) has a 13-byte header without signature: the properties byte, four bytes of dictionary size, eight bytes of output size (FFFFFFFFFFFFFFFF = unknown; then the stream ends with the end marker). Because there is no signature, the reader checks the properties byte and the size for plausibility.

How it is checked

  • Lzmabausteinprobe (58 checks): the constants; a range writer of its own following the LZMA SDK encodes 5000 model bits that come back bit-exactly, with equally learned probabilities on both sides and a clean end; direct bits (202 values of 1 to 26 bits), bit tree (207 values) and reverse bit tree (191 values); zeros beyond the end; the stream start with a zero byte. In addition the LZMA2 control and three liblzma anchors (see LZMA2 and XZ).
  • Xzprobe (55 checks): the anchors from liblzma, among them p1 with lc=0,lp=2,pb=0lc = 0, lp = 2, pb = 0 instead of the default, three .lzma files (text, empty, random), the decomposition of the properties byte (0x5D, 0, 224, rejection of 225 and negative values), and 104 single-bit flips in a file, 100 of which are noticed – the other four lie in the tail of the range stream.

Limits

  • Read-only: there is no range writer in the main code (only in the probes) and no LZMA encoder.
  • The output is at the same time the dictionary and is held completely; no ring buffer. Limit about 2 GiB and the decompression limit.
  • An error in the stream does not show locally: from that point on the output is noise. It is only detected at a reference into nowhere, at the size or at the check value of the container.
  • sauberBeendet() (value zero at the end) is not a checksum and only catches gross errors.
