Recording system sound – what goes to the speakers, without a driver

The operating system's audio interface can hand the stream it sends to an output device back to a program at the same time (loopback). The module uses this in two ways: for the whole output device and for individual programs. The interface is addressed through FFM and its COM vtables, without a third-party library. The microphone is never opened.

What it is about

A recording should contain exactly what was audible: the same timing, the same length, the pauses too. Three things make this harder than it sounds. The operating system delivers packets only while something is playing. The format is decided by the device, not by the program. And the interface consists of COM objects with reference counts that expect every release exactly once. The app (card Record system sound) stores the result as WAV, EVAS or MP3; this page describes what happens underneath.

Two ways to the stream

Device. The device enumerator names the default output; its client reports the mix format in which the operating system mixes all programs together. With exactly this format and the flag LOOPBACK it is initialized in shared mode, with one second of buffer. The mix format belongs to the caller and is released with CoTaskMemFree.

Program. There is no device for a single program. A virtual device is activated with a block holding process id and mode: include means the program and its child processes, exclude means everything else. Activation is asynchronous. It signals completion through a COM object that the module builds itself from callbacks and that declares itself free to move between threads. Such a stream has no device format. The module therefore asks for 48 kHz stereo, floating point first. If the interface rejects exactly this format, it takes 16-bit PCM. Any other error is reported, without a second attempt.

Silence instead of a gap

When nothing plays, the operating system delivers no packets, and the recording would simply be shorter. The thread therefore compares the frames delivered with the clock. If tt seconds have passed since the start and nn frames have arrived at the rate fsf_s,

m=⌊tfs⌋−nm = \lfloor t f_s \rfloor - n

frames are missing. If mm exceeds the threshold of 50 ms, it fills in mm minus 20 ms of zeros, at most one second at a time. The 20 ms remain as a margin for packets still in flight. Packets marked silent also become zeros instead of taking over the buffer content. Gaps reported by the stream itself are counted.

The format is a claim

The mix format comes as WAVEFORMATEX or WAVEFORMATEXTENSIBLE. Like any number from outside it is checked before anything is computed from it: 1 to 32 channels, 1 kHz to 768 kHz, PCM with 16, 24 or 32 bits, floating point with 32 bits, and the block size must be channels⋅bits/8\text{channels} \cdot \text{bits}/8. Conversion is to −1…1-1 \dots 1: floating point unchanged, PCM with the sign of the top byte. For 24 bits the sign is extended from the third byte,

x=b0+28b1+216s(b2)223,x = \frac{b_0 + 2^8 b_1 + 2^{16} s(b_2)}{2^{23}},

where s(b2)s(b_2) is the third byte taken as signed.

Which programs are playing

The list of programs comes from the session manager of the output device. Each session gives its process id and its state. The system sounds session is dropped, and several sessions of one process are merged. Active programs come first, the name is taken from the JVM's process table. The number of sessions is checked before the loop (at most 4096).

Cleaning up

At the end the thread stops the client (only if it was started) and releases the capture client, the client, the device and the enumerator, each exactly once. The callback object of the activation lives once in global memory, because the operating system may still call its release after the end.

How it is tested

  • Systemklangprobe runs without sound and without a device against rebuilt COM objects. The stand-ins count every reference and every call. Checked are the sequence with flags and format, conversion of all formats, the silent flag, filling in, errors on opening and during recording, activation for a program (block, mode, callback, fallback format), the program list, and that every reference is released at the end.
  • Systemklangechtprobe plays tones on the real computer and records them: via the device, one program only, everything except it. Because it is audible, it only runs on request with the long-running probes.

Limits

  • Recording a program needs a certain version of the operating system or later; before that there is an understandable error message.
  • Only the operating system's default output device; no other output device can be chosen.
  • The process loopback always delivers 48 kHz stereo, however the device is set.
  • In the native image, FFM calls and callbacks must be registered; until then loading reports that system sound is not set up.
