Runs, result store and start-value search – background

What the user interface computes itself before and after the solver core works: reading the log along, storing runs with their status codes, the comparison boxes in the flowsheet, rating start values, converting display units and outlining long model texts.

What this is about

Solving happens in the core commandline-eqnparser; the app calls it only through its programming interface and through the batch runner. What the app adds is the shell around it: it starts the run in the background, reads its messages, stores results in a database, puts computed states side by side and searches for start values. Each of these shells contains a small rule, and this page is about those rules.

Reading the log

The core reports its progress only as text lines. The app attaches a reader to its log and splits each line with regular expressions. An iteration line yields the number kk, the residual norm ‖F‖\lVert F\rVert, the index of the equation with the largest residual and its value; the Convergence tab draws its curve from these. The end of a run comes in three forms: converged, converged with violated bounds (status code 1300, with the list of affected variables) and not converged. The order of the checks matters because the message with status code 1300 also contains the word “converged”: it is searched first.

Numbers are read with a decimal point only. That is an agreement with the core, which writes its log without a locale; a comma never occurs there.

Storing runs

Every run can be stored as one row of the table RESULTS in an H2 database: all variable values as columns, plus whether it was a single or a batch run, a batch id, a time stamp and the status code HNSI. The codes mean:

HNSIMeaningin the run list
300convergedtime stamp and “(einzeln)” or “(Stapel)”
1300converged, but bounds violatedplus “HNSI 1300”
9001not convergedplus “HNSI 9001”

Only 300 counts as converged, strictly. A run with violated bounds does have a small residual, but a solution outside the permitted range; it therefore carries its code in the list and a star in the boxes.

Comparison boxes in the flowsheet

An info box at a unit puts several value sets side by side: the start point of the model, the solution of the last run, any number of stored runs, or a text file with lines of the form name = value or name; value. Names are compared regardless of case. Stored runs appear under a short name of at most eight characters of the time stamp, a non-converged one with a star.

The last column is the relative deviation between the first set aa and the last set bb:

Δ=100b−aa%,\Delta = 100\,\frac{b - a}{a}\ \%,

to three significant digits. If |a||a| is below 10−1210^{-12}, the box shows “0” when bb is zero as well, otherwise “n/a”: there is no reference from zero. Without a fixed selection the box shows the quantities with the largest deviation |b−a|/max⁡(|a|,10−12)|b-a|/\max(|a|, 10^{-12}) first; what stayed the same needs no room.

Searching start values

Newton methods converge only from a neighbourhood of the solution. The start-value search therefore lets the learning and search workbench search over the start values of the free variables: one gene per free variable, rated by a real run. Fixed variables, structural switches and variables that an operating-point file prescribes per point are not genes.

The range of a gene

A gene moves within the declared bounds. If they are missing, degenerate or wider than 106max⁡(1,|s|)10^6\,\max(1, |s|) around the model default ss, the search replaces them by

[s−10m,s+10m],m=max⁡(1,|s|),\big[\,s - 10\,m,\ s + 10\,m\,\big],\qquad m = \max(1, |s|),

intersected with the finite bounds that exist. Example: s=5s = 5 with declaration [0,109][0,\ 10^9] gives [max⁡(0,−45),min⁡(109,55)]=[0,55][\max(0, -45),\ \min(10^9, 55)] = [0,\ 55].

The rating

A candidate is solved at all PP operating points, with at most NN iterations per run. With KK converged points, their iteration counts IjI_j and residuals rjr_j, and the residuals rir_i of the other points, the fitness is

f=K(N+10)+1P∑jconv.[(N−Ij)+11+rj]−1P∑inot conv.min⁡(30,log10⁡(1+ri)).f = K\,(N + 10) + \frac{1}{P}\sum_{j\ \text{conv.}}\Big[(N - I_j) + \frac{1}{1 + r_j}\Big] - \frac{1}{P}\sum_{i\ \text{not conv.}} \min\!\big(30,\ \log_{10}(1 + r_i)\big).

The first term orders strictly by the number of converged points: one more converged point weighs N+10N + 10, more than any gain in iterations the other terms can bring. Within the same number of points, faster runs win; non-converged points cost according to the order of magnitude of their remaining residual, capped at 30. Two equal points with N=20N = 20 thus give f=60+(20−I)+1/(1+r)f = 60 + (20 - I) + 1/(1 + r).

A candidate is invalid if a gene is not a number or not finite. If the core does not compute at all – for example because the numbers of equations and variables do not match – the candidate is invalid as well, and a model the core rejects as unreadable is an error; otherwise both would enter the search as “not converged” with a penalty.

The operating-point file

Optionally a text file names several operating points: a header line with variable names separated by commas, then one line per point; empty lines and lines starting with # do not count. Rejected, with line number: an empty header, a line with fewer values than names, a value that is not a number, a file without points, and a name the model does not know.

Display units

In the Variables tab every variable can be shown and edited in another unit of the same kind of quantity. Computing and saving always use the unit of the model. With the factor cc of the display unit, xdisplay=xmodel/cx_\text{display} = x_\text{model}/c when showing and xmodel=cxdisplayx_\text{model} = c\,x_\text{display} when entering; for bar against Pa, c=105c = 10^5. A variable counts as changed as soon as value, bounds, status or description differ from their initial state; changing the display unit alone changes nothing.

Outlining long model texts

The structure tree of the CAS tab divides a model text into sections. Blocks that start with a keyword and end with $END are preferred. Without them the app looks for banners: a comment rule of at least eight = or - characters, a title line, and a closing rule within twelve lines. A section reaches up to the next banner; whatever comes before becomes “(Vorspann)”. Decorative dashes around the title are dropped, titles longer than 70 characters are cut to 69 and end with an ellipsis. Without blocks and banners a single section “Gesamte Datei” remains.

How this is checked

The rules on this page are checked headless by the app's line-coverage probe with 100 checks on generated models, operating-point files and a run store in a temporary folder; the expectations follow from the formulas above. In addition there are 21 counter-checks, each of which spoils one rule and must turn red. The other probes of the app check the user interface, the store, the log reader under a German locale and the tabs.
