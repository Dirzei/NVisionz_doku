Course of a call – background

What happens between the switches on the command line and the return code: where a switch gets its value, how a shape or a file becomes the mesh, which computing path is chosen, when a steady run counts as converged, in which order results are written and how adaptive refinement divides the run into sections. What the solver itself computes is on the pages of framework-cfd.

What this is about

A run without a user interface has to be judged from the return code and a few lines of text, and it has to be repeatable. The tool therefore fixes which value applies when a switch appears in several places, it reports every switch it does not evaluate, and it writes the result before something secondary such as a picture can fail.

Where a switch gets its value

A switch can appear in three places. The topmost applies:

  1. on the command line,
  2. in the case file (-fall:FILE, one switch per line, # starts a comment),
  3. as a default of an m-ACHIEVE case (boundaries from achieve.blk, free stream from achieve.inp) when -netz: names such a folder.

A switch given twice in the same place is a call error (return 1): which of the two was meant cannot be decided. A switch the chosen path does not evaluate is reported as WARNUNG Schalter -name wird hier nicht ausgewertet – a typo such as -ordnung: instead of -ordnungen: does not pass silently.

If you choose -zaehigkeit:stoffwerte yourself, the defaults re, mu and pr of an m-ACHIEVE case are dropped: viscosity and heat conduction then come from the properties, not from a reference number.

From the switches to the mesh

The mesh comes either from a built-in generator (-form:) or from a file (-netz:) whose format is decided by its content (input and output). Then, in this order:

  1. -netzskala:F multiplies all nodes by F (meshes in reference lengths, computation in SI).
  2. -rotationssymmetrisch:W turns the planar mesh into a wedge about the x axis. Boundaries lying on the axis disappear; if -randbedingung names one of them it is removed with a note. A name that did not exist in the planar mesh at all remains an error (return 1) – a typo is not swallowed.
  3. -umnummerieren:ja (default) orders the cells by reverse Cuthill-McKee.

A mesh that cannot be built or fails the check ends with return 3 and the reason.

When a steady run converges

As in the user interface (app-cfd) the tool measures relatively: the reference is the largest residual of the first ten steps of this call, separately for density, turbulence and species, and the measure is the largest of the relative residuals.

rn=max⁡(Rnmaxk≤10⁡Rk,RnTmaxk≤10⁡RkT,RnSmaxk≤10⁡RkS)<10−mr_n = \max\!\left(\frac{R_n}{\max_{k \le 10} R_k},\ \frac{R^{T}_n}{\max_{k \le 10} R^{T}_k},\ \frac{R^{S}_n}{\max_{k \le 10} R^{S}_k}\right) \lt 10^{-m}

One difference from the user interface: the command line starts the reference afresh with every call, also after -fortsetzen:. The user interface keeps it when continuing with the same solver.

Return codes

0task done; when computing: converged, end time reached or -schritte:0 (evaluate only)
1call error: switch missing, given twice, wrong value, boundary without condition, mutually exclusive switches
2file not readable or not writable; the message gives the reason
3mesh cannot be built or fails the check
4not converged: step limit reached; time-accurate: more than half of the time steps hit -innere:
5aborted: no physical state (negative density or internal energy), with cell, location and hint

In which order things are written

Images and early abort: -bildalle:N also writes an image every N steps in steady runs, -bildfeld:residuum shows the density residual per volume. If the case runs on the graphics device, the image arrives finished from there and the state stays on the card. -abbruchfaktor:F (F greater than 1) ends the run with return 5 as soon as the relative residual rises above F or is no longer a number.

After the last step: closing line, history (-verlauf:), forces, thrust, performance figures and checkpoint, species balance, then the result (-aus:) and only afterwards the picture (-bild:). The order is deliberate: a picture can fail for reasons that do not touch the computation – for instance a wedge mesh without -bildschnitt:. If it came before the result, a run of hours would be lost. After an abort (return 5) neither result nor picture is written: the state is not physical.

With -messebenen:X1,X2,… every output also writes the mass flow through planes across the axis – for a nozzle without rotation the x axis. This shows, time-accurately, whether a flow has become steady.

Adaptive refinement in sections

-verfeinern:S[,THRESHOLD] computes in S + 1 sections. After each section cells are marked (jump of density or pressure above the threshold, or the error estimator), optionally coarsened first, then refined, and the solution is transferred conservatively to the new mesh.

  • steady: every section runs until convergence or the step limit.
  • explicit time-accurate: time is divided into S + 1 equal pieces T/(S+1)T/(S+1); after refining the run continues from the time reached.
  • dual time-accurate: sections end on multiples of the time step; after refining BDF2 starts again with one BDF1 step, because the old time level is missing on the new mesh. A section shorter than one time step is a call error.

Refinement does not go together with -fortsetzen:: a checkpoint belongs to exactly one mesh (return 1).

How it is checked

The probe calls the tool like a script and reads return code and text: every return code with its cause, every mesh shape, every computing path, restart and continuation, pictures, performance figures and measuring planes, and every rejection of a wrong call. The counter-probes each spoil one place in the tool and demand that the probe turns red.

Limits

  • The output is in German, also in the user interface, which shows it in its log.
  • One call computes one case; parameter series are made with scripts.
  • The defaults of an m-ACHIEVE case cover its common boundary kinds and settings, not every one.
