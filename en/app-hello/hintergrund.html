The Life Cycle of a Note – Background

Which method of the template is called when: from creating a note through every keystroke in the title to saving, restoring and closing.

What this is about

The template has only two classes with behaviour: HelloApp fulfils the contract of the interface, HelloPanel holds the state and the controls. Whoever copies the template needs to know in which order the frame calls the methods and which of them do anything only once the view has been built. The general contract is described on the page App contract; this page shows how the smallest app fills it in.

Creating, writing, saving

When a note is created, the frame reads the descriptor, lets createView build the view and then calls onShown: the title field receives the focus and its text is selected, so that the first keystroke replaces it. While being built, the view attaches a listener to the title field; every change calls updateTabTitle, which updates the tab header through the context – an empty title becomes a fixed placeholder text.

When saving, captureState puts title, content and creation time into a tab state. When restoring, restoreState puts the three values back into the view and sets the tab title. Both do nothing as long as no view has been built. dispose has nothing to release and only writes a log line.

Limits

  • captureState returns nothing without a built view, and restoreState then does nothing. The frame therefore always calls createView first.
  • Content and creation time do not appear in the tab header; only the title is kept up to date.
