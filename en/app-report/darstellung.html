envisionz-app-report · Background

Display and output – background

The computation behind the sheet view and the output paths: how Excel widths become pixels, how a click finds its cell, how text runs into empty neighbouring cells, how error cells are highlighted and how Word gets a table with a vertically merged descriptor and a repeated header row. The computation within the sheet itself (lookup, formulas, case columns) is in View sheets from Excel.

What it is about

The sheet report draws its grid itself instead of using a table: cells merged over several rows and columns, borders per cell side, rotated text and overflow as in Excel fit no ordinary table view. For that the view needs a coordinate system of columns and rows in pixels. The Word output of the report tree, on the other hand, writes real Office Open XML so that Word knows headings, merges and the header row as such.

Widths, heights and the way from a click to a cell

Excel measures column widths in characters of the default font, row heights in points. The view converts as Excel does at 96 dpi with the default font:

w=round⁡(7b+5)px,h=round⁡(43p)px(at least 4),w = \operatorname{round}(7\,b + 5)\ \text{px},\qquad h = \operatorname{round}\!\left(\tfrac{4}{3}\,p\right)\ \text{px}\ \ (\text{at least } 4),

with the width bb in characters (default 8.43, i.e. 64 pixels as in Excel) and the height pp in points (20 pixels if not given). Hidden rows and columns drop out. The widths give the edges as prefix sums x0=0,xk+1=xk+wkx_0 = 0,\ x_{k+1} = x_k + w_k, likewise yky_k.

A click at (px,py)(p_x, p_y) finds its cell by binary search in the edges: the kk with xk≤px<xk+1x_k \le p_x < x_{k+1}, effort O(log⁡n)O(\log n) instead of a loop over all columns. Outside the grid, the nearest edge cell applies. Shift+click moves only the end of the selection, as does dragging. If a selection cuts a merged range, it grows by the whole range – repeatedly, until it cuts none.

Drawing: overflow, rotation, errors

  • Overflow. Left-aligned text that does not wrap and is wider than its cell runs on to the right as long as the neighbouring cells are empty and not merged (at most 2000 pixels). That is Excel's rule; right-aligned and centred text is clipped.
  • Rotation. Excel stores the angle as 0 to 90 (counter-clockwise), 91 to 180 (clockwise, α=90−d\alpha = 90 - d) and 255 (stacked, treated as 90 here). It is drawn rotated about the centre of the box.
  • Error cells. A cell that should carry something and stayed empty, or whose Excel formula could not be transferred, gets a translucent red (opacity 48/255) over its own fill and a red inner border. Its own colour therefore stays recognisable. Selecting the cell shows the reason in the status line.

Word: merges and header row

A table of the report tree has four kinds of columns: the vertical descriptor, the quantity, the unit and the values. Office Open XML has no row merge as an attribute of a cell, only a sequence: the first cell of a merge carries <w:vMerge w:val="restart"/>, each following one <w:vMerge/>. For row rr and the quantity column therefore

vMerge(r)={continuer merged with the row above,restartr+1 merged with r,noneotherwise.\text{vMerge}(r) = \begin{cases} \text{continue} & r \text{ merged with the row above},\\ \text{restart} & r + 1 \text{ merged with } r,\\ \text{none} & \text{otherwise.} \end{cases}

The descriptor is a single merge over all rows (first row restart, all further ones continue) with the text direction btLr, bottom to top as in the interface. The header row carries <w:tblHeader/> and repeats on every page. Word checks the order of the cell properties strictly (tcW, vMerge, shd, textDirection, vAlign); a continuation without a preceding restart is rejected as damaged.

PDF: tables across pages

The PDF path places the nodes one below the other. If the head of a table no longer fits on the page, it starts on the next one instead of leaving a lone header at the bottom. In the PDF the descriptor does not stand vertically but in the table heading; merged quantities appear with an empty name in the following rows.

How it is verified

  • Blattansichtprobe (BA, BW): mouse, shortcuts, headers, border kinds, widths, scrolling, clipboard without a screen, and the paths behind file choosers and fields of the cards.
  • Blattberichtprobe (R1 to R11): layout, filling from CSV, clipboard, selection around merges, rotation, saving, workspace state, help button, error cells, cases with a data sheet.
  • Docxprobe and Pdfprobe: document structure, merge groups, header row, page break.
  • Counter-probes rt14e-*, rt15-* and report-* in test/gegenproben.dat.

Limits

  • The width conversion holds for Excel's default font at 96 dpi; with a different default font in the workbook the width differs.
  • Stacked text (255) is drawn rotated by 90 degrees, not letter below letter.
  • Context menus, file choosers and the two dialog windows of the report tree (structure, cell format) need a screen and do not run in the probes; the paths behind them are tested as methods of their own.
