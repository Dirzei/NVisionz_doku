From the source reader to the image

How the system's device list becomes a running camera image: which threads do what, which format is chosen, how image rows are copied with a row stride and what happens on an error – always with a message, never with a second attempt.

Two kinds of threads

The system interface requires every thread to set up COM for itself and to start Media Foundation. Enumerating and reading formats therefore run on a thread of their own to which every request is handed; if it does not answer within 20 s, the message is "The camera does not answer". Every open camera has its reading thread, which opens source and source reader, reads and releases them again – all on the same thread.

COM is only uninitialised again if initialising succeeded. If the thread was already set up in another mode, the system reports that with an error code; uninitialising would then undo someone else's setup.

Whoever waits can be interrupted. The message is then "interrupted", the interrupt flag stays set and a half-opened camera is shut down. After closing, the camera accepts no further request.

Format choice

The camera lists its formats with subtype, size and frame rate. For each size and frame rate (to two decimals) the entry with the lowest rank remains:

RankSubtypeRoute
0NV12unchanged
1YUY2unchanged
2MJPEGthe source reader converts to NV12
3I420, IYUV, YV12, UYVYthe source reader converts to NV12
4RGB32unchanged, as ARGB
5RGB24the source reader converts to RGB32

Other subtypes, H.264 for instance, are dropped. NV12 needs even width and height, YUY2 an even width; a format that violates this is dropped as well. The list is sorted by pixels and then by frame rate, descending; the proposal is the first format with at least 15 frames per second.

A format that is not in the list is not opened: "format not offered". If the source reader delivers something other than NV12, YUY2 or RGB32 after setting the format, or does not name format and size, there is a message as well instead of guessing.

Rows with a stride

An image of nn rows of bb payload bytes each lies in the buffer with row stride ss; row rr starts at A+rsA + r\,s when AA is the top row. If ss is negative, the image is upside down: the top row is at the end of the buffer. The copy is tightly packed; it needs the range

u=min⁡(0,s(n−1)),U=|s|(n−1)+bu = \min\bigl(0,\ s\,(n-1)\bigr), \qquad U = |s|\,(n-1) + b

from address A+uA + u. A stride with |s|<b|s| < b is rejected, as is a buffer shorter than UU. For YUY2 with 16 × 8 pixels, b=32b = 32 and U=7⋅32+32=256U = 7 \cdot 32 + 32 = 256; if the camera reports 255 bytes, the message is "camera buffer too short: 255 instead of 256 bytes".

If the buffer offers a two-dimensional view, it names start and stride itself. Otherwise the stride comes from the media type, and with a negative stride the system hands out the lowest address; the top row then lies at Amin⁡+|s|(n−1)A_{\min} + |s|\,(n-1).

Reading and flags

Reading is synchronous, one sample per call. With every sample the source reader reports flags. An error ends reading with "The camera reports an error", the end of the stream with "The camera delivers no more images" – in both cases after exactly one read attempt, without restart. A format change makes the current format be read again; if the camera then no longer names a size, the message goes to the receiver.

Errors and messages

An error before the first image reaches the caller of open, a later one the receiver. An exception that is not a camera error becomes "camera error: …" with it as the cause. Then source reader and source are released and the reading thread ends.

System error codes are translated into sentences: blocked in the privacy settings, switched off by key or switch, disconnected, taken over or occupied by another program, not ready, format not available. Switched off in the camera's sense are only the cases triggered by a switch or the privacy setting; "taken over" and "occupied" are not among them.

If the source reader does not let the video stream be selected, it is not used; an error in the middle of the format list does not end it silently but is reported, and nothing stays cached.
