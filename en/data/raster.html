Slices, Grids and the Difference Plot – Background

The mathematics behind SliceExtractor, SliceSql, Regrid, GridSmoother, StructureCheck, Morph and Interp3D: how a table with many columns becomes a picture with three quantities, and how two data sets are compared without inventing values.

From the data set to the slice

A map usually has more than three quantities: speed, pressure ratio, mass flow, efficiency, plus ambient conditions. A contour plot always shows one surface f(x,y)f(x,y). The slice selects three columns (x,y,f)(x, y, f) from the table and restricts the rows: by constraints of the form column, operator, value (=, !=, >, >=, <, <=) and, for a volume f(x,y,z)f(x,y,z), by a z window z±hz \pm h around a fixed value. A slice carries for each point the number of its table row, so that exceptions and the comparison of two states can later rely on rows rather than on point numbers.

If the table does not fit into memory, it is not read and then filtered, but filtered and summarised at the same time. SliceSql generates queries that H2 runs itself. First the WHERE clause from constraints and z window (z BETWEEN z−h AND z+h, all identifiers quoted, numbers with twelve digits), then the classification into pixels with grid widths bxb_x, byb_y and origin (x0,y0)(x_0, y_0):

gx=ROUND⁡(x−x0bx),gy=ROUND⁡(y−y0by)g_x = \mathrm{ROUND}\!\left(\frac{x - x_0}{b_x}\right), \qquad g_y = \mathrm{ROUND}\!\left(\frac{y - y_0}{b_y}\right)

SELECT ROUND((x − x0)/bx) gx, ROUND((y − y0)/by) gy,
       AVG(x) x, AVG(y) y, AVG(f) f
FROM table WHERE …  GROUP BY gx, gy  ORDER BY gy, gx

Source: envisionz-framework-data/src/envisionz/data/slice/SliceSql.java, binned(...). Each class yields the means of xx, yy and ff; a picture with a million measurement points thus needs only as many points as it has pixels.

Grid or cloud?

StructureCheck answers the question on which it depends whether to contour directly or to triangulate first: do the points form a grid? Over the rows that satisfy all constraints it collects the distinct values per axis and the distinct tuples (x,y)(x,y) or (x,y,z)(x,y,z) and compares

expected=nxny(nz),present=|{(x,y,(z))}|,complete⟺present=expected>0.\text{expected} = n_x\,n_y\,(n_z), \qquad \text{present} = |\{(x,y,(z))\}|, \qquad \text{complete} \iff \text{present} = \text{expected} > 0.

In addition AxisInfo per axis: number of values, minimum, maximum and whether they are equidistant. The step is Δ=(max⁡−min⁡)/(n−1)\Delta = (\max - \min)/(n-1); equidistant means that every spacing deviates from Δ\Delta by at most max⁡(10−12,εrel⁡|max⁡−min⁡|)\max(10^{-12},\ \varepsilon_{\mathrm{rel}}\,|\max-\min|). Rows with unreadable numbers are skipped; numbers are read through Zahlenleser.heute.

ParameterStats gives per column the count, distinct values (up to a cap), minimum and maximum, and the criterion for "empty column".

Scattered points onto a grid: inverse distance weighting

A contour plot on a grid needs a value at every grid point. Regrid determines it, following Shepard, as a weighted mean of the points in the neighbourhood, weight 1/dp1/d^p with distance dd:

F(c→)=∑iwiFi∑iwi,wi=1dip,di=|x→i−c→|.F(\vec{c}) = \frac{\sum_i w_i F_i}{\sum_i w_i}, \qquad w_i = \frac{1}{d_i^{\,p}}, \qquad d_i = |\vec{x}_i - \vec{c}|.

The mean is a convex combination: the result never lies outside the range of the input values, unlike with polynomial methods. If a point falls on the grid point (d2<10−18d^2 < 10^{-18}), its value is taken unchanged. Defaults (RegridOptions.defaults()): grid 200 × 200, exponent p=2p = 2, search radius 2.5 cells, smoothing off.

Pseudocode – Regrid.toGrid(slice, options)

if the slice is empty:  return empty grid
(minX, maxX), (minY, maxY) ← spans of the points
dx ← (maxX − minX)/(nx − 1);  dy ← (maxY − minY)/(ny − 1)  span never smaller than 1e-12
for each point:  put it in the bucket of the nearest cell (rounded)  bucket index
rBase ← max(1, ⌈search radius⌉)  default: 3 cells
for each cell (i, j) with centre c:
    r ← rBase
    repeat:
        numerator, denominator ← 0
        for each point p in the buckets |Δi| ≤ r, |Δj| ≤ r:
            d² ← |p − c|²
            if d² < 1e-18:  cell ← F[p];  done  exact hit
            w ← 1 / d²^(p/2);  numerator += w·F[p];  denominator += w
        if points found:  cell ← numerator/denominator;  done
        if r ≥ max(nx, ny):  cell stays empty (NaN);  done
        r ← min(2r, max(nx, ny))  double the radius, finally the whole grid
if σ > 0:  GridSmoother.gaussian(grid, σ)

Source: envisionz-framework-data/src/envisionz/data/slice/Regrid.java. The bucket index makes the search per cell independent of the total number of points; only when the radius grows are more buckets read.

Decision in the framework: The search radius doubles (3, 6, 12, …), and the last attempt is exactly the grid size. An earlier version ended the search as soon as the radius exceeded the grid size without ever having searched with it; on 40 × 40 cells 450 of 1600 stayed empty although points existed. Every cell now gets a value as soon as there is any point at all.

Smoothing without closing gaps

GridSmoother.gaussian(g, σ) smooths with a Gaussian kernel, separated into x and y. The kernel has half-radius ⌈3σ⌉\lceil 3\sigma\rceil (at least 1), is normalised and reads

kt=e−t2/(2σ2)∑se−s2/(2σ2),t=−⌈3σ⌉,…,⌈3σ⌉.k_t = \frac{e^{-t^2/(2\sigma^2)}}{\sum_s e^{-s^2/(2\sigma^2)}}, \qquad t = -\lceil 3\sigma\rceil,\dots,\lceil 3\sigma\rceil.

Empty cells (NaN) do not contribute, the weight of the others is renormalised (∑ktvt/∑kt\sum k_t v_t / \sum k_t), and at the grid edge the missing neighbours are treated likewise. A linear trend is thereby preserved in the interior.

Decision in the framework: Holes stay empty. An earlier version silently filled a hole from the valid neighbours although the description only said that empty cells do not contribute – a smoothing that closes measurement gaps on the side invents values. Whoever wants the holes filled says so with gaussian(g, σ, true); the valid cells are computed the same either way.

Difference plot of two data sets

Showing two calculation states or measurement campaigns as a difference contour needs, for every point of state A, the matching point of state B. Morph does not match through the geometry of triangles but through key columns (say speed level and measurement point number) or, failing that, through the location – so the result is measured and not interpolated, and the whole contour path runs unchanged on top of it.

Morph.paare(A, B, keyA, keyB, tolerance):
    ka ← keyA, otherwise location key (x, y) of A;  kb likewise for B
    cell ← tolerance if > 0, else 0  at 0 the key itself is the bucket
    buckets ← every key of B in the raster bucket of its cell
    for each i in A:
        candidates ← bucket of ka[i] and all neighbouring buckets
        for each candidate j with |ka[i] − kb[j]| ≤ tolerance in every column:
            count += 1;  first hit becomes the partner
        partner[i] ← hit or −1;  also count withoutPartner, ambiguous

Morph.rechne(A, B, pairing, quantity, threshold):
    for each i with partner j, neither value NaN:
        if quantity ≠ DIFFERENZ and |A_i| < threshold:  skip, count  a division near zero is no statement
        DIFFERENZ:  B − A       RELATIV:  (B − A)/A · 100       VERHAELTNIS:  B / A

Source: envisionz-framework-data/src/envisionz/data/vergleich/Morph.java. Thanks to the raster bucket the matching is linear in the number of points instead of quadratic; the neighbouring buckets are read as well so that a pair is not lost at a bucket boundary.

Decision in the framework: The direction is fixed B−AB - A, and what is shown is selectable, because for a map it is not cosmetic: Δη=+0.01\Delta\eta = +0.01 is one percentage point, Δη/η\Delta\eta/\eta at η=0.85\eta = 0.85 however +1.18 %, and both are called "percent". The unit belongs written out on the colour scale (Morph.einheit). The choice of key is mandatory, because the row numbers of a slice assign the same row in two slices, but not the rows of two subsets (Var1 = 0 against Var1 = 1) that consist of different rows. An interpolation of the comparison onto the mesh of state A is deliberately not built: it would deliver partly computed instead of measured values.

Interpolation in space

Interp3D supplies two building blocks for values between support points. On a regular grid, trilinear interpolation: with the fractions tx,ty,tz∈[0,1]t_x, t_y, t_z \in [0,1] in the cell the values are mixed linearly first in x, then in y, then in z:

f=lerp⁡(lerp⁡(lerp⁡(c000,c100,tx),lerp⁡(c010,c110,tx),ty),lerp⁡(…),tz),lerp⁡(a,b,t)=a+(b−a)t.f = \mathrm{lerp}\big(\mathrm{lerp}(\mathrm{lerp}(c_{000},c_{100},t_x),\ \mathrm{lerp}(c_{010},c_{110},t_x),\ t_y),\ \mathrm{lerp}(\dots),\ t_z\big), \qquad \mathrm{lerp}(a,b,t) = a + (b-a)\,t.

Outside the axes the fraction is limited to [0,1][0,1] (edge clamping), so there is no extrapolation. In a point cloud the same weighting applies as in Regrid, in three dimensions (inverseDistance, exponent freely selectable); on an exact hit its value is returned.

Decision in the framework: Interp3D has no caller outside the tests today; it is there as a building block. One-dimensional Akima interpolation has lived in framework-math since 27.09.2026, no longer here.

How it is checked

  • Rasterprobe: IDW as a convex combination, the Gaussian kernel preserves linear fields in the interior, trilinear reproduces affine fields exactly, Shepard computed by hand. The early search-radius gap (450 of 1600 empty cells) and the silent hole filling are recorded as checks.
  • Schnittprobe (36 checks): the six operators against BigDecimal, row numbers, the number of discarded rows. Kennzahlprobe (38): count, distinct values, minimum, maximum, equidistant, grid or cloud.
  • The tests come with counter-experiments: the old fault is built back in and must turn red.

Limits

  • IDW is a pure distance method: it knows no direction and no trend, forms flat plateaus at the points and shows the means between widely separated points. It never exceeds the value range of the data, but it does not invent peaks either.
  • A single point anywhere in the grid is enough to fill a cell; where the measurement has a gap there is a value anyway. The boundary methods of the triangulation are the way to leave such regions out.
  • The relative deviation in the difference plot is useless for AA near zero; such points below the threshold are skipped and counted, not computed large.
  • SliceSql classifies into pixels; what happens inside a pixel is averaged away by AVG.
