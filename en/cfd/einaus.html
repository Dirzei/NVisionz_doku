Input and output – meshes, cases, results

How meshes from Gmsh, CGNS, PLOT3D and the multi-block grids of m-ACHIEVE become a face-based mesh, how a case is read from achieve.inp, what a VTK output contains and how a computation is continued: as a restart on another mesh or bit-identically from a checkpoint – with the rules, checks and limits.

What this is about

The solver knows only one mesh form: flat arrays of nodes, cells and faces, with owner and neighbour per face (mesh and geometry). Everything that comes in is brought into this form when it is read; everything that goes out is made from it. Three ways lead out of a computation and back in:

The content decides the format

Netzleser decides by the content of the file, never by the extension: the eight signature bytes of HDF5 mean CGNS, $MeshFormat means Gmsh, a folder or an achieve.grd with the companion achieve.blk is an m-ACHIEVE case, otherwise PLOT3D is tried. The old ADF format of CGNS is rejected with a hint to convert it. Planar meshes (2D) become a cell layer of thickness dicke in all formats, whose top and bottom faces are the boundary symmetrie; the orientation in the file does not matter, because the mesh builder points every face away from its owner.

Gmsh and CGNS

Gmsh (2.2 and 4.1): volume elements become cells, named face groups boundaries. Higher-order elements are rejected, not linearised.

CGNS (via HDF5): structured zones go through the same builder as the block grids (below), unstructured ones with linear elements, also mixed (MIXED). A boundary face is named after the boundary condition that lists it by element number, otherwise after a boundary condition by nodes (all nodes of the face in the list), otherwise after its element section. The boundary kind follows the BCType (wall, inlet, outlet, far field, symmetry; resolved through families); without a match it stays open and is reported. Nodes of several zones are merged when they are closer than 10−910^{-9} of the domain size. NGON, higher-order elements, cylindrical and spherical coordinates are rejected; periodic and non-matching connections are named as a note, not taken over.

Block grids: PLOT3D and merging

A structured block with ni×nj×nkn_i \times n_j \times n_k nodes gives (ni−1)(nj−1)(nk−1)(n_i - 1)(n_j - 1)(n_k - 1) hexahedra. Where blocks touch, they carry the same nodes twice on the common side. Blocknetz merges nodes closer than 10−910^{-9} of the domain size; the sides at a block interface thereby become interior faces without anyone having to name the interface. The remaining sides are named b<n>-imin to -kmax. Collapsed cells (a block with only one point in a direction) are rejected. Every cell keeps its position (block, i,j,ki, j, k) as structure information.

Cases from m-ACHIEVE

Mesh (achieve.blk, achieve.grd): per block the nodes, per side sections with a boundary kind. Every section becomes a boundary b<block>-s<side>; if the file uses the same number twice, the boundaries are named in file order. Block interfaces go through common nodes. The nodes are multiplied by rscale from achieve.inp, as m-ACHIEVE does; the thickness of the cell layer stays as given. Special kinds:

  • Periodic (kind 11 and shifted block interfaces of kind 4): pairs via the partner side, shift from the node mean, nodes cross-checked in the same or reverse order.
  • Gaps: cells of a side without a section become their own boundary with the fixed free-stream state, with a note.
  • Sliding interfaces (kinds 121 to 124) between rotor and stator blocks: paired, frame velocity from vtrans times the reference speed of sound (sliding interface).
  • Jet (kind 8): the jet cells become their own boundary with fixed state and composition.

Case (achieve.inp): inflow (Mach number, angle, total pressure, total temperature, back pressure pout=p/(γ0p0)p_{out} = p/(\gamma_0\,p_0)), gas constant from the molar mass, viscosity and turbulence model. It is read via the name lines; decks without name lines by the position of the records, as Fortran reads them from the front with read(2,*) – a stray record after the end is then never seen. The Reynolds number of the deck applies at the reference Mach number per unit length after scaling and is converted to the inflow. The gas model follows i_rg: 2 perfect gas, 0 only the ideal-gas part of AGA8 (cp(T)c_p(T) of the composition), 1 AGA8 with the composition from gascomp.inp.

Output as VTK

A result is a VTK file in the legacy format (UNSTRUCTURED_GRID, text or binary): nodes, cells in VTK node order, per cell the fields density, velocity, pressure, Mach number, temperature and – depending on the model – mass fractions and turbulence quantities, plus always the cell centre (for the restart, which does not read the cells themselves). The boundary faces go out separately as POLYDATA with the boundary number. A cell value of wrong length is rejected, not truncated.

Orientation of the cells (since 2026-11-12). The solver accepts cells of either handedness – the mesh builder orients the faces itself –, and several generators rely on that: cylinder, sector, Ringleb, the blade passage, the pyramids of the box and the tetrahedral mesh create left-handed cells, and every prism follows the Gmsh and CGNS convention. VTK requires the opposite for the wedge (the normal of 0-1-2 points away from triangle 3-4-5). A foreign viewer showed such cells with negative volume and inward normals. The writers therefore compute each cell's volume with Gauss' theorem over the outward faces of the VTK order, V=16∑a⋅(b×c)V = \tfrac16\sum \mathbf a\cdot(\mathbf b\times\mathbf c), and mirror the cell when V<0V < 0 (bottom and top traversed the other way). The same holds for CGNS, except that the prism (PENTA_6) runs opposite to the VTK wedge. Node positions and cell values stay bit-identical; only the node order per cell changes.

Duplicate nodes are intended. Two generators create nodes at the same position with different numbers, both as separating surfaces: the flat-plate cascade along the plate without thickness (the cells above use the copy, both sides are boundary schaufel), and the stage at the mixing plane (two blocks with their own pitch, boundaries mischung_a and mischung_b) where the pitches meet. A viewer that merges them turns them wrongly into interior faces.

Cutting a 3D mesh

For images and measuring planes, Schnitt cuts the mesh with a plane (x−x0)⋅n=0(\mathbf x - \mathbf x_0)\cdot\mathbf n = 0. For every node the distance s=(x−x0)⋅ns = (\mathbf x - \mathbf x_0)\cdot\mathbf n is computed; an edge with a change of sign is split at t=sp/(sp−sr)t = s_p/(s_p - s_r), a node with |s|≤ε|s| \le \varepsilon lies on the plane itself. Each cell face gives one or more segments; chained over their common end points they form closed loops – one polygon per piece, also for non-convex cells cut by the plane in several pieces.

If one face carries several segments, they are paired: on a planar face along the cutting line, on a warped one by the value at the face centre (there the cut is a hyperbola with two branches). If the segments do not close, Schnitt falls back to ordering the cut points around their centroid. This is exact only for convex cells; with the meshes of the own generators and readers the case does not occur.

Restart on another mesh

A restart reads density, velocity, pressure and, where present, mass fractions and temperature of an earlier VTK output and transfers them onto the mesh of the new run. Uebertragung finds for every target cell the kk nearest source cells (via a search grid) and fits a local thin-plate spline with linear part through them:

s(x)=∑j=1kλjϕ(|x−xj|)+a0+a⋅x,ϕ(r)=r2ln⁡r,s(\mathbf x) = \sum_{j=1}^{k} \lambda_j\,\phi(|\mathbf x - \mathbf x_j|) + a_0 + \mathbf a\cdot\mathbf x, \qquad \phi(r) = r^2\ln r,

with the constraints ∑λj=0\sum\lambda_j = 0, ∑λjxj=0\sum\lambda_j\mathbf x_j = 0. The linear part makes the transfer exact for linear fields – on the same as on a finer mesh –, and smooth fields are transferred with order 2. Density and pressure are limited from below to a tenth of the smallest source value, because the thin plate can overshoot at shocks; this is reported. Mass fractions stay non-negative with sum 1. Turbulence quantities start at the free stream. With temperature and mesh scale see boundaries with a real gas.

Checkpoint and bit-identical continuation

A checkpoint (-sichern:) holds the whole state of a computation: conserved quantities, the time levels of the dual time stepping, CFL and residual reference, turbulence and species quantities, the eddy viscosity and the fluxes of the last residual (some turbulence models read the flow direction at free boundaries from them before the residual recomputes them). Every class with state writes and reads its part in the same method. The mesh is recognised by cell count, face count and volume sum; another mesh, a missing entry or a truncated file is rejected. Continued (-fortsetzen:), the run then goes on bit-identically, as if it had never been interrupted.

How it is checked

  • Eingabeprobe: Gmsh 2.2 with all four cell kinds (volume 7/4), Gmsh 4.1 as a planar mesh, PLOT3D with two blocks, VTK text and binary read back bit-identically.
  • Cgnsnetzprobe (CN-01 … 09): six anchors made with an independent tool; structured and unstructured, boundaries by elements and nodes, two bases, boundary kinds, recognition by content, 150 corrupted files cleanly rejected.
  • Brueckenprobe (PB2-12 … 15), Achieveprobe (all cases of the example collection), Uebertragungsprobe (SN14-U1 … U5), Neustartprobe, Uebernahmeprobe (SN22-04: continued against uninterrupted, bit-identical for all models).

Limits

  • Only linear elements; higher-order elements and polyhedra (NGON) are rejected.
  • CGNS without cylindrical coordinates, without overset; periodic connections from the file are not taken over but set with -periodisch:.
  • The transfer is not conservative: mass and energy of the transferred field agree only up to the interpolation error. For a mesh refinement that must conserve, there is the conservative transfer of the refinement (mesh).
  • If the thin plate is singular for a target cell (source cells in a degenerate position), the transfer falls back to inverse-distance weighting of the same neighbours – no longer exact for linear fields.
  • A checkpoint is valid only for the same mesh and the same case; it is not an exchange format.
