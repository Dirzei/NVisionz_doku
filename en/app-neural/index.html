envisionz-app-neural

Neural networks for measured data and text, with judgement

Overview of the app, as of 29 September 2026. The user interface for the framework module neural: load tabular data, search, train and evaluate networks, and provide the result as a surrogate model for other apps. A second workflow trains small language models on one's own texts.

18source files in 4 packages
2workflows: surrogate model and sequence model
4optimisers: Adam, AdamW, SGD with momentum, L-BFGS
3learning-rate schedules: exponential, cosine, 1-cycle
> 230checks in nine probes
7help pages, German and English

What the app is for

Some calculations are too slow to repeat a thousand times: a flow simulation, a map model, a design calculation. A surrogate model is a small neural network that learns from existing results and then answers in microseconds. The app takes engineers from the table to a usable model without programming: load data, assign roles to columns, choose network and training, check the result.

The emphasis is on judgement, not on button positions. The help pages and the evaluation explain when a surrogate pays off and when interpolation is better, why R² flatters when the target scatters widely, why a random split looks too good on grid data, and that a network extrapolates smoothly and confidently outside its training data without saying so.

What it can do

Data and roles

Tables come from CSV files or from a database. Every column gets a role.

  • Roles: ignore, input, target or label. At least one target without a label is a regression; exactly one label column is a classification. Roles are tied to the column name and survive re-reading.
  • An optional row filter selects training rows (column, comparison, value, combined with AND).
  • Reading is strict: an empty or non-numeric cell aborts with column name and row instead of silently becoming zero. A decimal comma is understood, a mixed format such as “1.234,5” is rejected as ambiguous.

Model and training

Network structure and training run with a live loss curve.

  • Hidden layers, activation, initialisation, seed, normalisation and dropout are adjustable.
  • Optimisers Adam, AdamW, SGD with momentum and L-BFGS (whole data set per step); learning-rate schedule exponential, cosine or 1-cycle; epochs, batch size, training share and early stopping.
  • Ensemble: the same network several times with different seeds. The mean is usually a little better, but above all the spread between the members shows the uncertainty of the prediction; outside the training data it is several times larger.
  • Quantile regression: three models for 10, 50 and 90 percent give a band. It describes the spread of the data, not the uncertainty of the model; the two can be chosen separately.
  • Number fields accept with Enter, discard with Escape and show an unreadable number in red; the default value is shown beside them. Training can be stopped at any time.

Model search

Instead of guessing, the app tries settings out.

  • Grid search or random search (learning rate and weight decay log-distributed), cross-validation in parallel over the candidates.
  • The result table grows live and can be sorted; “take over spec” puts the settings into model and training. Works for classification too.

Evaluation

Quality measures, plots and the question of how the outputs depend on the inputs.

  • Per output R², RMSE and MAE, prediction against measurement, residuals; for classification the confusion matrix.
  • Slices along one quantity and contour plots over two, with a band for ensembles and quantiles.
  • Sensitivity: model-free before training (S1 over value ranges, Spearman), Sobol indices (S1, total, interaction) and permutation importance afterwards.
  • Test data set: a separate CSV is matched by column names. The verdict reads “generalises well”, “slight” or “marked overfitting” and appears with a table in the display, for classification with accuracy and confusion matrix. The test residuals appear in the residual plot as a second series.

Sequence model

A second workflow, switchable in the tool bar. It trains a small language model on one's own texts, with framework-autograd as the compute core.

  • Steps: corpus, tokeniser, model, training, sample. Every step is complete; there are no empty placeholders.
  • The model shares embedding and output layer (the matrix appears once in the parameter list). Model width and head count are checked before building.
  • Sample: the model continues text, with temperature, top-k and seed; the same seed gives the same text. A button speaks it with the rule-based voice of framework-voice.

Data and formats

  • Reading: CSV and database tables; a separate CSV for the test.
  • Models: .ennet, the model format of the framework module (with column names and quality figures as description). The app saves and loads it; sequence models have weight files of their own.
  • Working state: training, search and roles are saved with the workspace.
  • Hand-over: after every training and every load the model is published as an event and made available through a service. app-maps takes it up in expressions of the form SUR(…).

What it is built on

  • framework-neural: fixed-topology networks, optimisers, cross-validation, sensitivity and the model format. The app is only the user interface for it.
  • framework-autograd: arbitrary computation graphs for the sequence model.
  • framework-voice: the voice for the listening sample.
  • framework-data: loading CSV and database tables.
  • framework-swing: user interface, charts, input fields.
  • framework-core and framework-api: registration as an app, services, events and saving of the working state.

Status and limits

The path from table to published model is complete, and so is the sequence workflow up to the listening sample. The probes name 17 of 17 classes; among other things they check the test evaluation against independently computed values and the filter operators.

Deliberate limits: the row filter works on numeric columns only. Class targets are not normalised, and the app chooses the loss function itself for classification. The listening sample uses a rule-based voice, not a learned one.
