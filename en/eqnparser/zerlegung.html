Block ordering and pre-initialisation – background

How BlockOrdnung decomposes an equation system into a solution order (matching, Tarjan) and how AutoInitSweep computes a consistent starting value from it; with an honest delimitation from tearing.

What this is about

Large networks – an engine of dozens of components, an air system with hundreds of streams – have hundreds to thousands of equations. Usually the solver fails not at the equation but at the start: a pressure of 0 or a mass flow with the wrong sign, and the thermodynamic calls return nothing usable. Whoever puts the equations into the order "first this, then that" by hand has rebuilt the calculation sequence of a classical program. That order can be read from the equation system itself.

The framework does this in two steps: BlockOrdnung decomposes the system into blocks with a fixed order, AutoInitSweep solves the small blocks one by one and thereby hands the global solver a consistent starting value. The global method itself stays unchanged (Newton method).

Structure of an equation system

A table records which equation contains which variable (incidence matrix). Each equation is assigned one variable for which it is imagined to be "solved" (matching); each variable belongs to at most one equation. Equation ii then depends on equation jj if it uses a variable that belongs to jj. This gives a directed dependency graph on the equations.

A cycle in this graph is called an algebraic loop: the equations involved must be solved together. The maximal cycles (strongly connected components) are the blocks. Between the blocks there are no cycles left; they can be ordered so that every block depends only on earlier ones. In the incidence matrix this appears as block-triangular form.

The methods as implemented

1. Matching

First the LHS heuristic: if exactly one free variable stands left of the equals sign (VAR = … or CALL(VAR) = …), it belongs to that equation. This covers the typical models almost completely. All remaining equations are assigned by Kuhn augmentation: one tries to give the equation a free variable from its incidence; if it is taken already, one tries to give the previous owner another one (alternating path). Equations or variables without a partner are counted and reported.

2. Decomposition by Tarjan

The Tarjan algorithm finds all strongly connected components in one depth-first pass in time proportional to nodes plus edges. It delivers them in reverse topological order; the list is reversed so that dependencies come first. The implementation uses an explicit stack instead of recursion and therefore copes with chains of thousands of equations. A 1×1 block is an explicit assignment or a local one-dimensional problem, larger blocks are genuine algebraic loops.

3. The sweep

The AutoInitSweep walks through the blocks in solution order and works on the physical value table:

  • 1×1 block: one-dimensional Newton method with difference quotient h=max⁡(10−6|x|,10−8)h=\max(10^{-6}|x|,10^{-8}), step limited to ten times max⁡(1,|x|)\max(1,|x|), clamped to the variable bounds.
  • Block up to size 8: small Newton method with a difference Jacobian and direct solve (MatrixSimple.solveLinear).
  • Larger blocks: skipped – that is the global problem and belongs to the main solver; the sweep gives it a consistent environment. Optionally (autoInitGross) they are pre-initialised with a damped Gauss-Seidel pass: at most 8 rounds, in each round one one-dimensional Newton step per equation on its assigned variable (15 iterations), stop at less than 1 % progress; only the best state reached is kept.
Convention in the framework: INITIALIZE takes precedence. A block that contains a variable set by INITIALIZE is not touched; what the user specifies holds. If a block fails, its values are reset, the block is noted in the log, and the global solver starts anyway. The block size limit for local mini-solves is 8; the iteration limits are 60 (one-dimensional) and 40 (block). Convergence in a block: largest residual ≤10−10⋅max⁡(1,start residual)\le 10^{-10}\cdot\max(1,\text{start residual}), at the end more generously 10−810^{-8}.

Pseudocode – BlockOrdnung.analysiere and AutoInitSweep.ausfuehren

// matching
for each equation i: candidate[i] ← free variable left of "=" (VAR = … or CALL(VAR) = …), otherwise none
for each equation i with candidate k, if k still free: assign (i, k)
for each still unassigned equation i: kuhnAugment(i, visited = ∅)

kuhnAugment(i, visited):
    for each variable k of the incidence of i, not in visited:
        mark k visited
        if k free or kuhnAugment(owner(k), visited): assign (i, k);  return true
    return false

// dependency graph and blocks
for each equation i, each variable k in it, j ← owner(k), j ≠ i:  edge j → i
sccs ← tarjan(graph)                         iterative, explicit stack
blocks ← reversed order of sccs              dependencies first

// sweep
for each block b in solution order:
    if |b| > 8:  (if autoInitGross: Gauss-Seidel pre-initialisation);  continue
    if b contains an INITIALIZE variable:  continue
    ok ← if |b| = 1: newton1D(b)  else newtonBlock(b)
    if not ok: reset the values of the block;  note in the log

Worked example

For X+Y = 3, X−Y = 1, Z = 2X the LHS heuristic finds a variable only for the third equation (Z); the first two have an expression on the left and are assigned by Kuhn augmentation. E1 and E2 both use XX and YY and each owns one of them, so they depend on each other: a block of size 2. E3 uses XX, whose owner lies in that block, so E3 comes after. The sweep first solves X+Y=3,X−Y=1X+Y=3,\; X-Y=1 (solution X=2,Y=1X=2,\;Y=1) and then Z=2X=4Z=2X=4. The probe binds this model as text and checks the decomposition without solving.

How it is tested

SkalierungSelfTest (35 checks) contains the checks for BlockOrdnung; the models (X*X = 2, Y = X + 1 with two 1×1 blocks, and the one above) are bound as NFML text, not solved. For each class named there is a red counter-experiment: a copy of the class with exactly one behaviour change that makes the probe fail. A separate probe for AutoInitSweep does not exist so far.

Limits

  • Tearing in the strict sense (choosing a small set of "tear variables" that turns a large loop into a sequence of simple calculations) is not implemented; a block Newton method on the block order is listed as a candidate in the design notes. Large loops are solved by the global solver as a whole; the optional Gauss-Seidel pass is only a pre-initialisation.
  • The matching is a heuristic plus simple assignment; it takes neither derivative numerics nor bounds into account. Equations without a partner (structurally over-determined or singular) are reported, not repaired.
  • Conditional equations (IF/ELSE) enter the structure with their variable incidence; a branch switched later can change the order, the sweep sees only the state at the start.
  • Blocks with INITIALIZE variables stay untouched, even if the specified value is poor.
