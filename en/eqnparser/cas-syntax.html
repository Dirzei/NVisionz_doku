CAS Syntax – Reference

The classic input format .cas in grammar form: lexical rules, procedure and variable blocks, declarations, start values, the equation part with FOR and IF, quirks of the legacy parser and the path to NFML, with a complete example.

Role and notation

CAS (file extension .cas) is the classic input format of the NVISIONZ equation solver. It is kept as a legacy and reference path next to NFML: the parser switch decides by file extension, and everything except .nfml goes through the CAS parser. This reference gives the grammar as the legacy parser actually accepts it (reconstructed from an analysis of the parser and checked against a test corpus).

Notation as in the NFML syntax reference: from { } choose one element, [ ] may be omitted, | separates alternatives. Bold marks keywords and characters that appear literally in the text, including square brackets that are really written. Keywords and identifiers are case-insensitive; statements end with ; and may span several lines. Unit, Description and Latex are purely documentary.

Sections may appear in any order: the parser reads the file twice, first variables and procedures, then the equations.

Expressions and functions

An expression is opaque to the grammar: it extends to the next ; and is evaluated by the legacy evaluation chain. The operators + - * / ^ and parentheses are allowed; ^ is right-associative, and -x^2 = -(x^2) holds.

PROCEDURE – calling a built-in

PROCEDURE proc_name
  CALL : builtin_name ;
  INPUTS : REAL { , REAL } ;
  OUTPUTS : REAL ;
END

proc_name    → ident                        (convention: p + built-in name)
builtin_name → name from the built-in registry (identical to NFML, see the NFML syntax reference)

The name relhumfar25 is not registered.

VARIABLE and declarations

Long form: a user-defined type.

VARIABLE dottedName
  { { LOWER | VALUE | UPPER } : value ;  |  UNIT : string ; }
END

Short form (recommended):

declaration → dottedName [ [ arraySize ] ] AS typeRef [ ( attr { , attr } ) ] ;
            | ident AS INTEGERPARAMETER ( integer ) ;
typeRef     → REAL | ident                   (ident = name of a VARIABLE type block)
attr        → Description: string | Lower: value | Upper: value
            | Value: { value | [ value { , value } ] }
            | Spec: spec_name | Unit: string | Latex: string

Arrays are 0-based: A[N] is A[0] … A[N-1]; Value: [list] fills element by element. Missing attributes get the defaults 0, 0, 0 and FREE.

INITIALIZE – start values

INITIALIZE
  { initStmt }
{ ENDINIT | END }

initStmt → equationStmt | callStmt | initIf
           (the target may also be dottedName.Lower or dottedName.Upper: bound override)
initIf   → IF ( initCond ) { initStmt } [ ELSE { initStmt } ] ENDIF
initCond → specCond | intCond | ( { specCond | intCond } ) { AND | && } ( { specCond | intCond } )
specCond → dottedName.SPEC == spec_name
intCond  → operand relOp operand            (constant after INTEGERPARAMETER substitution)

Evaluation follows file order; right-hand sides may reference variables (values from the declaration).

Equation part

equationStmt → [ EQN-eqnId : ] expression = expression ;
               (residual LHS − RHS; NO chained equations in legacy CAS)
callStmt     → [ EQN-eqnId : ] CALL ( dottedName ) = proc_name ( dottedName { , dottedName } ) ;
               (inputs must be variables; count as declared in INPUTS)
forBlock     → FOR ( ident = integer ; ident { <= | < } { integer | ident } )
                 { equationStmt | ifBlock }
               ENDFOR
               (loop variable ONE character; no nested FOR;
                index expressions such as [i-1] are constant-folded)
ifBlock      → IF ( condition ) einZweig { ELSEIF ( condition ) einZweig } [ ELSE einZweig ] ENDIF
einZweig     → equationStmt | callStmt
               (run-time IF: exactly ONE statement per branch, no nesting; ELSEIF is sugar for ELSE IF)
condition    → operand relOp operand | specCond
specStmt     → ident.SPEC = spec_name ;
               (only UNDOTTED names; acts array-wide, only in structural branches)

If the IF condition is constant at parse time (Fixed quantities, INTEGERPARAMETER, specCond), it is folded structurally: only the active branch remains, and unlike the run-time IF it may contain several statements, including FOR blocks and spec statements.

Quirks and the path to NFML

  • A FOR loop whose upper limit is not above its lower limit silently creates no equation.
  • Unit, Description and Latex are purely documentary.
  • Old .cas models without VARIABLE and PROCEDURE blocks are, as a rule, valid flat NFML models unchanged. When porting, a VARIABLE block becomes the short form AS REAL, and the procedure name pName becomes the built-in name NAME.

Example

Intersection of a circle with a line (solution X=4,Y=3X=4,\ Y=3) and a sequence of values built by a loop: five free quantities, five equations. Because only short-form declarations occur, the file is at the same time a valid flat NFML model.

// circle and line, plus a sequence A[i] = 1.5 * A[i-1]
R AS REAL (Value: 5.0, Lower: 0.0, Upper: 100.0, Spec: Fixed, Unit: "m");
X AS REAL (Value: 1.0, Lower: 0.0, Upper: 10.0);
Y AS REAL (Value: 1.0, Lower: 0.0, Upper: 10.0);
N AS INTEGERPARAMETER(3);
A[N] AS REAL (Value: [1.0, 1.0, 1.0], Lower: 0.0, Upper: 100.0);

EQN-1: X^2 + Y^2 = R^2;
EQN-2: Y = 0.75 * X;
A[0] = 2.0;
FOR (i = 1; i < N)
  A[i] = A[i-1] * 1.5;
ENDFOR
