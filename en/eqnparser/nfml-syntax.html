NFML Syntax – Reference

The input language .nfml in grammar form: lexical rules, flowsheet level (stream types, models, macros, plant), model level (equations, loops, conditions), built-in functions and the .task run language, with a complete example.

Notation and scope

NFML (NVISIONZ Flowsheet Modeling Language, file extension .nfml) is the equation-oriented modelling language of the NVISIONZ equation solver, modelled on equation-oriented input languages of process simulation. This reference gives the language as the two parser stages actually accept it: the flowsheet level and the model level.

Notation of the grammar blocks: from { } choose one element, [ ] may be omitted, | separates alternatives, and { … } with an ellipsis means repeated any number of times, separated by the given separator. Bold marks keywords and characters that appear literally in the text; this includes square brackets that are really written (index, attribute list), as opposed to the meta brackets. Keywords and identifiers are case-insensitive (internally upper case); statements end with ; and may contain line breaks. Unit, Description and Latex are purely documentary; there is no unit arithmetic.

Comments and basic terms

Comments:

Basic terms of the grammar:

EndMark    → $END [ Kommentar ]
ident      → character string (letter or _, then letters, digits, _); case-insensitive
qname      → ident { . ident } [ [ index ] ]
value      → integer | real                    (3, 3., .5, 1.5e-4)
string     → "Zeichenband"
spec_name  → Free | Fixed
attr_name  → Value | Lower | Upper | Spec | Unit | Description | Latex | Start
vergleich  → == | != | <> | < | <= | > | >= | .EQ. | .NE. | .LT. | .LE. | .GT. | .GE.
attrs      → value | attr_name : { [ - ] value | string | spec_name | expression } { , … }
             (a bare (3) means (Value: 3))
groesse    → build-time expression of integer, INTEGERPARAMETER and SET constants  (4, N, N+1)

Expressions and conditions

expression    → ( expression ) | { + | - } expression
              | expression { + | - | * | / | ^ } expression
              | value | qname | stdfct ( expression ) | binfct ( expression , … )
log_condition → ( log_condition ) | NOT log_condition
              | log_condition { AND | OR } log_condition
              | expression vergleich expression
              | qname.spec == spec_name

INCLUDE and TITLE

INCLUDE "pfad" ;
TITLE free-text-to-end-of-line

INCLUDE takes over the DECLARE, MODEL and MACRO blocks of the library file; TITLE and PLANT stay behind. The path is relative to the including file. Repeated and circular inclusion are silently skipped (the root file counts as included), nesting goes to depth 16, and INCLUDE has no effect inside block comments.

DECLARE – stream types

DECLARE
  { STREAM stream_type ( feld { : feld } ) ; }
EndMark

stream_type → ident
feld        → ident [ [ attrs ] ]

Field attributes replace the defaults of the flattener (Value 1, bounds ±1012\pm 10^{12}).

MODEL – models

MODEL model_name
  [ SET ident [ [ groesse ] ] = value { , … } ; ]
  [ STREAM { { INPUT | OUTPUT } : port_name [ [ groesse ] ] ( stream_type ) ; } ]
  [ TYPE { REAL [ ( attrs ) ] : ident [ [ groesse ] ] { , … } ; } ]
  [ EQUATION { anweisung } ]
  [ INITIALIZE { anweisung } ENDINIT ]
EndMark

model_name → ident
port_name  → ident
Start:     expression in the TYPE attrs; emitted per instance as an INITIALIZE line

Ports, variables and SET parameters share one name space; variables and SET parameters are resolved first. A SET parameter can be overridden per instance.

MACRO – assemblies

MACRO macro_name
  [ SET ident = value { , … } ; ]                         (no SET arrays in a MACRO)
  [ STREAM { { INPUT | OUTPUT } : port_name ( stream_type ) ; } ]
  [ UNIT { { model_name | macro_name } : instanz
         [ ( ident = { value | set_ident } { , … } ) ] ; } ]
  [ FLOWSHEET { stream_type : macro_port = instanz.port ; } ]
  [ EQUATION { equation | assert } ]                (no IF, FOR or CALL in a MACRO)
EndMark

set_ident → SET parameter name of the macro
instanz   → ident

The FLOWSHEET lines of a macro are port bindings: an alias, no extra equation; every port gets exactly one binding. set_ident passes a SET value through: on instantiation the possibly overridden value is inserted. Macros may instantiate macros, recursively; cycles are reported with the chain.

PLANT – the plant

PLANT
  [ UNIT { { model_name | macro_name } : instanz
         [ ( ident = { value | [ value { , … } ] } { , … } ) ] ; } ]
  [ FLOWSHEET { stream_type : instanz.port [ [ index ] ] = instanz.port [ [ index ] ] ; } ]
  [ EQUATION { anweisung } ]
  [ INITIALIZE { anweisung } ENDINIT ]
EndMark

Each connection joins exactly one OUTPUT to exactly one INPUT; one equality is created per stream field. Whole-array and element connections exist.

Model-level statements

Statements appear in EQUATION and INITIALIZE of MODEL and PLANT, and in the flat model, which without sections consists only of declarations and statements.

anweisung → decl | equation | call | spec | assert | forBlock | ifBlock | initBlock

decl      → ident [ [ groesse ] ] AS { REAL [ ( attrs ) ] | INTEGERPARAMETER ( integer ) } ;
            (arrays are 0-based: A[N] = A[0] … A[N-1]; Value: [list] fills element by element)
equation  → [ EQN-zahl : ] expression = expression { = expression } ;
            (a chain creates several equations; residual LHS − RHS)
call      → CALL ( qname ) = builtin ( qname { , qname } ) ;
          | qname = builtin ( qname { , qname } ) ;
            (inputs must be variables; the count is checked against the built-in registry)
spec      → qname.spec = spec_name ;                          (array-wide and structural)
assert    → ASSERT expression vergleich expression ;
            (checked AFTER the converged run, not a constraint)
forBlock  → FOR ( ident = expression ; ident { <= | < } expression )
              { anweisung }
            ENDFOR
            (loop variable ONE character; resolved at flatten/parse time,
             index expressions such as [i-1] are constant-folded)
ifBlock   → IF ( log_condition ) [ THEN ] { anweisung }
            { ELSEIF ( log_condition ) [ THEN ] { anweisung } }
            [ ELSE { anweisung } ]
            ENDIF
initBlock → INITIALIZE { anweisung } { ENDINIT | END }
            (in INITIALIZE only .spec conditions, no ELSE)

If an IF condition is constant at parse or flatten time (Fixed quantities, INTEGERPARAMETER, .spec comparison), it is folded structurally: only the active branch exists. The condition variables are recorded; changing one of them triggers a rebinding before the next run (structure switching, including a change of degrees of freedom through spec statements). Non-constant conditions remain run-time IFs.

The .task run language

Run scripts (extension .task, executed by the TaskRunner or in the Task tab of the GUI) control sequences of solver runs over one model: specification changes, value transfer, ramps and convergence loops. One statement per line; comment with # to end of line. In the grammar each statement is shown on its own line.

MODEL pfad.nfml                          (loads the model; INCLUDE is resolved)
TOL value
MAXITER integer
RELAX value
SOLVER ident
ONFAIL { STOP | CONTINUE }
FIX qname [ = value ]                 (without value: freeze at the solved value)
FREE qname
SET qname = value
TRANSFER qname -> qname              (copies the solved value)
RUN [ freitext ]                       (solves; the text names the run in the log)
PRINT qname { qname }
LOOP integer [ UNTIL qname value ]
  { anweisung }
ENDLOOP

LOOP repeats the body up to integer times; with UNTIL the loop ends earlier as soon as the relative change of qname between two passes is below value. Loops cannot be nested. Before every RUN the runner checks the degrees-of-freedom balance (number of equations equals number of free quantities) and reports deviations together with the candidates from the bipartite matching.

Example

A compressor and a throttle in series, with boundary conditions at the inlet: twelve stream fields, nine model and connection equations and three boundary conditions. The ASSERT line is checked only after the run.

TITLE Compressor and throttle

DECLARE
  STREAM Gas (W : T : P) ;
$END

MODEL Compressor
  SET PRC = 4.0, ETA = 0.85;
  STREAM
    INPUT  : ein (Gas);
    OUTPUT : aus (Gas);
  EQUATION
    aus.W = ein.W;
    aus.P = ein.P * PRC;
    aus.T = ein.T * (1 + (PRC^0.2857 - 1) / ETA);
$END

MODEL Throttle
  SET K = 0.9;
  STREAM
    INPUT  : ein (Gas);
    OUTPUT : aus (Gas);
  EQUATION
    aus.W = ein.W;
    aus.P = K * ein.P;
    aus.T = ein.T;
$END

PLANT
  UNIT
    Compressor : v (PRC = 6.0);      # SET override per instance
    Throttle    : d;
  FLOWSHEET
    Gas : v.aus = d.ein;             # OUTPUT = INPUT
  EQUATION
    v.ein.W = 10.0;                  # boundary conditions
    v.ein.T = 288.15;
    v.ein.P = 1.0e5;
    ASSERT d.aus.P > v.ein.P;
$END
