envisionz-app-charts

Show tables as line, contour and 3D charts

Overview of the app, as of 29 September 2026. The chart app "Diagramme" loads tables from CSV, H2 or Tecplot, lets you assign a role to each column and draws lines, contours, 3D charts and further types from them. It also accepts tables from other apps.

What the app is for

Results of calculations and measurements come as tables: one row per calculation point, a hundred columns, speed, pressure ratio, efficiency, station quantities. Whether a usable picture comes out depends on which column belongs on which axis and which rows count at all. A performance map, for instance, looks right only if the points of one speed line are joined to each other and not to their neighbours.

The app makes this assignment visible and adjustable. You give each column a role (x, y, function value, group, condition), filter rows and pick a chart type. Whatever is not unambiguous is reported, not decided silently.

What it can do

Loading and roles

From the file to the definition of the chart.

  • Loading CSV, H2 databases and Tecplot files (.plt, with a layout file). An H2 table is mounted without a copy.
  • A tree table of the variables with the roles "as x", "as y", "as f", "as error id" (convergence filter), "as unique id" and conditions or ranges per column. Roles are not guessed from column names.
  • The row filter runs inside the database, not after fetching the whole table.
  • Aliases, computed columns (equations) and hidden columns as properties of the view; the formulas are saved, never the values.
  • Display units in several profiles (SI, imperial and others); the units come from the unit table of the data.
  • A per-column data analysis (minimum, maximum, count, number of distinct values) as the "data tab".

Chart types

The complete set of types of the 2020 predecessor program.

  • Lines (several curves), scatter, area, steps; the role "as y" separates the curves, one per value (one speed per curve).
  • Right-hand Y axis: with the role "as f right" a column goes onto a second axis.
  • 2D contours, as grid or triangulated, as bands or as isolines.
  • 3D: points, surface, volume, plus 3D lines, bars, areas and pies.
  • Category, pie, radar, spider and polar; time series, candlesticks (OHLC), wind and Gantt.
  • Joule or T-s cycle chart with stations and streams, dashed isobars and mixers.

Mesh, boundary and isolines

What a contour shows depends on the mesh beneath it.

  • One mesh choice: grid contour without triangles, triangulation, or cell structure from zone/i/j. Whoever picks triangulation gets triangulation; if the app takes another route, it says so and gives the reason.
  • Cell structure also without index columns (from the position of the points) and with holes where a filter cuts out points. The 3D volume takes the structured route by itself when it is possible, otherwise Delaunay.
  • Grid roles "as x grid", "as y grid", "as z grid": the mesh is built in columns of its own, for example speed times beta for compressor maps, instead of from image coordinates.
  • Triangulation and boundary methods can be chosen from a registry, per chart; the feedback says how many boundary triangles were dropped.
  • The mesh can be touched up by hand: keep or discard individual triangles.
  • Isolines of another variable lie on the chart's own mesh, with levels by count or step size, bounds, a colour per level and labels.

Colour, data points, zoom

Display and checking.

  • Colour scales with bands, legend step and delta coupling; a fixed range applies only if it was set.
  • Data points as an overlay: converged and non-converged points told apart, a crosshair, and a click on a point shows the whole row. The points are fetched without loading the whole table.
  • Min/max marks name a value from the picture; marks and a background image (with selectable alignment, also zoomed along with the data) survive saving.
  • A zoomed section stays, and undoing the zoom returns to the typed axis limits.

Comparing and envelopes

Two states against each other, boundaries on top.

  • Morph: the difference picture of two data states. The conditions of the comparison replace those of the base state; shown are the difference B − A, the relative deviation or the ratio. Points without a partner, ambiguous ones and omitted ones are reported.
  • Envelope as a card in the tool rail: lines, areas and labels individually adjustable (colour, dash, opacity, font, place, angle), chosen through a checkbox tree. Storage format .hkx (XML); writing back from the card is possible.
  • Tecplot layout: axes, zones, colours, line widths and symbols are taken from the layout file; several frames give a group with one chart each.

Saving, exchange, embedding

Nothing is lost on closing.

  • The complete chart definition (roles, aliases, equations, column filter, options) as XML; older files of the first version are still read.
  • Settings live next to the running program, so the folder can be taken along.
  • Export as SVG; tables from other apps arrive through an event, but only those addressed to "charts" or without a target.
  • The group interface (ChartWorkbench) is embedded as a building block for other apps, for example in the EPDS app.

Data and formats

  • Reads: CSV (type detection per column), H2 (.mv.db, units from <TABLE>_UNITS), Tecplot .plt with .plt.lay or .lay, envelopes .hkx, chart definitions; tables of other apps as an event.
  • Writes: chart definition (XML), envelopes (.hkx), SVG, the H2 file next to a loaded CSV with the shared table name CSV_DATA, the settings file.
  • Session: the path of the data source and the complete chart definition are remembered.

What it builds on

  • framework-chart: all the drawing, from lines and contours to cycle charts and envelopes.
  • framework-chart3d: the 3D view.
  • framework-data: CSV, H2, formulas, units, triangulation, Tecplot reader, slices through the database.
  • framework-swing: navigation tree, option cards, background runner, zoom field, checkbox tree, colour picker.
  • framework-thermo: the mixing calculation in the cycle chart.
  • framework-api: registration as an app, session, events.

The app is the first user of the framework's shared chart layer. The EPDS app embeds its interface and supplies it with tables; other applications use the same building blocks.

State and limits

The app is in use, and the whole set of types of the predecessor program has been built. Help exists in four topics (overview, roles of the variables, contours and 3D, saving and exchange) in both languages.

Tested are the main path from loading to a finished chart and many single questions: mesh choice and boundary methods, H2 mounting, isolines on the mesh, colour scales, data points, morph, zoom, background image, display units, equations and storage formats. The test programs draw into an image and measure on the image; they come with counter-tests using deliberately corrupted code.

Limits: In the cycle chart the computed mixer is finished in the calculation core, but its input in the interface is still missing. The second Y axis exists only for the line types. The move of all option dialogs of the predecessor program to cards is not finished.
