envisionz-app-hdf5reader

Viewing HDF5 files: tree, value table and experiment catalogue, read-only

Overview of the app, as of 29 September 2026. A viewer for HDF5 files in pure Java, without a native library and without a third-party library, which in addition opens collections of experiment files through a catalogue.

What the app is for

HDF5 is the usual format in which simulation and measurement programs store large number arrays: groups like directories, inside them datasets with units and attributes. Anyone who wants to know what is in such a file used to need a script of their own or a third-party program. The app opens the file, shows the tree, presents each dataset as a table and writes it out as CSV.

For result files stored in a fixed order of collection, project and experiment there is also the catalogue tab: it reads a catalogue file, lists the files of an experiment without opening them, and shows columns, values, the embedded model texts and the header data of a chosen file. The model texts are the most interesting part: the complete model that was used for the calculation sits next to the result.

What it can do

“File” tab: tree and values

The tree of the file on the left, the view of the selected node on the right. The tree fetches the children of a group only when it is expanded; the value table reads only the page (4096 rows) that contains the visible rows. Nothing is read that nobody looks at; that matters with a real file of tens of thousands of datasets.

Views

  • tree with groups, datasets and attributes
  • value table that scrolls horizontally: every column 80 px, the full name is in the header tooltip
  • status line that also states any capping

CSV card

  • separator: semicolon, comma, tab, vertical bar
  • decimal mark: point or comma
  • header row with or without column names, optionally with unit (pt3 [Pa])
  • only the 5000 rows shown, or all

Separator and decimal mark belong together: a German spreadsheet expects semicolon and decimal comma, and anyone who changes only the separator gets a file that opens and in which every number is wrong. Comma as both separator and decimal mark is rejected. Columns of unequal length get empty cells and are not truncated.

“Catalogue” tab: collection, project, experiment

Open a catalogue file (.dbs), then choose by collection, project and experiment. The file list shows name, creation time and version and reads only the header records for it; an experiment folder with hundreds of files stays usable. A file that merely has the right name but is unreadable stays in the list and is marked unreadable rather than disappearing. The content of a chosen file is loaded only on selection, and in the background.

One button takes the chosen file into the File tab and switches there. A second hands it to the byte viewer (see file analysis) if that is running; the apps do not know each other. The diagnosis shows the same text as the command-line checking tool for catalogues, produced by the same code.

Loading level by level

Next to each selection field there is a load button, plus a reset; the buttons are Fugue icons with tooltips. Each level stands on its own: collections from a .dbs, projects from a collecting directory or a single project directory, experiments likewise. Whoever loads one level locks the other two; the automatic chain of selection is then off. Reset frees everything and is always available.

Passing on as a table

“Load as table” publishes the table for applications such as Charts that can display it. The table route is the exception: it has a stated upper limit of 200,000 cells instead of silent memory use, because as text the same amount of numbers needs about thirteen times the memory (measured on a million values: 7.9 MB as numbers, 102 MB as text).

Data and formats

  • Reads: HDF5 files (.h5, .hdf5, .he5): groups, attributes, scalars and arrays of any rank, integers and floating-point numbers, fixed and variable-length text, compound types, chunked, deflate and shuffle datasets and unlimited growing ones, soft links.
  • Catalogue: .dbs catalogue files; containers with a name directory, soft links and model-text sections.
  • Writes: only CSV, and only on explicit request. The HDF5 files themselves are never changed.
  • State: the path of the open file; a vanished or invalid address is reported rather than answered with an error dialog.

What it builds on

  • The HDF5 module framework-hdf5 – the reader itself, pure Java, read-only and without dependencies. Plus a bridge of its own that provides datasets as number arrays (for plotting and computing) or as a table (for units, statistics, CSV).
  • framework-fileformats – the framework’s file-format building blocks; the app lists the module on its class path.
  • framework-data – loaded tables, which the app passes on.
  • framework-swing – the vertical toolbar with cards of 350 px, background runner, icons with tooltips.
  • framework-core and framework-api – basic building blocks and registration as an app.

Status and limits

The app is fully usable for tree, values, CSV, catalogue and diagnosis. It is tested on files written by a third-party implementation of the format: a file this reader had produced itself would only prove that it matches itself. The values in them follow closed formulas and are recomputed; a swapped index or a wrongly read byte order would show. The catalogue probe (84 checks) measures each level separately; the container-file probe (47) checks the header and model-text areas on real bytes, with nine counter-tests; the viewer probe (29) checks registration and state.

Deliberately absent or open: a write path for HDF5; a button that gives datasets directly as a number array to the charts (today it goes through the table); a second tree for netCDF files, although the framework can read them; very long or circular and external links are not yet measured against real bytes.
