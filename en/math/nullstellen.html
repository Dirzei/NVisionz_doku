Optimisation and root finding – Brent, Nelder-Mead, Levenberg-Marquardt

The computation behind Optimize: root and minimum in one variable after Brent, the simplex of Nelder and Mead without derivatives, and Levenberg-Marquardt for non-linear least squares – with pseudocode following the source, recomputed examples, checks and limits. The methods with gradient are on the page L-BFGS, L-BFGS-B and SQP.

What this is about

Optimize is the small toolbox used by framework-stats and framework-thermo; it moved here from framework-stats unchanged (bit-identical). Four tasks:

MethodTasktypical use
brentRoot(f, a, b, tol)f(x)=0f(x) = 0 in [a,b][a, b] with a sign changetemperature for an enthalpy, distribution quantiles
brentMin(f, a, b, tol)minimum of ff in [a,b][a, b]one-dimensional search, Box-Cox parameter
nelderMead(f, x0, tol, maxIter)minimum without derivatives, nn variablesmaximum likelihood, noisy or discontinuous objectives
levenbergMarquardt(r, p0, tol, maxIter)minp⁡‖r(p)‖22\min_p \|r(p)\|_2^2curve fitting to measured data

Unlike Lbfgs, LbfgsB and Sqp these methods return only the result (Levenberg-Marquardt additionally the sum of squares, iterations and converged), no message. What is returned on failure is listed under limits.

Root after Brent

If ff has different signs at the ends of [a,b][a, b], there is a root in between (for continuous ff). Bisection finds it for sure but only halves – one binary digit per evaluation. The secant and inverse quadratic interpolation (a parabola x(f)x(f) through three points, evaluated at f=0f = 0) converge superlinearly near the root but can jump far away. Brent's method (1973, after Dekker) combines both: it always keeps a bracket [b,c][b, c] with a sign change, tries the fast step and takes it only if it stays inside the bracket and shrinks faster than bisection; otherwise it bisects.

With the last three points a,b,ca, b, c (bb the best approximation) and s=fb/fas = f_b/f_a, q=fa/fcq = f_a/f_c, r=fb/fcr = f_b/f_c the interpolation step is

Δ=pq',p=s(2xmq(q−r)−(b−a)(r−1)),q'=(q−1)(r−1)(s−1),\Delta = \frac{p}{q'}, \qquad p = s\big(2 x_m q (q - r) - (b - a)(r - 1)\big), \qquad q' = (q - 1)(r - 1)(s - 1),

with xm=(c−b)/2x_m = (c - b)/2; with only two distinct points the secant p=2xmsp = 2 x_m s, q'=1−sq' = 1 - s.

Pseudocode – Optimize.brentRoot(f, a, b, tol)

fa ← f(a);  fb ← f(b)
if fa = 0: return a;   if fb = 0: return b
if fa · fb > 0: return NaN                                  no sign change
c ← a;  d ← e ← b − a
for iter ← 1 to 200:
    if fb · fc > 0:  c ← a;  fc ← fa;  d ← e ← b − a                renew the bracket
    if |fc| < |fb|:  a ← b, b ← c, c ← a (with values)                  b is the best approximation
    tol1 ← 2 · 1e−12 · |b| + tol/2;   xm ← (c − b)/2
    if |xm| ≤ tol1 or fb = 0: return b
    if |e| ≥ tol1 and |fa| > |fb|:
        secant (a = c) or inverse quadratic interpolation → p, q
        if 2p < min(3 xm q − |tol1 q|, |e q|):  e ← d;  d ← p/q      interpolation accepted
        else:  d ← xm;  e ← d                                         bisection
    else:  d ← xm;  e ← d
    a ← b;  fa ← fb
    b ← b + (|d| > tol1 ? d : sign(xm) · tol1);   fb ← f(b)
return b                                                           after 200 steps, without a flag

Source: envisionz-framework-math/src/envisionz/math/optimierung/Optimize.java, brentRoot (structure as zbrent in Numerical Recipes).

Convention in the framework: the internal machine precision is fixed as EPS = 1e-12, not 2.2⋅10−162.2 \cdot 10^{-16}. The achievable accuracy is therefore ≈2⋅10−12|x|+tol/2\approx 2 \cdot 10^{-12}\,|x| + \text{tol}/2: for a root around 3000 (a temperature in K) the search ends at the latest with a bracket of about 6⋅10−96 \cdot 10^{-9}, even if a smaller tol is requested.

Examples. x2−2x^2 - 2 on [0,2][0, 2], tol = 1e-12: 1.41421356237313641.4142135623731364, deviation from 2\sqrt 2 4.1⋅10−144.1 \cdot 10^{-14}, 9 evaluations. cos⁡x−x\cos x - x on [0,1][0, 1]: 0.73908513321515590.7390851332151559, 8 evaluations – bisection would need about 40 for the same accuracy.

Minimum after Brent

For the minimum of a function of one variable on [a,b][a, b] the same principle applies: the golden section reliably shrinks the bracket by the factor 0.6180.618 per evaluation; parabolic interpolation through the three best points x,w,vx, w, v converges faster but is only taken if the step lies inside the bracket and is smaller than half the step before last. The vertex of the parabola is at

x−pq,p=(x−v)2(fx−fw)−(x−w)2(fx−fv),q=2((x−v)(fx−fw)−(x−w)(fx−fv))x - \frac{p}{q}, \qquad p = (x - v)^2 (f_x - f_w) - (x - w)^2 (f_x - f_v), \qquad q = 2\big((x - v)(f_x - f_w) - (x - w)(f_x - f_v)\big)

(in the code with the sign rearranged so that the denominator is positive). The golden step is 0.3819660⋅0.3819660 \cdot (distance to the farther end of the bracket), with 0.3819660=(3−5)/20.3819660 = (3 - \sqrt 5)/2.

Pseudocode – Optimize.brentMin(f, a, b, tol)

x ← w ← v ← a + 0.381966 (b − a);  fx ← fw ← fv ← f(x);  d ← e ← 0
for iter ← 1 to 200:
    xm ← (a + b)/2;  tol1 ← tol·|x| + 1e−12;  tol2 ← 2 tol1
    if |x − xm| ≤ tol2 − (b − a)/2: return x
    if |e| > tol1:  parabola through x, w, v → p, q
        if |p| < |q e/2| and x + p/q in (a, b):  e ← d;  d ← p/q  (near an end: ±tol1)
        else golden section
    else golden section:  e ← (x ≥ xm) ? a − x : b − x;  d ← 0.381966 e
    u ← x + (|d| ≥ tol1 ? d : sign(d) · tol1);  fu ← f(u)
    update the bracket [a, b] and the three best points x, w, v
return x

Source: Optimize.java, brentMin (structure as brent in Numerical Recipes).

Example and accuracy limit. x4−3xx^4 - 3x on [0,2][0, 2] with tol = 1e-10: result 0.90856029256231810.9085602925623181, exact (3/4)1/3=0.9085602964160698(3/4)^{1/3} = 0.9085602964160698 – deviation 3.9⋅10−93.9 \cdot 10^{-9}, 19 evaluations. This is not a weakness of the method but a property of every minimum: near x*x_*, f(x)−f*≈12f''(x*)δ2f(x) - f_* \approx \tfrac12 f''(x_*)\,\delta^2, and as soon as this is below the rounding step of ff (ε|f*|\varepsilon\,|f_*|), the points can no longer be distinguished. Here: f*≈−2.04f_* \approx -2.04, f''≈9.9f'' \approx 9.9 → δ≈2⋅2.2⋅10−16⋅2.04/9.9≈10−8\delta \approx \sqrt{2 \cdot 2.2\cdot 10^{-16} \cdot 2.04/9.9} \approx 10^{-8}. A minimum can only be located in xx to about ε\sqrt\varepsilon relatively; tol below 10−810^{-8} gains nothing.

Nelder-Mead simplex

The method of Nelder and Mead (1965) needs no derivatives, only function values. It carries a simplex of n+1n + 1 points in Rn\mathbb{R}^n (a triangle in the plane) and in each iteration replaces the worst point by a better one on the line through the centroid of the others – the simplex moves, stretches in favourable directions and contracts around the minimum.

Pseudocode – Optimize.nelderMead(f, x0, tol, maxIter)

simplex: x0 and x0 + δ_i e_i with δ_i = 0.05 |x0_i| (or 0.00025 if x0_i = 0)
for iter ← 1 to maxIter:
    sort points by f ascending (x_0 best, x_n worst)
    if |f_n − f_0| ≤ tol · (|f_0| + |f_n| + 1e−12): stop
    c ← centroid of x_0 … x_{n−1}
    x_r ← c + (c − x_n)                                            reflection, α = 1
    if f(x_r) < f_0:                                              better than the best
        x_e ← c + 2 (x_r − c);  x_n ← (f(x_e) < f(x_r)) ? x_e : x_r         expansion, γ = 2
    else if f(x_r) < f_{n−1}:  x_n ← x_r
    else:
        x_c ← c + ½ (x_n − c)                                        inside contraction, ρ = ½
        if f(x_c) < f_n:  x_n ← x_c
        else:  x_i ← x_0 + ½ (x_i − x_0) for all i ≥ 1                  shrink, σ = ½
return the best point

Source: Optimize.java, nelderMead. There is only the inside contraction (from the worst point towards the centroid), no outside one.

Example. Rosenbrock from (−1.2,1)(-1.2,\ 1), tol = 1e-12, maxIter = 5000: (1.0000000000003,1.0000000000007)(1.0000000000003,\ 1.0000000000007) with 321 evaluations. For comparison, L-BFGS with gradient needs 47 evaluations – for smooth functions with a gradient Nelder-Mead is the slower route; its value lies with objectives without derivatives.

Convention in the framework: stopping solely on the relative spread of the function values in the simplex, not on its size. A simplex lying on a flat plateau therefore stops early; a function whose values at the minimum differ greatly in magnitude (e.g. f*=0f_* = 0) needs the term 10−1210^{-12} in the denominator. The step of the initial simplex is 5 % of each coordinate.

Levenberg-Marquardt

In curve fitting we seek parameters pp with which a model best matches the measured points: minp⁡∑iri(p)2\min_p \sum_i r_i(p)^2 with the residuals ri=model(xi;p)−yir_i = \text{model}(x_i; p) - y_i. The Gauss-Newton method linearises r(p+δ)≈r+Jδr(p + \delta) \approx r + J\delta (JJ the Jacobian of the residuals) and solves the normal equations JTJδ=−JTrJ^T J\,\delta = -J^T r. Far from the optimum these steps are often too large. Levenberg (1944) and Marquardt (1963) damp them:

(JTJ+λdiag⁡(JTJ))δ=−JTr.\big(J^T J + \lambda\,\operatorname{diag}(J^T J)\big)\,\delta = -J^T r.

Small λ\lambda: Gauss-Newton, fast near the solution. Large λ\lambda: a short step in the direction of (column-scaled) steepest descent, safe far away. Using the diagonal of JTJJ^T J instead of the identity makes the damping independent of the scaling of the parameters. λ\lambda is decreased after success and increased after failure.

Pseudocode – Optimize.levenbergMarquardt(r, p0, tol, maxIter)

p ← p0;  r ← r(p);  cost ← r·r;  λ ← 1e−3
for iter ← 1 to maxIter:
    J ← forward differences, column a with h = 1e−7 (|p_a| + 1e−7)         n evaluations
    form JᵀJ, Jᵀr
    up to 12 trials:
        δ ← LinAlg.solve(JᵀJ + λ (diag(JᵀJ) + 1e−12), −Jᵀr);  singular → λ ← 10 λ, continue
        if cost(p + δ) < cost:
            improvement ← cost − cost_new;  p ← p + δ;  λ ← max(0.3 λ, 1e−12)
            if improvement ≤ tol · (cost_new + 1e−12): converged
            break
        else λ ← 10 λ
    if converged or no trial successful: stop
return (p, cost, iter, converged)

Source: Optimize.java, levenbergMarquardt and jacobian. The linear system is solved by LinAlg.solve (LU without threshold, see dense linear algebra).

Examples. y=2e0.3xy = 2\,e^{0.3x} at x=0…5x = 0 \dots 5 (exact data), start (1,0.1)(1,\ 0.1), tol = 1e-14: after 10 iterations p=(2,0.3)p = (2,\ 0.3), sum of squares 0, 37 evaluations of the residuals. With noisy values y=(2.1,2.6,3.7,4.9,6.5,9.1)y = (2.1,\ 2.6,\ 3.7,\ 4.9,\ 6.5,\ 9.1): p=(1.978,0.3033)p = (1.978,\ 0.3033), sum of squares 0.0580.058, 9 iterations.

Convention in the framework: start with λ=10−3\lambda = 10^{-3}; after an accepted step λ←max⁡(0.3λ,10−12)\lambda \leftarrow \max(0.3\lambda, 10^{-12}), after a rejected one λ←10λ\lambda \leftarrow 10\lambda. Converged means: the last improvement of the sum of squares was relatively smaller than tol. The Jacobian is always formed with forward differences; an analytic one cannot be passed.

How it is checked

The Optimizeprobe (10 checks, from the former OptimizeRngTest in framework-stats) compares by |actual−expected|≤tol(1+|expected|)|\text{actual} - \text{expected}| \le \text{tol}\,(1 + |\text{expected}|):

  • NM4-OP-01: brentRoot x2−2x^2 - 2 on [0,2][0, 2] → 2\sqrt 2, tol 10−910^{-9}.
  • NM4-OP-02, 03: brentMin (x−3)2(x - 3)^2 → 3 and x4−3xx^4 - 3x → 0.90856029640.9085602964, tol 10−610^{-6}.
  • NM4-OP-04: nelderMead Rosenbrock from (−1.2,1)(-1.2,\ 1) → (1,1)(1, 1), tol 10−310^{-3}.
  • NM4-OP-05 … 07: levenbergMarquardt y=2e0.3xy = 2\,e^{0.3x} → (2,0.3)(2,\ 0.3), tol 10−410^{-4}, converged.
  • NM4-OP-08, 09 (new with the move): without sign change NaN; a root exactly at the end is returned exactly.

The proof “bit-identical” for the move: the probes of all modules involved were run before and after the move and the outputs compared line by line.

Limits

  • brentRoot needs a bracket with a sign change; without it the result is NaN. Double roots (touching points, no sign change) are not found. After 200 iterations the last approximation is returned without a flag. Accuracy at best ≈2⋅10−12|x|\approx 2 \cdot 10^{-12}|x| (see convention).
  • brentMin finds a local minimum in [a,b][a, b], with several not necessarily the lowest; accuracy in xx fundamentally only about ε\sqrt\varepsilon.
  • nelderMead has no convergence guarantee (there are examples where the simplex collapses at a non-minimum), returns no flag and becomes slow with many variables (from about ten).
  • levenbergMarquardt: forward differences limit the accuracy of the Jacobian to about 10−710^{-7} relative; with strongly correlated parameters JTJJ^T J becomes ill-conditioned (normal equations square the condition). Local minima as with all methods.
