Switches, comparison and continued training

What the command line decides itself, although table generator, comparison and training live in the framework: which switches apply, how a recognized CSV is read, what happens to missing pages and when a model is taken over from another architecture.

What this is about

The measuring path has three steps. The tool creates tables with a known truth, the PDF digitizer recognizes them, and the tool compares the result with the truth. The numbers of the comparison come from framework-ocr; the tool only decides which pages go into the sum.

Switches per task

Every task has its own set of allowed switches. A switch that does not fit the task gives return value 2 with its name instead of being skipped silently; a typo thus never changes a measurement unnoticed. An argument without a leading dash is an error as well. An unknown task names all existing tasks in the message.

Lists such as font sizes, resolutions, ruling styles, alignments and ageing steps are checked completely before any work. The wrong value is named in the message.

How the recognized CSV is read

The “all pages” CSV carries the page number in column 1. Quoted fields may contain the separator, inner quotes are doubled. A cell whose text ends in ? was marked as unsure by the recognizer itself: the question mark is cut off, and a wrong value in that cell counts as unsurely wrong, not as surely wrong. This distinction is the core of the measurement: a surely wrong value is dangerous because nobody checks it.

The measure itself (matching of cells, numbers exact, character error rate) is described on the digitizer's measuring page.

Which pages go into the sum

The pages of the truth are compared. If one of them is missing in the CSV, it is named and skipped, not counted as an empty page: otherwise a recognition run that did not process a page at all would be punished with missing numbers throughout and the sum would be distorted. If no page at all can be compared, there is no sum but the message “keine Seite verglichen” (no page compared).

Continued training from another architecture

If the target file of a line training already exists, it is continued. With -von: a new target starts with the weights of another model. This only works if the two architectures differ solely in the stride of the time axis (say 4 and 2): then all weights have the same shape. If anything else differs, the call ends with 3 and nothing is written.

Limits

  • The comparison only measures what the digitizer outputs as CSV; an error in splitting the table into cells shows up as wrong or missing numbers.
  • The training runs in the probes are deliberately tiny (two steps); they check the path, not the quality of a model.
