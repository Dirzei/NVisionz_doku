envisionz-app-settings

The settings of the host in one place

Overview of the app, as of 29 September 2026. A tree of areas on the left, the chosen area on the right. Appearance, sizes, language, start directories per app, database defaults, security and diagnostics are set here; every change takes effect at once and is written at once.

What the app is for

A workspace with many apps has settings that belong to no single app: the theme of the user interface, the language, the size of controls and icons, the directory where each app looks for files first. These values used to live in modal windows of the main window. The app puts them in one place, in the layout familiar from development environments: tree on the left, content on the right.

The app is an ordinary app of the host, not a fixed tab. It is opened like any other, and it can be opened more than once. Each card reads its state afresh when shown, so two open settings tabs always show the same thing.

What it can do

There are no OK and Apply buttons. Every card writes on every change, because when the program exits the apps are no longer closed one by one. What would only be written on closing would be lost on the usual way out.

Appearance

The theme of the user interface, as a list of all available themes. The list is generated from the host's inventory, so a newly added theme appears by itself.

Sizes

Scaling of the user interface and of the icons.

Language

User interface language. The change takes effect at once, without a restart.

Directories

The start directory per app. The card lists all apps, including those without an entry, and shows the same inventory the host remembers while working. The remembered state now survives across sessions.

Database

Size of the database row cache and the number of preview rows. Input outside the permitted range is clamped, and the field then shows the value that applies.

Security

Upper limit for unpacked data, as protection against decompression bombs. It applies to every unpack call of all compression methods in the framework and hence to all file formats built on them. Adjustable from 16 to 2047 MiB, default 1024 MiB, effective from the next unpacking. If a start option is set, the card shows which limit actually applies.

Diagnostics

Switches for the watchdog on the event thread and for the interaction trace, plus a report. The card switches the same facilities at run time that a start option otherwise switches on. The heap ceiling of the finished executable is shown as an actual value; it cannot be changed at run time.

About

Shows the information text of the program, formerly a modal window in the help menu.

An area can be opened from outside: the help menu focuses the app and sends it an event naming the wanted area.

Data and formats

The app reads and writes property files in the settings folder of the workspace. It creates no storage of its own but serves the existing ones:

AreaFile
Appearance (theme)theme.properties
Sizes, languagesettings.properties
Directoriesverzeichnisse.properties

A workspace without a file counts as “nothing set” and falls back to the defaults; it does not inherit values from the previous one.

What it builds on

  • swing: the storage of the host settings, theme, language, scaling, the directory list of the apps, the input fields and the event-thread watchdog. The app is the user interface for it.
  • api: the app interface, the event that opens an area and the list of available apps.
  • core: start-up of the host and registration of the apps.
  • data: the row cache of the database that is set here.
  • compress: the unpack limit. It reads the limit set here from a system property that swing sets at start-up, so that swing needs no compile-time dependency on it. The app itself is the only one that depends on compress.

State and limits

  • All eight areas exist and are written on every change.
  • Diagnostics cannot measure the program start: what happens before the first click still goes through the start options for the watchdog and the interaction trace.
  • The heap ceiling of the finished executable is a build-time setting and is therefore only a display, not a field.
  • The earlier modal windows for theme and settings still exist and are still offered in the Apps menu.
  • The preview limit of the database does not yet apply in every app; the chart app has so far kept its own.
  • Settings of individual apps live in the apps themselves, not here. There is no help page; the explanations are tooltips on the fields.
  • The file chooser of the directories card cannot be checked without a screen and is therefore not covered by the probes.
